# ForgePlan Project Map — гипотеза, материал, гайд

Проверка гипотезы: **«можно ли автоматически генерировать интерактивную карту проекта
(онбординг + архитектура) для любого проекта, где есть ForgePlan?»** — и что мы выяснили.

**Дата:** июнь–июль 2026. **Статус: гипотеза ПОДТВЕРЖДЕНА** — рабочий спайк есть, полная
архитектура спроектирована и выверена против реального кода `forgeplan-web`.

---

## 1. Гипотеза и как проверяли

Отправная точка — тула `effective-html` (генерит красивые интерактивные HTML-схемы по доке).
Вопрос: сделать **своё, ForgePlan-native** — чтобы в любом проекте с forgeplan агент собрал данные,
а фронт нарисовал интерактивную карту для онбординга и понимания архитектуры.

Проверяли в 3 шага:
1. **MVP-петля** (`run.mjs`) — headless `claude -p` сканирует репо → пишет self-contained HTML-карту.
   → сработало: получили `dev/forgeplan-map.html` (44 КБ, интерактив) по всему репо ForgePlan.
2. **Спайк** (`spike/index.html`) — вручную довели до нужного вида: детерминированный рендер из
   «файла фактов» (JSON) чистой функцией, зоны/карточки/связи/потоки/drag-pan/zoom/minimap/темы.
   → доказало: **данные ↔ вид разделяемы, рендер детерминирован** (тот же JSON → та же картинка).
3. **Дизайн полной системы** (`MASTER-SPEC.md`, 3 многоагентных design-воркфлоу) — выверен против
   реального `forgeplan-web` (у него УЖЕ 7 видов графа + mosaic-движок; мы добавляем 8-й вид +
   слоистую JSON-схему + агент-пак в marketplace).

## 2. Что выяснили (ключевые находки)

- **Разделяй модель и вид.** Агент(ы) выдают **слоистый JSON** (`canvas · composition · zones ·
  layers · nodes · mega-nodes · edges`); фронт рисует **чистой функцией** → детерминизм +
  идемпотентность. Ноды **без x/y** — геометрию считает рендер.
- **`forgeplan-web` — не пустой холст:** уже зрелый graph-фронтенд (Force/Radial/Tree/Sunburst/
  Matrix/Lanes/Sankey + Mosaic + layout-движки). **Расширяем, не переписываем.** `edges` карты —
  байт-точный суперсет его `GraphEdge {from,to,relation}` → 7 старых видов не ломаются.
- **Курируемая сетка зон, не авто-раскладка.** Глобальный авто-layout (ELK) выглядит «раскидано»;
  композиция задаётся дизайном (шаблоны-данные), внутри зон — алгоритмически. Зоны **нейтральные**
  (без рейнбоу, без левого бордюра).
- **Библиотека композиций** (шаблоны по типам проектов) + 6 примитивов раскладки из корпуса
  `effective-html` (рама+рельс · сетка карточек · граф · стек секций · дорожки · таймлайн).
- **Оркестрованный процесс (полный, 8-агентный)** в marketplace: дирижёр + 3 сканера (в СВОИ
  scratch-файлы, не общий) + zone-extractor + edge-verifier + map-emitter (единственный пишет
  map.json) + детерминированный guardian. Профиль EMITTER + write-path-хук → forgeplan-артефакты
  тронуть нельзя (красная линия #11 структурно).
- **Онбординг-лэйаут** в forgeplan-web: отдельный `/onboard`, tour по зонам (данные-driven, без
  модели), чат из map.json (мгновенно, с цитатами), drill в стандартные виды за деталями.
- **Совпало с индустрией 2026** (DeepWiki / Understand-Anything / Graphify): commit-граф,
  guided-tour, чат с цитатами, «найдено vs угадано». Наш дифференциатор — **типизированный граф
  решений ForgePlan** поверх структуры кода.

## 4. Как посмотреть / запустить

- **Спайк:** открой `spike/index.html` двойным кликом (или `open spike/index.html`). Потыкай зоны,
  блоки (справа описание + связи), чипсы-потоки, тему; тащи холст мышью, `Ctrl/⌘+колесо` — зум.
- **Первую карту:** открой `forgeplan-map.html`.
- **Петлю (нужен `claude` CLI):** `node run.mjs` (скан текущего репо → HTML) или `--dry-run`.
- **Спеку:** читай `MASTER-SPEC.md` — там всё, включая 3 запроса для чатов репозиториев.

## 5. Куда дальше (строим полноценно)

Спека размещена в трёх репо:
- `forgeplan-web/docs/PROJECT-MAP-SPEC.md` — рендерер (8-й вид + `/onboard`).
- `ForgePlanMarketplace/forgeplan-map-pack/` — агент-пак (процесс + скиллы + композиции + schema).
- ForgePlan core — тонкая CLI `forgeplan map build/serve/validate` + MCP `forgeplan_map_get`.

Готовые **три запроса** (marketplace / web / core) — в конце `MASTER-SPEC.md` §23 и в переписке.
Решение: строим **полный 8-агентный** процесс, с 5 обязательными защитами (render-proof сначала,
3 EMITTER-контроля, раздельный scratch, локальный демон для append, детерминированный guardian).
