# Идентичность документов: как она устроена

Документ в ForgePlan отвечает на три имени. Раньше они путались, и это давало
тихие ошибки: команда правила не тот файл, ссылка вела не туда, два разных
документа сливались в один. Здесь — что есть что и где какое правило
действует.

## Три имени одного документа

| Имя | Пример | Кто его знает |
|---|---|---|
| Номер (alias, display id) | `PRD-074` | человек; читаемые отчёты |
| Канонический ключ | `prd-authentication-rollout-k9bc36517…` | файл, строка индекса, sidecar-и |
| Неизменяемая идентичность | — | ключ после создания не меняется |

Файл документа называется по ключу: `prds/<ключ>.md`. Столкновение ключей
невозможно — в ключе 128 бит случайности.

## Где номер разрешается, а где отказывает

Номер однозначен **везде, кроме одного места**: индекса связей. Там два
документа с одним номером — законная неоднозначность, и она не разрешается
наугад.

Везде остальном команда, получив номер, обязана либо найти **один** документ,
либо отказать. Никогда — «первый попавшийся».

Три различаемых отказа, по коду выхода:

| Код | Что случилось |
|---|---|
| 3 | документа нет |
| 4 | ключ занят двумя документами (столкновение) |
| 5 | номер неоднозначен (несколько документов) |

При 4 и 5 отказ называет **всех** кандидатов: ключ, заголовок и путь файла, —
по ним можно открыть файл и обратиться точно. Отказ никогда не меняет ни
байта на диске.

## Что видно в ответах

Публичные ответы (`get`, `list`, `search`, `new`, `export`) сохраняют поле
`id` в прежнем смысле и **рядом** несут `canonical_key`. Старые читатели,
которые смотрят только `id`, продолжают работать; новые берут ключ.

## Sidecar-и: претензии, фаза, квитанции

Всё, что лежит рядом с документом — `claims/`, `state/`, квитанции, — адресуется
**ключом**, не номером. Имя файла получается из ключа с экранированием
(`/` → `%2F`), так что ключ никогда не выходит из своего каталога и два ключа
никогда не делят файл.

Файлы, записанные до появления ключа, называются номером. Такие файлы
находятся, и при первой записи переезжают на имя по ключу. Читать их можно
и после — старые имена не удаляются, пока миграция не завершена.

## Что осталось решением владельца

- **`git-sync` и миграция индекса.** Сейчас обычный `git pull` старый
  воркспейс не мигрирует — в коде это названо осознанным решением. Тест
  ждёт объявления миграции. Одно из двух должно измениться (issue #540).
- **Поля созданного документа.** Новый документ сейчас получает блок
  заготовки шаблона в теле (`assigned_number`, `depth: tactical / standard / …`).
  Нужно решить, какие поля принадлежат документу, а какие — заготовке.

## Как проверить

```
forgeplan new prd "Заголовок"      # файл по ключу, один frontmatter
forgeplan get <номер>             # 3/4/5 различаются
forgeplan claim <номер>           # претензия по ключу
forgeplan phase <номер>           # фаза по ключу
```
