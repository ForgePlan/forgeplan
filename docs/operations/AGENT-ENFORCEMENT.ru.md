# ForgePlan — Agent Enforcement Guide

Forgeplan **0.38.0** проверяет артефакты и может отказать в конкретной операции жизненного цикла. Он не может заставить произвольного агента соблюдать все инструкции проекта. Инструкции, навыки, хуки хоста, проверки core и CI — отдельные средства контроля с разными границами.

**Пять слоёв, а не пять гарантий:**

| Слой | Средство | Граница |
|---|---|---|
| L1 | `CLAUDE.md` / `AGENTS.md` | Обязательные для агента инструкции, но не блокировка файлов |
| L2 | Установленные навыки | Инструкции процесса; вызов не доказывает выполнение или проверку |
| L3 | Хуки хоста | Проверяют только зарегистрированные события и распознанные данные |
| L4 | Валидация и жизненный цикл CLI/MCP | Ограничения конкретной операции с учётом настроек и флагов обхода |
| L5 | Обязательные проверки CI | Блокируют merge, только если этого требует защита ветки |

## L1: CLAUDE.md / AGENTS.md Instructions

### Что добавить в CLAUDE.md

Опишите политику проекта, а не выдавайте число файлов за встроенный гейт. Следующий пример требует одобрения человеком архитектурных решений. Это выбранная политика, не универсальная проверка прав Forgeplan:

```markdown
## Методология Forgeplan

- До архитектурной работы прочитать правила проекта и относящиеся к ней решения.
- До выбора артефактов маршрутизировать задачу. Для явной автономной классификации
  по ключевым словам использовать `forgeplan route "задача" --level 0`.
  Сопоставить рекомендацию с риском, не принимать её автоматически.
- Для нетривиального архитектурного выбора представить альтернативы, ограничения
  и имеющиеся доказательства. До записи получить требуемое проектом одобрение.
- Выполнить ADI, если этого требует выбранный процесс: предложить гипотезы,
  логически оценить их, затем сопоставить с наблюдаемыми доказательствами.
- Создавать и обновлять артефакты через CLI/MCP, не прямой правкой файлов.
- Валидировать черновики до активации; доказательства описывают реальные проверки.
- Сгенерированный документ, успешная валидация схемы и статус задачи не означают
  завершения реализации. Указать незапущенные проверки и нерешённые находки.
```

Tactical может обходиться без артефакта. Standard, Deep и Critical описывают риск и глубину, а не пороги `<1`, `<5`, `>5` файлов. Выбранный процесс определяет, нужны ли PRD, Spec, RFC, ADR или Epic. Цепочка PRD → RFC → ADR сама по себе не является жизненным циклом: статусы артефакта меняют отдельные команды `activate`, `supersede`, `deprecate`.

### Что добавить в AGENTS.md

```markdown
## Роли агентов

| Роль | Ответственность |
|---|---|
| Исследователь | Читать состояние, решения и доказательства; вернуть находки |
| Маршрутизатор / оркестратор | Выбрать процесс, назначить точные файлы, запустить исполнителей |
| Исполнитель | Изменить назначенные исходники по согласованному контракту |
| Ревьюер / тестировщик | Независимо проверить реализацию, записать реальные результаты |
| Регистратор артефактов / gate | Выполнить разрешённые мутации Forgeplan и проверки готовности |
| Исполнитель трекера | Вести задачи и чеклисты в настроенном трекере |

Автор результата не является его независимым проверяющим. Имя роли в промпте
не выдаёт права: отдельно настройте доступные инструменты хоста.
```

Публичные роли маркетплейса уже, чем «всемогущий оркестратор». `agents-pro:smith` выбирает методологию; `forgeplan-orchestra:task-runner` ведёт настроенный трекер и делегирует правку исходников и мутации Forgeplan. Трекером может быть Orchestra, Jira, Linear, GitHub Issues или другая настроенная система. Orchestra не является универсальным центром управления Forgeplan.

## L2: Skills & Slash Commands

### Skill: `/forge`

`forgeplan setup-skill` устанавливает встроенный навык `/forge` для Claude Code. Команда не устанавливает весь маркетплейс, набор агентов или настройки безопасности хоста.

Для публичных процессов маркетплейса добавьте источник и установите нужные плагины через Claude Code:

```text
/plugin marketplace add ForgePlan/marketplace
/plugin install fpl-skills@ForgePlan-marketplace
/plugin install agents-pro@ForgePlan-marketplace
```

Выберите поставляемую точку входа: например, `/smith-plan` для маршрутизации конкретной задачи или `/forge-cycle` для процесса исполнения. Это инструкции маркетплейса, не дополнительные CLI-команды. Нельзя считать все навыки из личного окружения разработчика частью поставки Forgeplan.

### Proactive Trigger

Публичный prompt router `fpl-skills` даёт только рекомендации. Он не запускает навыки, не даёт согласие, не создаёт артефакты и не обеспечивает гейт одобрения. Автоматическое исполнение требует явной политики проекта и хоста; см. [хуки агентов](AGENT-HOOKS.ru.md).

## L3: Hooks (Pre/Post Automation)

Используйте реальные публичные манифесты плагинов либо осознанно настроенный локальный хук. В `forgeplan-workflow` зарегистрированы Bash safety hook и **рекомендательное предупреждение только для Write** о наличии active PRD. В `fpl-skills` — помощники старта сеанса, Bash safety hook, напоминания о тестах и отчёте, маршрутизатор промпта.

Это не полная проверка покрытия или соблюдения методологии:

- Канонического каталога `.forgeplan/decisions/*.md` нет. Артефакты находятся в каталогах типов: `adrs/`, `prds/`, `rfcs/`, `specs/`, `evidence/`.
- Не используйте вымышленные `drift --files`, `drift --quiet`, `status --brief` или файл `.forgeplan/status`. В 0.38.0 есть `forgeplan drift --json`, `forgeplan status`, `forgeplan health --compact`.
- Обязательные проверки нельзя скрывать через `2>/dev/null || true`.
- Шаблоны строк не блокируют все опасные команды. Важны регистрация и адаптер входных данных: публичный парсер верхнеуровневого `.command` не читает вложенное `.tool_input.command`.
- Установка CLI или одного плагина не устанавливает локальный pre-commit форматтер или evidence hook.

Рабочий JSON событий и точные пути опубликованных скриптов приведены в [AGENT-HOOKS.ru.md](AGENT-HOOKS.ru.md). Не полагайтесь на фрагменты с недокументированными переменными окружения.

## L4: MCP Server

### MCP Tools Design

Запускайте `forgeplan serve` из нужного workspace. Проектный `.mcp.json` Claude Code:

```json
{
  "mcpServers": {
    "forgeplan": {
      "command": "forgeplan",
      "args": ["serve"]
    }
  }
}
```

Флага `serve --mcp` нет. В 0.38.0 сервер предоставляет 73 инструмента. Клиентский список `tools` в таком примере не был бы серверной политикой авторизации.

### MCP Tool Definitions

Ниже — имена MCP без префикса окружения. Входные данные приведены для примера:

| Инструмент | Вход | Назначение |
|---|---|---|
| `forgeplan_status` | `{}` | Число артефактов по типам и статусам |
| `forgeplan_get` | `{"id":"ADR-007"}` | Прочитать решение и его тело |
| `forgeplan_new` | `{"kind":"adr","title":"Session storage"}` | Создать артефакт, не одобрить решение |
| `forgeplan_validate` | `{"id":"PRD-001"}` | Проверить обязательные секции типа и глубины |
| `forgeplan_score` | `{"id":"ADR-007"}` | Оценить связанные текущие доказательства |
| `forgeplan_drift` | `{}` | Отчёт об изменениях workspace; параметра `files` нет |
| `forgeplan_coverage` | `{}` | Покрытие модулей решениями |
| `forgeplan_guard` | `{"target_session_phase":"coding"}` | Проверить переход фазы методологического сеанса |

**MCP-инструмента `forgeplan_context` в 0.38.0 нет.** CLI `forgeplan context ADR-007 --json` принимает ID артефакта, а не путь к исходнику или список файлов. Найдите решения через coverage/search, затем прочитайте сами артефакты.

### CLAUDE.md with MCP

Укажите, какие операции разрешены каждой роли, а не только когда их вызывать. До заявления о завершении исполнитель должен прочитать ответ, включая ошибки и `_next_action`. Подсказка не разрешает выходить за пределы задания.

Claims обозначают намерение работать. `claim --agent worker-1` не запрещает другому исполнителю `update`; при `release` нужно то же имя. Сериализация записей workspace — отдельный механизм. См. [совместную работу агентов](MULTI-AGENT.ru.md).

Фазы артефакта (`shape/validate/adi/code/test/audit/evidence/done`) рекомендательные и отличаются от фаз методологического сеанса (`idle/routing/shaping/coding/evidence/pr`). Смена фазы не запускает тесты и не активирует артефакт. Для lifecycle-типов обычная активация проверяет длину тела, незаполненный шаблон, связь с доказательствами и MUST-правила; облегчённые типы пропускают эти гейты. `force` может обойти методологические гейты и валидацию. Наличие связи не доказывает качество доказательств или одобрение ревью: для приёмки нужна реальная проверка.

## L5: CI/CD Validation

### GitHub Action

Это **пример процесса проекта**, не готовая настройка защиты ветки. На runner должны быть установлен закреплённый бинарь 0.38.0, отслеживаемые файлы `.forgeplan/` и корректный производный индекс. В свежем клоне сначала инициализируйте/восстановите индекс по инструкции установки; `scan-import` для восстановления индекса не подходит.

```yaml
name: Forgeplan Compliance
on: [pull_request]
jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      # До этих шагов подготовить Forgeplan 0.38.0 и индекс workspace.
      - name: Validate artifacts
        run: forgeplan validate --ci
      - name: Check project health
        run: forgeplan health --strict
      - name: Report drift
        run: forgeplan drift --json
```

`validate --ci` завершится с кодом 1 при MUST-ошибках. `health --strict` даёт строгий сигнал health. Пустой workspace и только рекомендательные расхождения фаз могут дать exit 0. `drift --json` — отчёт, а не гейт `--fail-on-drift`. Флагов `validate --all --fail-on-incomplete`, `coverage --percent`, `score --stale-count` не существует.

Сопоставьте политику с требованиями репозитория и сделайте выбранную проверку обязательной в защите ветки. Успешный workflow сам по себе не доказывает смысловую корректность, качество доказательств или покрытие каждого изменённого модуля.

## Комбинированный подход (рекомендуемый)

### Порядок внедрения

1. Определите правила проекта, границы одобрения человеком и конфигурацию трекера.
2. Установите только необходимые навыки, агентов и хуки хоста.
3. Настройте выбор workspace CLI/MCP и доступные каждой роли инструменты.
4. Сделайте проверки CI обязательными только для свойств, которые они действительно проверяют.
5. До завершения сопоставьте приёмку с независимыми доказательствами; трекер обновляется отдельно.

### Пример полного CLAUDE.md section

```markdown
## Интеграция Forgeplan

- Читать относящиеся к работе решения; соблюдать точное владение файлами.
- Следовать выбранному процессу; архитектурное одобрение — политика проекта.
- Для артефактов использовать CLI/MCP, для статуса задач — настроенный трекер.
- Валидировать до активации. Обход жизненного цикла требует явных полномочий.
- Исполнитель реализации не является её независимым ревьюером.
- Указывать реально выполненные проверки, нерешённые находки и непроведённые проверки.
```
