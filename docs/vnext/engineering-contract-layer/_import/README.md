# Import provenance — ForgePlan vNext agent-ready pack

Этот каталог хранит **метаданные импорта**, которые не входят в сам payload. Сохранены,
чтобы импорт можно было воспроизвести и перепроверить, а не только прочитать результат.

## Что здесь лежит

| Файл | Назначение |
|---|---|
| `MANIFEST.json` | манифест пакета: schema, целевой репозиторий, install-targets, `issue_count` |
| `CHECKSUMS.sha256` | контрольные суммы всех 60 файлов пакета |
| `FILE-INVENTORY.md` | полный список файлов пакета |
| `01-IMPORT-MAP.md` | карта «источник в архиве → назначение в репозитории» |
| `00-START-HERE.md` | инструкция по установке (человеку) |
| `02-EXECUTION-PLAN.md` | дубликат `governance/EXECUTION-ORDER.md` |
| `PROMPT-START-AGENT.md` | дубликат `prompts/PROGRAM-COORDINATOR.md` |
| `install.sh` | скрипт импорта payload (отказывается перезаписывать при конфликте) |
| `validate.sh` | обёртка над `scripts/validate_pack.py` + проверка манифеста |

## Что проверено при импорте (2026-08-01)

- **Целостность**: `shasum -a 256 -c CHECKSUMS.sha256` → **60/60 OK**.
- **Точность установки**: `diff -r` между `payload/docs/vnext/engineering-contract-layer`
  и установленной копией → идентично, байт в байт.
- **Конфликтов нет**: ни `docs/vnext/`, ни `.github/PULL_REQUEST_TEMPLATE/` до импорта
  не существовали. Ни один существующий документ не перезаписан.
- **Валидатор пакета**: `validate_pack.py` → `OK: 16 issues, 5 schemas, prompts and
  governance present`.

Важно: `validate_pack.py` проверяет только существование файлов и парсабельность JSON.
Он **не** проверяет, что тела issue соответствуют обязательным секциям из
`governance/ISSUE-GOVERNANCE.md` — по этому критерию соответствие 0/16.

## Оговорка про CHECKSUMS.sha256

Строки `payload/*` верифицируются только пока рядом существует распакованный архив.
После удаления исходного каталога файл остаётся **записью провенанса импорта**, а не
живой проверкой. Установленную копию сверять через `diff -r` с исходным архивом.

## Пробел: у пакета нет собственного провенанса

`MANIFEST.json` не содержит ни автора, ни генератора, ни ревизии репозитория, против
которой пакет писался, ни лицензии. Для программы, чей центральный тезис —
«Verify the artifact, not the claim» — это существенный пробел: происхождение самой
программы не проверяемо.

Практическое следствие: значительная часть фактических утверждений пакета о текущем
ForgePlan не подтвердилась при проверке (см. раздел «Ложные предпосылки» в аудите).
Наиболее экономная гипотеза — пакет писался без доступа на чтение к репозиторию.
Гипотеза не подтверждена и проверяется одной строкой в манифесте.

Перед созданием GitHub Issues из этого пакета его источник стоит запросить и записать
сюда блоком `Provenance:` — кто, чем и против какого коммита.
