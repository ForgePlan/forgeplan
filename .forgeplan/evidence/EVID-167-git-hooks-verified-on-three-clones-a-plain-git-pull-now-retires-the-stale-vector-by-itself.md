## Что проверялось

Что после `git pull` индекс приходит в соответствие **сам**, без единой
команды forgeplan. Проверено тремя реальными клонами через bare-репозиторий,
а не рассуждением о коде.

## Результат

Carol ставит хуки, Alice переписывает NOTE-002 (было про обжарку кофе, стало
про квантовую коррекцию ошибок) и пушит. Carol выполняет **только** `git pull`:

| | до pull | после pull, без ручных команд |
|---|---|---|
| поиск «coffee roasting beans» | **0.81** | **не находит** |
| сообщение | — | «1 artifact(s) have no embedding… Run `forgeplan embed`» |

Врущий вектор снят автоматически. Остаток работы назван, а не умолчан.

## Стоимость измерена до того, как её тратить

`git-sync` на этом воркспейсе (411 артефактов) — **1.4 с**. Достаточно
дёшево, чтобы платить на каждый pull, вместо надежды, что все запомнят
команду, которой нет ни в одном документе.

## Границы, выбранные намеренно

- **Хуки не запускают `embed`.** Это 2.1 GB модели и секунды на артефакт;
  pull, непредсказуемо зависающий на минуты, хуже исходной проблемы. `search`
  сам сообщает о разрыве — там и место решению.
- **Чужой хук не перезаписывается.** Наши файлы несут маркер; без маркера мы
  сообщаем и не трогаем.
- **Хук не может уронить git-операцию.** Мерж уже прошёл; ошибка после него
  только путает, а устаревший индекс чинится `reindex`.
- **`git rev-parse --git-path hooks`, а не `.git/hooks`.** В worktree
  `.git` — файл, а `core.hooksPath` может увести в другое место; буквальный
  путь поставил бы хук туда, куда git не смотрит, и отрапортовал об успехе.

## Побочная находка: issue #348, и почему он выжил

`forgeplan link` печатал `Next: forgeplan score-all`. Такой команды не
существует — правильная `forgeplan score --all`.

Причина долгожительства: **тест утверждал сломанную подсказку.**
`cli_reff_cache_invalidation.rs:164` требовал ровно строку
`Next: forgeplan score-all`, то есть любой, кто чинил, получал красный тест
и откатывался. Тест, закрепляющий неверный контракт, хуже отсутствия теста —
он активно защищает дефект.

Исправлены три места эмиссии и сам тест.

## Детектор расширен на подсказки — и сначала проверен на себе

Документационный детектор не видел #348: строка живёт в Rust-исходнике, а не
в доке. Расширен на поверхности контракта PRD-071 (`with_action`,
`Next:`/`Fix:`/`Or:`).

Первый прогон дал **18 расхождений**. После проверки самого детектора
осталось **1**:

- 13 — не умел вложенные подкоманды (`--yes` принадлежит `playbook run`,
  а спрашивалось у `playbook`);
- 4 — проза из комментариев («the forgeplan binary built by cargo test»),
  прочитанная как имя команды.

Только одно было настоящим — #348. Число «18» не стоило ничего, пока
инструмент не был проверен; **17 из 18 находок оказались дефектами
инструмента, а не кода**. Итог после починки: 83 проверки, 0 расхождений.

## Чего этот замер НЕ покрывает

- **`rebase` не проверен.** Хуки стоят на `post-merge` и `post-checkout`;
  `post-rewrite` (rebase) — в FR-003 PRD-085, не сделано.
- **Только macOS.** Хуки — POSIX-скрипты; поведение на Windows не проверялось.
- **Арность аргументов детектор по-прежнему не ловит** — только имя команды и
  флаги. `remember "key" "value"` прошёл бы.
