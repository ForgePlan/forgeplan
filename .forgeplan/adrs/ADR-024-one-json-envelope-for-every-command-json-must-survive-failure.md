## Context

`--json` заявлен как машинный интерфейс, но контрактом не является (PROB-099,
замер 2026-09-04 на 0.36.0):

- **не переживает ошибку** — `get NOSUCH --json` печатает прозу и код 1;
- **формы расходятся** — `health`/`score` отдают объект, `list` голый массив;
- **`_next_action` в 60%** — 71 из 118 блоков;
- **118 рукописных `serde_json::json!` в 36 файлах, ноль общих помощников**;
- у 47 команд из 82 флага нет вовсе.

Первый порыв — добавить флаг остальным 47. Это неверный шаг: получим 82
несогласованных формата вместо 35, и зафиксируем их как публичный контракт.

Момент выбран не случайно. Пока агенты на форму не завязались, её можно
выбрать один раз. После — любая правка становится ломающим изменением сразу
для всех потребителей.

## Decision

**Одна обёртка на все команды, и `--json` обязан пережить отказ.**

```json
{
  "schema_version": 1,
  "ok": true,
  "data": { ... },
  "_next_action": "forgeplan validate PRD-001"
}
```

```json
{
  "schema_version": 1,
  "ok": false,
  "error": { "message": "Artifact 'NOSUCH-999' not found", "kind": "not_found" },
  "_next_action": "forgeplan list"
}
```

Четыре решения, каждое с ценой:

**1. Обёртка, а не голый payload.** Агент отличает успех от отказа одним
полем, не глядя на код возврата — который недоступен, когда вывод идёт через
MCP или лог. Цена: ломает все 35 существующих потребителей, включая `list`,
который сейчас отдаёт массив верхним уровнем.

**2. Код возврата сохраняется.** При отказе — JSON **и** ненулевой код.
Это не противоречие: shell читает код, агент читает поле. Убрать код значило
бы сломать `set -e` и CI-скрипты ради удобства, которое поле уже даёт.

**3. `schema_version` с самого начала.** Одно лишнее поле против того, чтобы
следующая правка формы снова оказалась ломающей. Сегодня дважды видели цену
обратного: смена формата команды установки молча испортила вывод имени плагина
(#351), потому что имя добывалось обрезкой строки.

**4. Один механизм эмиссии, миграция всех 118 сайтов сразу.** Оставить часть
на старом стиле — это и есть тот «разнокод», ради которого всё затевалось:
две формы в одном бинаре хуже одной плохой, потому что агент не знает, какая
ему достанется.

**Флаг `--json` становится глобальным** (`global = true` на корневом `Cli`).
Иначе `main` не знает, в каком формате отдавать ошибку, и путь отказа
пришлось бы дублировать в каждой команде — снова 82 копии.

## Options considered

**(a) Обёртка + глобальный флаг — принято.** Единственный вариант, где путь
отказа централизован по построению, а не по дисциплине.

**(b) Голый payload, ошибки отдельной формой.** Короче на успехе и не ломает
существующих. Отвергнут: агент не может отличить объект-ошибку от payload'а,
у которого просто есть поле `error`, без внешнего признака. Дискриминатор
нужен, и лучше явный.

**(c) Добавить `--json` остальным 47 в текущем стиле.** Дёшево и быстро.
Отвергнут: закрепляет 82 формата как контракт. Это ровно тот класс дефекта,
которому посвящён весь v0.36.0 — интерфейс, отчитывающийся о своём
существовании и ничего не гарантирующий.

**(d) Двухверсионная миграция с deprecation.** Аккуратно к потребителям.
Отвергнут для pre-1.0 инструмента: обряд дороже выгоды, а `CHANGELOG` уже
объявляет minor-бампы носителями ломающих изменений.

## Consequences

**Положительные**

- Агент пишет **один** парсер на 82 команды, и он не ломается на отказе.
- `_next_action` есть всегда — контракт PRD-071 перестаёт быть выборочным.
- Новая команда получает корректный JSON по умолчанию, а не по внимательности
  автора.
- 118 рукописных блоков сходятся в один механизм.

**Отрицательные и принимаемые**

- **Ломающее для всех 35 текущих потребителей.** `list --json` меняет форму
  с массива на `{"ok":true,"data":[…]}`. Minor-бамп, явная запись в CHANGELOG.
- Ответ на успехе становится длиннее на три поля.
- Разовая большая правка: 118 сайтов, каждый нужно прочитать, а не заменить
  регуляркой — часть блоков собирает вложенные структуры.

## Invariants

1. **`--json` всегда даёт валидный JSON** — на успехе, на отказе, на частичном
   результате. Нарушение — дефект, а не особенность команды.
2. **Ненулевой код возврата при `ok: false`.** Поле не заменяет код.
3. **Обёртка одна.** Команда не имеет права отдать payload верхним уровнем.
4. **`schema_version` растёт при любом несовместимом изменении формы.**

## Rollback Plan

Механизм сосредоточен в одном модуле, поэтому откат — revert коммита: формы
вернутся к прежним, потребители 35 команд не заметят. Откатывать частично
(вернуть форму одной команде) нельзя — это воссоздаёт разнокод, ради которого
решение и принято.

## Что должно стать правдой для пересмотра

1. **Появился потребитель, которому обёртка мешает** — измеренный случай, а не
   предположение об удобстве.
2. **Понадобился поток событий** (`watch`) — это NDJSON и отдельное решение;
   обёртка на строку потока не натягивается без разговора.
