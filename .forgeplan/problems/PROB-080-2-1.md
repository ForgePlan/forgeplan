# PROB-080: Каталог видов расходится с фактическим употреблением

## Problem

Каталог «10 типов артефактов» (`CLAUDE.md`, `FORGEPLAN-GUIDE.ru.md`) не сверялся
с реальным употреблением с момента написания. Расхождение идёт **в обе стороны**:

- **`Solution` и `Refresh` объявлены, но не созданы ни разу** — 0 из 372 артефактов;
- **`memory` используется, но в каталоге отсутствует** — его там просто нет.

Начато с наблюдения пользователя про `Solution` («не участвует каждый раз»); проверка
показала, что случай не единичный и не односторонний.

## Evidence

Замер 2026-07-25 на `dev` (v0.33.0), 372 артефакта, граф ведётся с 2026-04-06:

| Kind | В каталоге | Записей | Комментарий |
|---|---|---|---|
| evidence | да | 135 | |
| problem | да | 72 | |
| prd | да | 64 | |
| note | да | 43 | |
| adr | да | 15 | |
| rfc | да | 12 | |
| epic | да | 8 | |
| spec | да | 6 | |
| **memory** | **НЕТ** | **2** | живой, но скрыт от читателя |
| **solution** | да | **0** | см. ниже |
| **refresh** | да | **0** | вынесен в [[PROB-081]] |
| 6 brownfield-видов | частично | **0** | всё, что было — заглушки от `scan-import` (PROB-047) |

`git log --all --diff-filter=A -- '.forgeplan/solutions/*'` → ни одного добавления
за всю историю. Шаблон и механика исправны — это неиспользование, а не поломка.

## Case 1: `Solution` — роль поглощена

Заявленная роль — «2–3 варианта решения, оценка по слабейшему звену». Её уже выполняют
два механизма, встроенные в путь плотнее:

**ADR несёт варианты внутри себя.** Форма MADR 3.0 требует разделов
`## Considered Options` и `## Pros and Cons of the Options`. Живой пример — ADR-018:
четыре гипотезы с состязательными баллами (7 / 6.5 / 6.5 / 5), у каждой разбор,
major-возражения и вердикт. Ровно то, что описывает `Solution`, только там, где это
нужно читателю.

**`forgeplan reason` (ADI) генерирует гипотезы.** Для Deep/Critical разбор обязателен
(шаг 4 полного цикла) — варианты появляются автоматически.

## Case 2: `memory` — обратный случай

`memory` (префикс `mem-`) хранит **факт, конвенцию или процедуру** — то, что надо
помнить, но что не тянет на решение. Отличие от `Note`: Note — микро-**решение**
(«решили пока не выносить»), живёт 90 дней; memory — **факт** («префикс API — `/v1`»),
не протухает.

Создаётся своей парой команд, не через `new`:
`forgeplan remember "текст"` / `forgeplan recall "запрос"`.

**Используется формально, но не по-настоящему:**

- Обе записи созданы **2026-03-31, с разницей в 82 миллисекунды** (14:38:36.577 и
  14:38:36.659) — то есть одним заходом, почти наверняка проверочным. За последующие
  ~4 месяца — ни одной.
- Содержание — реальные конвенции проекта («префикс API `/v1` без `/api`»,
  «PostgreSQL для конкурентных записей, не SQLite»), то есть вид попадает в свою нишу.
- `remember` / `recall` **не упоминаются в полном цикле** `CLAUDE.md` (0 вхождений
  в шагах 1–16).

**Главная причина, по которой не растёт — конкуренция за ту же нишу.** В этом проекте
одновременно работают три хранилища памяти:

| Где | Объём | Кто ведёт |
|---|---|---|
| `MEMORY.md` + файлы Claude Code | **80 записей, 83 файла** | автоматически, каждую сессию |
| Hindsight MCP (`.mcp.json`) | отдельный банк | авто-хуки при каждом промпте |
| `.forgeplan/memory/` | **2** | вручную, командой |

Восемьдесят против двух. Память ведётся активно — просто не здесь. Два конкурента
пишутся сами, третий требует осознанного действия и не подсказывается ниоткуда.

### Два технических дефекта, мешающих пользоваться

Обнаружены при разборе, **заслуживают отдельной записи**:

1. **Slug дублируется в имени файла.** Реальное имя:
   `mem-api-prefix-is-v1-without-api-added-at-ingress-api-prefix-is-v1-without-api-added-at-ingress.md`
   Заголовок вставлен дважды.
2. **Двойной frontmatter в теле.** Файл содержит два блока `---...---` подряд: первый
   от проекции (`author`, `depth`, `id`, `kind`, `status`, `title`), второй — исходный
   (`category`, `created`, ...). Второй попадает в тело как текст.

Оба воспроизводятся на обеих существующих записях, то есть на 100% выборки.

## Impact

- **Каталог врёт в обе стороны одновременно**: показывает два вида, которыми никто не
  пользуется, и скрывает один, который работает. Новичок тратит внимание на мёртвое
  и не узнаёт о живом.
- **Справочные материалы наследуют искажение.** Любая шпаргалка, построенная по
  каталогу, повторит эту пропорцию как равнозначную.
- **`memory` теряется как возможность.** Конвенции проекта («префикс `/v1`») сегодня
  оседают в памяти Claude Code, которая живёт вне репозитория и не переживает смену
  инструмента. В `.forgeplan/memory/` они были бы в git, рядом с кодом, доступны любому
  агенту через `recall`.

## Как сделать, чтобы `memory` использовался

Не «напоминать чаще» — встроить в путь. По убыванию отдачи:

**1. Поставить в цикл.** После шага 12 (активация) — явный шаг: «конвенция, вытекающая
из решения, → `forgeplan remember`». Решение живёт в ADR, вытекающее из него правило
(«теперь всегда так») — в memory. Сегодня такому правилу деться некуда.

**2. Подсказка в hint-протоколе.** После `forgeplan activate` выдавать
`Or: forgeplan remember "<конвенция из решения>"`. Проект уже строит работу агентов на
маркерах `Next:` / `Or:` — это существующий механизм, а не новый.

**3. Разграничить с двумя другими хранилищами явно.** Сейчас граница нигде не записана,
и по умолчанию всё уходит в Claude Code / Hindsight. Предлагаемое правило:

| Куда | Что | Почему |
|---|---|---|
| `.forgeplan/memory/` | конвенции **кода и продукта**, переживающие смену инструмента | в git, рядом с кодом, доступны через `recall` любому агенту |
| Hindsight | разговорное знание, уроки сессий, предпочтения | не относится к коду, не место в репозитории |
| `MEMORY.md` Claude Code | указатель, всегда в контексте | по определению инструмент-специфичен |

**4. Починить два дефекта.** Пока имена файлов дублируют slug, а в теле два
frontmatter — вид выглядит недоделанным, и это само по себе отталкивает.

## Options по каталогу

**A. Привести каталог в соответствие с фактом.** Добавить `memory` с его командами;
пометить `Solution` состоянием, отражающим реальность. Обратимо, чинит дезинформацию
немедленно.

**B. Упразднить мёртвое.** Пометить `Solution` устаревшим.
*Против:* набор видов — публичный контракт (`ArtifactKindArg` в MCP-схеме, `dir_name`
в `types.rs`); удаление ломает совместимость. Необратимо без версионирования.

**C. Встроить мёртвое.** Найти случай, где `Solution` нужен именно отдельной записью,
и поставить шагом в цикл. Требует доказать, что случай реален, а не придуман ради
спасения вида.

## Recommendation

**A немедленно** — каталог обязан отражать факт, это не требует решения об архитектуре
и обратимо.

**B/C — одним ADR вместе с [[PROB-081]].** Общий вопрос: *что делает вид артефакта
живым*. Ответ нужен не двум видам, а восьми: `Solution`, `Refresh` и шесть
brownfield-видов, у которых после чистки PROB-047 тоже ноль настоящих записей.

**Восемь видов из шестнадцати не имеют ни одной реальной записи.** Общее у всех —
ни один не стоит на пути, по которому идут каждый день. Чинить по одному виду —
лечить симптомы.

## Acceptance criteria

- [ ] Каталог видов в `CLAUDE.md`, `ARTIFACT-MODEL.ru.md`, `FORGEPLAN-GUIDE.ru.md`
      сверен с замером по графу; `memory` присутствует с описанием и командами
- [ ] Граница между тремя хранилищами памяти записана явно
- [ ] `memory` встроен в цикл или в hint-протокол (минимум одно из двух)
- [ ] Два технических дефекта `memory` заведены отдельной записью
- [ ] Решение по `Solution` (и `Refresh`) принято одним ADR, а не правкой каталога
- [ ] Если выбран путь упразднения — проверено влияние на `ArtifactKindArg` и
      обратную совместимость
