## Problem

Два связанных дефекта, вскрытых один за другим.

**PROB-088** — релизные бинари (Homebrew, `install.sh`, GitHub Releases, все пять таргетов)
собирались cargo-dist с default-features, а `semantic-search` не входит в default. Векторный
поиск BGE-M3 не был доступен ни в одной бинарной установке с момента введения cargo-dist.
Отягчающее обстоятельство: документация не молчала, а **утверждала обратное** —
`getting-started/configuration.md:141` в обеих локалях писал «included in official release
binaries».

**PROB-089** — когда фича собрана, кэш модели дублировался на каждый проект (4.2 GB на двух),
корневой путь не был покрыт `.gitignore` (2.1 GB untracked), а размер модели указывался в
трёх местах тремя разными неверными числами.

Продуктовое требование владельца: пользователь ставит `fpl` и **сразу пользуется** — модель
докачивается при первом запуске с видимым прогрессом; если это технически невозможно,
пользователю говорят внятно и дают рабочую команду.

## Goals

- **G1.** Знать по измерению, а не по предположению, собирается ли `--features semantic-search`
  на всех пяти релизных таргетах.
- **G2.** Пользователь получает работающий векторный поиск из коробки — либо внятное
  объяснение с исполнимой командой, если это невозможно.
- **G3.** Модель скачивается один раз на машину, а не на каждый проект, и не попадает в git.
- **G4.** Размер загрузки назван честно и **до** её начала, из единственного источника правды.
- **G5.** Не подвергать риску публикацию релиза.

## Non-Goals

- **NG1.** Не выбираем другой embedding-бэкенд и не мигрируем с `fastembed`/BGE-M3.
- **NG2.** Не вшиваем модель в бинарь.
- **NG3.** Не трогаем поведение fallback в `fpf search --semantic` — оно корректно.
- **NG4.** Не поднимаем `ort` с release-candidate до stable — вне нашего контроля.
- **NG5.** Не переносим автоматически существующие кэши пользователей.
- **NG6.** Не переопределяем `HF_HOME`.

## Target Users

- **Пользователь бинарной установки** (brew / `install.sh` / GitHub Releases) — основная
  аудитория, именно она натыкалась на отказ.
- **Пользователь с несколькими проектами** — страдал от дублирования кэша сильнее всех.
- **Агент (LLM), читающий hint-протокол** — потребитель `Fix:`-строки.
- **Мейнтейнер релиза** — рискует уронить публикацию всех таргетов разом.

## Outcome

**G2 достигнута во второй формулировке, не в первой.** Измерение (EVID-158) показало, что
включить фичу в дистрибутив нельзя: из пяти таргетов собрался один. Поэтому реализован
второй путь — честный контракт плюс исполнимая команда. Решение и отвергнутые альтернативы
зафиксированы в **ADR-022**.

| Таргет | Итог | Причина |
|---|---|---|
| `aarch64-apple-darwin` | PASS | — |
| `x86_64-apple-darwin` | FAIL | prebuilt ONNX для этого таргета в ort rc.12 не публикуется |
| `x86_64-unknown-linux-gnu` | FAIL | `__isoc23_strtol*` — prebuilt требует glibc ≥ 2.38 |
| `aarch64-unknown-linux-gnu` | FAIL | то же |
| `x86_64-pc-windows-msvc` | FAIL | `LNK1120: 66 unresolved externals` из `libort_sys` |

## Functional Requirements

**Дистрибуция (PROB-088)**

- [x] **FR-001.** Проверить, применяется ли ключ `features` в `[dist]`. Синтаксис сверен с
      официальной документацией cargo-dist; `dist plan` конфиг принял.
- [x] **FR-002.** Доказать `dist build` на всех пяти таргетах. Выполнено через
      `pr-run-mode = "upload"` — единственный способ, поскольку `release.yml` на PR по
      умолчанию выполняет только `plan`, а реальная сборка идёт лишь при push тега.
      Результат: 1 из 5.
- [x] **FR-003.** Результат оформлен как EvidencePack — **EVID-158**, `evidence_type:
      measurement`, активен.
- [x] **FR-004.** Размер бинаря с фичей замерен на `aarch64-apple-darwin`: 47.4 → 67.2 MB
      (+41.8 %). Оговорка о несверенных профилях зафиксирована в EVID-158.
- [x] **FR-005.** **ADR-022** — решение о составе фич дистрибуции, с четырьмя рассмотренными
      вариантами, причинами отказа и условиями пересмотра. Активен.
- [x] **FR-006.** Оба временных ключа (`features`, `pr-run-mode`) сняты до мержа. В конфиге
      остался комментарий с измерением, запрещающий бездумное возвращение ключа.

**Кэш модели (PROB-089)**

- [x] **FR-007.** `embed::resolve_cache_dir()` — `FORGEPLAN_MODEL_CACHE` → платформенный
      user-cache → фоллбэк. Один кэш на машину.
- [x] **FR-008.** `.gitignore`, `GITIGNORE_CANONICAL_BODY` и `GITIGNORE_DRIFT_PATTERNS`
      покрывают `.fastembed_cache/` на любой глубине.
- [x] **FR-009.** Единственный источник размера — `embed::MODEL_DOWNLOAD_SIZE_HINT`.
- [x] **FR-010.** `embed::first_run_notice()` предупреждает до загрузки, молчит при
      наполненном кэше, предлагает `mv` вместо повторной закачки.
- [x] **FR-011.** Ошибка инициализации оборачивается в сообщение про сеть/диск/override.

**Хинты и документация**

- [x] **FR-012.** `Fix:`-хинт заменён на `cargo install --git … --features …`.
- [x] **FR-013.** Тест закрепляет контракт хинта.
- [x] **FR-014.** README: раздел Install + исправленная таблица Cargo features.
- [x] **FR-015.** Сайт `configuration.md` EN + RU: снято ложное утверждение, исправлен
      неработающий совет диагностики.
- [x] **FR-016.** Сайт `installation.md` EN + RU: контракт, размер, расположение кэша,
      приоритет `HF_HOME`.
- [x] **FR-017.** `RELEASE-PROTOCOL` EN + RU: проверка опубликованного артефакта по маркеру
      линковки вместо доверия зелёной сборке.
