# Git-delta provenance gate for code-claiming Evidence

Реализует GitHub #360. Первый слайс — проверка происхождения, без запуска тестов
и без владения рабочим деревом.

## Problem

Когда активируется EvidencePack, заявляющий выполненную работу над кодом,
ForgePlan верит заявлению исполнителя. Проверки, что заявленное изменение
вообще существует в git, нет.

Измерено на этом репозитории:

```
ls .forgeplan/evidence/*.md | wc -l                    -> 148
grep -rl 'base_sha\|result_sha' .forgeplan/evidence/   -> 0
grep -rn 'git' crates/forgeplan-core/src/scoring/      -> 0
```

Ни одно из 148 доказательств не несёт ссылки на коммит, и слой оценки о git не
знает вообще. То есть «доказательство» сегодня — это утверждение исполнителя о
самом себе, и архитектура структурно не может отличить сделанную работу от
рассказа о ней.

Сценарий из #360, воспроизведённый минимально: воркер ничего не делает,
рапортует «готово», тесты зелёные на неизменённом дереве — наивный вердикт
DONE, при этом `git diff` пуст. **Зелёные тесты на пустой дельте — это NULL,
а не успех.**

Класс известен и вне ForgePlan: Claude Code #44035 — терминал отрапортовал
успех, `git log` показал ноль коммитов.

## Goals

- EvidencePack, заявляющий работу над кодом, несёт проверяемое происхождение:
  base SHA, result SHA, изменённые пути.
- Core умеет **пересчитать** факт: `git diff --name-only base..result` в
  разрешённом workspace и сравнить с заявленным.
- Пустая дельта при заявленной работе над кодом — отказ, а не пропуск.
- Отсутствие полей происхождения — не ошибка: доказательство, не заявляющее
  код (бенчмарк, аудит, ручной тест), проходит как прежде.

## Non-Goals

- ForgePlan **не** запускает тесты, сборки и линтеры.
- ForgePlan **не** владеет рабочим деревом, worktree и веткой (ADR-019).
- Не проверяем содержание диффа по существу — только факт и совпадение путей.
- Не вводим Protocol v1, WorkContract, адаптеры и сервер. Слайс живёт против
  текущей границы.
- Не трогаем формулу R_eff в этом слайсе.

## Target Users

Сопровождающий, принимающий результат работы агента, и агент-верификатор,
которому нужен машинный ответ «дельта на месте» вместо чтения прозы.

## Functional Requirements

- [x] **FR-001** — `git::changed_paths_between(repo_root, base, result)`:
      валидирует оба ref через существующий `validate_git_ref`, выполняет
      `git diff --name-only base result`, возвращает пути. Ошибка git —
      типизированная, не паника. *5 тестов на настоящих git-репозиториях.*
- [x] **FR-002** — извлечение полей происхождения из тела EvidencePack тем же
      механизмом `extract_field`, что уже читает `verdict` /
      `congruence_level` / `evidence_type`: `base_sha`, `result_sha`,
      `changed_paths` (список через запятую в одной строке — формат согласован
      с построчной моделью `extract_field`).
- [x] **FR-003** — `verify_code_provenance(body, repo_root) -> ProvenanceVerdict`.
      **Отступление от плана:** исходов не четыре, а пять. Добавлен
      `Incomplete` для частично заполненного заявления. Без него заявление с
      `base_sha`, но без `changed_paths`, прошло бы как «полей нет → не наше
      дело» — то есть ровно тот тихий обход, который вся фича и должна
      исключать. Отступление в сторону строгости.
- [x] **FR-004** — пустая фактическая дельта при заявленных `changed_paths`
      даёт `EmptyDelta`. Центральный случай #360.
- [x] **FR-005** — заявленный путь, отсутствующий в фактической дельте, даёт
      `PathMismatch` с перечислением недостающих. Лишние фактические пути не
      блокируют — контроль scope это отдельная задача.
- [x] **FR-006** — тесты на каждый исход на настоящих временных git-репозиториях,
      не на моках. *10 тестов в `scoring::provenance` + 5 в `git`.*

Отдельно закрыт риск, которого в плане не было: неизвестный `base_sha`
возвращает **ошибку**, а не пустую дельту. Иначе опечатка в SHA читалась бы как
«ничего не изменилось» и проходила бы гейт.

## Success Criteria

- [x] `verify_code_provenance` возвращает `EmptyDelta` на сценарии #360
      (заявлены пути, `git diff` пуст) — воспроизведено на реальном репо.
- [x] Существующие 148 доказательств не ломаются: без полей происхождения
      исход `NotClaimed`, `is_acceptable() == true`.
- [x] Пайплайн зелёный: `cargo fmt --check` 0, `clippy -D warnings` 0,
      84 набора тестов проходят.

## Out of scope for this slice

Подключение к `forgeplan_activate` как гейта BLOCKER/WARN — следующий шаг,
отдельным FR. Сначала должна существовать и быть проверяемой сама функция
установления факта. Она существует и проверена.
