# PRD-088: Constellation documentation and drift audit

## Meta Header

| Field | Value |
|---|---|
| Author | Eli Rum |
| Priority | P1 |
| Scope | Документация существующего поведения, без изменения реализации |

## Executive Summary

Пользователь должен находить переносимые инструкции Constellation рядом с остальными функциями, отличать полный MCP от дополнительного чтения и понимать условия автоматического embed. Общий аудит показывает фактическое покрытие документации, подтверждённые расхождения и границы проведённой проверки.

## Problem Statement

Документация разделена между contributor-материалами и пользовательским порталом на двух языках. Описание Constellation сейчас сосредоточено во внутренней архитектурной заметке и персональном журнале пилота, а условия настройки фонового embed не видны из обычного пути установки. Некоторые актуальные страницы противоречат друг другу: например, справочник одновременно объявляет единственную поддерживаемую модель и предлагает другие модели. Это влияет на воспроизводимость настройки, потому что пользователь может выполнить синтаксически правдоподобные команды и получить другой результат. Наличие страницы само по себе не доказывает её точность.

## Goals

- Goal-1: Покрыть пользовательский путь Constellation на EN и RU: настройка, MCP, индексирование, проверка и диагностика (FR-001, FR-002, FR-003).
- Goal-2: Зафиксировать инвентарь всех документационных поверхностей и проверить механическое покрытие команд, ссылок и языковых пар (FR-004).
- Goal-3: Для каждого подтверждённого расхождения в отчёте указать доказательство и результат: исправлено либо отдельная задача с условием повторной проверки (FR-005).

## Non-Goals

- Не менять Rust-поведение, публичные API, настройки пользовательских проектов и установленный бинарник.
- Не объявлять опубликованным локальный 0.39.0 и не принимать S1-G/S2–S4.
- Не считать механический анализ всех файлов семантическим чтением каждого документа; отчёт различает эти методы.

## Target Audience

| Persona | Need |
|---|---|
| Пользователь CLI/MCP | Настроить функцию и отличить готовый поиск от отставшего индекса |
| Разработчик ForgePlan | Найти актуальные контракты, источники reference и результаты проверки дрейфа |

## User Stories

- Как пользователь, я хочу включить авто-embed без потери инструментов изменения артефактов и проверить готовность по ответам программы.
- Как разработчик, я хочу видеть измеренный перечень расхождений между документацией и реализацией, чтобы исправления не зависели от памяти разговора.

## User Journeys

### Journey 1: Пользователь настраивает Constellation

Открывает руководство в навигации, проверяет подходящую версию, создаёт отдельный workspace, настраивает модель, запускает нужный профиль MCP и проверяет текст/семантическое покрытие.

### Journey 2: Разработчик проверяет актуальность

Находит карту документации, повторяет имеющиеся проверки ссылок и reference, читает отчёт с методами и ограничениями, затем исправляет или регистрирует подтверждённые расхождения.

## Product Scope

Пользовательские EN/RU how-to и reference, связанная архитектурная заметка, переносимые operations-инструкции, навигация и проверяемые примеры. Общий аудит охватывает инвентарь, командный/reference контракт, языковую симметрию и выборочное чтение рискованных инструкций.

## Functional Requirements

- [ ] FR-001: Пользователь может найти EN/RU инструкции Constellation из штатной навигации документации (Must; Journey 1).
- [ ] FR-002: Пользователь может отличить full MCP от constellation-read и настроить модель, кэш и фоновое обслуживание (Must; Journey 1).
- [ ] FR-003: Пользователь может проверить exact get, keyword search, семантическое покрытие и ошибки источников на отдельном workspace (Must; Journey 1).
- [ ] FR-004: Разработчик может воспроизвести документированные проверки покрытия, ссылок и языковых пар (Must; Journey 2).
- [ ] FR-005: Разработчик получает отчёт с доказательствами дрейфа, состоянием исправлений и границами общего аудита (Must; Journey 2).

## Non-Functional Requirements

- Публичные примеры не содержат машинных путей владельца, credentials или инструкций незаметно мигрировать настоящие проекты.
- EN и RU описывают одинаковые условия и ограничения; исторические release notes не подменяют текущие гарантии.
- Проверка команд выполняется готовым бинарником в изолированном окружении; сборку сайта выполняет один владелец после правок.

## Success Metrics

| Metric | Current | Target |
|---|---|---|
| Найденные пользовательские руководства Constellation EN/RU | 0 в просмотренном разделе Guides | 1 полное руководство на каждом языке плюс reference |
| Подтверждённые расхождения из отчёта без результата | Не измерено до аудита | 0: каждому назначено исправление или сохранённая задача |
| Битые локальные ссылки в изменённых страницах | Не измерено до проверки | 0 |
| Сборка затронутого сайта | Не запускалась для этой документационной дельты | Фактически выполнена, exit 0, новые страницы проверены в браузере |

## Success Criteria

- Все FR связаны с результатами проверки в итоговом Evidence.
- В отчёте есть измеренный инвентарь и отдельное обозначение прочитанной выборки.
- Новые инструкции не требуют ручного embed после каждой правки при выполненных условиях фонового обслуживания.

## Acceptance Criteria

- Given пользователь новой локальной сборки, When он следует how-to, Then точное чтение, поиск и диагностика соответствуют наблюдаемым ответам CLI/MCP.
- Given корпус EN/RU, When выполнены проверки, Then новые страницы и изменённые контракты доступны в обеих локалях и из навигации.
- Given найденный drift, When аудит завершён, Then он не остаётся только в чате и не маскируется общей зелёной оценкой.

## Dependencies

Существующие CLI/MCP и валидаторы, текущий код Constellation, опубликованный v0.38.0 как база сравнения и локальная 0.39.0+constellation.s1.1 как проверяемая реализация. Действующие генераторы и проверки сайта.

## Risks

| Risk | Mitigation |
|---|---|
| Непроверенная функция выглядит опубликованной | Явно отделить unreleased-описание и сохранённые границы приёмки |
| Локальные адреса пилота попадают в публичную документацию | Перенести личный журнал в .local, публичные шаги сделать переносимыми |
| Проверка скрипта ошибочно принимается за полный semantic audit | Записывать методы, входы, числа, ошибки и ограничения |
