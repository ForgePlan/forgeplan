# Forgeplan Website

Forgeplan's Astro site: landing, Starlight user documentation, blog and embedded guides. Repository-root `docs/` is contributor documentation and is not published by this app.

## Stack

- **Astro 6** — SSG, partial hydration (React islands)
- **Starlight** — docs portal (sidebar, Pagefind search)
- **React 19** — interactive components (Hero animation)
- **GSAP** — ScrollTrigger for Hero pin + crystallization animation
- **Tailwind CSS 4** — utility-first styling with forge design tokens

## Development

```bash
cd website
npm install
npm run dev      # http://localhost:4321
npm run build    # static output in dist/
```

## Documentation maintenance

Write a task-oriented guide and a separate reference when both are needed.
Constellation lives in `guides/constellation.md` and `reference/constellation.md`,
paired in EN/RU. Guides, Reference, CLI and MCP sidebar groups are autogenerated;
Getting Started and Methodology entries are explicit in `astro.config.mjs`.

Generate interface metadata from a **built binary from the same source snapshot**:

```bash
FPL=/absolute/path/to/built/forgeplan
node scripts/generate-cli-docs.mjs --binary "$FPL"
node scripts/generate-mcp-docs.mjs --binary "$FPL"
node scripts/check-content-completeness.mjs --binary "$FPL"
node scripts/check-translation-drift.mjs --verbose
npm run build
node scripts/check-dead-links.mjs
```

- CLI discovery reads real nested `--help`. `index-command.md` documents the
  `index` command; `cli/index.md` remains the overview.
- MCP discovery uses `tools/list` JSON Schema for **full and constellation-read**
  in isolated temporary processes; it calls no artifact tools. It rejects a
  temporary directory with a `.forgeplan` ancestor before starting MCP; set
  `TMPDIR` outside existing workspaces if rejected. The current unpublished
  interface requires a matching Constellation binary, not stable 0.38.0.
- Both generators update EN/RU. Only `forgeplan-runtime:start/end` marked
  blocks are owned on detail pages; manual prose/examples survive. Overviews
  are fully generated. Never hand-edit managed blocks. Obsolete pages are
  reported for review, not silently deleted; discovery failure is a failure.
- `--check` is read-only. `--out-dir <directory>` renders/checks an independent
  candidate tree. Scripts never launch Cargo or guess required arguments.
- The completeness check proves registered-interface coverage and metadata
  freshness, not the correctness of all manual examples. Translation mtime
  is only a review heuristic, not semantic equivalence. `changelog.md` is
  intentionally EN-only.
- `npm run build` runs `copy-changelog.mjs` first. Edit the root `CHANGELOG.md`,
  not its generated website copy. Interface generators and the three checks
  are not implicitly run by the build.
- Check rendered new EN/RU routes, sidebar, locale links and anchors in a
  browser. The existing dead-link script checks target files, not fragments
  or external URLs. A successful build does not prove layout or translation.

Contributor architecture, rollback and audit records remain under `../docs/`.
Audit records must name their source/binary snapshot and review scope. Earlier
mechanical checks and semantic samples do not establish a complete corpus review;
the documentation-closure ledger records per-file reads and claim authorities.

## Pin Strategy (critical knowledge)

**ONE GSAP ScrollTrigger pin per page.** Multiple GSAP pins from separate React islands conflict because GSAP requires strict top-to-bottom registration order, but React islands hydrate in arbitrary order.

| Section | Pin Method | Why |
|---------|-----------|-----|
| Hero | **GSAP ScrollTrigger** `pin:true` | Complex rAF animation needs GSAP scrub |
| Trust | **CSS `position: sticky`** | Simple scroll-reveal, no GSAP conflict |
| Pipeline | **CSS `position: sticky`** | Same — CSS sticky is independent |
| Install | None (static) | No animation needed |

### CSS Sticky pattern:
```html
<section style="height: 200vh">           <!-- tall = scroll room -->
  <div class="sticky top-0 h-screen">    <!-- content sticks -->
    <!-- animated content, progress from scroll position -->
  </div>
</section>
```

Progress calculated from section scroll position:
```typescript
const scrolled = -rect.top;
const scrollRange = sectionHeight - viewportHeight;
const progress = clamp(scrolled / scrollRange, 0, 1);
```

## Animation: Crystallization

Hero animation sequence (GSAP ScrollTrigger progress 0→1):

```
0%:       Chaos — lines fly, bounce off walls/each other, dots travel along lines
0-35%:    Lines converge toward hex edge positions
35-65%:   Hexagons fly in from 4x scale (biggest first, ember last)
65-80%:   Outer hexagons fade, only ember hex + dot + iso cube remain
80-100%:  Ember hex + dot shift left, "Forge your plan" typewriter
```

### Physics Engine
- 16 lines (10 artifact + 6 ambient), each with position, velocity, angle
- Segment-to-segment collision detection (not center-to-center)
- Wall bounce by endpoints, torque on collision
- MAX_SPEED: 0.35 px/frame, MAX_ANGULAR: 0.002 rad/frame
- Collision epsilon: 0.5 (prevents NaN from near-zero distances)

## Known Issues / Gotchas

### Astro scoped CSS breaks parent→child selectors
`.header-full .header-logo` gets `:where(.astro-xxx)` scope. **Fix**: put parent→child selectors in `global.css`.

### prefers-reduced-motion
Currently removed. If re-adding: show static initial state (chaos), NOT final scene. Test on device with Reduce Motion enabled.

### Multiple GSAP pins = conflict
Never create multiple `ScrollTrigger.create({pin:true})` from separate React islands. Use CSS sticky for additional pinned sections.

### Pencil mockups: rotation vs position
`snapshot_layout` shows rotated bounding box. Center = `(x + width/2, y + height/2)` in unrotated coords. Don't fix positions by snapshot data.
