---
title: Глоссарий
description: Ключевые термины, используемые в методологии Forgeplan
---

| Термин | Определение |
|------|-----------|
| **Артефакт** | Структурированный канонический Markdown с frontmatter (PRD, RFC, ADR и т. д.); строки БД производны |
| **R_eff** | Надёжность по слабому звену. Явный score report учитывает eligible evidence и зависимости; captured record fields используют более плоский расчёт. Terminal evidence исключены; без eligible ordinary evidence — ноль. |
| **Доказательство** | Measurement, test, benchmark или audit с verdict `supports`, `weakens` или `refutes`; важны явные поля контекста/конгруэнтности |
| **Уровень конгруэнтности (CL)** | Насколько контекст доказательства близок к контексту решения. CL3=идентичный, CL0=противоположный |
| **Глубина** | Строгость методологии: Tactical, Standard, Deep, Critical; текущий core принимает Critical как alias Deep |
| **Конвейер** | Последовательность создания артефактов (например, PRD → RFC для стандартной глубины) |
| **ADI** | Цикл рассуждений: абдукция → дедукция → индукция |
| **Слепое пятно** | Активное решение без связанных доказательств |
| **Сирота (артефакт без связей)** | Артефакт без связей с другими артефактами |
| **Просроченный** | Истёк `valid_until`; detection не меняет автоматически сохранённый lifecycle status и не задаёт каждому артефакту итог `0.1` |
| **Замещённый** | Конечное состояние - заменён более новым артефактом |
| **Устаревший** | Конечное состояние - более не актуален |
| **Гейт валидации** | Правила схемы и эвристики для kind/depth; у активации есть отдельные evidence, length и stub gates |
| **Состязательная ревью** | Активный поиск обоснованных дефектов. Документированный review-протокол допускает ноль подтверждённых дефектов с записью scope и непроверенных рисков; native admission gates отдельны и этим определением не отменяются |
| **PRD** | Документ с требованиями к продукту - что и почему |
| **RFC** | Запрос комментариев - как строить |
| **ADR** | Запись архитектурного решения - почему именно такой подход |
| **Epic** | Группирует PRD, RFC, ADR в инициативу |
| **Spec** | Спецификация - контракты API, модели данных |
| **Проблема** | Сигнал с контекстом - ошибка, риск, наблюдение |
| **Решение** | Сравнение 2-3 вариантов с оценкой по принципу слабого звена |
| **Note** | Микро-решение. Пересмотр через 90 дней — конвенция методологии, не автоматически назначаемая текущим `new` дата expiry |
| **Переоценка** | Переоценка просроченного артефакта |
| **Угасание доказательств** | Расчёт по дате: eligible expired item даёт `0.1` вместо обычной оценки; плавного угасания до expiry нет |
| **F-G-R** | В upstream FPF — Formality, ClaimScope, Reliability. Forgeplan отдельно считает Formality/Granularity/Reliability на шкалах 0–1 с геометрическим средним; это не вероятность и не `min(F,G,R)` |
| **FPF** | First Principles Framework - методология рассуждений |
| **MCP** | Model Context Protocol - интеграция AI-агентов |
| **Роутинг** | Команда, которая предлагает глубину + конвейер для задачи |
| **Проекция** | Канонический Markdown-файл артефакта, не одноразовый экспорт из индекса |
| **Рабочее пространство** | Директория `.forgeplan/` с конфигурацией + хранилищем |
| **LanceDB** | Встраиваемая БД для производных метаданных и векторных индексов, не канонического содержимого артефактов |
| **Constellation** | Протокол индексирования/чтения локальной `0.39.0+constellation.s1.1`; legacy и Constellation layouts не взаимозаменяемы |
| **Поколение (Generation)** | Опубликованное состояние индекса; свежий canonical file read может ещё не входить в сохранённое поколение |
| **Кэш модели** | Общие файлы модели/токенизатора; отличается от semantic build support и векторов workspace |
| **Handle** | Ссылка на scope/snapshot внутри процесса отдельного MCP-профиля `constellation-read` |

См. [руководство Constellation](/ru/docs/guides/constellation/) и
[контракт](/ru/docs/reference/constellation/).
