---
title: Глоссарий
description: Ключевые термины, используемые в методологии Forgeplan
---

| Термин | Определение |
|------|-----------|
| **Артефакт** | Структурированный markdown-документ (PRD, RFC, ADR и т.д.) в `.forgeplan/`; файлы — источник истины, LanceDB — производный индекс |
| **R_eff** | Оценка надёжности CLI: рекурсивный min(собственные текущие доказательства, допустимые оценки зависимостей после штрафов за тип связи). Собственные доказательства учитывают verdict, CL и тип; истёкшие допустимые пакеты вместо этого получают 0.1 до вычитания штрафов. Терминальные исключаются, черновики учитываются; без допустимых собственных доказательств собственная оценка — 0 |
| **Доказательство** | Записанный результат теста, измерения, бенчмарка или аудита, который поддерживает, ослабляет или опровергает утверждение; в теле указывают `verdict`, `congruence_level`, `evidence_type` |
| **Уровень конгруэнтности (CL)** | Близость контекста доказательства к контексту решения: от CL3 (тот же контекст, без штрафа) до CL0 (слабая переносимость, штраф 0.9); CL0 не означает опровергающий вердикт |
| **Глубина** | Уровень строгости: `Tactical`, `Standard`, `Deep`, `Critical` |
| **Конвейер** | Последовательность создания артефактов (например, PRD → RFC для стандартной глубины) |
| **ADI** | Цикл рассуждений: абдукция → дедукция → индукция |
| **Слепое пятно** | Активное решение без связанных доказательств |
| **Сирота (артефакт без связей)** | Артефакт без связей с другими артефактами |
| **Просроченный** | Истёкший `valid_until` отражается в отчёте stale, но не меняет сохранённый статус автоматически в 0.38. Истёкший допустимый EvidencePack оценивается в 0.1; это не оценка любого просроченного решения |
| **Замещённый** | Конечное состояние - заменён более новым артефактом |
| **Устаревший** | Конечное состояние - более не актуален |
| **Гейт валидации** | Проверки содержимого/схемы до обычной активации; для PRD/RFC/ADR/Epic/Spec также проверяются длина, заполнение шаблона и наличие связанных доказательств |
| **Состязательная ревью** | Независимое ревью с активным поиском дефектов, доказательствами, областью и границами проверки; нельзя выдумывать находки ради квоты |
| **PRD** | Документ с требованиями к продукту - что и почему |
| **RFC** | Запрос комментариев - как строить |
| **ADR** | Запись архитектурного решения - почему именно такой подход |
| **Epic** | Группирует PRD, RFC, ADR в инициативу |
| **Spec** | Спецификация - контракты API, модели данных |
| **Проблема** | Сигнал с контекстом - ошибка, риск, наблюдение |
| **Решение** | Сравнение 2-3 вариантов с оценкой по принципу слабого звена |
| **Note** | Краткая запись контекста или небольшого решения; `new` не задаёт автоматически срок в 90 дней |
| **Переоценка** | Переоценка просроченного артефакта |
| **Угасание доказательств** | Оценка допустимых доказательств по сроку действия. Истёкшие пакеты оцениваются в 0.1; терминальные исключаются, а не угасают |
| **F-G-R** | Формальность, гранулярность, надёжность. Оценки артефакта CLI используют шкалы 0–1 и среднее геометрическое; шкала ревью плагина FPF — 0–3 |
| **FPF** | First Principles Framework - методология рассуждений |
| **MCP** | Model Context Protocol - интеграция AI-агентов |
| **Роутинг** | Команда, которая предлагает глубину + конвейер для задачи |
| **Проекция** | Markdown-представление, синхронизированное с производным индексом; markdown остаётся источником истины, а не одноразовым выводом из LanceDB |
| **Рабочее пространство** | Каталог `.forgeplan/` с конфигурацией, markdown артефактов и производным хранилищем |
| **LanceDB** | Встраиваемый производный индекс артефактов, связей и векторных эмбеддингов; восстанавливается из файлов через `reindex`, а не `scan-import` |
| **DerivedStatus** | Вычисляемая метка прогресса: STUB, SHAPED, VALIDATED, EVIDENCED, ACTIVATED; не отдельный сохранённый статус и не независимая гарантия качества |
| **BMAD** | Greenfield-конвейер публичного `agents-bmad`: Analyst → PM → Architect → Scrum-Master → Dev → QA; для блокирующего хука нужен `/bmad-init` |
| **SPARC** | Конвейер публичного `agents-sparc` для одной функции в существующей активной системе: Specification → Pseudocode → Architecture → Refinement → Completion; порядок фаз без отдельного блокирующего хука |
| **TDD** | Подцикл Build публичного `agents-tdd` для активных PRD и SPEC со сценариями: план → RED → независимая проверка/фиксация → GREEN → передача в Audit |
| **Автор ≠ проверяющий** | Автор не сертифицирует собственный результат; передача между фазами требует независимого контекста и записанного вердикта ревью |
| **Зафиксированный эталон (frozen oracle)** | Спецификация и тесты, по которым оценивают код; публичный TDD фиксирует нормализованный хеш SPEC и блокирует изменение тестов в GREEN |
| **Claim** | Ограниченная по времени координационная запись о работе агента над артефактом; не общая блокировка записи файлов или исполнения методологии |
| **Git sync** | Инкрементальная синхронизация изменений артефактов относительно Git-ref; не создаёт эмбеддинги и не заменяет полное восстановление через `reindex` |
| **Restore** | Восстановление случайных delete/deprecate/supersede по квитанции, обычно в течение 30 дней; не обычный выход из терминального состояния |
