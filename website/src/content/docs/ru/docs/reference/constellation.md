Справочник описывает локальный интерфейс **`0.39.0+constellation.s1.1`**. Это не список возможностей опубликованной `0.38.0` и не заявление о полной приёмке S1-G/S2. Воспроизводимая последовательность есть в [гайде с двумя проектами](/ru/docs/guides/constellation/). Наблюдения о совместимости относятся только к проверенным бинарнику и сценариям; изменённому срезу исходников нужны собственные результаты компиляции и проверки работы.

В зафиксированных проверках совместимости прежние имена и формы аргументов CLI, включая CLI-валидацию, работали на legacy-раскладке и раскладке под управлением Constellation. Имена команд, инструментов и скиллов не изменились. Это не подтверждает работу каждого обработчика или готовность семантики.

## Данные и ответственность

| Расположение | Назначение |
|---|---|
| `<project>/.forgeplan/<kind>/*.md` | Канонические инженерные артефакты. Их нужно сохранять при перестройке индекса. |
| `<project>/.forgeplan/config.yaml` | Активные настройки этого workspace, включая явное включение фонового embedding. |
| `<project>/.forgeplan/lance/` | Производный индекс. Constellation публикует поколения через `CURRENT.json`; migrated index — не legacy-хранилище `artifacts.lance`. |
| `~/.forgeplan/constellations.yaml` | Пользовательский реестр групп и required/optional-источников. Он не копирует документы и не запускает писателей. |
| `FORGEPLAN_MODEL_CACHE`, иначе `~/.forgeplan/models` | Общий кэш файлов модели, а не самих векторов документов. |
| `~/.forgeplan/snapshots/` | Git snapshot lockfiles. Сохранённый snapshot ID отличается от MCP handle, живущего в процессе. |

`constellation add` принимает каталог `.forgeplan/`. Создание и переключение группы меняет выбор в реестре, не содержание артефактов. Один full-сервер не обслуживает автоматически всех участников группы.

## Индекс и свежесть

Поколение именует точные версии таблиц артефактов, связей и секций. Читатели фиксируют эти версии, а не открывают последние таблицы незаметно для вызывающего. Reconcile захватывает канонические данные, вычисляет изменения и публикует производный результат.

- `forgeplan index` выполняет явный проход обслуживания и может начать переход на новую раскладку.
- `forgeplan reindex` на уже migrated workspace передаёт работу Constellation. Это не повод удалять `.forgeplan/` или переинициализировать config.
- Обычное каноническое чтение может увидеть Markdown новее опубликованного индекса. CLI JSON показывает `persisted: false` для такого временного представления; это не подтверждённая публикация.
- Full MCP запись может вернуть `index_pending: true`. Канонический файл записан, но публикация ещё не подтверждена. Прочитайте причину и проверьте последующее опубликованное состояние.
- `index --list`, `--generations` и `--gc` — отдельные параметры просмотра и обслуживания. См. [точный интерфейс index](/ru/docs/cli/index-command/); не придумывайте параметры вроде `index --json`, которых сборка не объявляет.

## Контракты чтения

Не сравнивайте каждое поле `body` с одной и той же строкой байтов.

| Операция | Выбор | Тело и версия |
|---|---|---|
| CLI `forgeplan get ID --json` | Текущий workspace | Весь захваченный Markdown-файл, включая frontmatter; метаданные свежести отличают временное представление от опубликованного. |
| Full MCP `forgeplan_get` | `id`, необязательный `workspace` | Каноническое/captured-чтение; `body` включает полный Markdown. Это не envelope pinned-get. |
| Full MCP `forgeplan_constellation_get` | `key`, необязательный `workspace` | Опубликованная строка в `artifact`; `artifact.body` — разобранное тело после внешнего frontmatter. Возвращаются поколение и `source_digest`. |
| Federation get / read MCP со `scope_handle` | `id`, при необходимости с источником | Проверяйте `source.channel`. У опубликованной строки `pinned` тело разобрано; это не полный файл обычного CLI get. |
| Read MCP со `snapshot_handle` | `id` внутри выбранного snapshot | `pinned_git` содержит полный закоммиченный Git-файл с frontmatter, не текущую правку рабочей копии. |

Разобранное тело само может содержать YAML и Markdown-разделители: это не означает удаление всех похожих на frontmatter блоков. Ориентируйтесь на операцию и канал, а не на самодельное обрезание текста.

### Идентичность и неоднозначность

Используйте возвращённые ключи как непрозрачные идентификаторы. Не собирайте их из заголовка или имени файла. Один display ID, например `NOTE-001`, может существовать в нескольких проектах.

Тогда federation get вернёт `result: "ambiguous"` и список источников. Уточните ID как `KEY@source-fragment`, например через возвращённый `src:<hash>` или уникальный сегмент пути. Успех выбора подтверждают `result: "found"` и правильный источник; одного exit code 0 недостаточно.

Live и Git-pinned source IDs могут отличаться. После выбора snapshot выполните поиск внутри него и заново возьмите его `source_id`. Квалификатор из live-ответа может дать `error: "no_source"`, даже если документ есть в Git snapshot.

## MCP-профили и выбор workspace

| Профиль | Зарегистрировано в этой сборке | Назначение |
|---|---:|---|
| `full` по умолчанию | 76 | Обычные операции с артефактами, включая запись, и локальное чтение опубликованного индекса. Регистрация не подтверждает работу каждого инструмента на всех раскладках workspace. |
| `constellation-read` | 9 | Чтение через registry-bound scope/snapshot; нет инструментов записи артефактов и аргумента с произвольным workspace path. |

`--profile` принимает только `forgeplan serve`. У `forgeplan mcp serve` и standalone `forgeplan-mcp` есть настройки workspace/maintenance, но нет этого выбора профиля.

Для full-запросов приоритет workspace такой:

1. Параметр запроса `workspace`, если он поддержан и передан.
2. `FORGEPLAN_WORKSPACE`.
3. Серверный default, заданный через `--workspace`.
4. Поиск от текущего каталога процесса.

На старте full-сервера цель обслуживания: `FORGEPLAN_WORKSPACE` → default из `--workspace` → поиск от текущего каталога. Задайте нужный проект или явно `FORGEPLAN_WORKSPACE=""`. Одного `unset` недостаточно: CLI до разбора аргументов загружает `.env` из родительских каталогов. Загрузчик сохраняет уже заданное пустое значение, а resolver его пропускает. Поздний запрос к другому проекту **не** перемещает хост и не запускает там обслуживание. У физического индекса один владелец публикации; не запускайте против него старых и новых писателей одновременно.

На legacy layout обслуживание включается явно через `--auto-index` или `watch --constellation`. Уже migrated workspace также поднимает обслуживание в full-сервере. Read-профиль такого писателя не создаёт.

См. [настройку MCP](/ru/docs/guides/mcp-setup/), [каталоги профилей](/ru/docs/mcp/) и [`serve`](/ru/docs/cli/serve/).

### Последовательность read-профиля

| Инструмент | Существенные аргументы / результат |
|---|---|
| `constellation_open` | Необязательное имя группы `constellation`; возвращает `scope_handle` и источники. |
| `constellation_sources` | `handle` того же процесса; проверьте идентификаторы и роли. |
| `constellation_search` | `query` и ровно один scope/snapshot handle. |
| `constellation_get` | `id` и ровно один scope/snapshot handle. |
| `constellation_graph` | Handle, необязательный `limit`. Пустой граф не доказывает корректность impact. |
| `constellation_impact` | Handle и изменённый `id`, необязательные `depth`/`max_nodes`. |
| `constellation_pack` | Handle, `task`, необязательный оценочный `budget`. |
| `constellation_snapshot` | `handle` открытого scope; возвращает `snapshot_handle`, `pinned` и `skipped`. |
| `constellation_close` | `handle`; scope и snapshot закрываются отдельно. |

Для чтения передавайте `scope_handle` **или** `snapshot_handle`, не оба сразу. Параметр `handle` используется у sources/snapshot/close. Полные схемы, nullable и defaults приведены на [страницах инструментов](/ru/docs/mcp/).

Handles принадлежат одному работающему процессу, не сохранённой конфигурации клиента. Закрытый, неизвестный или утративший актуальность handle — не просьба прочитать latest. При `snapshot_expired` получите новый scope или осознанно выберите новый snapshot. Проверка версии источников scope и закоммиченная ревизия Git snapshot — разные контракты.

MCP возвращает JSON-текст внутри tool result. Разберите его и проверьте предметные поля `error`, `result`, `failures`, `partial`: успешный обмен сообщениями ещё не означает успешного чтения.

## Required, optional и partial

Сбой required-источника нельзя незаметно трактовать как «артефактов не найдено». Strict-операция отказывает при недоступном обязательном источнике. Регистрируйте `--optional` только там, где отсутствие допустимо; проверяйте поимённые отказы даже в разрешённом ответе.

CLI `--allow-partial` и read MCP `strict: false` разрешают частичный ответ там, где поддержаны. Они не делают истёкший неизменяемый handle действительным. Состав snapshot закреплён lockfile; не рассчитывайте изменить его через `strict`.

Проверяйте `failures`, `partial`, `truncated`, ожидаемые источники и `skipped` у snapshot. Здоровый `doctor` не доказывает чтение каждого файла или пригодность всех векторов. Неполные чтения и совместимость отслеживаются в [#538](https://github.com/ForgePlan/forgeplan/issues/538).

## Готовность семантики

Это разные ресурсы: сборка с `semantic-search`, файлы модели в кэше, активный embedding profile и пригодные векторы, связанные с текущим захваченным содержимым.

Для автоматической обработки нужна активная конфигурация workspace, например:

```yaml
embedding:
  model: bge-m3
  chunk_size: 2000
```

Также нужны поддерживаемый BGE-M3 snapshot в выбранном кэше и живой maintenance host этого workspace. Без `config.embedding` очередь пропускается; ручной `embed` настройку не сохраняет. Если cached profile не разрешился, работа остаётся pending, а причина выводится в stderr; фон не скачивает модель незаметно.

`init --force` заменяет активные настройки defaults. Прежний embedding-блок остаётся лишь в backup до ручного восстановления; это может отключить фоновый пересчёт.

| Сигнал | Значение |
|---|---|
| `semantic_available: true` | Локальный семантический запрос использовал доступный профиль/векторы. Всё ещё нужны проверка релевантности и покрытия. |
| `eligible_rows` / `expected_rows` | Пригодные строки, связанные с этим captured input, против ожидаемых строк префикса артефакта и секций; это не число документов. |
| `semantic_scope: "prefix+sections"` | Локальная семантика покрывает префикс и секции, не только обрезанное начало документа. |
| `ready` / `pending` / `failed` / `unavailable` | Готовность строки, не наличие канонического Markdown. |

Принудительный локальный `search --semantic` может отказать без опубликованного профиля или пригодных векторов. Keyword fallback не гарантирован. Smart search и federation — разные интерфейсы: у `constellation search` и read-профиля здесь лексический поиск без аргумента semantic-mode. Поле `semantic_state` не доказывает межпроектное векторное ранжирование.

### Окна секций

`s1-token-layout-v2` строит последовательные окна из точного разобранного `artifact.body`. Смещения — UTF-8 байты внутри этого тела, не число символов и не смещения полного файла с внешним frontmatter. При применении диапазонов сохраняйте именно тело, использованное планом.

Токеновый бюджет ограничен `min(model_max_length, 512)` с учётом служебных токенов и заголовка/контекста. Длинная секция даёт несколько окон. Байты заголовков, преамбула, повторы заголовков и пробелы не нормализуются. Новая layout identity требует повторной индексации и embedding; старые векторы не доказывают покрытие новой раскладки.

`chunk_size` задаёт вход префикса артефакта/профиля, не заменяет токеновый бюджет окон. Принудительный локальный semantic search может вернуть несколько строк одного документа; для группировки используйте `document_key`, а не считайте каждый ключ секции отдельным артефактом.

## ContextPack и расширенные чтения

ContextPack выбирает ранжированные units с ролями, пропусками и receipt. `receipt.token_kind: "estimated_chars_div_4"` означает оценку выбранного содержимого, **не** строгий предел токенов модели для всего сериализованного JSON. Проверяйте `payload_bytes`, если интерфейс его возвращает; CLI, live и snapshot могут иметь разные обёртки.

Реализация graph/impact принимает квалифицированные ссылки. Это не заявление о приёмке всех межпроектных зависимостей или аварийных сценариев. Доступность экспорта также не доказывает round-trip внешнего адаптера. Для таких выводов смотрите незакрытые критерии [#538](https://github.com/ForgePlan/forgeplan/issues/538), не само наличие инструмента.

## Диагностика и восстановление

| Наблюдение | Действие |
|---|---|
| CLI сообщает об отказе legacy store на workspace под управлением Constellation | Сверьте выбранный бинарник и срез исходников с зафиксированными проверками совместимости. Не обходите ошибку, открывая выведенные из эксплуатации таблицы старым бинарником. Проверенный сценарий валидации не подтверждает работу всех остальных инструментов. |
| Get свежий, но `persisted: false`, либо запись `index_pending` | Сравнивайте канонические байты и опубликованное поколение отдельно. Дайте единственному владельцу опубликовать изменения либо остановите его перед явным проходом. |
| Нет embedding profile / ноль eligible rows | Проверьте активный config, build feature, совместимость кэша/профиля и stderr писателя. Сам запуск сервера не проверяет готовность. |
| Queue skipped / failed | Сохраните ошибку и состояние источника. Не удаляйте кэш модели или канонический workspace ради проверки догадки. |
| `ambiguous` / `no_source` | Возьмите идентификатор из того же live/snapshot ответа. Не угадывайте проект по display ID. |
| `snapshot_expired` | Откройте заново осознанно. Не подставляйте более свежий текст незаметно. |

Перестраивайте производный индекс подходящим `index`/`reindex`, сохраняя Markdown и config. `scan-import` — не рецепт восстановления индекса. При откате нужно сохранить новые канонические изменения и вернуть согласованные бинарник, индекс и настройки; замены только программы недостаточно.
