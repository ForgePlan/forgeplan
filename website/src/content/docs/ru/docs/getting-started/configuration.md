`.forgeplan/config.yaml` задаёт настройки workspace. Справочник различает
поля схемы и настройки, которые читают текущие CLI/MCP пути: наличие поля
или env helper в схеме не означает, что его использует каждая команда.
Схема задаёт defaults и для метаданных, и для необязательных секций.

Примечания Constellation ниже относятся к локальной сборке
`0.39.0+constellation.s1.1`, а не опубликованной 0.38.0. См.
[руководство](/ru/docs/guides/constellation/) и
[справочник](/ru/docs/reference/constellation/).

## Структура рабочего пространства

После `forgeplan init -y` каталог `.forgeplan/` создается рядом с вашим кодом:

```
.forgeplan/
├── config.yaml         ← конфигурация рабочего пространства (GITIGNORED - содержит ссылки на переменные окружения)
│
├── adrs/               ← отслеживаемые Git markdown-артефакты (источник истины)
├── rfcs/
├── prds/
├── epics/
├── specs/
├── problems/
├── solutions/
├── evidence/
├── notes/
├── refresh/
├── memory/             ← журнал решений (отслеживаемый Git)
│
└── lance/              ← GITIGNORED - производный индекс, layout зависит от версии
```

**Markdown каноничен**; индекс производный. Для Constellation используйте
`forgeplan index`, для legacy layout — `forgeplan reindex`, а не
`scan-import`, который импортирует документы. Не коммитьте локальные config
и индекс согласно ignore-политике проекта. Кэш модели общий и находится вне проекта.

:::caution[Повторная инициализация и defaults]
`forgeplan init -y` ничего не меняет, если найден `.forgeplan/`, в том числе
в родительском каталоге. Он не восстанавливает отсутствующий config после
клонирования. `init -y --force` сохраняет Markdown артефактов и создаёт
резервную копию, но активирует новый config с defaults. Верните нужные
настройки из копии осознанно; не удаляйте workspace.
:::

## Ключи верхнего уровня

```yaml
version: 1
project_name: ForgePlan
default_depth: standard
id_digits: 3
created_at: 2026-03-24
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `version` | `u32` | `1` | Версия схемы конфигурации. Обновляется только при критических изменениях схемы. |
| `project_name` | `string` | `""` | Человекочитаемое имя проекта. Отображается в `forgeplan health`, отчетах и экспорте. |
| `default_depth` | `string` | `standard` | Метаданные схемы, не fallback текущей команды `route`. Keyword routing без сигналов возвращает Tactical. Методология различает Tactical, Standard, Deep и Critical; runtime преобразует `critical` в Deep. |
| `id_digits` | `u32` | `3` | Ширина заполнения нулями для ID артефактов (например, `PRD-001` против `PRD-0001`). Изменяйте только при создании рабочего пространства - существующие ID не перенумеровываются. |
| `created_at` | `date` | сегодня | Дата `ГГГГ-ММ-ДД` инициализации рабочего пространства. Метаданные только для чтения. |

### Значения глубины

| Значение | Когда использовать |
|-------|-------------|
| `tactical` | Быстрое исправление, обратимое за день. Артефакт не требуется. |
| `standard` | Функция на 1–3 дня, один явный компромисс. Конвейер PRD -> RFC. Рекомендуется ADI. |
| `deep` | Новый модуль, 1–2 недели. PRD -> Spec -> RFC -> ADR. ADI обязателен. |
| `critical` | Межкомандная подсистема, стратегическая. Epic -> N артефактов. ADI + состязательная ревью. |

Эвристики описаны в [руководстве по глубине](/ru/docs/methodology/routing/).

## `llm:` - Провайдер LLM

Используется `forgeplan generate`, `forgeplan reason` (ADI), `forgeplan route` (уровень 1+) и инструментами MCP, которые вызывают LLM.

```yaml
llm:
  provider: gemini
  model: gemini-3-flash-preview
  api_key_env: GEMINI_API_KEY
  # base_url: https://...        # переопределение для пользовательских конечных точек
  # max_tokens: 4096
  # temperature: 0.7
  # reason_temperature: 0.3      # ниже для структурированного вывода ADI
  # timeout_seconds: 120         # обычные вызовы LLM
  # reason_timeout_seconds: 600  # только forgeplan reason
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `provider` | `enum` | `openai` | HTTP: `openai`, `claude`, `gemini`, `ollama`, `custom`. CLI с подпиской: `claude-code`, `codex-cli`, `devin-cli`, `gemini-cli`, `cursor-agent`. |
| `model` | `string` | `gpt-4o-mini` | Идентификатор HTTP-модели. Для локального CLI допустимы только `[A-Za-z0-9._:-]` (до 64 байт); `model: ""` выбирает модель CLI по умолчанию. |
| `api_key_env` | `string?` | зависит от провайдера | Только для HTTP-провайдеров: имя переменной окружения с ключом API. |
| `base_url` | `string?` | зависит от провайдера | Только для HTTP-провайдеров: адрес самостоятельно размещённого или прокси-сервиса. Полезно для Ollama, LiteLLM и Azure-совместимых шлюзов. |
| `max_tokens` | `u32` | `4096` | Максимальное количество токенов ответа. Увеличьте для длинных рассуждений ADI; уменьшите для экономии средств. |
| `temperature` | `f32` | `0.7` | Температура HTTP-генерации. Низкие значения уменьшают вариативность; `0.0` не гарантирует детерминированный ответ провайдера. Локальные CLI-профили используют не все HTTP-настройки. |
| `reason_temperature` | `f32?` | - | Переопределение для `forgeplan reason`. Если не задано, используется `min(temperature, 0.3)`, а не `temperature` без ограничения. |
| `timeout_seconds` | `u64` | `120` | Общий таймаут обычных вызовов LLM, включая передачу stdin и чтение вывода локального CLI. |
| `reason_timeout_seconds` | `u64?` | фактически `600` | Переопределение только для `forgeplan reason`; заменяет `timeout_seconds` при ADI. |

### Матрица провайдеров

| Провайдер | Бинарь / транспорт | Вход | Безопасный режим | Ограничение | Production |
|----------|---------------------|------|-------------------|-------------|------------|
| `openai` | HTTP | `OPENAI_API_KEY` | граница API | Платный API | поддерживается |
| `claude` | HTTP | `ANTHROPIC_API_KEY` | граница API | Платный API | поддерживается |
| `gemini` | HTTP | `GEMINI_API_KEY` | граница API | Платный API | поддерживается |
| `ollama` | локальный HTTP | не нужен | локальная модель | Сервером управляет оператор | поддерживается |
| `custom` | HTTP | явный `api_key_env` | задаёт оператор | Нужно задать `base_url` | поддерживается |
| `claude-code` | `claude`; промпт через stdin | `claude login` | инструменты не разрешены | Наследует рабочий каталог вызывающего процесса | только локально |
| `codex-cli` | `codex`; промпт через stdin | `codex login` / `codex login status` | одноразовая сессия, read-only sandbox, отдельный home | Квота подписки | только локально |
| `devin-cli` | `devin`; закрытый файл промпта | `devin auth login` / `devin auth status` | sandbox + `auto` в пустом временном каталоге; автоматически разрешены только read-only tools | Нет документированного строгого read-only; отключён на Windows | только локально |
| `gemini-cli` | `gemini`; промпт через stdin | интерактивный вход в `gemini` | sandbox + обычное одобрение в пустом временном каталоге | Headless-доступ зависит от аккаунта/продукта | только локально |
| `cursor-agent` | `cursor-agent`; промпт через stdin | `cursor-agent login` / `cursor-agent status` | `ask` + sandbox в пустом временном каталоге | Агентский CLI, не completion API | только локально |

Devin Desktop может содержать агентский CLI, но не добавлять `devin` в `PATH`
(`/Applications/Devin.app/Contents/Resources/app/extensions/windsurf/devin/bin/devin`
в проверенной сборке для macOS). Выведите этот бинарь как `devin` в доверенном
каталоге `PATH`, затем выполните `devin auth login`: входы Desktop и CLI
раздельны.

CLI-провайдеры с подпиской включаются только явно: ForgePlan не выбирает их
автоматически, не читает и не копирует токены входа. Они предназначены для
личной локальной разработки, а не для production, общих машин или CI. Промпт
передаётся через stdin/закрытый файл, имя модели проверяется, переменные с
API-ключами не передаются. Четыре новых профиля (`codex-cli`, `devin-cli`,
`gemini-cli`, `cursor-agent`) запускаются в новых временных каталогах;
существующий профиль `claude-code` сохраняет рабочий каталог вызывающего
процесса, но использует общий ограниченный runner и общий recursion guard. Если
`model` не задан для одного из четырёх новых профилей, исторический HTTP default
`gpt-4o-mini` считается пустым; явный `model: ""` даёт тот же результат.

Это примеры конфигурации, не измеренный рейтинг цены/качества и не гарантия
доступности. Проверьте ID модели и доступ у своего провайдера. Default схемы —

| Провайдер | Модель | Когда использовать |
|----------|-------|-------------|
| Gemini | `gemini-3-flash-preview` | Пример выбора модели; нужна модель, доступная вашему аккаунту. Default конфигурации остаётся `gpt-4o-mini`. |
| Gemini | `gemini-3-pro` | Глубокие рассуждения, критические решения, длинный контекст. |
| OpenAI | `gpt-5-mini` | Сбалансированная цена/качество для generate + route. |
| OpenAI | `gpt-5` | Критический ADI, состязательная ревью. |
| Anthropic | `claude-haiku-4-5-20251001` | Дешевый роутинг и классификация. |
| Anthropic | `claude-sonnet-4-6` | Пример для generate + reason, не default конфигурации. |

Вы можете сменить провайдера в любое время - артефакты не зависят от модели. Существующие записи ADI, ревью и сгенерированный контент остаются действительными. Только новые вызовы LLM будут использовать нового провайдера.
:::

### Переопределения переменных окружения (LLM)

Следующие переменные окружения переопределяют поля `llm:` во время выполнения без редактирования `config.yaml`:

| Переменная окружения | Переопределяет |
|---------|-----------|
| `FORGEPLAN_LLM_PROVIDER` | `provider` |
| `FORGEPLAN_LLM_MODEL` | `model` |
| `FORGEPLAN_LLM_BASE_URL` | `base_url` |
| `FORGEPLAN_LLM_MAX_TOKENS` | `max_tokens` |
| `FORGEPLAN_LLM_API_KEY_ENV` | `api_key_env` (имя, а не значение) |

Приоритет: **переменная окружения > config.yaml > значение по умолчанию**.

## `embedding:` - Семантический поиск

Нужна build feature `semantic-search`. Текущий движок tract принимает только
`bge-m3` (1024 измерения). Имена из прежних релизов fastembed эта реализация
не поддерживает.

Модель занимает около 2.1 GB. Приоритет кэша: `FORGEPLAN_MODEL_CACHE` →
`~/.forgeplan/models` → платформенный/старый fallback лишь при отсутствии home.
`HF_HOME` не переопределяет путь tract. Для явной подготовки модели есть
`forgeplan setup`; запросы и обслуживание используют готовый снапшот из кэша.

```yaml
embedding:
  model: bge-m3
  chunk_size: 2000
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `model` | `string` | `bge-m3` | Единственное имя модели, поддерживаемое runtime. |
| `chunk_size` | `usize` | `2000` | Бюджет символов префикса тела для embedding profile, не общий лимит токенов и не ограничение канонического Markdown. Constellation также индексирует окна секций. |

### Условия автоматических эмбеддингов

На мигрированном workspace фоновая обработка очереди читает **явный**
`config.embedding` напрямую. Нужны поддерживаемая модель, полный снапшот
в кэше, опубликованное поколение, build feature и работающее обслуживание.
Без `embedding:` ожидающие строки так и остаются pending. Одного
`serve --auto-index` недостаточно; ручной `forgeplan embed` настройку не сохраняет.

`EmbeddingConfig::with_env_overrides()` существует для
`FORGEPLAN_EMBEDDING_MODEL`, но автоматический drain его не вызывает.
Переменная не заменяет секцию `embedding:`. После изменения входов профиля
используйте [процедуру индексирования Constellation](/ru/docs/guides/constellation/),
не удаляйте кэши и не перестраивайте индекс через `scan-import`.

## `storage:` - Бэкенд хранилища

```yaml
storage:
  driver: lancedb
  # path: /custom/workspace-root
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `driver` | `string` | `lancedb` | Поддержка зависит от вызывающего пути; см. ниже. |
| `path` | `string?` | корень workspace | Корень для storage factory, не универсальное переопределение путей всех индексов. |

Storage factory реализует `lancedb` (`lance`) и хранилище в памяти
(`memory`, `in_memory`). `sqlite` упомянут в комментариях схемы, но
**не реализован фабрикой**. In-memory factory не заменяет постоянное
хранилище Constellation. Другие команды открывают workspace stores напрямую;
эта секция не переключает все CLI/MCP операции на другой backend или каталог.

`StorageConfig::with_env_overrides()` определяет `FORGEPLAN_STORAGE_DRIVER`
и `FORGEPLAN_STORAGE_PATH`; текущее открытие storage не вызывает helper.
Это не универсальные runtime overrides.

## `memory:` - Поле схемы

```yaml
memory:
  driver: file
```

Схема принимает строку `driver` (default `file`) и определяет helper
`FORGEPLAN_MEMORY_DRIVER`. Это не гарантия, что `driver: none` отключает
журнал: текущие команды не выбирают memory backend через эту настройку.
Не используйте её как средство защиты приватности.

## `estimate:` - Движок оценки

Конфигурирует `forgeplan estimate` - многоуровневую модель оценки, которая сочетает ваш экспертный опыт с мультипликаторами типов задач ИИ. Каждое поле необязательно; опустите всю секцию, чтобы использовать значения по умолчанию.

Мультипликаторы ниже — предположения модели оценки, не измеренные ускорения
и не ограничения возможностей ИИ. Калибруйте их по своей работе.

```yaml
estimate:
  grade_profile:
    backend: middle          # ваш уровень в бэкенд-разработке
    frontend: junior         # ваш уровень во фронтенде
    devops: senior           # ваш уровень в devops/инфраструктуре
    ai_ml: principal         # ваш уровень в AI/ML
    default: senior          # запасной вариант для неуказанных областей
  grade_multipliers:
    junior: 2.0              # относительно senior (базовый 1.0)
    middle: 1.5
    senior: 1.0
    principal: 0.7
    ai: 0.4                  # значение схемы; текущий расчёт AI-часов его не использует
  ai_task_multipliers:
    pure_coding: 0.10        # предполагаемая доля базовых часов Senior
    coding_infra: 0.25       # смешанное кодирование + инфраструктура
    design_coding: 0.30      # проектирование + реализация
    pure_infra: 0.50         # только инфраструктура
    coordination: 1.00       # предполагает отсутствие сокращения времени
  review_overhead: 0.30      # 30% добавляется к времени ИИ для человеческого ревью
  safety_margin: 0.50        # принятое схемой default-значение; расчёт/предупреждения его не используют
```

### Поля

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `grade_profile` | `map<string, grade>` | - | Уровень разработчика по областям. Ключи - это произвольные имена областей; как минимум определите `default`. |
| `grade_multipliers` | `map<string, f64>` | см. ниже | Мультипликатор времени для каждого уровня, относительно базового уровня senior `1.0`. |
| `ai_task_multipliers` | `map<string, f64>` | см. ниже | Доля человеческого времени, которую ИИ занимает для каждого типа задачи. |
| `review_overhead` | `f64` | `0.30` | Доля, добавляемая к времени, затраченному ИИ, для покрытия человеческого ревью. `0.30` = 30%. |
| `safety_margin` | `f64` | `0.50` | Принимаемое схемой поле с этим default; текущий расчёт estimate и путь предупреждений о загрузке спринта его не используют. Встроенное предупреждение о превышении ёмкости оно не запускает. |

### Уровни

| Уровень | Мультипликатор по умолчанию | Значение |
|-------|-------------------:|---------|
| `junior` | 2.0 | Изучает область - занимает в 2 раза больше времени, чем senior. |
| `middle` | 1.5 | Может работать самостоятельно - в 1.5 раза больше, чем senior. |
| `senior` | 1.0 | Базовый уровень. |
| `principal` | 0.7 | Предполагает на 30% меньше времени относительно Senior, не на 30% большую производительность. |
| `ai` | 0.4 | Сохранённое поле config; текущий расчёт AI-часов использует вместо него `ai_task_multipliers`, затем добавляет review overhead. |

### Типы задач ИИ

| Тип задачи | По умолчанию | Типичная работа |
|-----------|--------:|--------------|
| `pure_coding` | 0.10 | Написание чистого кода - функций, тестов, рефакторинга. ИИ здесь превосходит. |
| `coding_infra` | 0.25 | Кодирование, смешанное с инструментами (CI, скрипты, конфигурации). |
| `design_coding` | 0.30 | Проектные решения + реализация. |
| `pure_infra` | 0.50 | Только инфраструктурная работа - ИИ помогает, но человек валидирует каждый шаг. |
| `coordination` | 1.00 | Встречи, ревью, согласование; предполагает отсутствие сокращения времени. |

### Рабочий пример

> Старший бэкенд-инженер оценивает задачу в **8 часов**. ИИ обрабатывает задачу как `pure_coding`:
>
> ```
> raw_time       = 8h × grade_multipliers.senior   = 8h × 1.0 = 8h
> ai_time        = 8h × ai_task_multipliers.pure_coding = 8h × 0.10 = 0.8h
> with_review    = 0.8h × (1 + review_overhead)    = 0.8h × 1.30 = 1.04h
> ```
>
> Итоговая оценка: **~1 час** времени ИИ, управляемого человеком.

CLI: [`forgeplan estimate`](/ru/docs/cli/estimate/).

## `fpf:` - Движок Trust Calculus FPF

[Движок FPF](/ru/docs/methodology/adi/) имеет пороги explore/exploit,
веса надёжности и отдельный расчёт trust model. Схема также принимает
ADI-настройки, которые текущий CLI `reason` не использует; см. ниже.

```yaml
fpf:
  weights:
    reff: 0.5
    links: 0.3
    freshness: 0.2
  thresholds:
    explore_reff: 0.01
    investigate_reff: 0.5
    exploit_reff: 0.7
    exploit_fgr: 0.6
    explore_fgr: 0.4
  cl_penalties:
    cl0: 0.9
    cl1: 0.4
    cl2: 0.1
    cl3: 0.0
  decay:
    expired_score: 0.1
  adi:
    max_hypotheses: 5
    kb_sections_limit: 5
    temperature_cap: 0.3
    auto_save: true
```

### `fpf.weights` - Веса компонентов надёжности

Компоненты оценки надёжности внутри F-G-R. Значения не обязательно должны суммироваться до 1.0, но обычно это так.

| Поле | По умолчанию | Значение |
|-------|--------:|---------|
| `reff` | `0.5` | Вес оценки R_eff (качество доказательства). |
| `links` | `0.3` | Максимальный бонус, присуждаемый за входящие/исходящие типизированные связи. |
| `freshness` | `0.2` | Бонус, если артефакт не классифицирован stale; отсутствие даты expiry не доказывает недавнюю проверку. |

### `fpf.thresholds` - Отсечки исследования/эксплуатации

Пороги explore/exploit в модели FPF. Они не настраивают глубину задач
в [`forgeplan route`](/ru/docs/cli/route/).

| Поле | По умолчанию | Вызываемое действие |
|-------|--------:|------------------|
| `explore_reff` | `0.01` | R_eff ниже этого -> **ИССЛЕДОВАТЬ** (рассматривать как черновик). |
| `investigate_reff` | `0.5` | R_eff ниже этого -> **ИЗУЧИТЬ** (требуется больше доказательств). |
| `exploit_reff` | `0.7` | Порог R_eff для рекомендации модели **EXPLOIT**, не гарантия того, что на артефакт безопасно полагаться. |
| `exploit_fgr` | `0.6` | Общий F-G-R, необходимый для подтверждения ЭКСПЛУАТАЦИИ (в сочетании с `exploit_reff`). |
| `explore_fgr` | `0.4` | F-G-R ниже этого -> **ИССЛЕДОВАТЬ** приоритет 1 (в сочетании с `explore_reff`). |

### `fpf.cl_penalties` - Штрафы за уровень конгруэнтности

Штраф, применяемый к доказательствам в зависимости от того, насколько хорошо их контекст соответствует артефакту, который они информируют. `CL3` (тот же контекст) без штрафа; `CL0` (противоположный контекст) сильно дисконтируется.

| Поле | По умолчанию | Значение |
|-------|--------:|---------|
| `cl0` | `0.9` | Противоположный контекст - почти нулевое доверие. |
| `cl1` | `0.4` | Другой контекст - значительная скидка. |
| `cl2` | `0.1` | Похожий контекст - незначительная скидка. |
| `cl3` | `0.0` | Тот же контекст - без штрафа. |

Поле `congruence_level` описано в [доказательствах](/ru/docs/methodology/evidence/).

### `fpf.decay` - Угасание доказательств

| Поле | По умолчанию | Значение |
|-------|--------:|---------|
| `expired_score` | `0.1` | Оценка, присваиваемая доказательству после `valid_until`. `0.1` отражает "просрочено, но не отсутствует" - доказательство существовало, просто нуждается в повторной проверке. |

Эти настройки параметризуют trust model FPF. Текущий обычный путь `score`
отдельно использует фиксированные CL-штрафы и оценку просроченного
доказательства `0.1`; этот блок не является глобальным scoring override.

### `fpf.adi` - Конфигурация рассуждений ADI

Это допустимые поля схемы, не действующие настройки текущего CLI `reason`.
Его промпт запрашивает 3+ гипотезы, поиск KB использует фиксированную
процедуру, а связанный Note сохраняется только с `--save`.

| Поле | Тип | По умолчанию | Значение |
|-------|------|--------:|---------|
| `max_hypotheses` | `u32` | `5` | Поле схемы; текущий CLI-промпт его не читает. |
| `kb_sections_limit` | `usize` | `5` | Поле схемы; текущий CLI-поиск KB его не читает. |
| `temperature_cap` | `f32` | `0.3` | Поле схемы; CLI использует `llm.reason_temperature` либо `min(llm.temperature, 0.3)`. |
| `auto_save` | `bool` | `true` | Поле схемы; сохранением CLI управляет `reason --save`. |

### `fpf.rules` - Декларативные правила исследования-эксплуатации (продвинутый уровень)

Необязательные пользовательские explore/exploit rules. При пустом списке
используются `default_rules()`. Схема и примеры:
[правила FPF](/ru/docs/cli/fpf-rules/).

:::caution[Валидация FPF]
Валидатор FPF проверяет конечность и неотрицательность thresholds, weights,
CL penalties и decay, структуру правил и уникальность их имён. Это не
равнозначная проверка каждого поля схемы; ранний выход `init` в существующем
workspace также не является успешной проверкой config.
:::

## `integrity:` - Ограничения на ввод Health & MCP

Пороги, используемые `forgeplan health` (обнаружение дубликатов, обнаружение заглушек) и ограничения защиты от DoS, применяемые сервером MCP к входящим вызовам `forgeplan_new` / `forgeplan_update`.

```yaml
integrity:
  duplicate_threshold: 0.7
  duplicate_pairs_limit: 10
  stub_marker_threshold: 3
  mcp_max_title_len: 256
  mcp_max_body_len: 1048576      # 1 MiB
  evidence_provenance_gate: warn # block | warn | off
```

| Поле | Тип | По умолчанию | Диапазон | Описание |
|-------|------|--------:|-------|-------------|
| `duplicate_threshold` | `f64` | `0.7` | `[0.0, 1.0]` | Сходство Жаккара, выше которого два артефакта помечаются как дубликаты в `forgeplan health`. |
| `duplicate_pairs_limit` | `usize` | `10` | `[1, 10000]` | Максимальное количество пар дубликатов, отображаемых в выводе health (пагинация). |
| `stub_marker_threshold` | `usize` | `3` | `>= 1` | Минимальное количество маркеров заглушек (`TODO`, `TBD`, пустые заголовки и т. д.), необходимое для пометки тела артефакта как заглушки. |
| `mcp_max_title_len` | `usize` | `256` | `[16, 4096]` | Максимальная длина заголовка артефакта, принимаемая через MCP. Предотвращает злоупотребление памятью со стороны вредоносных клиентов. |
| `mcp_max_body_len` | `usize` | `1048576` | `[1024, 104857600]` | Максимальная длина тела артефакта (байты), принимаемая через MCP. По умолчанию: 1 МиБ. Жесткий лимит: 100 МиБ. |
| `evidence_provenance_gate` | `string` | `warn` | `block` \| `warn` \| `off` | Гейт git-provenance при активации для code-claiming EvidencePack (PRD-082). Если пак объявил `base_sha` / `result_sha` / `changed_paths`, `forgeplan activate` перепроверяет claim против реальной git-дельты вместо доверия самоотчёту. `block` — отказать в активации (артефакт остаётся `draft`); `warn` — активировать и показать расхождение (CLI в stderr, MCP в success-payload); `off` — пропустить проверку. Паки без provenance-полей не затронуты. Нерезолвимая SHA всегда только предупреждает. `activate --force` обходит гейт. |

:::note[Почему существуют эти ограничения]
MCP по stdio общается с клиентом через каналы, а не сетевой listener.
Ограничения защищают от чрезмерно больших запросов агента.
:::

## `phase:` - Рекомендательные фазы артефакта

```yaml
phase:
  enabled: true
```

`enabled` - boolean, default `true`, в том числе без секции. Управляет
рекомендательными фазами артефактов в `.forgeplan/state/`.
Это не настройка статуса артефакта или фазы methodology session.

## `playbook:` - Политика запуска shell

```yaml
playbook:
  allow_shell: false
```

`allow_shell` - boolean, default `false`. Значение `true` разрешает шаги
command-delegation без `--allow-shell` для каждого вызова; это не sandbox.
Оставляйте `false` для загруженных/marketplace playbooks. Включайте только
для проверенных доверенных локальных сценариев; подтверждение запуска -
отдельный gate.

но не скрывает содержимое файла и не делает любой config безопасным для передачи.

## Важные замечания и безопасность Git

:::caution[.forgeplan/ частично в gitignore]
- **Отслеживаемые**: `adrs/`, `rfcs/`, `prds/`, `epics/`, `specs/`, `problems/`, `solutions/`, `evidence/`, `notes/`, `refresh/`, `memory/` - это источник истины.
- **Локальные**: конфигурация, секреты и производные индексы; перед коммитом проверьте ignore-политику репозитория.

Свежий клон может содержать `.forgeplan/`, но не `config.yaml`.
`init -y` тогда завершается раньше. Проверьте корень нужного workspace,
прежде чем осознанно обновлять defaults через `--force`.
:::

### Осознанно обновить defaults

```bash
forgeplan init -y --force
# Проверьте автоматически указанную резервную копию.
# Верните нужные настройки в .forgeplan/config.yaml.
forgeplan index  # Constellation; для legacy layout используйте forgeplan reindex
```

Markdown артефактов сохраняется. Прежний config **не** переносится обратно
автоматически. Не удаляйте `.forgeplan/`, чтобы попасть в этот путь.

### Рабочий процесс после свежего клонирования

```bash
git clone <repo>
cd <repo>
# Если .forgeplan/ отсутствует:
forgeplan init -y
# Если он есть, но config.yaml отсутствует и нужны defaults:
# forgeplan init -y --force
# Проверьте/восстановите локальный config перед индексированием.
forgeplan index  # Constellation; для legacy layout используйте forgeplan reindex
forgeplan list
```

### Режим ИИ-агента

ИИ-агенты (Claude Code, Codex и другие), работающие с Forgeplan, должны всегда использовать:

```bash
forgeplan init -y      # НИКОГДА без -y - интерактивный режим зависнет в харнесе агента
```

Интерактивный режим может заблокировать агента. `-y` пропускает запросы;
defaults записываются только при фактической инициализации, а не при раннем выходе.

## Устранение неполадок

### "API key not found"

```
error: LLM API key not set - expected env var GEMINI_API_KEY
```

**Причина**: `llm.api_key_env` указывает на незаданную переменную, или переменная окружения по умолчанию для провайдера не задана.

**Исправление**:
```bash
export GEMINI_API_KEY=your-key          # для текущей оболочки
# или
export FORGEPLAN_LLM_API_KEY_ENV=MY_CUSTOM_KEY
export MY_CUSTOM_KEY=your-key
```

Наличие config или ключа не доказывает готовность провайдера. Проверьте
фактический ответ следующей нужной LLM-операции: сводка health не является
тестом генерации с аутентификацией.

### Ошибки ограничения скорости LLM / 429

**Причина**: ограничения скорости провайдера (бесплатный уровень Gemini особенно строг).

**Исправление**:
1. Уменьшите `llm.max_tokens` для снижения стоимости каждого запроса.
2. Переключитесь на более дешёвую модель (`gemini-3-flash-preview`, `gpt-5-mini`, `claude-haiku-4-5-20251001`).
3. Повторяйте по backoff-рекомендации провайдера. Проверяйте сообщённый
   статус и диагностику: ошибка может быть обёрнута или очищена,
   а не передана дословно.

### Эмбеддинги не загружаются / семантический поиск возвращает пустой результат

Различайте следующие условия:

- В бинарнике нет `semantic-search`; `--version` не показывает features.
- Полный снапшот BGE-M3 отсутствует в выбранном кэше модели.
- В поколении workspace есть pending, отсутствующие или устаревшие эмбеддинги.
- Автоматическое обслуживание не работает либо нет секции `embedding:`.

Прочитайте диагностику `forgeplan embed` и проверьте корень кэша до изменений.
Недостающие веса подготовьте через `forgeplan setup`, затем выполните
индексирование/embed по [руководству](/ru/docs/guides/constellation/).
Не удаляйте кэш модели. На мигрированном workspace принудительный semantic
не обещает автоматический keyword fallback.

### "Invalid config: fpf.thresholds.explore_reff must be finite"

**Причина**: некорректный YAML - числовое поле содержит `NaN`, `Infinity` или строку, которая не распарсилась как число.

**Исправление**: откройте `.forgeplan/config.yaml` и убедитесь, что каждое числовое поле в секциях `fpf:`, `estimate:` и `integrity:` является обычным десятичным числом. Запустите `forgeplan health` для повторной проверки.

### "integrity.mcp_max_body_len must be in [1024, 104857600]"

**Причина**: ограничение размера тела MCP задано за пределами допустимого диапазона (от 1 КиБ до 100 МиБ).

**Исправление**: выберите значение внутри диапазона. Для большинства проектов значение по умолчанию (1 МиБ) является правильным.

### Миграция / дрейф схемы после обновления

Сохраните Markdown, config и существующий индекс для диагностики.
Legacy и Constellation layouts не взаимозаменяемы.
[Руководство Constellation](/ru/docs/guides/constellation/) поможет определить
layout и перестроить индекс нужной командой. Повторный `init -y` не
исправляет схему; `scan-import` не предназначен для штатной перестройки индекса.
