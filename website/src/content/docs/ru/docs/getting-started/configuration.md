Справочник описывает `.forgeplan/config.yaml` в **Forgeplan 0.38.0**. Здесь настройки рабочего пространства отделены от полей, которые схема принимает, но CLI и MCP пока не используют.

Значения по умолчанию есть у всех полей, включая метаданные верхнего уровня (`version`, `project_name`, `default_depth`, `id_digits`, `created_at`). Отсутствие секции `llm:` означает отсутствие явно настроенного провайдера, а не автоматический выбор локального CLI. Ключи хранятся в окружении процесса или `.forgeplan/secrets.env`, не в YAML.

## Структура рабочего пространства

После `forgeplan init -y` каталог `.forgeplan/` создается рядом с вашим кодом:

```
.forgeplan/
├── config.yaml         ← общие настройки рабочего пространства (без значений ключей)
│
├── adrs/               ← отслеживаемые Git markdown-артефакты (источник истины)
├── rfcs/
├── prds/
├── epics/
├── specs/
├── problems/
├── solutions/
├── evidence/
├── notes/
├── refresh/
├── memory/             ← отслеживаемые Git артефакты Memory
├── discovery/          ← отслеживаемые Git артефакты исследования
├── secrets.env         ← GITIGNORED - локальные ключи API
│
├── lance/              ← GITIGNORED - производный индекс LanceDB (восстанавливаемый)
└── .fastembed_cache/   ← GITIGNORED - старый локальный кэш модели
```

Согласно ADR-003, **источник истины — файлы markdown**. Производный индекс `lance/` восстанавливается командой `forgeplan reindex`. `scan-import` ищет и импортирует другие документы, а не заменяет синхронизацию существующих артефактов из файлов. Векторы создаются отдельно командой `forgeplan embed`.

Управляемый блок `.gitignore` исключает состояние выполнения, кэши моделей, `secrets.env`, его резервные и временные файлы. `config.yaml` он **не исключает**. В существующем репозитории могут быть дополнительные правила; не помещайте ключи в конфигурацию независимо от того, отслеживает ли её Git.

:::caution[Повторная инициализация]
`forgeplan init -y` не меняет существующее рабочее пространство. `forgeplan init --force -y` обновляет конфигурацию и создаёт недостающие каталоги, не перезаписывая тела артефактов. Автоматическая резервная копия создаётся, если не передан `--no-backup`. Перед намеренным обновлением сохраните копию и затем проверьте перезаписанную конфигурацию. Для смены провайдера удалять `.forgeplan/` не нужно.
:::

## Ключи верхнего уровня

```yaml
version: 1
project_name: ForgePlan
default_depth: standard
id_digits: 3
created_at: 2026-03-24
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `version` | `u32` | `1` | Версия схемы конфигурации. Обновляется только при критических изменениях схемы. |
| `project_name` | `string` | `""` | Человекочитаемое имя проекта. Отображается в `forgeplan health`, отчетах и экспорте. |
| `default_depth` | `string` | `standard` | Метаданные глубины рабочего пространства. Не считайте это поле переопределением правил маршрутизации. |
| `id_digits` | `u32` | `3` | Принимается как метаданные конфигурации. В выпущенных CLI и MCP создание ID использует фиксированные три цифры. Значение `4` не меняет ширину новых ID и не перенумеровывает существующие. |
| `created_at` | `date` | сегодня | Дата `ГГГГ-ММ-ДД` инициализации рабочего пространства. Метаданные только для чтения. |

### Значения глубины

| Значение | Как его понимает выпущенное ядро |
|-------|----------------------------------|
| `note` | Режим лёгкой заметки. |
| `tactical` | Обязательной цепочки артефактов нет. |
| `standard` | PRD → RFC. |
| `deep` | PRD → Spec → RFC → ADR. |
| `critical` | Принимается как псевдоним `deep`, отдельного конвейера ядра нет. |

Оценки длительности, группировка в Epic, требования ADI и состязательного ревью относятся к правилам методологии. Разбор depth и команда `activate` сами эти действия не выполняют. Процессы marketplace могут требовать более строгой подготовки и проверки.

См. [руководство по калибровке глубины](/docs/methodology/routing/) для эвристики роутинга.

## `llm:` - Провайдер LLM

Используется командами `generate`, `reason` (ADI), LLM-маршрутизацией, `decompose`, `capture` и соответствующими инструментами MCP. Основные операции с артефактами не требуют LLM. Маршрутизация может вернуться к ключевым словам; чтобы явно исключить вызовы модели, используйте `forgeplan route --level 0 "Описание задачи"`.

```yaml
llm:
  provider: codex-cli
  model: ""                    # модель выберет сам CLI
  timeout_seconds: 120
  reason_timeout_seconds: 600
```

Для этого примера нужно отдельно установить `codex` и выполнить `codex login`. Forgeplan не устанавливает CLI поставщика и не выполняет вход за пользователя.

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `provider` | `string` | `openai` | Точное имя HTTP-провайдера или локального CLI-профиля из таблиц ниже. Профиля для произвольной команды нет. |
| `model` | `string` | `gpt-4o-mini` | Идентификатор модели HTTP или значение CLI-флага `--model`. Для модели по умолчанию самого CLI задайте `""`; различия профилей описаны ниже. |
| `api_key_env` | `string?` | зависит от провайдера | Имя переменной с ключом API, не сам ключ. Явно заданное имя важнее стандартного имени провайдера. |
| `base_url` | `string?` | зависит от провайдера | Базовый HTTP URL. Совместимые с OpenAI запросы добавляют `/chat/completions`, `claude` — `/messages`. CLI-профили это поле не используют. |
| `max_tokens` | `u32` | `4096` | Лимит токенов HTTP-ответа. Локальным CLI-профилям не передаётся. |
| `temperature` | `f32` | `0.7` | Передаётся совместимым с OpenAI HTTP-сервисам. Нативный HTTP-путь `claude` и локальные CLI-профили её не передают; ноль не гарантирует детерминированный ответ. |
| `reason_temperature` | `f32?` | не задано | Переопределение для ADI. Без него `reason` использует `min(temperature, 0.3)`, а не неизменённую общую температуру. Ограничения транспорта выше сохраняются. |
| `timeout_seconds` | `u64` | `120` | Общий бюджет HTTP-запроса или подпроцесса в секундах. |
| `reason_timeout_seconds` | `u64?` | не задано; фактически `600` | Отдельный бюджет ADI. Без этого поля `reason` использует 600 секунд, а не `timeout_seconds`. |

### Матрица провайдеров

| HTTP-провайдер | Переменная ключа API по умолчанию | Базовый URL по умолчанию | Требования |
|---------------|---------------------|------------------|--------------|
| `openai` | `OPENAI_API_KEY` | `https://api.openai.com/v1` | Ключ API; совместимый с OpenAI chat completions. |
| `claude` | `ANTHROPIC_API_KEY` | `https://api.anthropic.com/v1` | Ключ Anthropic API; нативный Messages API, не подписка Claude Code. |
| `gemini` | `GEMINI_API_KEY` | `https://generativelanguage.googleapis.com/v1beta/openai` | Ключ API; совместимый с OpenAI сервис Google, не Gemini CLI. |
| `ollama` | нет | `http://localhost:11434/v1` | Запущенный сервис Ollama и установленная модель. Локальный HTTP без обязательного ключа. |
| `custom` | нет | без переопределения используется URL OpenAI | Явно задайте `base_url` и `api_key_env` для своего совместимого с OpenAI сервиса. CLI-команды, требующие настройки LLM, отклоняют HTTP-конфигурацию без ключа. |

Например, для HTTP можно задать `provider: openai`, `model: gpt-5-mini` и `api_key_env: OPENAI_API_KEY`. Доступность моделей, цены и квоты определяет поставщик; Forgeplan не ведёт каталог моделей.

### Локальные CLI-профили (0.38)

Все пять профилей **не требуют ключа API в Forgeplan**, но это не означает бесплатную или автономную работу. Они используют вход в штатный CLI и тариф поставщика. Профили предназначены **только для личной локальной разработки, не для production, общих сред или CI**. Действуют условия и квоты поставщика. Каждый вызов работает без интерактивного интерфейса и не продолжает вашу текущую беседу.

| `provider` | Установить в безопасный `PATH` | Выполнить вход отдельно | Поведение профиля |
|------------|------------------------|---------------------------|------------------|
| `claude-code` | `claude` | `claude login` | `--print --output-format json`; читает `result`. |
| `codex-cli` | `codex` | `codex login` | Одноразовый запуск, песочница только для чтения; игнорирует пользовательские настройки и правила; читает файл итогового ответа. |
| `devin-cli` | `devin` | `devin auth login`; проверить `devin auth status` | Песочница, фиксированный профиль разрешений, приватный файл промпта, текстовый ответ. **Windows не поддерживается**, поскольку обязательный режим песочницы штатного CLI там недоступен. |
| `gemini-cli` | `gemini` | Запустить `gemini` интерактивно и завершить вход | Песочница, стандартный режим подтверждения, поле JSON `response`. |
| `cursor-agent` | `cursor-agent` | `cursor-agent login`; проверить `cursor-agent status` | Режим ask, включённая песочница, поле `result` успешного JSON-ответа. |

Четыре новых профиля (`codex-cli`, `devin-cli`, `gemini-cli`, `cursor-agent`) трактуют историческое значение по умолчанию `gpt-4o-mini` как отсутствие выбора модели. У `claude-code` это не так: для стандартной модели Claude явно задайте `model: ""`. Непустое имя CLI-модели должно содержать 1–64 ASCII-буквы, цифры, `.`, `_`, `:` или `-` и не начинаться с `-`. Поля `base_url`, `api_key_env`, `max_tokens` и температуры не настраивают эти CLI-вызовы.

Новые профили работают в изолированных временных рабочих каталогах. Промпты передаются через stdin, а у Devin — через приватный файл; они не подставляются в команды оболочки. Штатный бинарник должен находиться вне активного рабочего пространства: обёртки из принадлежащего проекту `node_modules/.bin` не принимаются. В Unix отклоняются бинарники и родительские каталоги, доступные на запись группе или остальным пользователям.

Дочерний процесс получает ограниченное окружение:

- Базовые переменные — `PATH`, `HOME` и `USER`; пути рабочего пространства удаляются из `PATH`.
- Для штатной авторизации и настроек Codex сохраняется `CODEX_HOME` либо исходный `HOME/.codex`, а `HOME` заменяется изолированным временным каталогом.
- Gemini и Cursor дополнительно получают `XDG_CONFIG_HOME`, `XDG_DATA_HOME` и `XDG_RUNTIME_DIR`; Claude получает их в Linux.
- Переменные с ключами API и посторонние секреты не передаются. Forgeplan не извлекает токены поставщика. Общий маркер `FORGEPLAN_LOCAL_LLM_PROVIDER_ACTIVE` запрещает вложенную генерацию локальным провайдером, в том числе со сменой профиля.

Эти меры не означают универсальную гарантию запрета инструментов внутри CLI поставщика. Forgeplan передаёт фиксированные флаги; их действие зависит и от установленного CLI, и от требований его песочницы. Отсутствие бинарника, истёкший вход, неподдерживаемые флаги или платформа, таймаут, некорректный либо пустой ответ завершаются ошибкой, а не скрытым переключением провайдера.

### Рекомендуемые модели (2026)

Выбирайте модель, доступную вашему API-аккаунту или CLI-тарифу. Значение схемы по умолчанию `gpt-4o-mini` — не рекомендация для любого провайдера. HTTP-идентификаторы передаются без изменений, CLI-идентификаторы проверяются по правилам выше. Для стандартной модели CLI используйте `model: ""`, а не копируйте имя модели API в другой профиль.

:::note[Смена провайдера в середине проекта]
Изменение `llm:` влияет на будущие вызовы, а не на существующие артефакты и записи ADI. Смена провайдера не перепроверяет ранее сгенерированный контент.
:::

### Переопределения переменных окружения (LLM)

| Переменная окружения | Переопределяет |
|---------|-----------|
| `FORGEPLAN_LLM_PROVIDER` | `provider` |
| `FORGEPLAN_LLM_MODEL` | `model` |
| `FORGEPLAN_LLM_BASE_URL` | `base_url` |
| `FORGEPLAN_LLM_MAX_TOKENS` | `max_tokens`, если значение разбирается как `u32` |
| `FORGEPLAN_LLM_API_KEY_ENV` | `api_key_env` (имя, не значение) |

Приоритет этих полей: **окружение процесса > YAML > значение поля по умолчанию**. Переопределения не создают отсутствующую секцию `llm:` для CLI-команд, которым она обязательна, и не сбрасывают остальные поля. При смене HTTP-профиля удалите устаревшее `api_key_env` и выберите подходящую модель. В релизе нет соответствующих переменных окружения для таймаутов и температур.

Выбор провайдера явный. Исполняемый код не ищет установленные CLI и не выбирает между OpenAI, Anthropic и Gemini по наличию ключа. `ollama` и пять CLI-профилей с авторизацией по подписке никогда не выбираются автоматически. Имена не проверяются как enum: неизвестное имя попадает в общий совместимый с OpenAI HTTP-путь. Проверяйте написание, не рассчитывая на ошибку конфигурации.

## `embedding:` - Семантический поиск

Конфигурирует модель эмбеддингов, используемую для семантического поиска и векторного индекса FPF KB. Требует флага функции `semantic-search` во время сборки.

> **Сейчас поддерживается только `bge-m3`.** Движок сам выполняет пулинг, а пулинг у моделей разный: семейства BGE используют CLS, семейства E5 и MiniLM берут усреднение. Прогнать модель с усреднением через CLS-пулинг не приводит к ошибке: вернутся правдоподобные векторы, посчитанные не тем способом. Поэтому другие имена отклоняются явно, а не обслуживаются молча неверно. Расширение списка отслеживается в PROB-091.
>
> Модель скачивается при первом использовании: ~2.1 GB один раз на машину, в платформенный кэш (`~/Library/Caches/forgeplan/models` на macOS, `~/.cache/forgeplan/models` на Linux). Путь переопределяет `FORGEPLAN_MODEL_CACHE`. Загрузчику tract в релизе этот путь передаётся явно; не полагайтесь на прежний приоритет `HF_HOME` из fastembed. `forgeplan setup` позволяет скачать модель заранее; `init -y` не скачивает её без `--with-model`.

```yaml
embedding:
  model: bge-m3
  chunk_size: 2000
```

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `model` | `enum` | `bge-m3` | Имя модели эмбеддингов. См. таблицу ниже. |
| `chunk_size` | `usize` | `2000` | Максимальное количество символов тела артефакта, включенных в текст эмбеддинга. Большие значения дают более богатые эмбеддинги за счет размера кэша и времени загрузки. |

### Поддерживаемые модели

| Модель | Размерность | Языки | Когда выбирать |
|-------|-----|-----------|--------------|
| `bge-m3` | 1024 | Многоязычная (100+) | **По умолчанию** - лучшее качество, поддерживает смешанные рабочие пространства на русском + английском. |

:::caution[Модель и индекс — разные операции]
Движок релиза поддерживает только `bge-m3`; остальные имена отклоняются. `forgeplan reindex` синхронизирует markdown с LanceDB, но не создаёт векторы. Для создания или обновления векторов отдельно выполните `forgeplan embed`.
:::

### Переопределения переменных окружения (эмбеддинг)

У `FORGEPLAN_EMBEDDING_MODEL` есть вспомогательный метод в типе конфигурации, но код эмбеддингов CLI/MCP в релизе его не применяет. Задавайте `embedding.model` в YAML; не полагайтесь на эту переменную как на рабочее переопределение.

Релизные бинарники 0.38 включают семантический поиск. В собственной сборке `semantic-search` может быть отключён; поиск по ключевым словам остаётся доступен. См. [руководство по поиску](/docs/guides/search-v2/).

## `storage:` - Бэкенд хранилища

```yaml
storage:
  driver: lancedb
```

| Поле | Тип | По умолчанию | Контракт в 0.38 |
|-------|------|---------|------------------|
| `driver` | `string` | `lancedb` | Настройка фабрики драйверов, не глобальный переключатель хранилища CLI/MCP. |
| `path` | `string?` | каталог рабочего пространства | Переопределение корня рабочего пространства для фабрики драйверов. Lance-драйвер добавляет `lance/`; это не прямой путь к каталогу БД. |

### Поддерживаемые драйверы

Фабрика библиотеки поддерживает `lancedb` (алиас `lance`) и `memory` (алиас `in_memory`), но не `sqlite`. Обычные операции CLI/MCP с артефактами открывают `LanceStore` напрямую в выбранном `.forgeplan/lance/`; эта секция не перенаправляет их в другое хранилище.

### Переопределения переменных окружения (хранилище)

`FORGEPLAN_STORAGE_DRIVER` и `FORGEPLAN_STORAGE_PATH` существуют во вспомогательном методе конфигурации, но код открытия хранилища CLI/MCP в релизе их не применяет. Это не поддерживаемые глобальные переопределения.

## `memory:` - Банк памяти решений

```yaml
memory:
  driver: file
```

Схема принимает строковую настройку `driver: file` (по умолчанию) или `none`, но обычные операции журнала CLI/MCP строят хронологию из записей артефактов LanceDB. Это поле не подключено как переключатель отключения журнала. `.forgeplan/memory/` содержит артефакты Memory, а не конфигурацию сервера Hindsight.

### Переопределения переменных окружения (память)

`FORGEPLAN_MEMORY_DRIVER` существует во вспомогательном методе конфигурации, но код журнала в релизе его не применяет. Не используйте эту переменную для отключения журнала.

## `estimate:` - Движок оценки

Конфигурирует `forgeplan estimate` - многоуровневую модель оценки, которая сочетает ваш экспертный опыт с мультипликаторами типов задач ИИ. Каждое поле необязательно; опустите всю секцию, чтобы использовать значения по умолчанию.

```yaml
estimate:
  grade_profile:
    backend: middle          # ваш уровень в бэкенд-разработке
    frontend: junior         # ваш уровень во фронтенде
    devops: senior           # ваш уровень в devops/инфраструктуре
    ai_ml: principal         # ваш уровень в AI/ML
    default: senior          # запасной вариант для неуказанных областей
  grade_multipliers:
    junior: 2.0              # относительно senior (базовый 1.0)
    middle: 1.5
    senior: 1.0
    principal: 0.7
    ai: 0.4                  # принимается, но не участвует в расчёте часов ИИ
  ai_task_multipliers:
    pure_coding: 0.10        # доля базовых часов в модели, не измеренное ускорение
    coding_infra: 0.25       # смешанное кодирование + инфраструктура
    design_coding: 0.30      # проектирование + реализация
    pure_infra: 0.50         # только инфраструктура
    coordination: 1.00       # доля базовых часов до учёта ревью
  review_overhead: 0.30      # 30% добавляется ко времени ИИ для ревью
  safety_margin: 0.50        # сохраняется; предупреждение о загрузке не подключено
```

### Поля

| Поле | Тип | По умолчанию | Описание |
|-------|------|---------|-------------|
| `grade_profile` | `map<string, grade>` | стандартный уровень `senior` | Уровень разработчика по областям. Ключи — произвольные имена областей; необязательный `default` задаёт запасной уровень. |
| `grade_multipliers` | `map<string, f64>` | см. ниже | Мультипликатор времени для каждого уровня, относительно базового уровня senior `1.0`. |
| `ai_task_multipliers` | `map<string, f64>` | см. ниже | Доля базовых часов senior для типа задачи в модели, до добавления ревью. |
| `review_overhead` | `f64` | `0.30` | Доля, добавляемая к времени, затраченному ИИ, для покрытия человеческого ревью. `0.30` = 30%. |
| `safety_margin` | `f64` | `0.50` | Принимаемая настройка; код оценки в релизе не использует её для предупреждений о загрузке спринта. |

### Уровни

| Уровень | Мультипликатор по умолчанию | Значение |
|-------|-------------------:|---------|
| `junior` | 2.0 | Изучает область - занимает в 2 раза больше времени, чем senior. |
| `middle` | 1.5 | Может работать самостоятельно - в 1.5 раза больше, чем senior. |
| `senior` | 1.0 | Базовый уровень. |
| `principal` | 0.7 | Глубокий эксперт в области - на 30% быстрее, чем senior. |
| `ai` | 0.4 | Настройка уровня принимается, но не участвует в расчёте часов ИИ. Вместо неё используются `ai_task_multipliers`, затем добавляется ревью. |

### Типы задач ИИ

| Тип задачи | По умолчанию | Типичная работа |
|-----------|--------:|--------------|
| `pure_coding` | 0.10 | Написание чистого кода - функций, тестов, рефакторинга. ИИ здесь превосходит. |
| `coding_infra` | 0.25 | Кодирование, смешанное с инструментами (CI, скрипты, конфигурации). |
| `design_coding` | 0.30 | Проектные решения и сам код. |
| `pure_infra` | 0.50 | Только инфраструктурная работа - ИИ помогает, но человек валидирует каждый шаг. |
| `coordination` | 1.00 | Встречи, ревью и согласования; модель предполагает отсутствие сокращения времени до учёта ревью. |

### Рабочий пример

> Пример расчёта с **базовыми 8 часами** и типом задачи `pure_coding`:
>
> ```
> human_senior   = 8h × grade_multipliers.senior   = 8h × 1.0 = 8h
> ai_time        = 8h × ai_task_multipliers.pure_coding = 8h × 0.10 = 0.8h
> with_review    = 0.8h × (1 + review_overhead)    = 0.8h × 1.30 = 1.04h
> ```
>
> Оценка времени ИИ по модели: **1.04 часа**, включая ревью. Это результат настроенной модели, не гарантия измеренной производительности.

См. [`forgeplan estimate`](/docs/cli/estimate/) для справки по CLI.

## `fpf:` - Движок Trust Calculus FPF

Настраивает [движок FPF](/docs/methodology/adi/): пороги исследования/эксплуатации, веса надёжности, штрафы за уровень конгруэнтности и ограничения рассуждений ADI. Каждое подполе имеет безопасные значения по умолчанию - настраивайте только при наличии эмпирических причин.

```yaml
fpf:
  weights:
    reff: 0.5
    links: 0.3
    freshness: 0.2
  thresholds:
    explore_reff: 0.01
    investigate_reff: 0.5
    exploit_reff: 0.7
    exploit_fgr: 0.6
    explore_fgr: 0.4
  cl_penalties:
    cl0: 0.9
    cl1: 0.4
    cl2: 0.1
    cl3: 0.0
  decay:
    expired_score: 0.1
  adi:
    max_hypotheses: 5
    kb_sections_limit: 5
    temperature_cap: 0.3
    auto_save: true
```

### `fpf.weights` - Веса компонентов надёжности

Компоненты оценки надёжности внутри F-G-R. Значения не обязательно должны суммироваться до 1.0, но обычно это так.

| Поле | По умолчанию | Значение |
|-------|--------:|---------|
| `reff` | `0.5` | Вес оценки R_eff (качество доказательства). |
| `links` | `0.3` | Максимальный бонус, присуждаемый за входящие/исходящие типизированные связи. |
| `freshness` | `0.2` | Бонус, если артефакт не просрочен (`valid_until` в будущем). |

### `fpf.thresholds` - Отсечки исследования/эксплуатации

Пороги доверия и действий над артефактами для правил FPF, заданных в коде. Это другой механизм, чем выбор глубины задачи: `forgeplan route` не использует `fpf.thresholds`.

| Поле | По умолчанию | Вызываемое действие |
|-------|--------:|------------------|
| `explore_reff` | `0.01` | R_eff ниже этого -> **ИССЛЕДОВАТЬ** (рассматривать как черновик). |
| `investigate_reff` | `0.5` | R_eff ниже этого -> **ИЗУЧИТЬ** (требуется больше доказательств). |
| `exploit_reff` | `0.7` | R_eff на этом уровне или выше -> подходит для **ЭКСПЛУАТАЦИИ** (можно полагаться). |
| `exploit_fgr` | `0.6` | Общий F-G-R, необходимый для подтверждения ЭКСПЛУАТАЦИИ (в сочетании с `exploit_reff`). |
| `explore_fgr` | `0.4` | F-G-R ниже этого -> **ИССЛЕДОВАТЬ** приоритет 1 (в сочетании с `explore_reff`). |

### `fpf.cl_penalties` - Штрафы за уровень конгруэнтности

Штраф, применяемый к доказательствам в зависимости от того, насколько хорошо их контекст соответствует артефакту, который они информируют. `CL3` (тот же контекст) без штрафа; `CL0` (противоположный контекст) сильно дисконтируется.

| Поле | По умолчанию | Значение |
|-------|--------:|---------|
| `cl0` | `0.9` | Противоположный контекст - почти нулевое доверие. |
| `cl1` | `0.4` | Другой контекст - значительная скидка. |
| `cl2` | `0.1` | Похожий контекст - незначительная скидка. |
| `cl3` | `0.0` | Тот же контекст - без штрафа. |

См. [руководство по доказательствам](/docs/methodology/evidence/) о том, как `congruence_level` устанавливается в теле EvidencePack.

### `fpf.decay` - Угасание доказательств

| Поле | По умолчанию | Значение |
|-------|--------:|---------|
| `expired_score` | `0.1` | Оценка, присваиваемая доказательству после `valid_until`. `0.1` отражает "просрочено, но не отсутствует" - доказательство существовало, просто нуждается в повторной проверке. |

### `fpf.adi` - Конфигурация рассуждений ADI

Эти поля принимаются схемой FPF, но **не подключены к генерации `reason` в релизе**:

| Поле | Тип | Значение схемы по умолчанию | Отличие исполняемого кода |
|-------|------|---------------:|---------------------|
| `max_hypotheses` | `u32` | `5` | Не заменяет инструкции о гипотезах в промпте рассуждения. |
| `kb_sections_limit` | `usize` | `5` | `build_fpf_context` сейчас берёт не более трёх секций. |
| `temperature_cap` | `f32` | `0.3` | `reason` использует `llm.reason_temperature` либо `min(llm.temperature, 0.3)`. |
| `auto_save` | `bool` | `true` | Не управляет сохранением в CLI; используйте флаг `reason --save`. |

### `fpf.rules` - Декларативные правила исследования-эксплуатации (продвинутый уровень)

Необязательный список пользовательских правил исследования/эксплуатации (FPF Engine Phase 2). Если список пуст, используются встроенные `default_rules()`. Схема и примеры находятся в [руководстве по правилам FPF](/docs/cli/fpf-rules/).

:::caution[Валидация FPF]
Загрузчик проверяет конечность и неотрицательность `f64` в порогах FPF, весах, штрафах CL и угасании. У правил должны быть непустые условия и уникальные имена. Эти проверки выполняются при загрузке конфигурации, в том числе командой `health`; они не проверяют каждое значение ADI/estimate.
:::

## `phase:` и `playbook:`

```yaml
phase:
  enabled: true
playbook:
  allow_shell: false
```

`phase.enabled` по умолчанию равен `true` и управляет рекомендательным отслеживанием фаз отдельных артефактов, а не блокировкой сессии. `playbook.allow_shell` по умолчанию равен `false`. Значение `true` разрешает делегирование команд оболочки без `--allow-shell` на каждый запуск. Включайте это только для доверенных локальных playbook, не для непроверенного загруженного контента. Остальные ограничения выполнения playbook сохраняются.

## `integrity:` - Ограничения на ввод Health & MCP

Пороги, используемые `forgeplan health` (обнаружение дубликатов, обнаружение заглушек) и ограничения защиты от DoS, применяемые сервером MCP к входящим вызовам `forgeplan_new` / `forgeplan_update`.

```yaml
integrity:
  duplicate_threshold: 0.7
  duplicate_pairs_limit: 10
  stub_marker_threshold: 3
  mcp_max_title_len: 256
  mcp_max_body_len: 1048576      # 1 MiB
  evidence_provenance_gate: warn # block | warn | off
```

| Поле | Тип | По умолчанию | Диапазон | Описание |
|-------|------|--------:|-------|-------------|
| `duplicate_threshold` | `f64` | `0.7` | `[0.0, 1.0]` | Сходство Жаккара, выше которого два артефакта помечаются как дубликаты в `forgeplan health`. |
| `duplicate_pairs_limit` | `usize` | `10` | `[1, 10000]` | Максимальное количество пар дубликатов, отображаемых в выводе health (пагинация). |
| `stub_marker_threshold` | `usize` | `3` | `>= 1` | Минимальное количество маркеров заглушек (`TODO`, `TBD`, пустые заголовки и т. д.), необходимое для пометки тела артефакта как заглушки. |
| `mcp_max_title_len` | `usize` | `256` | `[16, 4096]` | Максимальная длина заголовка артефакта, принимаемая через MCP. Предотвращает злоупотребление памятью со стороны вредоносных клиентов. |
| `mcp_max_body_len` | `usize` | `1048576` | `[1024, 104857600]` | Максимальная длина тела артефакта (байты), принимаемая через MCP. По умолчанию: 1 МиБ. Жесткий лимит: 100 МиБ. |
| `evidence_provenance_gate` | `string` | `warn` | `block` \| `warn` \| `off` | Гейт git-provenance при активации для code-claiming EvidencePack (PRD-082). Если пак объявил `base_sha` / `result_sha` / `changed_paths`, `forgeplan activate` перепроверяет claim против реальной git-дельты вместо доверия самоотчёту. `block`: отказать в активации (артефакт остаётся `draft`); `warn`: активировать и показать расхождение (CLI в stderr, MCP в success-payload); `off`: пропустить проверку. Паки без provenance-полей не затронуты. Нерезолвимая SHA всегда только предупреждает. `activate --force` обходит гейт. |

:::note[Почему существуют эти ограничения]
MCP-сервер общается со своим клиентом через stdio; stdio сам по себе не является сетевым слушателем. Эти лимиты ограничивают входные данные артефактов от клиента, в том числе при чрезмерных промптах и ошибках агента.
:::

## Переменные окружения - Полный список

Рабочие переопределения полей LLM перечислены [выше](#переопределения-переменных-окружения-llm). Переменные ключей — `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` либо явное имя из `api_key_env`. `FORGEPLAN_MODEL_CACHE` управляет кэшем эмбеддингов. Переменные расположения учётных данных CLI и внутренний маркер рекурсии описаны в [локальных профилях](#локальные-cli-профили-038); маркер не является пользовательской настройкой.

Не каждый вспомогательный метод для `FORGEPLAN_*` применяется каждой командой. Секции эмбеддингов, хранилища и памяти указывают, какие переопределения не подключены.

### Локальные секреты проекта

Для HTTP-провайдера поиск ключа сначала проверяет непустую переменную процесса, состоящую не только из пробелов, затем `.forgeplan/secrets.env` выбранного рабочего пространства. Файл перечитывается при каждом поиске и не исполняется оболочкой. Поддерживаются `NAME=value` и `export NAME=value`, в том числе буквальные значения в кавычках. Подстановки команд, раскрытие переменных и обработка escape-последовательностей не выполняются. Лимит файла — 64 KiB. Некорректный синтаксис вызывает предупреждение; без подходящей переменной процесса ключ не находится. В Unix задайте права `0600`; более широкие права вызывают предупреждение, но не блокируют чтение.

`forgeplan migrate-secrets` по умолчанию только показывает план миграции. С `--apply` команда копирует три известных API-переменных из окружения процесса в локальный файл, делает копию существующего файла и не перезаписывает его записи. Разные значения в окружении и файле отмечаются как конфликт, а не скрыто заменяются. Команда не извлекает токены входа CLI и не переносит ключ, вписанный в YAML.

Никогда не коммитьте `secrets.env`, `secrets.env.bak-*` и `.secrets.env.tmp-*`. В YAML хранится **имя** переменной, не её значение.

## Важные замечания и безопасность Git

:::caution[.forgeplan/ частично в gitignore]
- **Можно передавать через Git**: markdown артефактов и `config.yaml` без значений ключей.
- **Локальные данные выполнения**: `lance/`, кэши моделей, состояние сессии и фаз, логи, блокировки, корзина и файлы секретов, перечисленные в управляемом блоке исключений.

Не считайте, что `config.yaml` обязательно отсутствует после клонирования или что правила исключения удаляют уже отслеживаемые файлы. Проверьте реальные правила репозитория.
:::

### Перед любой повторной инициализацией

Для смены провайдера отредактируйте `llm:`. Если нужно полностью обновить конфигурацию, сначала экспортируйте данные и сохраните копию:

```bash
forgeplan export --output backup.json
cp -r .forgeplan .forgeplan-backup-$(date +%Y%m%d)
forgeplan init --force -y
```

Проверьте обновлённую конфигурацию; при необходимости выполните `forgeplan reindex`, чтобы синхронизировать существующие markdown артефактов. Обычное восстановление конфигурации не требует удаления каталога артефактов.

### Рабочий процесс после свежего клонирования

```bash
# В клонированном репозитории:
forgeplan init -y                   # ничего не меняет, если уже инициализировано
$EDITOR .forgeplan/config.yaml      # проверить или добавить секцию llm
# HTTP: приватно задать именованный ключ в env/secrets.env.
# Локальный CLI: отдельно установить штатный бинарник и выполнить вход.
forgeplan reindex                   # синхронизировать markdown артефактов с LanceDB
forgeplan list                      # просмотреть артефакты в индексе
```

### Режим ИИ-агента

В среде агента используйте неинтерактивную инициализацию:

```bash
forgeplan init -y
```

`-y` пропускает вопросы и использует значения по умолчанию. Модель не скачивается без дополнительного `--with-model`. Флаг не выбирает и не авторизует LLM-провайдера.

## Устранение неполадок

### "API key not found"

**Причина**: у переменной `api_key_env` действующего HTTP-профиля либо у стандартной переменной провайдера нет подходящего значения в окружении процесса и `.forgeplan/secrets.env`.

**Исправление**: приватно задайте именованную переменную, проверьте буквальный синтаксис присваивания и права файла либо явно выберите профиль без обязательного ключа и выполните его требования. Не выводите ключи в диагностику. Изменение только `FORGEPLAN_LLM_PROVIDER` может оставить прежние `api_key_env` и модель.

`forgeplan health` не проверяет вход у поставщика или действительность ключа API. Автономная проверка не может установить, что будущий авторизованный LLM-вызов будет успешным.

### Ошибки ограничения скорости LLM / 429

**Причина**: поставщик API или CLI отклонил запрос из-за ограничения частоты либо квоты.

**Исправление**: перед повторным вызовом проверьте тариф и правила повторных попыток поставщика. Меньший HTTP-лимит токенов может снизить стоимость, но не обходит ограничения частоты. HTTP-клиент ядра формирует ошибку со статусом и ограниченным фрагментом ответа; клиентская ошибка MCP скрывает тело HTTP-ответа. При сбое локального CLI stderr поставщика намеренно скрывается: он может содержать промпт или данные окружения. Используйте подсказку о штатном входе или проверке статуса.

### Эмбеддинги не загружаются / семантический поиск возвращает пустой результат

Релизные бинарники 0.38 включают семантический поиск, но модель всё равно нужно скачать и загрузить. В собственной сборке функция может быть отключена. Другие причины — неподдерживаемая модель, отсутствующие или устаревшие векторы артефактов, ошибки диска или сети, повреждение кэша.

Задайте `embedding.model: bge-m3`, проверьте настроенный путь кэша и текст ошибки. Для создания или обновления векторов используйте `forgeplan embed`. При отсутствии модели команда может скачать ~2.1 GB. `reindex` синхронизирует только markdown; `scan-import` не скачивает модель и не создаёт эмбеддинги. Не удаляйте кэш, пока не установили, какой путь реально использует движок.

Поиск по ключевым словам доступен и без семантического поиска. См. [руководство по поиску](/docs/guides/search-v2/).

### "Invalid config: fpf.thresholds.explore_reff must be finite"

**Причина**: некорректный YAML - числовое поле содержит `NaN`, `Infinity` или строку, которая не распарсилась как число.

**Исправление**: исправьте указанное в ошибке поле `.forgeplan/config.yaml`. Загрузчик проверяет конечность и неотрицательность `f64` в FPF и диапазоны integrity; не считайте, что все поля estimate/ADI проходят ту же проверку. После исправления выполните `forgeplan health`.

### "integrity.mcp_max_body_len must be in [1024, 104857600]"

**Причина**: ограничение размера тела MCP задано за пределами допустимого диапазона (от 1 КиБ до 100 МиБ).

**Исправление**: выберите значение внутри диапазона. Для большинства проектов значение по умолчанию (1 МиБ) подходит.

### Миграция / дрейф схемы после обновления

При открытии хранилище выполняет идемпотентные миграции схемы. Если после обновления или операции Git разошлись файлы и индекс, сохраните рабочее пространство и используйте `forgeplan reindex` либо `forgeplan git-sync` для изменений Git. Перед восстановлением сделайте копию. Если ошибка запуска LanceDB не позволяет выполнить эти команды, сохраните исходный каталог и точную ошибку для диагностики вместо удаления `.forgeplan/` или слепой переинициализации.
