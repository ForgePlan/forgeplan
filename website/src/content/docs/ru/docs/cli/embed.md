Генерирует векторные эмбеддинги для каждого артефакта в рабочем пространстве, чтобы семантический поиск мог находить связанные работы по смыслу, а не только по ключевым словам. Эмбеддинги хранятся вместе с метаданными LanceDB и используются командами `forgeplan search --semantic` и семантическими инструментами MCP.

## Использование

```text
forgeplan embed
```

## Опции

```text
  -h, --help     Вывести справку
  -V, --version  Вывести версию
```

## Флаг функции

Команда требует Cargo feature `semantic-search`. При установке из исходников
её включают явно:

```bash
cargo install --path crates/forgeplan-cli --features semantic-search
```

Сборка без feature отказывает с подсказкой по установке. Для генерации нужен совместимый снапшот модели; для последующего semantic-поиска - также совместимые векторы, опубликованные в индексе. Уже существующие векторы не требуются для их создания.

## Что делает команда

Локальная сборка `0.39.0+constellation.s1.1` использует движок `tract` на
Rust, а не прежний fastembed runtime. Поддерживается только `bge-m3`
(1024 измерения). На мигрированном workspace `embed` обрабатывает очередь
для опубликованного поколения Constellation, включая prefix и section
units; это не только один вектор на артефакт.

Если опубликованного поколения нет, команда сначала запускает обслуживание индекса; это может мигрировать legacy-workspace. Заранее подготовьте полный кэш. Интерфейс ниже относится к выбранной сборке `0.39.0+constellation.s1.1`, а не к неизменённому установленному релизу `0.38.0`.

Модель занимает около 2.1 GB и хранится вне проекта. Приоритет кэша:
`FORGEPLAN_MODEL_CACHE` → `~/.forgeplan/models` → платформенный кэш или
старый относительный путь лишь при отсутствии home. `HF_HOME` не
переопределяет путь tract. Указывайте корень кэша, не путь снапшота.

Запросы и фоновое обслуживание не скачивают недостающие веса.
Для явной подготовки есть `forgeplan setup`. Не удаляйте кэш модели
ради диагностики.

## Автоматические эмбеддинги

Ручной `embed` не сохраняет секцию `embedding:`. Для автоматической обработки
очереди явно настройте `model: bge-m3`, подготовьте полный снапшот и
запустите обслуживание. Одного `serve --auto-index` недостаточно.
См. [руководство Constellation](/ru/docs/guides/constellation/).

## Когда это нужно

- Вы хотите использовать **семантический поиск** - запрос "найти артефакты о снижении доверия" должен выводить работы по R_eff / доказательствам, даже если эти точные слова не встречаются.
- Вы создаёте **рабочие процессы AI-агентов**, где инструмент MCP извлекает связанный контекст по сходству, а не по ключевым словам.
- Вам нужны эмбеддинги артефактов; ingestion FPF KB - отдельная операция.

## Когда это не нужно

- Для задачи достаточно keyword-поиска.
- Вы предпочитаете сборку без feature `semantic-search`.
- Вы не можете выделить место или доступ для загрузки модели.

По умолчанию `forgeplan search` использует smart-поиск: keyword и доступные semantic-сигналы. Для явно keyword-only режима есть `--keyword`; ему не нужны веса модели. Успешный keyword-результат не доказывает готовность semantic.

## Пример

```bash
# Сборка с включённым семантическим поиском
cargo install --path crates/forgeplan-cli --features semantic-search

# Явно подготовить полный снапшот модели
forgeplan setup --skip-alias --skip-hooks

# Генерируем эмбеддинги для всего рабочего пространства
forgeplan embed

# Запрос после публикации эмбеддингов
forgeplan search "trust calculus" --semantic
```
