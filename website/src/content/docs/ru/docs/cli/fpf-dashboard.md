`forgeplan fpf dashboard` отображает обзор проекта на одном экране через призму **First Principles Framework**: какие ограниченные контексты здоровы, какие несут долг рассуждений и что рекомендует движок правил дальше (исследовать больше вариантов, изучить существующие доказательства или использовать проверенный путь).

Это FPF-аналог `forgeplan health` - `health` сообщает факты на уровне артефактов (сироты, просроченные, слепые пятна); `fpf dashboard` интерпретирует их через Trust Calculus и модель explore/exploit.

## Когда использовать

- **В начале сессии**, вместе с `forgeplan health` - понять, куда направить усилия по рассуждениям сегодня.
- **При планировании спринта** - выбрать следующий ограниченный контекст для продвижения на основе R_eff и сигналов explore/exploit.
- **Перед важным решением** - проверить, не эксплуатируете ли вы преждевременно путь с низким доверием.
- **После пакета активаций** - подтвердить, что оценки сдвинулись в ожидаемом направлении.

## Когда НЕ использовать

- Для сырой статистики артефактов (счётчики, сироты) - используйте `forgeplan health`.
- Для правил одного артефакта - используйте [`forgeplan fpf check <id>`](/ru/docs/cli/fpf-check/).
- Для состояния загрузки KB - используйте [`forgeplan fpf status`](/ru/docs/cli/fpf-status/).

## Использование

```text
forgeplan fpf dashboard
```

## Примеры

```bash
# Полный дашборд
forgeplan fpf dashboard

# Типичная комбинация в начале сессии
forgeplan health
forgeplan fpf dashboard
forgeplan blocked

```

## Что вы увидите

Дашборд группирует вывод в три блока:

1. **Ограниченные контексты** - каждый контекст (например, `search`, `scoring`, `fpf-kb`) с агрегированным R_eff, количеством артефактов и флагами слепых пятен.
2. **Оценки качества** - explore_reff / investigate_reff / exploit_reff для каждого контекста, показывающие, где доверие наиболее сильное.
3. **Рекомендуемые действия** - одно из `EXPLORE` (недостаточно гипотез), `INVESTIGATE` (гипотезы есть, но доказательства слабые) или `EXPLOIT` (доказательства сильные, отправляйте в продакшн).

Рекомендация действия исходит из того же движка правил, что и в [`forgeplan fpf rules`](/ru/docs/cli/fpf-rules/).

## Как это вписывается

`fpf dashboard` - это визуальный синтез PRD-041 (движок правил FPF) и PRD-043 (целостность методологии). Он читает:

- Метаданные артефактов (тип, статус, R_eff) из LanceDB
- Активные правила из FPF KB
- Связи доказательств и уровни конгруэнтности

...и проецирует их на ось explore→investigate→exploit, определённую в разделе B FPF (Trust Calculus).
