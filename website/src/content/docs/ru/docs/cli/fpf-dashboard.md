`forgeplan fpf dashboard` объединяет выведенные из графа ограниченные контексты, оценки F-G-R, рекомендации движка правил и счётчики жизненного цикла. Это текстовый отчёт, а не агент автоматического рассуждения или реализации. Для артефактов без связей, просрочки и слепых пятен используйте `health`.

## Когда использовать

- **В начале сессии**, вместе с `forgeplan health` - понять, куда направить усилия по рассуждениям сегодня.
- **При планировании спринта** — изучить кластеры артефактов и рекомендации правил.
- **Перед важным решением** - проверить, не эксплуатируете ли вы преждевременно путь с низким доверием.
- **После пакета активаций** - подтвердить, что оценки сдвинулись в ожидаемом направлении.

## Когда НЕ использовать

- Для сырой статистики артефактов (счётчики, сироты) - используйте `forgeplan health`.
- Для правил одного артефакта - используйте [`forgeplan fpf check <id>`](/ru/docs/cli/fpf-check/).
- Для состояния загрузки KB - используйте [`forgeplan fpf status`](/ru/docs/cli/fpf-status/).

## Использование

```text
forgeplan fpf dashboard
```

## Опции

```text
  -h, --help     Print help
  -V, --version  Print version
```

## Примеры

```bash
# Full dashboard
forgeplan fpf dashboard

# Typical session-start combo
forgeplan health
forgeplan fpf dashboard
forgeplan blocked
```

## Что вы увидите

Дашборд содержит четыре раздела:

1. **Bounded Contexts** — кластеры графа: имя, число участников, процент связности и ID участников. Это вывод из связей, а не заданная классификация предметной области.
2. **Quality (F-G-R)** — число артефактов по оценкам, а не explore/investigate/exploit-оценки контекстов.
3. **Next Actions** — счётчики `EXPLORE`, `INVESTIGATE`, `EXPLOIT`, затем до десяти рекомендаций для артефактов с причинами.
4. **Pipeline** — общее число артефактов, количество active и draft.

Данные берутся из записей и связей LanceDB и конфигурации FPF воркспейса. Непустой `fpf.rules` заменяет встроенные правила; загруженная база знаний FPF и LLM-провайдер не нужны. Рекомендации не разрешают активацию или замещение в обход их собственных проверок. Проверка срока в дашборде принимает полный формат `%Y-%m-%dT%H:%M:%S`; даты без времени здесь не считаются stale, в отличие от отдельной команды `fgr`.
