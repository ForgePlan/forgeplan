Показывает зарегистрированные изменения артефактов из таблицы change-log,
сначала новые. Запись содержит артефакт, действие, изменение поля, источник,
время и необязательный коммит; отдельного поля автора/исполнителя нет.
Журнал не гарантирует регистрацию каждой правки файла или операции.

## Когда использовать

- "Что изменилось за последний день?" - контекст для утреннего стендапа
- Отладка причин неожиданного изменения оценки или статуса
- Просмотр активности коллеги в общем рабочем пространстве
- Проверка успешности синхронизации Git или переиндексации

## Когда не использовать

- Если нужны _только решения_ (а не все мутации) → используйте [`forgeplan journal`](/ru/docs/cli/journal/)
- Если нужен сводный отчёт о состоянии проекта → используйте [`forgeplan health`](/ru/docs/cli/health/)
- Если нужно искать _содержимое_ → используйте [`forgeplan search`](/ru/docs/cli/search/)

## Использование

```text
forgeplan log [OPTIONS] [ID]
```

## Аргументы

```text
  [ID]  Filter by artifact ID
```

## Опции

```text
  -n, --limit <LIMIT>    Maximum number of entries (default: 20) [default: 20]
      --source <SOURCE>  Filter by source (cli, file_edit, git_sync, reindex)
      --json             Output as JSON for machine consumption
  -h, --help             Print help
  -V, --version          Print version
```

## Примеры

Последние 20 событий по всем артефактам (по умолчанию):

```bash
forgeplan log
```

История одного конкретного PRD:

```bash
forgeplan log PRD-001
```

Только мутации, инициированные через CLI, последние 50 - отфильтровать шум от редактирования файлов:

```bash
forgeplan log --source cli --limit 50
```

## Интерпретация вывода

Текстовые столбцы: `TIMESTAMP`, `ARTIFACT`, `ACTION`, `FIELD`, `CHANGE`,
`SOURCE`, `COMMIT`. Время сокращается до сохранённых даты и минуты,
не переводится в локальный часовой пояс. `CHANGE` — сокращённая дельта
старого/нового значения; изменения тела могут показывать хеши.
Коммит имеет отдельный столбец.

`--json` возвращает `entries` и `_next_action`. Запись содержит `timestamp`,
`artifact_id`, `action`, `field`, `old_value`, `new_value`, `source`,
`commit_hash`; необязательные значения равны null, не пропущены.
Пустой запрос успешен и возвращает `entries: []`. Фильтры — переданный ID
и источник; флага временного окна у команды нет.

## Как это работает

`log` читает зарегистрированные изменения. `journal` отдельно строит сводку
текущих записей артефактов по времени создания, а `health` отдельно анализирует
текущее пространство; это не фильтры над change-log.
