`forgeplan setup` готовит алиас, модель и проектные Git-хуки синхронизации: создаёт **алиас `fpl`** и скачивает **модель эмбеддингов** для семантического поиска. Оба шага идемпотентны, и ни один не обязателен для работы Forgeplan. Без модели поиск деградирует в keyword-ранжирование BM25, без алиаса `forgeplan` по-прежнему запускается под полным именем.

Алиас нужен потому, что два пути установки приводят к разным состояниям. Бинарники Homebrew и `install.sh` собирает cargo-dist, который создаёт алиас через настройку `bin-aliases`. У `cargo install` эквивалента нет и **post-install хука нет вовсе**, поэтому при сборке из исходников есть `forgeplan` и нет `fpl`.

Загрузка модели касается **любой** установки. Семантический поиск вкомпилирован во все релизные бинарники (ADR-023), а вот 2.1 GB весов BGE-M3 туда не входят: модель подгружается лениво при первом использовании, и скачать её осознанно лучше, чем обнаружить ожидание посреди работы, когда первый семантический поиск выглядит как зависание.

## Forgeplan 0.38.0

Третий шаг setup устанавливает проектные Git-хуки post-merge и post-checkout, если доступен Git-репозиторий; `--skip-hooks` отключает его. Эти хуки синхронизируют индекс, но не запускают embed и не загружают модель. Алиас и кеш общие для машины, хуки — для репозитория. Для настройки только алиаса используйте `--skip-model --skip-hooks`, только модели — `--skip-alias --skip-hooks`. `init -y --with-model` — явное согласие на загрузку; один `-y` не загружает.

## Когда использовать

- Сразу после любой установки: Homebrew, `install.sh`, архив GitHub Releases или `cargo install`. Семантический поиск есть во всех, модели нет ни в одной.
- Один раз на машину: и алиас, и кэш модели общемашинные, а не по проектам.
- После переноса или переустановки бинаря, чтобы алиас указывал на новое расположение.
- Перед уходом в офлайн, если планируете семантический поиск, а модель ещё не скачана.

## Когда НЕ использовать

- На бинарнике из Homebrew или `install.sh`, если нужен только алиас: там `fpl` уже создан cargo-dist. Модель при этом всё равно нужна, так что передавайте `--skip-alias`, а не пропускайте команду целиком.
- В CI: раннерам редко нужна загрузка на 2.1 GB; если там нужен только алиас, передавайте `--skip-model`.
- Вместо `forgeplan init`: эта команда готовит машину, а не рабочее пространство.

## Использование

```text
forgeplan setup [OPTIONS]
```

## Опции

```text
      --skip-model
          Skip the embedding-model download

      --skip-alias
          Skip creating the `fpl` alias

      --skip-hooks
          Skip installing the git hooks that keep the index in step with `git pull` and branch switches (PROB-097)

  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version
```

## Примеры

### Пример 1: полная последовательность первой установки

```bash
cargo install --git https://github.com/ForgePlan/forgeplan --features semantic-search
forgeplan setup
forgeplan init
```

Сначала готовится машина, затем пространство. Для установки проектных хуков
запускайте `setup` в нужном Git-репозитории. Чужие хуки сохраняются,
собственные обновляются, путь определяется через Git. Другие проекты
используют тот же кеш; эмбеддинги их артефактов setup не создаёт.

### Пример 2: только алиас, без загрузки

```bash
forgeplan setup --skip-model --skip-hooks
```

Полезно на лимитном соединении или когда нужна только короткая команда `fpl`, а keyword-поиска пока достаточно. Запустите `forgeplan setup` позже, чтобы получить модель.

### Пример 3: только модель, не трогая PATH

```bash
forgeplan setup --skip-alias --skip-hooks
```

Для тех, у кого уже есть собственный `fpl` в PATH или кто управляет шимами своими средствами.

## Что делает шаг с алиасом

Симлинк создаётся **рядом с тем бинарём, который запущен**, и путь берётся из собственного расположения исполняемого файла, а не угадывается как `~/.cargo/bin`. Это важно, когда установок несколько: алиас всегда указывает на тот бинарь, который вы действительно вызвали, а не на другую копию где-то в PATH.

Существующий `fpl` **никогда не перезаписывается**. Если по этому пути уже лежит файл и это не наш симлинк, команда сообщает и идёт дальше:

```text
! Not touching /Users/you/.cargo/bin/fpl — something is already there.
  Remove it first if you want the alias.
```

Симлинки создаются на Unix-подобных системах. На Windows шаг пропускается с пояснением, поскольку непривилегированные симлинки там ненадёжны.

## Что делает шаг с моделью

Создание эмбеддера tract запускает загрузку модели из HuggingFace с показом прогресса. Модель кэшируется общемашинно:

| Платформа | Расположение кэша |
|---|---|
| macOS | `~/Library/Caches/forgeplan/models` |
| Linux | `~/.cache/forgeplan/models` |
| Windows | `%LOCALAPPDATA%\forgeplan\models` |

Путь переопределяется через `FORGEPLAN_MODEL_CACHE`. Релизный tract передаёт этот кеш в HuggingFace явно; не рассчитывайте на прежний приоритет HF_HOME из fastembed.

Ошибка загрузки модели — предупреждение, она не проваливает setup.
Но I/O-сбой создания алиаса или установки хуков может завершить команду
ошибкой ещё до шага модели. Smart может использовать keyword/граф;
принудительный `--semantic` имеет собственное поведение при ошибках.
Флага JSON у setup нет.

## Связь с `forgeplan init`

`forgeplan init` предлагает ту же загрузку при интерактивном запуске, чтобы пользователь, начавший с `init`, не остался без этой возможности. Три пути различаются намеренно:

| Вызов | Загрузка модели |
|---|---|
| `forgeplan init` (интерактивно) | спрашивает, по умолчанию **нет** |
| `forgeplan init --with-model` | да, без вопроса |
| `forgeplan init -y` | нет, если явно не добавлен `--with-model` |

Под `-y` загрузки нет, потому что агенты и CI-раннеры вызывают эту команду постоянно. Тянуть гигабайты из-за того, что кто-то выполнил `init -y` в контейнере, это отказ в обслуживании чужой сборки. Интерактивный дефолт тоже «нет»: желание пользоваться только keyword-поиском не должно требовать знания флага, чтобы избежать передачи двух гигабайт.

Шаг с алиасом живёт только здесь, а не в `init`, потому что это машинный уровень, а не уровень отдельного рабочего пространства.
