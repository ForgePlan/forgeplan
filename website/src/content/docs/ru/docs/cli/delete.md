---
title: forgeplan delete
description: "Удалить артефакт с квитанцией для восстановления."
---

Удаляет артефакт после явного `--yes`. До изменения Markdown и производных связей
сохраняется квитанция в `.forgeplan/trash/`. `forgeplan restore <ID>` или
`undo-last` обычно позволяют восстановление в пределах 30-дневного TTL,
если нет конфликта идентичности; отсутствующие цели связей могут быть пропущены.

Для отменённого или заменённого решения предпочтительны
[`deprecate`](/ru/docs/cli/deprecate/) и [`supersede`](/ru/docs/cli/supersede/):
они сохраняют запись решения в рабочем пространстве.

## Использование

```text
forgeplan delete [OPTIONS] <ID>
```

## Аргументы

```text
  <ID>  ID артефакта
```

## Опции

```text
      --yes      Пропустить подтверждение
  -h, --help     Вывести справку
  -V, --version  Вывести версию
```

## Что делает команда

1. Отказывает без `--yes`; интерактивного запроса CLI не делает.
2. Предупреждает о входящих зависимостях; `--yes` подтверждает удаление и при их наличии.
3. Сохраняет квитанцию с артефактом и связями.
4. Удаляет канонический файл и производные записи. На Constellation публикация после изменения может остаться в ожидании.
5. Не переписывает тела других артефактов; текстовые ссылки требуют ревью.

## Примеры

Посмотреть отказ до явного разрешения удаления:

```bash
forgeplan delete NOTE-042
```

Скриптовое удаление (без запроса):

```bash
forgeplan delete NOTE-042 --yes
```

## Безопасность: когда НЕ следует удалять

НЕ следует `удалять` активный артефакт как способ его «отмены». Методология рассматривает отменённые решения как полноценную часть истории - они остаются доступными для обнаружения и объясняют, почему проект пошёл по другому пути.

| Ситуация                                        | Вместо этого сделайте                                            |
|-------------------------------------------------|------------------------------------------------------------------|
| Решение было замещено новым                     | [`forgeplan supersede <old> --by <new>`](/docs/cli/supersede/)   |
| Решение больше не актуально                     | [`forgeplan deprecate <id> --reason "..."`](/docs/cli/deprecate/)|
| Артефакт является сиротой (артефакт без связей) и ещё не содержит контента       | Удаление допустимо                                               |
| Вы создали ID с опечаткой (`PRD-0001` вместо `PRD-1`) | Удаление допустимо                                               |
| Экспериментальная Note, которая никогда не была связана         | Удаление допустимо                                               |

Эмпирическое правило: если что-либо ссылается **на** артефакт, отмените его. Если это тупиковый заглушка без истории, удалите.

## Перед удалением - сделайте резервную копию

Квитанция поддерживает восстановление, но не заменяет резервную копию. Перед массовым удалением:

```bash
forgeplan export --output backup-$(date +%Y%m%d).json
```

А для спокойствия:

```bash
cp -r .forgeplan .forgeplan-backup-$(date +%Y%m%d)
```

При ошибке используйте `forgeplan restore NOTE-042`. Сохраните экспорт и копию workspace для восстановления за пределами возможностей квитанции; правила безопасности - в [настройке агента](/ru/docs/guides/claude-code-setup/).

## Примечания

- Входящие зависимости проверяются; для продолжения требуется `--yes`.
- Канонические чтения видят удаление; производная публикация может отставать.
- Восстановление по квитанции также пытается вернуть связи и сообщает о пропущенных целях.
