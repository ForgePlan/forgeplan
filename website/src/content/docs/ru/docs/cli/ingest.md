`forgeplan ingest` - это мост от вывода сторонних инструментов к нативным артефактам forgeplan. Команда принимает YAML-маппинг (рецепт SPEC-004) и путь к источнику, обходит источник в поисках файлов, соответствующих паттернам маппинга, выполняет все подходящие правила трансформации и записывает получившиеся черновики как заметки, проблемы или другие артефакты forge - каждый из них содержит защищённую от галлюцинаций секцию `## Sources`, указывающую на исходный файл и диапазон строк.

Это CLI-сторона конвейера инжеста Wave-3. MCP-поверхность (`forgeplan_ingest`) по дизайну работает только в режиме dry-run: она валидирует пути, выводит параметры и возвращает планируемое представление, указывающее на эту команду. Полное выполнение, включая запись в LanceDB и проекцию в markdown, происходит здесь.

## Когда использовать

- Когда C4-модель, хранилище Obsidian, пакет ADR из другого инструмента или любой вывод плагина должен попасть в это рабочее пространство как полноценные артефакты.
- В качестве поверхности для dry-run Wave-3: комбинируйте `--dry-run --json` с CI-гейтом, чтобы валидировать, что маппинг + набор источников производят ожидаемые черновики перед записью.
- Для повторяемых ре-импортов: передайте `--update`, чтобы обновить существующие артефакты, когда содержимое источника изменилось; повторный запуск без `--update` - это безопасная no-op операция для источников с одинаковым хешем.

## Когда НЕ использовать

- Для разового импорта одного файла в артефакт, написанный вручную. `forgeplan new` быстрее, и вы контролируете каждое поле.
- Когда маппинг ещё не существует. Нет резервного варианта; пустой массив `rules:` - это ошибка десериализации.
- Для изменения тел артефактов вне шаблонов маппинга. CLI записывает черновики; остальное делают последующие `forgeplan validate`, `forgeplan reason` и человек-ревьюер.

## Что делает команда

1. Валидирует пути `--mapping` и `--source`. `--mapping` должен существовать, быть не более 1 МиБ и парситься как SPEC-004. `--source` должен указывать на существующий файл или директорию.
2. Парсит YAML-маппинг в `Mapping` (sources, rules, опциональные guards, опциональная error policy). Неизвестные поля верхнего уровня отклоняются.
3. Обходит источник (файл или рекурсивно директорию), и для каждого файла выбирает первый `SourceSpec`, чей паттерн совпадает. Скрытые директории (начинающиеся с `.`) также обходятся, чтобы были доступны структуры вроде `.local/spike-*.md`.
4. Выполняет каждое `Rule`, чьи селекторы `when` совпадают с распарсенным источником. Неподходящие правила молча пропускают файл (записывается в массив `skipped` отчёта).
5. Рендерит тело артефакта из шаблонов правила (Tera 1.x с фиксированным белым списком фильтров). Записывает секцию `## Sources` для каждого артефакта, используя формат `sources_section` правила и хеш содержимого источника для идемпотентности.
6. С `--dry-run`: выводит отчёт (текст или JSON) и завершается. Файлы не записываются.
7. Без `--dry-run`: идемпотентно записывает каждый черновик в LanceDB и его markdown-проекцию. Существующие артефакты с совпадающим хешем источника пропускаются; существующие артефакты с отличающимся хешем источника пропускаются с сообщением "differs but --update not passed", если не установлен `--update`, в этом случае они перезаписываются.
8. Добавляет каждую автоссылку, объявленную правилом (с учётом политики `if_exists` для каждой ссылки).

## Использование

```text
forgeplan ingest [OPTIONS] --mapping <MAPPING> --source <SOURCE>
```

## Опции

```text
      --mapping <MAPPING>  Путь к YAML-файлу маппинга
      --source <SOURCE>    Исходный путь (файл или директория для импорта)
      --dry-run            Вывести черновики без записи
      --update             Разрешить обновление существующих артефактов (вместо пропуска при совпадении хеша)
      --json               Вывод в формате JSON
  -h, --help               Вывести справку
  -V, --version            Вывести версию
```

## Примеры

Примеры ниже используют `crates/forgeplan-cli/tests/fixtures/c4-to-forge-test.yaml` - тестовый маппинг Phase-5 Wave-4, плюс исходный фикстур `c4-mini/` с двумя компонентами. Оба поставляются вместе с репозиторием.

### Пример 1: Dry-run, текстовый режим

```bash
forgeplan ingest --mapping mapping.yaml --source c4-mini --dry-run
```

```
  - dry-run: 2 черновик(а) будут записаны
    + note     "Auth Service"  (c4-component-to-note)
    + note     "Database"  (c4-component-to-note)

Готово.
```

Код выхода `0`. Два черновика будут записаны; файлы не изменены.

### Пример 2: Dry-run, JSON

JSON-отчёт содержит `drafts`, `skipped` (несовпадения селектора) и `errors`. Каждый черновик имеет `source_path`, `source_hash`, `rule_id`, `kind`, `title` и план автоматических связей.

```bash
forgeplan ingest --mapping mapping.yaml --source c4-mini --dry-run --json

```json
{
  "_next_action": null,
  "drafts": [
    {
      "kind": "note",
      "links": [],
      "rule_id": "c4-component-to-note",
      "source_hash": "8e566a017d00c0a4b27df9174d9e2d7681586cff5b282a10eb1c90799390245d",
      "source_path": "c4-mini/components/auth.md",
      "title": "Auth Service"
    },
    {
      "kind": "note",
      "links": [],
      "rule_id": "c4-component-to-note",
      "source_hash": "c6ffcfc0e79d217f33e855b0b644756d68f523cac9b33d6d44ba55bba9334ad1",
      "source_path": "c4-mini/components/database.md",
      "title": "Database"
    }
  ],
  "errors": [],
  "skipped": [
    { "SelectorMismatch": { "rule_id": "c4-struct-to-note", "source_path": "c4-mini/components/auth.md" } },
    { "SelectorMismatch": { "rule_id": "c4-struct-to-note", "source_path": "c4-mini/components/database.md" } }
  ]

```

`_next_action` равен `null`, потому что dry-run является терминальным. После реальной записи значение переключается на следующую подсказку PRD-071, например `forgeplan validate <id>`.

### Пример 3: Реальная запись

Без `--dry-run` черновики записываются в `.forgeplan/<kind>/<ID>-<slug>.md` и индексируются в LanceDB.

```bash
forgeplan ingest --mapping mapping.yaml --source c4-mini
```

```
  v 2 черновик(а) создано (2 пропущено движком, 0 ошибок)

  Записано:
    + NOTE-001 note     "Auth Service"  (c4-component-to-note)
    + NOTE-002 note     "Database"  (c4-component-to-note)

Далее: forgeplan validate NOTE-001
```

Тело `NOTE-001` содержит защищённую от галлюцинаций секцию `## Sources` из SPEC-004:

```
---
depth: tactical
id: NOTE-001
kind: note
status: draft
title: Auth Service
---

# Auth Service

## Summary

(no purpose section)

## Sources

- c4-mini/components/auth.md:1-35

<!-- source_hash: 8e566a017d00c0a4b27df9174d9e2d7681586cff5b282a10eb1c90799390245d -->
```

Строка `## Sources` указывает на исходный файл и диапазон строк; HTML-комментарий содержит хеш содержимого, используемый для идемпотентных повторных запусков.

### Пример 4: Повторный запуск на неизменённых источниках

Повторный запуск с тем же исходным содержимым и без `--update` — это no-op при совпадении хеша.

```bash
forgeplan ingest --mapping mapping.yaml --source c4-mini
```

```
  v 2 черновик(а) создано (2 пропущено движком, 0 ошибок)

  Идемпотентные пропуски:
    ~ NOTE-001 не изменён (совпадение хеша)
    ~ NOTE-002 не изменён (совпадение хеша)

Готово.
```

Код выхода `0`.

### Пример 5: Источник изменён, без `--update`

Измените исходный файл (даже на один байт), и хеш существующего артефакта больше не совпадает. Без `--update` запуск откажется перезаписывать и сообщит об этом:

```bash
printf '\n<!-- tweak -->\n' >> c4-mini/components/auth.md
forgeplan ingest --mapping mapping.yaml --source c4-mini
```

```
  v 2 черновик(а) создано (2 пропущено движком, 0 ошибок)

  Идемпотентные пропуски:
    ~ NOTE-001 отличается, но --update не передан
    ~ NOTE-002 не изменён (хеш совпадает)

Готово.
```

Передайте `--update`, чтобы обновить отличающийся артефакт:

```bash
forgeplan ingest --mapping mapping.yaml --source c4-mini --update
```

```
  v 2 черновик(а) создано (2 пропущено движком, 0 ошибок)

  Записано:
    + NOTE-001 note     "Auth Service"  (c4-component-to-note)

  Идемпотентные пропуски:
    ~ NOTE-002 не изменён (хеш совпадает)

Далее: forgeplan validate NOTE-001
```

Защита `forbid_overwrite_active: true` (установленная в блоке `guards:` маппинга) запрещает перезапись *активного* артефакта даже с `--update`; таким образом можно обновлять только черновики.

### Пример 6: Источник из одного файла

Путь `--source` может указывать на один файл. В этом режиме движок выбирает первый `SourceSpec`, чей паттерн совпадает (или использует первую объявленную спецификацию), и обрабатывает только этот файл.

```bash
forgeplan ingest --mapping mapping.yaml --source c4-mini/components/auth.md --dry-run

  - dry-run: 1 черновик(ов) будет записано
    + note     "Auth Service"  (c4-component-to-note)

Готово.
```

Код выхода `0`. Полезно при отладке одного правила на одном источнике.

## Ограничения ресурсов

Оба файла ограничены перед парсингом:

- Mapping YAML: максимум 1 МиБ, 256 уровней вложенности открывающих символов (`{`/`[`).
- Исходные файлы: максимум 10 МиБ, 256 уровней вложенности открывающих символов.

Файл, превышающий любой из лимитов, отклоняется до того, как `serde_yaml` его увидит, поэтому враждебный источник размером 10 МиБ не может вызвать переполнение стека парсера.

## Примечания

- `--source` сопоставляется с полем `sources[].pattern` маппинга текстуально. Переданный путь обходится рекурсивно, и обнаруженные файлы сравниваются как есть. Ведущий `./` или абсолютный путь в `--source` приводит к успешному обнаружению, но к молчаливому провалу сопоставления с глобом с сообщением `no files matched mapping patterns under <path>` и кодом выхода `0` — проверьте, что паттерн и префикс источника совпадают. Одиночный файл в `--source` пропускает сопоставление с глобом в режиме директории и откатывается к первой объявленной спецификации.
- Поверхность MCP (`forgeplan_ingest`) работает только в режиме dry-run по дизайну Wave-3: она валидирует пути, выводит параметры и генерирует планируемое JSON-представление, указывающее обратно на этот CLI. Подключение Wave-4 перенесёт полное выполнение в поверхность MCP.
- Белый список фильтров: только десять фильтров, объявленных в `forgeplan_core::ingest::types::ALLOWED_FILTERS`, доступны внутри шаблонов. Всё остальное вызывает ошибку десериализации при загрузке маппинга.
- Шаблоны используют синтаксис Tera 1.x. Обратите внимание, что фильтр `default` требует именованного аргумента (`default(value="...")`), в отличие от Tera 2.x; фикстурный маппинг показывает правильную форму.
- Маппинг с нулём `sources:` или нулём `rules:` отклоняется при загрузке. Каждое правило должно объявлять непустую карту `fields:`.
- Секция `## Sources` обязательна для каждого артефакта (согласно ADR-009); правило с `sources_section.include: false` вызывает ошибку десериализации, а не откат во время выполнения.

## Структура файла маппинга (минимальная)

Фикстура с двумя правилами, использованная в примерах:

```yaml
schema_version: "1.0"
name: c4-to-forge-test
title: "C4 -> Forge (Wave 4 test fixture)"
compat_spec_version: "^1.0"
source_kind: c4-documentation
target_kind: forge

```yaml
sources:
  - pattern: "c4-mini/**/*.md"
    type: markdown
    parser: front_matter_plus_sections

rules:
  - id: c4-component-to-note
    when:
      file_glob: "**/c4-mini/components/*.md"
      front_matter:
        kind: component
    target:
      kind: note
    fields:
      title: "{{ front_matter.name | default(value=\"Unnamed component\") }}"
      summary: "{{ section.purpose | default(value=\"(no purpose section)\") }}"
    sources_section:
      include: true
      format: "{path}:{line_start}-{line_end}"
      precision: line
      source_hash: true
```

Шаблон `format` использует переменные Tera для пути и диапазона строк; именно это становится строкой `## Sources` в отрендеренном артефакте.
