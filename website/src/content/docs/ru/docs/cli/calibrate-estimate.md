title: forgeplan calibrate-estimate

---

`forgeplan calibrate-estimate` заново рассчитывает оценку существующего артефакта и сравнивает её с положительным конечным числом фактических часов. Команда печатает оценку, уверенность, фактические часы, отношение (`actual / estimated`), точность и рекомендацию. Она не сохраняет набор данных для калибровки и не меняет конфигурацию.

## Когда использовать

- После завершения PRD/RFC сравните фактические часы с текущей оценкой.
- После значительного превышения или сокращения времени изучите отношение, пока контекст свеж.
- Сохраняйте вывод самостоятельно, если хотите агрегировать сравнения или настроить `estimate.grade_profile`.

## Когда НЕ использовать

- Фактические часы ещё неполны; сравнение будет предварительным.
- В артефакте нет извлекаемых элементов FR/Phase; команда отклонит его.

## Использование

```text
forgeplan calibrate-estimate [OPTIONS] --actual-hours <ACTUAL_HOURS> <ID>
```

## Аргументы

```text
  <ID>  Artifact ID to calibrate
```

## Опции

```text
      --actual-hours <ACTUAL_HOURS>  Actual hours spent
      --grade <GRADE>                Grade to compare (junior, mid, senior). Defaults to total score
  -h, --help                         Print help
  -V, --version                      Print version
```

## Примеры

### Калибровка одного PRD после закрытия спринта

```bash
forgeplan calibrate-estimate PRD-001 --actual-hours 18
```

Вывод содержит `Estimated: …h (confidence …%)`, `Actual: …h`, `Ratio: …x (actual / estimated)` и `Accuracy: …%`. Значения зависят от артефакта и конфигурации оценки.

### Сравнение с грейдом

```bash
forgeplan calibrate-estimate PRD-001 --actual-hours 18 --grade senior
```

Без `--grade` используется `total_score`, а не сумма часов senior. Реализация ищет подстроку без учёта регистра в debug-имени грейда; если совпадения нет, молча использует `total_score`. Указывайте полное имя, например `senior` или `middle`, чтобы избежать такого возврата.

### Агрегация по всему спринту

```bash
for id in PRD-001 PRD-002 PRD-003; do
  forgeplan calibrate-estimate "$id" --actual-hours "$(cat actuals/$id.txt)"
done
```

Передайте результаты в скрипт для расчёта среднего отклонения по грейду/домену и предложения новых
множителей для `.forgeplan/config.yaml`.

## Интерпретация вывода

Отношение — фактические часы, делённые на оценочные. Точность равна `100 × min(ratio, 1 / ratio)`.

Рекомендации выбираются по порядку: отношение `> 1.5` предлагает буфер; `> 1.1` сообщает о небольшом оптимизме; `< 0.5` — об очень консервативной оценке; `< 0.7` — о более быстром завершении; иначе — о хорошей калибровке. Это сообщения CLI, а не автоматическая смена глубины или множителей грейда. Сравните несколько завершённых артефактов перед изменением конфигурации.

## Как это вписывается в рабочий процесс

```
sprint close → calibrate-estimate (per artifact) → tune grade_profile → next sprint sharper
```

Представьте это как телеметрию для вашей собственной оценки. CLI не настраивает конфигурацию
автоматически - вы просматриваете отклонение и решаете, что изменить.
