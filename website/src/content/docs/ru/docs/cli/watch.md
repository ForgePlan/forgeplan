Запускает наблюдатель на переднем плане для Markdown-файлов непосредственно в существующих каталогах артефактов `.forgeplan/`. Удобен при работе между редактором и CLI: обработанные изменения тела попадают в LanceDB без ручного `reindex`, после задержки объединения событий, а не мгновенно.

## Использование

```text
forgeplan watch
```

## Опции

```text
  -h, --help     Print help
  -V, --version  Print version
```

## Как это работает

1. Наблюдает за каждым существующим каталогом артефактов нерекурсивно, а не за произвольными `.forgeplan/**/*.md`.
2. Объединяет события за 500 мс и исключает повторяющиеся пути внутри пакета.
3. Для существующих записей использует вспомогательную синхронизацию проекции; новым файлам нужен `id` во frontmatter для создания записи.
4. Печатает `NEW`/`SYNC` в stdout, ошибки — в stderr.
5. По `Ctrl-C` останавливается со строкой `Shutting down watcher.` Обработка всех ожидающих событий перед выходом не гарантируется.

Удаление файла вызывает только предупреждение и не удаляет запись из индекса. Это не полная перестройка метаданных, связей, оценок и векторов. `reindex` сканирует проекции пространства, импортирует новые записи из frontmatter, обновляет различающиеся тела существующих записей, добавляет отсутствующие связи frontmatter и удаляет осиротевшие записи и связи. Существующие title/depth/status/tags не обновляются, удалённые связи между оставшимися записями не убираются; для таких изменений используйте поддерживаемые явные команды, например `update --depth`.

## Когда это использовать

- **Интерактивные сессии написания** - вы составляете PRD в VS Code и хотите, чтобы `forgeplan list` / `forgeplan search` отражали каждое сохранение.
- **Совместная работа с ИИ-агентами** - агент редактирует Markdown, наблюдатель отправляет изменения в LanceDB, следующий вызов `search` видит обновление без полного цикла переиндексации.
- **Периодические сохранения** — держите вывод наблюдателя видимым и ждите сообщения синхронизации перед запросом. После перемещения и переименования проекций используйте `reindex` для поиска путей и очистки сирот с учётом ограничений метаданных и связей существующих записей. Произвольные вложенные каталоги не добавляются в набор наблюдения.

## Когда НЕ использовать

- **Пакетный импорт** — используйте `reindex` для сканирования проекций пространства, `scan-import` — для импорта внешнего Markdown. `scan-import` пропускает уже импортированные артефакты, а не обновляет существующие записи.
- **CI / скриптовая синхронизация тел** — однократный `reindex` не требует постоянно работающего наблюдателя, но сохраняет указанные ограничения метаданных и связей.
- **После `git pull`** - используйте [`git-sync`](/ru/docs/cli/git-sync/), который точно знает, что изменилось на основе git diff.

## Пример

```bash
# Terminal 1: leave this foreground process running.
forgeplan watch

# Terminal 2: edit an existing artifact's actual projection file.
# Wait for the sync message, then query the stored content.
forgeplan search "auth"
```

Иллюстративный вывод для существующего артефакта (команда не запускалась):

```text
SYNC PRD-001 — body updated from file
```

Остановите с помощью `Ctrl-C`:

```text
^C
Shutting down watcher.
```

## Альтернативы

- **Вручную** — запускайте [`forgeplan reindex`](/ru/docs/cli/reindex/) после серии правок тела или для импорта новых проекций пространства. Это не полный сброс frontmatter и связей существующих записей.
- **После pull** - [`forgeplan git-sync`](/ru/docs/cli/git-sync/) сравнивает с `ORIG_HEAD` и переиндексирует только те файлы, которые были затронуты слиянием/pull.

## Ограничения

- Не работает как фоновая служба - работает на переднем плане, поэтому используйте его с `tmux`, панелью терминала или управлением заданиями вашей оболочки, если хотите, чтобы он был постоянным.
- Нет поддержки удалённых файловых систем - опирается на inotify/FSEvents/kqueue (все нативные ОС-наблюдатели), поэтому сетевые монтирования могут пропускать события.
- Одно рабочее пространство - запускайте один `watch` для каждого корневого каталога `.forgeplan/`.
- Ошибки отдельных событий записываются в вывод и не останавливают цикл; работающий наблюдатель не доказывает, что каждое сохранение попало в индекс.
- Удаление файла оставляет запись в LanceDB. Прежде чем явно менять статус или удалять артефакт, изучите намерение; не считайте, что переименование удалило прежнюю запись.
