`forgeplan renew` переводит `stale` артефакт обратно в `active` состояние, устанавливая новую дату `valid_until` и записывая причину продления. valid_until необязателен и не назначается автоматически каждому оцениваемому артефакту. Истечение отражается в отчётах stale/health; продление предназначено для пересмотренного артефакта с сохранённым статусом stale. `renew` - это быстрый путь, когда проверка подтверждает, что решение всё ещё актуально - без переписывания, без преемника, просто расширенное окно действия и примечание, объясняющее, почему команда доверяет ему ещё один цикл.

## Forgeplan 0.38.0

Используйте renew для пересмотренного устаревшего решения, не вместо activate для черновика. Реализация 0.38.0 проверяет формат даты и общий переход в active; отдельной проверки «дата в будущем» или «исходный статус строго stale» нет. Это ограничение реализации, а не гарантия проверки. Выбирайте осмысленную будущую дату сами; команда добавляет раздел Renewal с причиной и обновляет статус и valid_until.

## Когда использовать

- Срок `valid_until` для ADR истёк, но ежеквартальный архитектурный обзор подтвердил, что решение всё ещё действует - продлите срок действия, указав причину со ссылкой на обзор.
- PRD стал просроченным во время медленного спринта, но требования не изменились и всё ещё точны.
- Окно измерения EvidencePack истекло, но повторный запуск того же бенчмарка дал эквивалентные результаты.
- RefreshReport пришёл к выводу «изменения не требуются», и вы хотите, чтобы исходный артефакт отражал этот результат.

## Когда НЕ использовать

- Решение фактически изменилось - создайте черновик преемника и используйте [`forgeplan supersede`](/ru/docs/cli/supersede/) вместо этого.
- Вы хотите переоценить проблему с нуля - используйте [`forgeplan reopen`](/ru/docs/cli/reopen/), чтобы отменить старый артефакт и начать новый черновик.
- Артефакт больше не актуален вообще - используйте [`forgeplan deprecate`](/ru/docs/cli/deprecate/).
- Артефакт ещё active — общий автомат отклоняет active → active, а не молча продлевает срок.

## Использование

```text
forgeplan renew --reason <REASON> --until <UNTIL> <ID>
```

## Аргументы

```text
  <ID>  Artifact ID
```

## Опции

```text
      --reason <REASON>  Reason for renewal
      --until <UNTIL>    New valid_until date (YYYY-MM-DD)
  -h, --help             Print help
  -V, --version          Print version
```

## Примеры

### Пример 1: Продление ADR после архитектурного обзора

```bash
forgeplan renew ADR-001 --reason "still valid after Q2 architecture review, no changes" --until 2027-10-01
```

Канонический вариант использования: обзор подтвердил, что решение остаётся в силе, поэтому продлите срок действия и зафиксируйте доказательства этого обзора в причине.

### Пример 2: Найти и продлить все просроченные артефакты, которые вы хотите сохранить

```bash
forgeplan stale
forgeplan renew PRD-004 --reason "requirements unchanged, confirmed with product" --until 2026-12-31
forgeplan renew RFC-006 --reason "implementation phases still on track" --until 2027-09-15
```

Запустите `forgeplan stale` для поиска истёкших сроков и изучите сохранённый статус через `get`. Само истечение не сохраняет stale. Для пересмотренного истёкшего active-решения явно задайте stale через `forgeplan update ID --status stale`, подставив реальный ID, и затем продлевайте. Не применяйте этот процесс к draft или terminal.

### Пример 3: Краткосрочное продление, пока готовится последующий документ

```bash
forgeplan renew ADR-007 --reason "temporary extension until RFC-018 is ratified" --until 2027-05-01
```

Полезный промежуточный шаг, когда вы знаете, что замена готовится, но текущее решение должно оставаться авторитетным тем временем.

## Как это вписывается в рабочий процесс

`renew` входит в цикл поддержки решений и работает параллельно с основным циклом `Shape → Validate → Code → Evidence → Activate`. Для артефактов с valid_until отчёты stale/health показывают истечение срока; отчёт не является фоновым автоматом смены статуса. Для каждого просроченного артефакта команда выбирает: продлить (всё ещё актуально), заместить (заменено), отменить (выведено из использования) или переоткрыть (переоценить). `renew` - это самый низкозатратный вариант: он сохраняет прежнее тело и добавляет раздел Renewal с причиной, обновляя status и valid_until.

## Распространённые ошибки

| Ошибка | Причина | Исправление |
|---|---|---|
| `Invalid date format` | Неправильный формат (например, `10/01/2026`) | Используйте ISO: `2026-10-01` |
| `Invalid transition` | Исходный статус active или terminal | Продлевайте пересмотренный артефакт со статусом stale; для terminal создайте отдельный новый черновик. |
