`forgeplan undo-last` восстанавливает самую новую неиспользованную квитанцию
деструктивной операции в заданном временном окне независимо от ID артефакта.
Поддерживает квитанции delete, supersede, deprecate, но не выводит операции
из change-log или истории Git.

Важно наличие квитанции: CLI 0.38.0 `delete` создаёт её, а CLI `supersede`
и `deprecate` — нет. Их MCP-обработчики создают квитанции. Поэтому «последняя»
означает последнюю **доступную квитанцию**, не обязательно последнее
деструктивное действие. Перед вызовом изучите операцию и артефакт;
предпросмотра и запроса подтверждения у команды нет.

Это CLI-вариант [`forgeplan_undo_last`](/ru/docs/mcp/forgeplan_undo_last/) на MCP-стороне.

## Когда использовать

- После ошибочного delete с квитанцией или MCP supersede/deprecate с квитанцией.
- После определения нужной операции по артефакту и контексту квитанции.
- В скрипте восстановления, проверяющем возвращённый ID и предупреждения.

## Когда НЕ использовать

- Знаете точный ID - [`forgeplan restore <ID>`](/ru/docs/cli/restore/) точнее (нет риска откатить не ту операцию).
- Вне максимального окна 720 часов или после удаления квитанции/тела — восстанавливайте из системы контроля версий. Срок хранения по умолчанию 30 дней, очистка попутная, не гарантированно по таймеру.
- Ошибка - это опечатка или неверный заголовок (не деструктивная операция) - правьте файл напрямую, потом `forgeplan reindex`.

## Использование

```text
forgeplan undo-last [OPTIONS]
```

## Опции

```text
      --within-hours <WITHIN_HOURS>  Time window (hours) to search for the last destructive op (1..=720, default 24) [default: 24]
      --json                         Output as JSON for machine consumption
  -h, --help                         Print help
  -V, --version                      Print version
```

## Примеры

### Пример 1: Откат за 24 часа по умолчанию

```bash
forgeplan undo-last
```

Выбирает новейшую доступную неиспользованную квитанцию за 24 часа. Успешное восстановление помечает её использованной; повторный вызов идёт к более старой. При сбое часть изменений может уже примениться, а квитанция остаться неиспользованной — перед повтором изучите состояние.

### Пример 2: Расширенный поиск после паузы

```bash
forgeplan undo-last --within-hours 720
```

Ищет по всему 30-дневному окну. Используйте, когда возвращаетесь в воркспейс через несколько дней и поиск по умолчанию (24 часа) ничего не находит.

### Пример 3: Машинно-читаемый вывод для скриптов

```bash
forgeplan undo-last --json | jq '.restored, .op_reversed'
```

Возвращает JSON, потом вытаскивает ID восстановленного артефакта и тип откатанной операции. Полезно, когда `undo-last` - часть скрипта восстановления, которому нужно залогировать что именно сделано.

Успешный JSON содержит `ok: true`, `restored` (ID), `op_reversed`,
`receipt_id`, `relations_restored` (число), `relations_skipped` (ID),
`projection_restored` (boolean), `warnings`, `_next_action`.
CLI не выводит `restored_status`. Если кандидата нет, код `1`,
`ok: false`, `error`, `_next_action`; другие ошибки восстановления могут
выводиться в stderr. Беззнаковое число часов ограничивается диапазоном 1–720.

Для delete воссоздаётся запись, а проекция возвращается из trash при наличии;
существующий ID вызывает отказ. Для supersede/deprecate запись того же типа
получает прежние статус/заголовок; при supersede удаляется связь замещения.
Это не откатывает все последующие изменения тела и не перерисовывает проекцию.
Связи с отсутствующим другим концом пропускаются и перечисляются в отчёте.
После восстановления изучите предупреждения и состояние файла/хранилища.

## Место в рабочем процессе

Используйте, только если новейшая доступная квитанция — именно нужная операция. Когда ID известен, [`forgeplan restore <ID>`](/ru/docs/cli/restore/) выбирает восстановление этого артефакта, не обходит квитанции пространства от новых к старым.
