Перечисляет артефакты с истёкшим valid_until. Сам отчёт не продлевает их и не меняет статус. `decay` отдельно показывает текущее влияние просроченных связанных доказательств; ни одна команда не прогнозирует будущее истечение срока.

## Использование

```text
forgeplan stale [OPTIONS]
```

## Опции

```text
      --json     Output as JSON for machine consumption
  -h, --help     Print help
  -V, --version  Print version
```

## Примеры

```bash
forgeplan stale
forgeplan stale --json | jq '.stale[] | select(.days_expired > 30)'
# After reviewing the selected stale decision:
forgeplan renew ADR-002 --reason "still valid after review" --until 2027-10-01
forgeplan reopen PRD-007 --reason "replace with a new approach"
```

## Выбор действия

Используйте `renew`, если решение подтверждено, `reopen` для нового черновика с сохранением происхождения, `deprecate`, если решение больше не применяется. Изучайте связанные доказательства отдельно: просроченное доказательство даёт вклад 0.1, но попадание артефакта в список не означает R_eff 0.1.

## JSON

Объект содержит `stale` и `_next_action`; массива `hints` в этом ответе CLI нет. Поля записи: `id`, `title`, `valid_until`, `days_expired`. Отсутствие valid_until — не просрочка; не считайте, что каждый Note от capture автоматически истекает.

Хранилище включает любую запись с разобранной датой раньше сегодняшней по UTC, без фильтра статуса, и сортирует по `valid_until`. Даты RFC 3339 тоже могут попасть в список, но расчёт CLI `days_expired` разбирает только `YYYY-MM-DD` и выводит 0 для других принимаемых форматов. Перед подсказкой продления изучите артефакт: задуманное ограничение `renew` только просроченными записями в 0.38.0 реализовано не полностью (#547).
