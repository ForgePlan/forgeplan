---
title: forgeplan fpf ingest
description: "Загружает спецификацию FPF в локальную базу знаний (однократная настройка)"
---

`forgeplan fpf ingest` разбирает внешние установленные разделы FPF и заменяет
вспомогательную таблицу `fpf_spec`. Число разделов зависит от ревизии корпуса;
фиксированные 204 раздела в бинарник не включены. С `semantic-search` разделы
также кодируются BGE-M3. Проверки и правила используют конфигурацию/defaults отдельно.

## Когда использовать

- **Сразу после `forgeplan init -y`** - для заполнения базы знаний перед началом любой работы по рассуждению.
- **В новом клоне** - загрузить отсутствующую БЗ; существующее состояние сохраняйте для диагностики.
- **После обновления установленного корпуса FPF** - осознанно загрузить выбранную ревизию.
- **Когда `fpf status` сообщает, что база знаний просрочена или пуста.**

## Когда НЕ использовать

- Вам не нужно запускать его перед каждой сессией рассуждения; база знаний сохраняется между вызовами.
- Не запускайте его параллельно с `forgeplan reason --fpf` - сначала дождитесь завершения загрузки.
- Это не индексация артефактов: для перестройки индекса из канонического Markdown есть `index`/`reindex`. `scan-import` импортирует внешний Markdown, в том числе через migrated file-first путь, а не перестраивает канонический индекс.

## Использование

```text
forgeplan fpf ingest [OPTIONS]
```

## Опции

```text
      --path <PATH>  Путь к каталогу разделов FPF
  -h, --help         Вывести справку
  -V, --version      Вывести версию
```

**Спецификация FPF не вшита в бинарник** — она поставляется как скилл Claude Code и ставится отдельно. Без неё индексировать нечего, а `fpf search` продолжит отвечать «нет совпадений», что читается как пустой корпус, а не как отсутствующий.

По умолчанию `fpf ingest` ищет разделы в каталоге скиллов, начиная с актуального имени:

```text
~/.claude/skills/fpf-knowledge/sections
~/.claude/skills/fpf/sections
~/.claude/skills/fpf-simple/sections     # историческое имя, всё ещё принимается
```

Скилл `fpf` ставится из [маркетплейса](https://github.com/ForgePlan/marketplace). Передайте `--path`, чтобы взять разделы откуда угодно ещё — из чекаута спецификации, из исправленного корпуса или прямо из клона маркетплейса:

```bash
forgeplan fpf ingest --path <marketplace>/plugins/fpf/skills/fpf-knowledge/sections
```

## Примеры

```bash
# Первоначальная настройка - использует установленный скилл
forgeplan init -y
forgeplan fpf ingest

# Повторная загрузка после обновления
forgeplan fpf ingest
forgeplan fpf status

# Загрузка из внешнего каталога разделов FPF
forgeplan fpf ingest --path ./fpf-sections/
```

## Что происходит

1. Forgeplan находит разделы FPF — установленный скилл или то, на что указывает `--path`.
2. Разделы разбираются на структурированные фрагменты (ID, заголовок, часть, тело).
3. Старые FPF-строки очищаются. С `semantic-search` BGE-M3 кодирует разделы;
   ошибка загрузки модели/кодирования возвращается вызывающему. Без feature записываются только keyword-данные.
4. Вспомогательная таблица `fpf_spec` хранит разделы и необязательные векторы.
5. У записей есть время создания; `fpf status` не показывает время загрузки.

Длительность не гарантируется. Очистка предшествует кодированию: ошибка может
оставить БЗ пустой. Сохраните исходный внешний корпус.

## Как это вписывается

Загрузка - это шаг начальной загрузки для всего остального в `forgeplan fpf`:

```
forgeplan fpf ingest      ← однократно
  ├── fpf search          ← работает после загрузки
  ├── fpf section B.3
  ├── fpf list
  └── fpf status          ← проверка количества
```

`reason --fpf` запрашивает контекст FPF, но выбранный CLI не открывает retired legacy KB на мигрированном workspace. Успешная загрузка не доказывает поддержку там всех FPF-команд.
