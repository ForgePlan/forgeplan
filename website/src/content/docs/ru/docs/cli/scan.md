title: forgeplan scan

---

`forgeplan scan` обходит каталоги исходников и печатает сводку по модулям, файлам и строкам. Он не сохраняет `.forgeplan/modules.json` и постоянный граф модулей. `coverage` выполняет собственный скан, а `drift` изучает объявленные affected files и историю Git; ни одной из этих команд `scan` не требуется.

При поиске каталогов сканер пропускает явные имена каталогов и символические ссылки. Однако при подсчёте файлов и строк внутри найденных модулей он может следовать по ссылкам на исходные файлы. `.gitignore` не применяется как общая политика игнорирования.

## Когда использовать

- Просмотр модулей перед изучением покрытия решений.
- Изучение текущего дерева после рефакторинга.
- Сравнение печатной сводки при ревью.
- Помощь коллеге в понимании распознаваемых каталогов исходников.

## Когда НЕ использовать

- Просто для чтения файлов - используйте вашу оболочку. `scan` учитывает рабочее пространство, а не является универсальным списком файлов.
- Если coverage/drift уже запускались, а ваш код не изменился - `scan` идемпотентен, но расточителен.

## Использование

```text
forgeplan scan [OPTIONS]
```

## Опции

```text
      --path <PATH>  Путь к корню проекта (по умолчанию: текущая директория)
  -h, --help         Вывести справку
  -V, --version      Вывести версию
```

## Примеры

### Сканирование текущего проекта

```bash
forgeplan scan
```

Отчёт печатает столбцы `Module`, `Files`, `Lines`, затем суммарные числа.
Счётчики зависят от просканированного дерева; файл модулей не создаётся.

### Сканирование каталога внутри текущего корня

```bash
forgeplan scan --path crates
```

Путь канонизируется и должен оставаться внутри текущего рабочего каталога. Соседний путь вроде `../other-project` отклоняется.

### Полный конвейер coverage

```bash
forgeplan scan && forgeplan coverage && forgeplan drift
```

Это необязательный просмотр, затем отчёты coverage и drift, а не конвейер с сохранённым перечнем.

## Интерпретация вывода

| Строка | Значение |
|---|---|
| Строка модуля | каталог исходников с распознанными файлами, число файлов и строк |
| Итого | модули, файлы и строки, наблюдаемые этим сканом |

Распознаются расширения Rust, JS/TS, Python, Go, Java, Kotlin, Swift и C/C++.
Скрытые каталоги и именованные деревья `target`, `node_modules`, `vendor`, `sources`,
`research`, `docs`, `templates` пропускаются ниже указанного корня.
Общего исключения всех тестовых модулей нет.

## Как это вписывается в рабочий процесс

```
scan → coverage (modules ↔ artifacts) → drift (artifacts ↔ git history) → remediate
```

Используйте `scan` как просмотр. Coverage сканирует заново; вывод scan не является обязательным сохранённым входом для coverage или drift.
