---
title: forgeplan score
description: "Вычисляет R_eff - показатель доверия к доказательствам по принципу «слабого звена» для решения."
---

`forgeplan score` вычисляет локальный **R_eff** как минимум слабого звена, не среднее. Связанные нетерминальные EvidencePack входят в расчёт, superseded/deprecated исключаются. Выбранный скорер также рекурсивно обходит зависимости; минимум только собственных доказательств не описывает весь результат.

Вердикты: `supports`, `weakens`, `refutes`; это не `review_verdict`. На вклад влияют конгруэнтность и тип. Ветка просроченности возвращает 0.1 даже для refutes: это не постепенный распад до даты и не универсальный потолок. Обычное решение без доказательств/поддерживающих зависимостей получает ноль, Evidence-лист имеет собственную оценку. Слепое пятно означает отсутствие связанных доказательств, не любой нулевой балл.

## Когда использовать

- Сразу после связывания нового EvidencePack (`forgeplan link EVID-012 PRD-001 --relation informs`).
- Перед `forgeplan activate` - если R_eff всё ещё равен 0, вы активируете обещание без доказательств.
- `--all` обрабатывает активные PRD/RFC/ADR/Epic/Spec/Problem/Solution; Note не входит в массовый набор решений.
- JSON помогает отличить отсутствие доказательств от связанных опровержений и изучить слабое звено.

## Когда НЕ использовать

- Скалярная оценка не является приёмкой реализации, lifecycle-статусом или соответствием upstream FPF.
- Явный ID можно оценить за пределами массового набора; Problem и Epic не исключены безусловно.

## Использование

```text
forgeplan score [OPTIONS] [ID]
```

## Аргументы

```text
  [ID]  ID артефакта (опустите с --all, чтобы оценить всё)
```

## Опции

```text
      --all      Оценить активные decision kinds (кэш пишется только на legacy-пути)
      --json     Вывести в формате JSON для машинной обработки
  -h, --help     Вывести справку
  -V, --version  Вывести версию
```

## Примеры

### Оценка одного PRD

```bash
forgeplan score PRD-001
```

Иллюстрация плоских вкладов test/measurement без зависимостей, не записанный runtime-вывод:

```text
PRD-001 - Auth System
  Evidence contributions:
    EVID-012  supports  CL3  valid  → 1.00
    EVID-015  supports  CL2  valid  → 0.90
    EVID-018  weakens   CL1  valid  → 0.10
  R_eff = 0.10   (weakest link: EVID-018)
  Status: AT RISK
```

Исследуйте слабое доказательство, не удаляйте неудобный результат ради метрики. Реальная замена может вытеснить устаревший пакет через `supersede --by`; нужны основания и новый пакет, а не обещание немедленного роста. Пересчитайте и изучите результат: опровержение слабого пакета его не усиливает.

### Обновление всех активных решений одновременно

```bash
forgeplan score --all
```

Legacy-путь обновляет кэш. На migrated-workspace выбранная команда вычисляет свежий результат из канонического снимка, не записывая старые score-кэши. Не считайте, что все поля health используют ту же рекурсивную оценку.

### JSON для конвейеров

```bash
forgeplan score PRD-001 --json | jq '.r_eff, .weakest_link'
```

## Интерпретация вывода

Человекочитаемые метки отчёта: `Adequate` при R_eff ≥ 0.5, `Needs Review` при ≥ 0.3, `AT RISK` ниже 0.3. Это не отображение в lifecycle/DerivedStatus и не разрешение на выпуск.

Штрафы CL3=0, CL2=0.1, CL1=0.4, CL0=0.9. Базы supports=1, weakens=0.5, refutes=0; живой weakens/CL1 даёт 0.1 до поправки типа. Рекурсивный расчёт дополнительно штрафует benchmark на 0.1, audit на 0.2, measurement/test - без штрафа. Плоская детализация и CI не учитывают этот штраф типа и могут отличаться от верхней рекурсивной оценки.

## Эвристическая полоса неопределённости

`r_eff_ci` - эвристика плоской проекции, не статистический доверительный интервал и не доказательство согласия независимых измерений. Для `n` допустимых пакетов и `k` просроченных неопределённость равна `min(0.5, 0.3 / sqrt(n) + min(0.3, 0.1*k))`, границы вокруг плоской оценки ограничены [0,1]. При числе пакетов меньше трёх данные помечаются недостаточными. Для полного отсутствия доказательств есть отдельная ветка.

Арифметические примеры, не измерения:

| Плоский набор | Точка | Полоса |
|---|---|---|
| Один живой supports/CL3 | 1.0 | [0.7, 1.0] |
| Пять живых supports/CL3 и один живой weakens/CL2 | 0.4 | примерно [0.278, 0.522] |
| Один просроченный пакет | 0.1 | [0, 0.5] |

Ширина прямо зависит от числа пакетов и просроченности, а не от проверки независимости, распределения CL или близости будущей даты. Узкая полоса не гарантирует выпуск. Сравнивайте плоский CI и рекурсивную оценку осознанно, не как одно значение.

## Как это вписывается в рабочий процесс

```
code → new evidence → link → score → review → activate
                              ↑
                              └── R_eff must be > 0 to pass review gate
```

Ревью оценки отделено от сбора доказательств и приёмочных гейтов. На migrated чтение не обновляет retired-кэш R_eff; плоские и рекурсивные потребители могут различаться.
