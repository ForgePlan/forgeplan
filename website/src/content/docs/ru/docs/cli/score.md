Вычисляет рекурсивную эффективную надёжность R_eff по минимуму, а не среднему. Черновики доказательств учитываются; пакеты `superseded` и `deprecated` исключаются. У решения без подходящих доказательств собственная оценка равна 0. Для конечного EvidencePack есть исключение: он может оцениваться по своим структурированным полям без придуманных дочерних доказательств.

## Использование

```text
forgeplan score [OPTIONS] [ID]
```

## Аргументы

```text
  [ID]  Artifact ID (omit with --all to score everything)
```

## Опции

```text
      --all      Score all active decision artifacts and update cached R_eff
      --json     Output as JSON for machine consumption
  -h, --help     Print help
  -V, --version  Print version
```

## Структурированные поля доказательства

В разделе Structured Fields задайте `verdict` (`supports`, `weakens`, `refutes`), `congruence_level` (0–3), `evidence_type` (`measurement`, `test`, `benchmark`, `audit`). Для заявления о поддержке нужен распознанный вердикт и явный CL либо распознанный source_tier. Отсутствующие или нераспознанные поля ведут к CL0, а не к полному доверию. При расхождении CL и уровня источника выбирается меньший CL.

## Правила рекурсивного вклада

Для актуального доказательства вклад равен `max(0, verdict_score - CL_penalty - type_penalty)`. Оценки вердиктов: supports = 1.0, weakens = 0.5, refutes = 0.0. Штрафы CL: CL3 = 0, CL2 = 0.1, CL1 = 0.4, CL0 = 0.9. Штрафы типов: test/measurement = 0, benchmark = 0.1, audit = 0.2. Просроченное доказательство вместо этого даёт ровно 0.1. Собственная оценка решения — минимум вкладов подходящих связанных пакетов. Например, актуальный supports/CL3/benchmark даёт 0.9, не 1.0.

## Зависимости и конечные доказательства

Обход следует исходящим `based_on`, `refines`, `informs` и прежним `depends_on`; создавать новую связь depends_on через link нельзя. Из оценки зависимости вычитается 0.1 для based_on/informs и 0 для refines/прежнего depends_on, не ниже 0. Итог — минимум собственной оценки и учитываемых зависимостей. Зависимости draft/deprecated/superseded и типов note/memory пропускаются. Конечный EvidencePack без дочерних доказательств и без исключённых terminal-пакетов возвращает вклад собственных полей; случай «все дочерние пакеты terminal» под исключение не подпадает. Исходящие informs/based_on от доказательства к поддерживаемому решению не переносят доверие решения обратно в доказательство. Фактический обход виден в `factors` и `weakest_link`.

## Примеры

```bash
forgeplan score PRD-001
forgeplan score --all
forgeplan score PRD-001 --json | jq '.r_eff, .weakest_link, .evidence'
```

## Пересчёт и замена

Команда обновляет кешированный R_eff. После добавления или замены доказательства пересчитайте оценку. Текущий опровергающий пакет нельзя прятать ради числа: изучите его и применяйте supersede только при настоящей замене его утверждения. `--all` обновляет активные артефакты решений, включая Epics.

## Исходный разбор, JSON и интервал

Верхнеуровневый `r_eff` — рекурсивный результат. Совместимые `evidence[].score` и `r_eff_ci.point` используют плоскую исходную формулу без штрафов типа доказательства и зависимостей; они могут отличаться от рекурсивной оценки, особенно у конечного EvidencePack. Интервал эвристический, не статистическая гарантия: база `0.30 / sqrt(n)`, плюс 0.10 за просроченную запись, максимум 0.30; общая неопределённость ограничена 0.50, границы — [0, 1]. При числе пакетов меньше трёх отмечается недостаточность доказательств. JSON одного артефакта содержит `id`, `title`, `r_eff`, `r_eff_ci`, `weakest_link`, `factors`, `evidence`, `fgr`, `_next_action`. `--all --json` возвращает другой объект: `results` и `errors`.

## Исторический формат вывода

Для сравнения: пример документации до v0.17 показывал только точечную оценку. Это история, не текущий вывод терминала:

```text
PRD-001 - Auth System
  R_eff = 0.80
```
