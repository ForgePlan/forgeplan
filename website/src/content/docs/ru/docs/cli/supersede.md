---

`forgeplan supersede` выводит из эксплуатации активный артефакт и фиксирует замену. Он записывает отношение `supersedes` от старого ID к замещающему и переводит старый статус в `superseded`. Обычные переходы жизненного цикла не выходят из этого состояния; восстановление по действительному receipt — отдельная операция. Исторический артефакт остаётся читаемым.

## Когда использовать

- Вы переписали ADR с новым решением, и более новая версия уже активна (`ADR-005` заменяет `ADR-003`).
- RFC v2 поглощает RFC v1: та же проблема, лучшая архитектура, старый план больше не применим.
- PRD был разделён на два более сфокусированных PRD, и один из них продолжает охватывать первоначальную область.
- Spec был рефакторингован, и старый контракт больше недействителен, но должен оставаться читаемым для истории.

- **EvidencePack** больше неприменим после повторной верификации: слинкуйте обоснованного преемника и выведите вытесненный пакет из эксплуатации. Terminal-пакеты покидают допустимые популяции R_eff. Пересчитайте оценки и изучите затронутые значения; немедленный пересчёт кэша предков гарантирован не на каждом пути хранения.

## Когда НЕ использовать

- Старый артефакт просто устарел без прямой замены - вместо этого используйте [`forgeplan deprecate`](/docs/cli/deprecate/) с указанием причины.
- Вы хотите заново изучить проблему и создать черновик преемника с нуля - используйте [`forgeplan reopen`](/docs/cli/reopen/), который автоматически создаёт новый черновик.
- Замещающий артефакт ещё не существует. Сначала создайте и активируйте его, затем заместите.
- Старый артефакт всё ещё находится в состоянии `draft` (черновик). Черновики не нуждаются в замещении - просто удалите или перепишите их.

## Использование

```text
forgeplan supersede --by <BY> <ID>
```

## Аргументы

```text
  <ID>  ID артефакта для замещения
```

## Опции

```text
      --by <BY>  ID замещающего артефакта
  -h, --help     Вывести справку
  -V, --version  Вывести версию
```

## Примеры

### Пример 1: Заменить ADR-003 на ADR-005

```bash
forgeplan activate ADR-005
forgeplan supersede ADR-003 --by ADR-005
```

Сначала активируйте преемника, чтобы ссылка на замену указывала на активное решение, затем заместите оригинал.

### Пример 2: Переход RFC с v1 на v2

```bash
forgeplan supersede RFC-002 --by RFC-014
```

`RFC-002` переходит в состояние `superseded` (замещённый) (терминальное). Любой, кто переходит по просроченной ссылке на `RFC-002`, видит указатель `--by` на `RFC-014`.

### Пример 3: Проверить родословную

```bash
forgeplan supersede PRD-007 --by PRD-021
forgeplan graph
```

Изучите граф или `forgeplan get PRD-007 --json`, чтобы увидеть ребро `supersedes` от старого артефакта к замене. Команды `forgeplan links` нет.

## Как это вписывается в рабочий процесс

Supersede - это чистый выход из цикла `Shape → Validate → Code → Evidence → Activate` для решения, которое должно быть заменено, а не выведено из эксплуатации. Он всегда сочетается с активацией преемника: новый артефакт проходит полный цикл, становится `active` (активным), и только затем вы запускаете `supersede` для предшественника. Поскольку состояние является терминальным, убедитесь, что замена действительно является ответом - если вы всё ещё исследуете, используйте `reopen`.

## Распространённые ошибки

| Ошибка | Причина | Исправление |
|---|---|---|
| `--by артефакт не найден` | ID замены не существует | Сначала создайте и активируйте преемника |
| Преемник в черновике (предупреждение) | Преемник ещё не активирован | Команда предупреждает, а не отказывает только из-за статуса draft; активируйте обоснованного преемника как правило рабочего процесса |
| `Невозможно заместить из черновика` | Оригинал всё ещё в черновике | Черновики не нуждаются в замещении - отредактируйте или удалите |
| Уже terminal | Артефакт уже замещён или отменён | Обычный переход отклоняется; восстановление по receipt изучите отдельно |
