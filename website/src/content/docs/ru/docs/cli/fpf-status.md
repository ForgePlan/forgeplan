title: forgeplan fpf status

`forgeplan fpf status` показывает найденный локальный каталог FPF, число Markdown-файлов в нём, количество загруженных секций и строк. Дата последней загрузки не сохраняется; версии спецификации и время изменения не сравниваются.

## Когда использовать

- **Сразу после `fpf ingest`** - проверить, что загружено ожидаемое количество секций.
- **Когда `fpf search` возвращает ноль результатов** - убедиться, что база знаний действительно заполнена.
- **После обновления Forgeplan** - проверить, нужна ли повторная индексация.
- **При свежем клонировании** - поскольку `.forgeplan/lance/` находится в gitignore, новые чекауты начинаются с пустой базы знаний.
- **В smoke-тестах CI** - убедиться, что база знаний готова перед запуском потоков рассуждений.

## Когда НЕ использовать

- Для проверки здоровья проекта на уровне артефактов - используйте [`forgeplan health`](/ru/docs/cli/health/).
- Для полного списка секций - используйте [`fpf list`](/ru/docs/cli/fpf-list/).

## Использование

```text
forgeplan fpf status
```

## Опции

```text
  -h, --help     Print help
  -V, --version  Print version
```

## Примеры

```bash
# Check KB status
forgeplan fpf status

# Common "empty workspace" flow
forgeplan init -y
forgeplan fpf status       # → not ingested
forgeplan fpf ingest
forgeplan fpf status       # → ingested, N sections
```

## Что вы увидите

- **Source** — найденный сейчас стандартный путь либо инструкция для `fpf ingest --path <dir>`. Это не сохранённый путь последней загрузки.
- **Files** — записи `.md` непосредственно в дочерних каталогах источника первого уровня, кроме `_index.md`, если их число ненулевое. Markdown в корне и на более глубоких уровнях не учитывается; это не рекурсивный обход.
- **Ingested** — not initialized, empty либо число секций и общее число строк.
- **Status** — `STALE`, если ненулевое число учтённых исходных файлов отличается от числа секций, иначе `UP TO DATE` при ненулевом числе файлов. Эвристика не обнаруживает изменение содержимого при прежнем количестве; структура источника за пределами одноуровневого обхода также может делать этот индикатор ошибочным.

Полей готовности семантического поиска и полноты эмбеддингов нет. Отсутствие источника или пустая KB отображаются текстом и сами по себе не дают ошибку завершения.

## Как это вписывается

Используйте эту проверку перед `fpf search` или рассуждением, которому нужны выдержки из KB. Это не CI-гейт по коду завершения. `fpf check` использует настроенные или встроенные правила независимо от загрузки KB.

```
fpf ingest  →  fpf status (verify)  →  fpf search / reason --fpf
```
