---

`forgeplan export` записывает артефакты и типизированные связи выбранного workspace в JSON с версией формата `1`. Это не резервная копия всего workspace: конфигурация, секреты, журналы, клеймы, сессии, кэш модели и поколения индекса не входят в пакет. Сохраняйте канонические файлы и необходимую приватную файловую копию, не воссоздавая старые таблицы.

## Когда использовать

- **Всегда перед `rm -rf .forgeplan`, `forgeplan init --force` или любой другой деструктивной операцией с рабочим пространством.** Без исключений.
- Перед обновлением бинарного файла Forgeplan, в качестве подстраховки на случай сбоя `forgeplan migrate`.
- Периодически в качестве резервной копии для аварийного восстановления, особенно перед крупными реструктуризациями методологии.
- Для переноса записей артефактов и связей; остальные файлы сохраняйте отдельно.
- Для отладки - для обмена снимком рабочего пространства с коллегами или прикрепления его к задаче.

## Когда НЕ использовать

- В качестве цели для ежедневного git-коммита - отслеживаемый markdown в `.forgeplan/{adrs,prds,rfcs,...}` уже является каноническим источником истины (ADR-003). Экспорт предназначен для состояния, хранящегося в LanceDB.
- Для публикации или обмена с инструментами, отличными от Forgeplan, - схема JSON является внутренней и нестабильной между версиями.
- В качестве замены git - это не инструмент истории версий, а лишь снимок состояния на определённый момент времени.

## Использование

```text
forgeplan export [OPTIONS]
```

## Опции

```text
  -o, --output <OUTPUT>  Путь к выходному файлу (по умолчанию: .forgeplan/export.json)
  -h, --help             Вывести справку
  -V, --version          Вывести версию
```

## Примеры

### Пример 1: Резервное копирование по умолчанию

```bash
forgeplan export
```

Записывает в `.forgeplan/export.json`. Удобно, но находится внутри той же папки, которую вы, возможно, собираетесь удалить - для реальных резервных копий предпочтительнее указывать явный внешний путь.

### Пример 2: Резервное копирование перед повторной инициализацией

```bash
backup="$HOME/backups/forgeplan-$(date +%Y%m%d-%H%M).json"
forgeplan export --output "$backup"
cp -r .forgeplan .forgeplan-backup-$(date +%Y%m%d)
# Сохраните исходный workspace; попробуйте импорт в отдельном пустом каталоге.
mkdir forgeplan-restore-demo && cd forgeplan-restore-demo
forgeplan init -y
forgeplan import "$backup"
```

Исходный workspace и файловая копия сохраняются, а импорт JSON показан отдельно. Проверьте записи и связи после импорта; это не проверенная процедура восстановления полного состояния.

### Пример 3: Снимок перед обновлением

```bash
forgeplan export --output pre-upgrade.json
cp -r .forgeplan .forgeplan-backup-$(date +%Y%m%d)
# Обновите до нужного релиза по его инструкции установки.
forgeplan migrate
forgeplan health
# При проблеме сохраните оба снимка и разберитесь до восстановления.
```

Сделайте резервную копию до обновления. У выбранной Constellation-сборки и установленного релиза может быть разная раскладка индекса.

### Пример 4: Обмен состоянием рабочего пространства с коллегой

```bash
forgeplan export --output snapshot.json
# Проверьте snapshot.json на приватные данные перед передачей по одобренному каналу.
```

Пакет позволяет передать записи артефактов и связи, но сам по себе не воспроизводит всё состояние health, конфигурации, сроков и runtime.

## Как это вписывается в рабочий процесс

`export` - это операция безопасности, не являющаяся частью жизненного цикла артефакта. Это должно быть доведено до автоматизма перед любым из следующих действий:

- `rm -rf .forgeplan`
- `forgeplan init --force`
- `forgeplan migrate` в значимом рабочем пространстве
- Обновление бинарного файла до новой основной версии
- Экспериментальные массовые изменения markdown

Правило простое: **если вы собираетесь изменить рабочее пространство таким образом, что это нельзя отменить с помощью `git`, сначала выполните экспорт.**

## Примечания по безопасности

- **Путь по умолчанию находится внутри `.forgeplan/`.** `forgeplan export` без аргументов записывает в `.forgeplan/export.json`, который будет потерян, если вы затем выполните `rm -rf .forgeplan`. Всегда передавайте `-o` с путём вне рабочего пространства для реальных резервных копий.
- **Экспортированные данные не шифруются.** Они могут содержать подсказки LLM, внутренние заметки и другой конфиденциальный контент. Не коммитьте их в публичные репозитории.
- **Сохраняйте файловую копию.** Экспорт вместе с копией сохраняет больше, чем один JSON; примеры не доказывают проверенное аварийное восстановление.
- **Конфигурация и секреты сохраняются отдельно.** Приватно сохраните `.forgeplan/config.yaml` и `.forgeplan/secrets.env`, если они есть; не публикуйте учётные данные.
- **У JSON собственная версия формата.** Экспортёр записывает `"version": 1`, а не номер релиза бинарника.

## См. также

- [`forgeplan import`](/ru/docs/cli/import/) - импорт записей и связей
- [`forgeplan init`](/ru/docs/cli/init/) - инициализация; `--force` переписывает конфигурацию, но сохраняет тела артефактов
- [`forgeplan migrate`](/ru/docs/cli/migrate/) - обновление схемы; сначала резервная копия
- [`forgeplan scan-import`](/ru/docs/cli/scan-import/) - импорт новых внешних Markdown, не перестройка канонического индекса
- [`forgeplan health`](/ru/docs/cli/health/) - проверка состояния
