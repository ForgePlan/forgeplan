---

`forgeplan fpf rules` выводит каждое активное правило в движке правил **First Principles Framework**, сгруппированное по рекомендуемой категории действий: **EXPLORE** (генерировать больше гипотез), **INVESTIGATE** (собирать больше доказательств для существующих гипотез) или **EXPLOIT** (придерживаться проверенного пути).

Правила берутся из непустого `fpf.rules` воркспейса либо из встроенного набора, а не из загруженной базы знаний FPF. Они задают рекомендации [`fpf check`](/ru/docs/cli/fpf-check/) и дашборда. Приоритет проверяется по возрастанию, побеждает первое совпадение; метка действия — совет, а не разрешение перехода жизненного цикла.

## Когда использовать

- **Перед спринтом** - просмотрите набор правил, чтобы понять, что ищет движок.
- **Когда правило срабатывает неожиданно** - прочитайте полный текст правила, чтобы понять причину срабатывания.
- **При написании документации по методологии** - ссылайтесь на правила по ID.
- **При отладке вывода `fpf check`** - см. полное определение правила, стоящее за совпадением.

## Когда НЕ использовать

- Для совпадений по отдельным артефактам - используйте [`fpf check <id>`](/ru/docs/cli/fpf-check/).
- Для рекомендаций по действиям в масштабе проекта - используйте [`fpf dashboard`](/ru/docs/cli/fpf-dashboard/).

## Использование

```text
forgeplan fpf rules [OPTIONS]
```

## Опции

```text
      --flat     Flat priority-linear table instead of action-grouped tree
      --json     Output full rule dump as JSON
  -h, --help     Print help
  -V, --version  Print version
```

Представление по умолчанию группирует правила по действиям (EXPLORE / INVESTIGATE / EXPLOIT). `--flat` переключает на единую таблицу, упорядоченную по приоритету, если вы хотите просмотреть правила с наивысшим приоритетом независимо от действия. `--json` выводит полный дамп правил для клиентов MCP и скриптов аудита.

## Примеры

```bash
# Default: action-grouped tree
forgeplan fpf rules

# Flat priority-ordered table
forgeplan fpf rules --flat

# Machine-readable full dump
forgeplan fpf rules --json

# Typical review flow
forgeplan fpf rules
forgeplan fpf check PRD-019
forgeplan fpf dashboard
```

## Три категории действий

Правила соответствуют оси explore→investigate→exploit из части B FPF:

- **EXPLORE** — рекомендация рассмотреть альтернативы.
- **INVESTIGATE** — рекомендация собрать или обновить подтверждения.
- **EXPLOIT** — рекомендация действовать на основе имеющихся подтверждений, без обхода валидации и ограничений жизненного цикла.

Конкретные условия и пороги задаёт активный набор. Не считайте число гипотез или пороги R_eff универсальными. Правило содержит имя, приоритет, условие, действие и необязательное сообщение. JSON содержит `source` (`Config` или `Default`), `count`, `rules`, `_next_action`; объект правила — `name`, `priority`, `action`, `condition`, `condition_summary`, `message`. `--json` имеет приоритет над `--flat`.

## Как это работает

Используйте `fpf check <id>` для совпавших и победившего правил, `fpf dashboard` — для рекомендаций по проекту. Список только читает данные и требует конфигурацию воркспейса, но не провайдера и не загрузку KB. У валидации и активации собственные проверки; рекомендация `EXPLOIT` их не заменяет.
