Просит настроенный LLM предложить задачи масштаба RFC для существующего PRD. Печатает названия, описания, границы задач и зависимости. В 0.38.0 команда не создаёт артефакты RFC и связи.

## Использование

```text
forgeplan decompose <ID>
```

## Аргументы

```text
  <ID>  PRD artifact ID to decompose
```

## Опции

```text
  -h, --help     Print help
  -V, --version  Print version
```

## Когда использовать

После проработки и валидации PRD уровня Standard или выше, если реализация требует нескольких этапов. Не декомпозируйте пустой шаблон и не подменяйте этим согласование целей. Если работа уже описана в RFC, обновите его вместо создания дубликатов.

Нужны существующие пространство и исходный артефакт, а также `llm` с аутентификацией выбранного провайдера или локальным входом. Веса модели векторов не требуются. Если вход не PRD, команда предупреждает, но выполняет декомпозицию. Валидация, глубина, статус и предшествующий ADI — рекомендации процесса, не проверяемые условия. Отсутствие настройки LLM, артефакта и ошибка вызова LLM завершаются ошибкой. Результат — текст провайдера, не гарантированный структурированный DTO задач; флага `--json` нет.

## Пример рабочего процесса

```bash
forgeplan validate PRD-019
forgeplan reason PRD-019 --fpf
forgeplan decompose PRD-019
# Review suggestions and create chosen RFCs explicitly:
forgeplan new rfc "Authentication provider abstraction"
# Use the returned ID, for example RFC-018:
forgeplan link RFC-018 PRD-019 --relation refines
```

## Проверка и сохранение

Напечатанные задачи — предложения, а не сохранённые этапы. Заполните обязательные разделы и списки этапов RFC, свяжите с PRD отношением `refines` и валидируйте до реализации. После появления флажков их отслеживает `progress`. Проверьте придуманные требования, слишком большие задачи, критерии приёмки, откат и доказательства. Декомпозиция не реализует и не проверяет решение.
