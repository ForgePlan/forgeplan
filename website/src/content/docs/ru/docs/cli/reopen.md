`forgeplan reopen` создаёт новый черновик того же типа, связывает его с исходным через `based_on`, затем переводит старый артефакт в deprecated с вашей причиной. Используйте для пересмотра, а не продления срока. Это последовательность записей, не обещание атомарного отката при сбое позднего шага. В отличие от `supersede`, команда создаёт замену, а не ссылается на уже существующую.

## Forgeplan 0.38.0

Исходный статус может быть active или stale; terminal-статусы отклоняются. Новый черновик связан с прежним через based_on, прежний получает deprecated. Это создание преемника, а не возврат terminal-артефакта в draft.

## Когда использовать

- ADR просрочился, и по результатам ревью было решено, что сам подход нуждается в переосмыслении, а не просто в продлении срока действия.
- Исходные предположения PRD больше не соответствуют реальности, и вы хотите переписать его, а не просто внести исправления.
- RefreshReport выявил множество тревожных сигналов по ранее активному решению - переоткройте его, чтобы начать новый черновик.
- ProblemCard, который вы считали решенным, вновь появился в новой форме, и вам нужен новый артефакт, чтобы переопределить его область действия.

## Когда НЕ использовать

- Решение все еще актуально и просто нуждается в обновлении срока действия - используйте [`forgeplan renew`](/ru/docs/cli/renew/).
- У вас уже есть активная замена - используйте [`forgeplan supersede`](/ru/docs/cli/supersede/) с `--by`.
- Решение просто выведено из эксплуатации, и ему нет замены - используйте [`forgeplan deprecate`](/ru/docs/cli/deprecate/).
- Вам нужна небольшая поправка - отредактируйте артефакт напрямую или создайте последующий артефакт, не затрагивая текущий.

## Использование

```text
forgeplan reopen --reason <REASON> <ID>
```

## Аргументы

```text
  <ID>  Artifact ID to reopen
```

## Опции

```text
      --reason <REASON>  Reason for reopening
  -h, --help             Print help
  -V, --version          Print version
```

## Примеры

### Пример 1: Переоткрыть ADR для полной переоценки

```bash
forgeplan reopen ADR-007 --reason "storage strategy needs rethinking after LanceDB v0.8 changes"
```

`ADR-007` переходит в состояние `deprecated` (конечное), и создается новый черновик ADR со ссылкой на родословную, указывающей на `ADR-007`. Заполните его и проведите через обычный цикл Shape → Validate → ADI.

### Пример 2: Переоткрыть PRD, чьи предположения изменились

```bash
forgeplan reopen PRD-010 --reason "target users changed after 2026 Q1 persona research"
```

Черновик наследует тип, глубину, автора, родительский epic и теги, сбрасывает срок действия и добавляет к заголовку ` (reopened)`. Тело содержит раздел Lineage, а не прежний текст или полный шаблон. Старый PRD остаётся доступен с разделом Reopened.

### Пример 3: Использование reopen как части цикла обновления

```bash
forgeplan stale
forgeplan review ADR-012
forgeplan reopen ADR-012 --reason "review identified 3 invalidated invariants"
```

Комбинируйте с артефактом `forgeplan new refresh`, когда переоценка требует структурированного отчета до открытия нового черновика.

## Как это вписывается в рабочий процесс

Reopen - это самый затратный переход в жизненном цикле: он перезапускает цикл `Shape → Validate → ADI → Code → Evidence → Activate` для всего решения. После переоткрытия вы должны рассматривать новый черновик как артефакт полной глубины - заполните разделы MUST, запустите `forgeplan reason`, если глубина этого требует, создайте новые доказательства, и только затем активируйте. Старый артефакт сохраняется в конечном состоянии, поэтому ссылки из исторического контекста (другие артефакты, история git, предыдущие обсуждения) по-прежнему разрешаются. Обращайтесь к нему, когда простое `renew` скрыло бы реальное изменение, и когда еще нет преемника, чтобы `supersede` с ним.

## Распространенные ошибки

| Ошибка | Причина | Исправление |
|---|---|---|
| `--reason обязателен` | Флаг пропущен | Передайте `--reason "..."`, объясняющий, почему требуется переоценка |
| `Cannot reopen …: status 'draft'. Reopen requires active or stale.` | Исходный статус draft | Редактируйте этот черновик |
| `Cannot reopen …: status '…' is terminal.` | Исходный статус deprecated или superseded | Создайте новый артефакт через `forgeplan new` |
| Новый черновик содержит только Lineage | Ожидаемое поведение, не ошибка | Напишите обязательные разделы и выполните валидацию |
