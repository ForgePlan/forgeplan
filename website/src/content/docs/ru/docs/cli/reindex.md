---
title: forgeplan reindex
description: "Перестроение индекса LanceDB из файлов .md (синхронизация files-first, ADR-003)"
---

Синхронизирует индекс LanceDB из markdown артефактов `.forgeplan/`, не записывая в эти исходные файлы. Это основная команда восстановления индекса после клонирования, не обещание воспроизвести все локальные данные пространства.

## Использование

```text
forgeplan reindex
```

## Опции

```text
  -h, --help     Print help
  -V, --version  Print version
```

## Что делает команда

1. Читает Markdown в каталогах артефактов и создаёт недостающий индекс.
2. Для новой записи восстанавливает поддерживаемые поля frontmatter и тело. Для уже существующего ID синхронизирует только тело: изменение статуса, заголовка и прочих метаданных через ручную правку не гарантирует обновления записи.
3. Добавляет недостающие связи из frontmatter, но не удаляет существующее ребро только потому, что ссылку убрали из файла. Для удаления используйте `unlink`, для метаданных — подходящую CLI-команду.
4. Убирает записи без соответствующего файла или с повреждённым kind и связи с отсутствующими концами.
5. Не пересчитывает R_eff и не восстанавливает векторы, историю событий или полный снимок всех таблиц. При необходимости отдельно выполните `score --all` и `embed`.

## Когда запускать

- **После `git clone`** существующего пространства: выполните `forgeplan reindex`; отдельный init для недостающего индекса не нужен.
- **После ручной правки тела**: reindex синхронизирует тело. Метаданные и удаление связей меняйте через CLI, как описано выше.
-   **После `git pull`**, который принес новые артефакты от коллег - см. также
    [`forgeplan git-sync`](/ru/docs/cli/git-sync/) для инкрементального варианта.
- **Восстановление или обновление**: сохраните markdown и выполните reindex. Если повреждённая база не открывается, команда тоже может завершиться ошибкой; она не заменяет произвольное повреждённое состояние и не воспроизводит историю.

## Пример

```bash
# In an existing checkout containing tracked .forgeplan Markdown:
forgeplan reindex
forgeplan list
# After editing an actual artifact body in your editor:
forgeplan reindex
forgeplan search "auth"
```

## Безопасность

`reindex` не меняет markdown, но обновляет и очищает индекс. Работайте с полным checkout и изучайте сводку, предупреждения, ошибки файлов и коллизии ID; ошибки отдельных файлов могут сообщаться без ненулевого кода процесса. Один exit 0 не доказывает чистое восстановление; удаление индекса не является обычным предварительным шагом.

## Примечание к v0.18.0 (PROB-027)

До v0.18.0 `reindex` предполагал, что `.forgeplan/lance/` уже существует и
мог завершиться ошибкой при свежих клонированиях. Начиная с v0.18.0 команда инициализирует
директорию индекса, если она отсутствует, поэтому рабочий процесс "клонирование → переиндексация" теперь
работает полностью без отдельного шага `init` в существующих рабочих пространствах.

## Очистка сиротских связей (хотфикс v0.17.1)

Начиная с v0.17.1 (PROB-028, PRD-044) `reindex` выполняет проход **Фазы 3**, который удаляет
сиротские связи - ссылки в таблице `relations`, чей исходный или целевой
артефакт больше не существует в таблице `artifacts`.

До v0.17.1 удаление или отмена артефакта оставляло его строки связей
в LanceDB. Эти сиротские ссылки приводили к появлению фантомных строк `?` в
выводе `forgeplan tree` и завышали количество ссылок в `forgeplan health`. Фаза 3
удаляет их и выводит счетчик:

```
Reindex complete: 147 artifacts, 3 removed (corrupt kind), 5 orphan relations trimmed
```

Причины удаления, сообщаемые в выводе:

| Причина                            | Что произошло                                    |
|:-----------------------------------|:-------------------------------------------------|
| `corrupt kind field`               | Строка с непарсируемым полем kind - нет допустимой директории |
| `no .md file found`                | Строка LanceDB без соответствующего файла markdown   |
| `orphan relation (source missing)` | Связь, указывающая от удаленного артефакта     |
| `orphan relation (target missing)` | Связь, указывающая на удаленный артефакт      |
| `orphan relation (both missing)`   | Оба конца связи отсутствуют               |

### Когда запускать

-   **После массовых удалений** - если вы вручную удалили несколько файлов `.md`.
-   **После ручного удаления `.md`** - `rm .forgeplan/prds/prd-old.md` оставляет
    висячую строку LanceDB до тех пор, пока вы не переиндексируете.
-   **Начало сессии после `git pull`** - коллеги могли отменить или удалить
    артефакты в своих ветках.
-   **После обновления с версии до v0.17.1** - одна переиндексация очищает все накопленные
    сиротские связи из эпохи до исправления.

## `reindex` против `scan-import`

-   **`reindex`** - целенаправленное перестроение LanceDB из текущего состояния markdown.
    Используйте в обычной повседневной работе.
-   **[`scan-import`](/ru/docs/cli/scan-import/)** - импортёр внешнего markdown при подключении проекта, не средство обновления существующих артефактов. Предпочтительнее
    использовать `reindex`, если вы не выполняете одноразовый импорт или миграцию.
