---
title: forgeplan discover show
description: "Показать статус и накопленные находки сессии обнаружения"
---

`forgeplan discover show <SESSION_ID>` выводит текущее состояние brownfield-сессии обнаружения - на каком этапе протокола она находится, сколько находок отправил агент, и категоризированную сводку того, что было захвачено на данный момент.

Используйте команду во время выполнения, чтобы отслеживать прогресс, и перед `discover complete`, чтобы проверить покрытие.

## Когда использовать

- **В процессе выполнения** - агент добавляет находки, и вы хотите увидеть текущую картину.
- **Перед `discover complete`** - проверить, что сессия действительно охватила интересующие вас области.
- **При отладке** - убедиться, что находки агента попадают в правильную сессию (полезно при параллельном выполнении нескольких сессий).
- **При возобновлении** остановленной сессии после перерыва.

## Когда НЕ использовать

- Для списка всех сессий - используйте [`discover list`](/ru/docs/cli/discover-list/).
- Для запуска новой сессии - используйте [`discover start`](/ru/docs/cli/discover-start/).

## Использование

```text
forgeplan discover show <SESSION_ID>
```

## Аргументы

```text
  <SESSION_ID>   Идентификатор сессии обнаружения
```

## Опции

```text
  -h, --help     Вывести справку
  -V, --version  Вывести версию
```

## Примеры

```bash
forgeplan discover show disc-001
forgeplan discover show disc-001 | less

# Типичная проверка в процессе выполнения
forgeplan discover start
# ...агент работает некоторое время...
forgeplan discover show disc-001
```

## Что вы увидите

Типичные блоки вывода:

- **Заголовок сессии** - ID, created_at, статус (active / completed), владелец/агент.
- **Покрытие** - какие уровни источников были затронуты (code / git / tests / docs), с подсчётами.
- **Находки по категориям** - решения, инварианты, дрифт, технический долг, риски.
- **Последние находки** - последние N записей с текстом сводки.
- **Подсказка следующего действия** - либо "продолжить сканирование", либо "готово к завершению".

## Как это работает

`discover show` - это **читающая** сторона цикла обнаружения. Команда читает напрямую из хранилища сессий (LanceDB), поэтому всегда отражает последние вызовы `discover_finding` через MCP без необходимости обновления.

```
discover start → [агент добавляет через MCP] → discover show → discover complete
```
