`forgeplan gaps` показывает требования к PRD по глубине, активные решения без
актуальных доказательств, старые черновики и артефакты без связей. Замечания
имеют уровни `MUST`, `SHOULD`, `COULD` и печатаются в таком порядке.

Это диагностика только для чтения, не переход статуса и не блокировка активации.
`MUST` обозначает серьёзность пробела; после вывода замечаний команда всё равно
завершается успешно.

## Когда использовать

- В середине спринта: "Я сказал, что это Deep, действительно ли я создал Spec + ADR?"
- После изучения рекомендации `calibrate` — проверить требования для глубины, реально сохранённой в каждом PRD.
- Проверка состояния перед релизом: "соответствует ли проект собственной методологии?"
- Очистка brownfield-проекта: импортированные артефакты часто имеют глубину без последующей цепочки.

## Когда НЕ использовать

- Для проверки только структуры и тела используйте `validate`. У Tactical-артефактов тоже возможны замечания о доказательствах, возрасте черновика или отсутствии связей.
- В качестве блокиратора для активации: пробелы носят рекомендательный характер, а блокирует `validate`.

## Использование

```text
forgeplan gaps
```

## Примеры

### Просмотр всех пробелов конвейера

```bash
forgeplan gaps
```

Иллюстративный фрагмент замечаний (значения артефактов вымышлены, команда не запускалась):

```text
  MUST:
    ! PRD-004 "Search Intelligence"
      PRD-004 Deep depth but no linked RFC

  SHOULD:
    ~ PRD-004 "Search Intelligence"
      PRD-004 Deep depth but no linked Spec
```

Полный текстовый отчёт также содержит сводные счётчики по уровням и подсказку следующего действия.

### Исправление пробелов

Для каждой строки:

1. **Нет RFC/Spec/ADR** → создайте действительно нужный артефакт, заполните его и свяжите с PRD. Например, после `new rfc` подставьте полученный ID в `forgeplan link RFC-018 PRD-004 --relation refines`.
2. **Активное решение без доказательств** → выполните реальную проверку и свяжите актуальный EvidencePack; сгенерированный анализ не является результатом теста.
3. **Critical PRD без родительского Epic** → проверьте границы работы и задайте реальные метаданные родителя.
4. **Старый черновик или артефакт без связей** → изучите актуальность и недостающие связи, не добавляйте бессмысленные связи ради исчезновения замечания.

## Интерпретация вывода

| Реализованная проверка глубины PRD | Уровень при отсутствии |
|-----------------------------------|------------------------|
| Tactical                          | нет требований только по глубине |
| Standard                          | RFC: MUST |
| Deep                              | RFC: MUST; Spec и ADR: SHOULD |
| Critical                          | `parent_epic`, RFC, ADR: MUST |

Проверки пропускают PRD со статусами deprecated/superseded. Связанные типы учитываются в обоих направлениях независимо от типа связи; команда не проверяет полную упорядоченную цепочку и не требует нескольких RFC у Epic. Для Critical наличие Spec сейчас не проверяется.

Другие проверки: активные типы решений без нетерминальных доказательств (MUST), слабые доказательства с оценкой ниже 0.1 по плоскому вспомогательному расчёту (SHOULD), черновики возрастом не менее 90 дней (COULD), артефакты вообще без связей (COULD; Notes и Problems исключены). Evidence и Refresh пропускаются. Плоский расчёт слабых доказательств не равен рекурсивному расчёту `score`.

## Как это вписывается в рабочий процесс

```
review depth → gaps → resolve real omissions → validate → review → activate
```

`calibrate` рекомендует глубину, но не переписывает её. `gaps` читает сохранённую глубину и связи. Если после разбора глубина действительно неверна, используйте `forgeplan update PRD-004 --depth standard` с реальным ID и нужной глубиной. Команда обновляет сохранённую глубину и проекцию; правка frontmatter с последующим `reindex` в 0.38.0 не обновляет глубину существующей записи индекса. Не понижайте глубину только ради исчезновения замечания.
