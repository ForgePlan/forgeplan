`forgeplan fpf search` ищет по загруженным разделам **First Principles Framework** и печатает ID, заголовки, предпросмотр и число строк. Это отдельная база знаний, не артефакты проекта. Размер корпуса зависит от загруженных файлов.

По умолчанию используется взвешенное сопоставление подстрок без учёта регистра. `--semantic` вместо него выбирает векторный поиск BGE-M3. Это разные режимы, а не BM25/гибридный конвейер поиска артефактов. Ни один режим не вызывает провайдер LLM.

## Когда использовать

- **При формировании PRD или ADR** - получите контекст First Principles по концепции перед написанием (`"trust calculus"`, `"bounded context"`, `"explore exploit"`).
- **При аудите решения** - проверьте позицию фреймворка по шаблону, который вы рассматриваете.
- **При онбординге** - рассматривайте базу знаний как учебник с возможностью поиска.
- **Перед `forgeplan reason <ID> --fpf`** — изучите возможный контекст базы знаний. Reason сам выбирает слова из заголовка артефакта, поэтому ручной запрос не воспроизводит его точный контекст.

## Когда НЕ использовать

- Для поиска артефактов - используйте [`forgeplan search`](/ru/docs/cli/search/) вместо этого.
- Для чтения целого раздела - используйте [`forgeplan fpf section <id>`](/ru/docs/cli/fpf-section/).
- Для просмотра полного индекса - используйте [`forgeplan fpf list`](/ru/docs/cli/fpf-list/).

## Использование

```text
forgeplan fpf search [OPTIONS] <QUERY>
```

## Аргументы

```text
  <QUERY>  Search query
```

## Опции

```text
      --limit <LIMIT>  Max results [default: 5]
      --semantic       Use semantic vector search (requires --features semantic-search; falls back to keyword otherwise)
  -h, --help           Print help
  -V, --version        Print version
```

## Примеры

```bash
# Default: weighted keyword search, top 5 results
forgeplan fpf search "trust calculus"

# Widen the result window
forgeplan fpf search "explore exploit tradeoff" --limit 10

# Semantic retrieval (warns and falls back to keyword on propagated runtime errors)
forgeplan fpf search "adversarial review" --semantic

forgeplan fpf search "weakest link"
```

## Как работает конвейер

- **Поиск по словам:** разбивает очищенный запрос по пробелам, оставляет слова длиннее двух байт и ищет любое из них в заголовке или теле. Совпадение в заголовке добавляет 50, вхождения в теле — до 20 на слово, все слова в заголовке — 100, весь запрос в заголовке — 200. Если слов не осталось, ищется весь запрос как подстрока. Стемминга и BM25 нет.
- **Семантический режим:** кодирует запрос через BGE-M3 и получает ближайшие разделы LanceDB по косинусному расстоянию. Нужны сборка с семантическим поиском, кешированные или доступные для загрузки веса и векторы разделов после ingest. Успешный поиск печатает `[semantic search: BGE-M3]`.
- **Резервный режим:** отсутствие функции в сборке, ошибки инициализации или кодирования модели и переданные наверх ошибки векторного поиска вызывают предупреждение в stderr и поиск по словам. Некоторые ошибки LanceDB хранилище превращает в пустой результат, поэтому пустой семантический ответ не всегда запускает резервный поиск.
- **Ввод и вывод:** пустые запросы отклоняются; предел длины — 8192 байта (ошибка называет их “chars”). Число результатов ограничивает `--limit` (по умолчанию 5). Предпросмотр содержит до трёх строк тела, не более 200 символов, затем число строк раздела. Флага JSON и числовой оценки в выводе CLI нет.

Если совпадений нет, изучите `fpf status` и `fpf list` до повторной загрузки. Причиной может быть отсутствие совпадений, пустая база знаний или недоступные векторы. [Руководство поиска артефактов](/ru/docs/guides/search-v2/) описывает другой конвейер.

## Как это вписывается

`fpf search` — команда ручного поиска по базе знаний. `forgeplan reason <ID> --fpf` напрямую обращается к поиску по словам, выбирает значимые слова заголовка, оставляет до трёх уникальных разделов и включает первые 300 символов каждого в промпт ADI.

```
ingest → search → (human reads OR reason consumes) → better decisions
```
