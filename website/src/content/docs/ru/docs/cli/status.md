title: forgeplan status

---

`forgeplan status` печатает метаданные проекта и workspace, общее число артефактов и
отдельные счётчики по типу и по статусу. Команда не показывает сводку «тип × статус»
и не показывает недавнюю активность. Для разбора проблем используйте `health`;
для исторических событий — подходящую команду журнала или журнала изменений.

Используйте её для ориентации и текущих чисел, а не для измерения скорости спринта.

## Когда использовать

- Ориентация в незнакомом рабочем пространстве
- Написание еженедельного отчёта/отчёта о состоянии спринта
- Подтверждение числа артефактов после импорта внешних документов
- Проверка на адекватность после массового импорта или слияния
- Перед стендапом — изучить текущий состав
- Демонстрация - быстрый обзорный слайд для заинтересованных сторон

## Когда НЕ использовать

- Обнаружение технического долга или проблем с качеством - используйте `forgeplan health` (слепые пятна, сироты)
- Проверка отдельного артефакта - используйте `forgeplan get <ID>` или `forgeplan context <ID>`
- Гейтинг CI - status не имеет семантики кода выхода; используйте `health --ci`
- Поиск конкретного артефакта - используйте `forgeplan search` или `forgeplan list`

## Использование

```text
forgeplan status
```

## Опции

```text
  -h, --help     Вывести справку
  -V, --version  Вывести версию
```

## Примеры

### Пример 1: Базовый снимок

```bash
forgeplan status
```

Текстовая сводка состоит из этих разделов:

- Project, Workspace, Created и Artifacts — метаданные и общее число
- By kind — счётчики по типам артефактов
- By status — счётчики по сохранённым статусам жизненного цикла

Данных о недавней активности и синтетических состояний `resolved`/`expired`,
которые встречаются в старых примерах, команда не печатает. Числа и даты
берутся из фактического workspace.

### Пример 2: Проверка на адекватность после импорта

```bash
forgeplan scan-import
forgeplan status
```

Сравните ожидаемое число артефактов после импорта. У `scan-import` нет `--verbose`;
внешние документы просматривайте через `--dry-run`. Для обслуживания канонических
файлов используйте обслуживающий их индекс, а не повторный внешний импорт.

### Пример 3: Однострочник для спринт-стендапа

```bash
forgeplan status | head -15
```

Усечение текстовой сводки; это не стабильный машиночитаемый формат. Части
с недавней активностью команда не выдаёт.

## Интерпретация вывода

- **By kind** и **By status** — независимые итоги, а не сводная таблица.
- Основные сохранённые статусы: `draft`, `active`, `stale`, `superseded`, `deprecated`.
- Одни счётчики не доказывают, что проект заброшен, здоров или движется быстро.
- Низкое число доказательств может быть поводом для проверки; изучайте `health` и реальные связи, а не выводите покрытие из простого отношения.
- Эта сводка не реализует и не проверяет автоматическое истечение Note.

## Как это вписывается в рабочий процесс

```
session start → [status] → health → route → Shape → ...
                   ^
             optional warmup
```

- **Status** отвечает на вопрос "что существует?"
- **Health** отвечает на вопрос "что сломано?"
- Запустите status для ориентации, затем health для списка действий
- Вместе они образуют пару дашбордов для начала сессии
