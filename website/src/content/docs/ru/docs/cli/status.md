---
title: forgeplan status
description: "Показывает метаданные пространства, общее число артефактов и отдельные суммы по типам и lifecycle-статусам."
---

`forgeplan status` выводит имя проекта из конфигурации, путь пространства,
время создания, общее число артефактов и отдельные суммы по типам и статусам.
Матрицы «тип × статус», недавней активности и скорости спринта нет.
Для зарегистрированных изменений используйте `log`, для снимка решений по
времени создания — `journal`, для целостности — `health`.

## Когда использовать

- Ориентация в незнакомом рабочем пространстве
- Написание еженедельного отчёта/отчёта о состоянии спринта
- Подтверждение, что `forgeplan reindex` обнаружил недавно отредактированные файлы
- Проверка на адекватность после массового импорта или слияния
- Перед стендапом — узнать текущие суммы, затем изучить зарегистрированные изменения через `log`
- Демонстрация - быстрый обзорный слайд для заинтересованных сторон

## Когда НЕ использовать

- Обнаружение технического долга или проблем с качеством - используйте `forgeplan health` (слепые пятна, сироты)
- Проверка отдельного артефакта - используйте `forgeplan get <ID>` или `forgeplan context <ID>`
- Гейтинг CI - status не имеет семантики кода выхода; используйте `health --ci`
- Поиск конкретного артефакта - используйте `forgeplan search` или `forgeplan list`

## Использование

```text
forgeplan status
```

## Опции

```text
  -h, --help     Print help
  -V, --version  Print version
```

## Примеры

### Пример 1: Базовый снимок

```bash
forgeplan status
```

Условный вывод для пространства с тремя записями:

```text
Forgeplan Status
================

  Project:    Example API
  Workspace:  /path/to/project/.forgeplan
  Created:    2026-10-01T00:00:00Z
  Artifacts:  3 total

  By kind:
    adr              1
    prd              2

  By status:
    active           1
    draft            2
Next: forgeplan health
```

### Пример 2: Проверка на адекватность после импорта

```bash
forgeplan reindex
forgeplan status
```

Показывает число индексированных записей после синхронизации проекций пространства.
Для ещё не импортированного внешнего Markdown используйте `scan-import`;
это не замена переиндексации уже принадлежащих пространству проекций.

## Интерпретация вывода

- **By kind** — суммы по сохранённому типу.
- **By status** — отдельные суммы по сохранённому статусу. Обычные lifecycle-статусы:
  `draft`, `active`, `stale`, `superseded`, `deprecated`; рендерер выводит сохранённые
  значения, не валидирует их.
- Раздела недавней активности и флага JSON в CLI 0.38.0 нет.

Красные флаги:

- Много черновиков и нет активных - вы создаёте артефакты, но никогда их не завершаете
- По одним суммам нельзя установить, заброшен ли проект и какова скорость работы.
- Количество доказательств непропорционально низкое по сравнению с количеством PRD - отсутствует покрытие доказательствами; запустите `forgeplan health` для получения подробностей
- Изучайте сроки через `stale`; не считайте, что каждый Note истекает автоматически и не требует пересмотра.

## Как это вписывается в рабочий процесс

```
session start → [status] → health → route → Shape → ...
                   ^
             optional warmup
```

- **Status** отвечает на вопрос "что существует?"
- **Health** отвечает на вопрос "что сломано?"
- Запустите status для ориентации, затем health для списка действий
- Вместе они образуют пару дашбордов для начала сессии
