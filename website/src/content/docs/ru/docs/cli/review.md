---
title: forgeplan review
description: "Read-only ревью валидации и методологических условий: PASSED, FAILED или BLOCKED."
---

`forgeplan review` выполняет валидацию и общие методологические условия без изменения артефакта. CLI сообщает:

- **Review PASSED** — нет находок MUST, условия длины тела, связи с доказательством и отсутствия заглушек выполнены.
- **Review FAILED** — есть находки MUST.
- **Review BLOCKED** — методологические условия не выполнены, но находок MUST нет.

Находки SHOULD и предупреждения о зависимости от черновика печатаются отдельно.
Это не вычисляемая сводка R_eff/F-G-R/роутинга. Успешное ревью не заменяет проверку
текущего перехода статуса и provenance-гейта активации CLI.

## Когда использовать

- Всегда запускайте перед `forgeplan activate` - это каноническая предстартовая проверка.
- В конце спринта при пакетной активации - сначала пройдитесь по каждому кандидату с помощью `review`.
- При возвращении к черновику после перерыва, чтобы увидеть, что ещё требует внимания.

## Когда НЕ использовать

- Для Note / Problem - им не нужен гейт валидации для активации.
- В конвейерах CI — `review` сообщает находки, но не завершается ошибкой только из-за неуспешного ревью; используйте подходящий гейт валидации или здоровья.

## Использование

```text
forgeplan review <ID>
```

## Аргументы

```text
  <ID>  ID артефакта
```

## Опции

```text
  -h, --help     Вывести справку
  -V, --version  Вывести версию
```

## Примеры

### Проверка перед активацией

```bash
forgeplan review PRD-001
```

Иллюстративный фрагмент чистого вывода (не результат прогона):

```text
Review PASSED
Ready to activate
```

При находках MUST заголовок — `Review FAILED`, далее идут находки. Когда не выполнены
только методологические условия — `Review BLOCKED` и
`Methodology gates not met (see warnings below)`.

Команда также выводит контекстные подсказки. Она не печатает чек-лист с родителем,
доказательствами, R_eff, FGR и роутингом — такой сводкой занимается отдельный отчёт контекста.

### Проверка перед пакетной активацией

```bash
for id in PRD-001 PRD-002 PRD-003; do
  forgeplan review "$id"
done
```

Быстрая сортировка результатов спринта.

## Интерпретация вывода

| Заголовок CLI | Значение | Действие |
|---|---|---|
| Review PASSED | MUST и методологические условия выполнены | Проверьте переход и остальные требования активации |
| Review FAILED | Есть находки MUST | Исправьте указанные находки |
| Review BLOCKED | Не выполнено условие длины, связи с доказательством или отсутствия заглушек | Устраните напечатанные предупреждения |

Условие связи с доказательством проверяет наличие связи, а не положительный вычисленный R_eff.

## Как это вписывается в рабочий процесс

```
code → new evidence → link → score → REVIEW
                                        │
                                        ├── PASSED → проверьте остальные требования активации
                                        ├── FAILED → исправьте MUST
                                        └── BLOCKED → исправьте методологические условия
```

Ревью — это read-only отчёт перед активацией, а не автоматическая смена состояния.
Лёгкие типы пропускают методологические условия, структурированные решения проверяются
на достаточную длину тела, связь с доказательством и оставшиеся заглушки шаблона.
