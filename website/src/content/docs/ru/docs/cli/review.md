`forgeplan review` показывает замечания валидации и методологических проверок
активации для сохранённого артефакта. Ничего не активирует и не вызывает LLM.

- **Review PASSED** — нет MUST-замечаний, все методологические проверки пройдены.
- **Review FAILED** — есть MUST-замечания.
- **Review BLOCKED** — MUST-замечаний нет, но методологическая проверка не пройдена.

SHOULD и предупреждения build-on-draft могут присутствовать при PASSED.
Успешное ревью не гарантирует, что `activate` примет текущий статус или
переход конкретного типа. Активация выполняется отдельно.

## Когда использовать

- Всегда запускайте перед `forgeplan activate` - это каноническая предстартовая проверка.
- В конце спринта при пакетной активации - сначала пройдитесь по каждому кандидату с помощью `review`.
- При возвращении к черновику после перерыва, чтобы увидеть, что ещё требует внимания.

## Когда НЕ использовать

- Для Note / Problem - им не нужен гейт валидации для активации.
- Для CI-гейта — `review` возвращает `0` даже при FAILED или BLOCKED; для кодов завершения валидации используйте `validate --ci`.

## Использование

```text
forgeplan review <ID>
```

## Аргументы

```text
  <ID>  Artifact ID
```

## Опции

```text
  -h, --help     Print help
  -V, --version  Print version
```

## Примеры

### Проверка перед активацией

```bash
forgeplan review PRD-001
```

Условный фрагмент успеха (далее возможны SHOULD и подсказки):

```text
  Review PASSED
  Ready to activate
```

Условный фрагмент блокировки методологической проверкой:

```text
  Review BLOCKED
  Methodology gates not met (see warnings below)

  ! No evidence linked — create evidence and link it before activating
```

При MUST-ошибках выводятся `Review FAILED`, `Fix MUST validation errors first`
и строки `x [MUST] <rule-id>: <message>`. Таблицы сравнения родителя/F-G-R/роутинга
эта команда CLI не выводит.

### Проверка перед пакетной активацией

```bash
for id in PRD-001 PRD-002 PRD-003; do
  forgeplan review "$id"
done
```

Быстрая сортировка результатов спринта.

## Интерпретация вывода

| Результат | Смысл | Действие |
|---|---|---|
| PASSED | Нет MUST, методологические проверки пройдены | Изучите предупреждения, затем активируйте |
| FAILED | Есть MUST-замечания | Исправьте указанные правила |
| BLOCKED | Не пройдена проверка тела/доказательств/заглушек | Устраните причину предупреждения |

Для PRD/Epic/Spec/RFC/ADR общие проверки требуют минимум 100 байт тела после
trim, подходящую связь с доказательством и отсутствие распознанной заглушки.
Другие типы пропускают эти методологические проверки, но review всё равно
запускает валидацию. Исходящая связь с черновиком даёт build-on-draft warning.
Review не требует положительного R_eff, не калибрует глубину и не показывает F-G-R.
Читается хранилище; после прямых правок файлов синхронизируйте его перед ревью.

## Как это вписывается в рабочий процесс

```text
code → evidence → link → synchronize stored content → review → activate
```

Отсутствующий артефакт и сбои I/O/конфигурации — ошибки. Выведенный FAILED или
BLOCKED остаётся успешной диагностической командой, не CI-гейтом с ненулевым кодом.
