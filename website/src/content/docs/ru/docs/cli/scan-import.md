`forgeplan scan-import` находит внешние Markdown в стандартных каталогах документации или по `--path` и записывает канонические артефакты Forgeplan. На Constellation после успешного пакета запрашивается reconciliation. Команда не синхронизирует существующие канонические файлы и не перестраивает их индекс; используйте `forgeplan index` для Constellation и соответствующий legacy `forgeplan reindex`.

## Когда использовать

- **Адаптация существующих проектов (Brownfield onboarding).** У вас есть существующие RFC, PRD или ADR в markdown, и вы хотите перевести их под методологию Forgeplan без переписывания.
- **Просмотр незнакомой коллекции документов.** Сначала используйте `--dry-run`.
- **Пользовательские каталоги документации.** Укажите внешний источник через `--path`.
- **Не восстановление канонического индекса.** Не удаляйте `.forgeplan/lance/` или его маркеры владения, чтобы команда выглядела восстанавливающей индекс.

## Когда НЕ использовать

- Для восстановления полной копии workspace — у JSON-импорта тоже есть ограничения; сохраняйте канонические файлы и прочее состояние.
- Для создания новых артефактов - используйте `forgeplan new <kind>`. `scan-import` предназначен для обнаружения существующих файлов.
- Для исправления несоответствий схемы - используйте [`forgeplan migrate`](/docs/cli/migrate/). `scan-import` предполагает, что схема уже актуальна.

## Использование

```text
forgeplan scan-import [OPTIONS]
```

## Опции

```text
      --path <PATH>  Каталог для сканирования (по умолчанию: стандартные каталоги документации)
      --dry-run      Только предварительный просмотр, без фактического импорта
  -h, --help         Вывести справку
  -V, --version      Вывести версию
```

## Примеры

### Пример 1: Просмотр документов после клонирования

```bash
git clone <repo>
cd <repo>
# Инициализируйте, только если в проекте ещё нет workspace
forgeplan init -y
forgeplan scan-import --dry-run
```

Для клона, где уже есть канонический Markdown в `.forgeplan/`, обслуживайте его собственный индекс. Сканирование внешних документов не является перестроением канонического индекса.

### Пример 2: Сухой запуск перед подтверждением импорта

```bash
forgeplan scan-import --dry-run
```

Выводит список файлов, которые будут импортированы, их обнаруженный тип артефакта и любые предупреждения парсинга - без затрагивания LanceDB. Используйте это для незнакомых устаревших репозиториев перед реальным запуском.

### Пример 3: Адаптация существующих проектов с пользовательским путём

```bash
forgeplan init -y
forgeplan scan-import --path docs/architecture
forgeplan list
forgeplan health
```

Направляет сканер на нестандартный каталог. Полезно, когда устаревшая документация находится в `docs/`, `architecture/` или `decisions/` вместо `.forgeplan/`.

### Пример 4: Обслуживание индекса Constellation без удаления

```bash
forgeplan index
forgeplan index --list
forgeplan health
```

Это другая операция, не `scan-import`. Сохраняйте канонический Markdown, файлы поколений и маркеры владения; при сбое публикации следуйте указаниям для конкретной раскладки.

## Как это вписывается в рабочий процесс

`scan-import` переносит внешние документы в канонические артефакты.

- **Настройка существующих проектов**: просмотр через `scan-import --dry-run`, затем импорт принятого.
- **Комбинированная настройка**: `init --scan` запрашивает сканирование при инициализации.
- **Обслуживание канонического состояния**: `index` на Constellation, а не повторный внешний импорт.

Существующие ID могут пропускаться. Повторный импорт не гарантирует, что внешние правки обновят существующий артефакт.

## Примечания по безопасности

- **Не удаляйте каталоги workspace/индекса как обычную процедуру восстановления.** Сохраняйте канонические источники и текущий снимок при диагностике.
- **Сначала используйте `--dry-run` для незнакомых репозиториев.** Сканирование может выявить файлы, которые вы не собирались импортировать (`README.md`, `CHANGELOG.md` и т. д.). Предварительно просмотрите перед подтверждением.
- **Для осознанных правок канонических файлов используйте `forgeplan update`.** Согласуйте производное состояние через его владельца, а не через `scan-import`.
- **Сканирование учитывает frontmatter.** Файлы без действительного YAML frontmatter Forgeplan (kind, id, status) могут быть пропущены или импортированы как общие Note в зависимости от эвристики обнаружения.
- **Полная история не восстанавливается.** Ни сканирование внешних документов, ни импорт пакета артефактов не возвращают все поля истории workspace.
