title: forgeplan estimate
description: "Калиброванная оценка трудозатрат по элементам функциональных требований/фаз с профилями грейдов и AI-множителями."
---

`forgeplan estimate` извлекает FR и пункты фаз, назначает сложность Фибоначчи и переводит её в базовые senior-часы. Рассчитываются все грейды; `--grade` и `--my-grade` выбирают подсвеченный грейд, а не переопределяют все элементы. Для людей используются множители грейдов, для AI - тип задачи и накладные расходы ревью. Поле `safety_margin` калькулятор сейчас не применяет. Это эвристика планирования, не измеренная гарантия срока.

## Когда использовать

- Планирование спринта: оценивайте каждый кандидат PRD/RFC, чтобы он соответствовал пропускной способности (≈40–50% от номинальной).
- Проверка пропускной способности перед началом Epic - это 2 недели или 2 месяца?
- Делегирование коллеге по команде - `--grade middle`, чтобы увидеть, как задача выглядит для него.
- Планирование агентов - `--grade ai` подсвечивает AI-оценку; множители типов по умолчанию 0.10–1.00 до ревью.

## Когда НЕ использовать

- Для Note или ProblemCard - у них нет структуры FR/Phase для оценки.
- В качестве контракта - оценки предназначены для планирования, а не для обещаний. Откалибруйте с помощью `calibrate-estimate` постфактум.

## Использование

```text
forgeplan estimate [OPTIONS] <ID>
```

## Аргументы

```text
  <ID>  ID артефакта для оценки
```

## Опции

```text
      --grade <GRADE>            Подсветить итог выбранного грейда (junior|middle|senior|principal|ai)
      --my-grade                 Использовать профиль грейда из конфигурации (с учётом предметной области)
      --llm-score                Использовать оценку сложности на основе LLM вместо эвристики, основанной на правилах
      --complexity <COMPLEXITY>  Ручное переопределение сложности: FR-001=5,FR-002=3 (числа Фибоначчи: 1,2,3,5,8,13)
      --json                     Вывод в формате JSON для машинной обработки
  -h, --help                     Вывести справку
  -V, --version                  Вывести версию
```

## Примеры

### Оценка PRD для вашего собственного профиля грейда

```bash
forgeplan estimate PRD-001 --my-grade
```

Отчёт показывает элементы, сложность, типы задач, суммы по грейдам и confidence.
По умолчанию сложность 3 соответствует 8 senior-часам, а AI pure coding -
`8 × 0.10 × 1.30 = 1.04` часа. Это арифметические примеры, не бенчмарк;
настройки могут изменить множители.

### Сравнение человеческого и AI-помощного пути

```bash
forgeplan estimate PRD-001 --grade senior
forgeplan estimate PRD-001 --grade ai
```

Множители AI по умолчанию: coding 0.10, coding/infra 0.25, design/coding 0.30, infra 0.50, coordination 1.00; накладные расходы ревью 30%.

### Ручное переопределение сложности

```bash
forgeplan estimate PRD-001 --complexity FR-001=8,FR-002=2
```

Используйте, когда эвристика неверно оценивает сложность (например, «простое» FR скрывает миграцию).

### Оценка с помощью LLM

```bash
forgeplan estimate PRD-001 --llm-score
```

Просит LLM оценить сложность элементов; при ошибке модели используются правила. Проверяйте классификацию, не считайте её гарантированно точнее.

## Интерпретация вывода

| Строка                | Что она показывает                                                              |
|-----------------------|---------------------------------------------------------------------------------|
| Элемент | сложность → базовые senior-часы → множитель грейда/типа |
| Суммы | сумма рассчитанных часов по каждому грейду |
| Ревью | настраиваемые накладные расходы только AI, по умолчанию 30% |
| Запас | поле есть в конфигурации, но калькулятор его не прибавляет |
| Confidence | эвристика полноты входа, не измеренная граница ошибки |

Красный флаг: общая сумма более 40 часов - рассмотрите возможность разделения PRD или увеличения глубины.

## Как это вписывается в рабочий процесс

```
route → new → validate → estimate → sprint commit → code → calibrate-estimate
```

Внесите общую сумму в пропускную способность вашего спринта (senior разработчик, планирующий с 50% загрузкой, имеет около 20 «часов оценки» в неделю). После завершения спринта `calibrate-estimate` покажет, насколько точной была оценка.
