Публикует артефакт, меняя статус на `active`. Для PRD, Epic, Spec, RFC и ADR обычный путь требует методологических проверок и валидации схемы. Активация — не простая смена статуса и не доказательство реализации кода.

## Использование

```text
forgeplan activate [OPTIONS] <ID>
```

## Аргументы

```text
  <ID>  Artifact ID
```

## Опции

```text
      --force    Force activation even if validation has MUST errors
  -h, --help     Print help
  -V, --version  Print version
```

## Проверки по умолчанию

Для пяти проверяемых типов сохранённое тело после обрезки пробелов должно занимать не менее 100 байт UTF-8; нужны подходящая связь с доказательством, отсутствие распознанного шаблонного содержимого и отсутствие ошибок MUST. Без `--force` короткое тело, отсутствие связи, шаблон или ошибка MUST отклоняют активацию. SHOULD не блокируют её. `review` показывает общие методологические проверки и валидацию; `score` помогает изучить качество доказательств до активации.

## Что не доказывает проверка связи

Релизная эвристика принимает исходящую `informs` или прежнюю `supports`, либо входящую связь от ID с префиксом `EVID-`. Это не подтверждает содержательную достаточность, вердикт, согласованность, актуальность доказательства или положительный R_eff. Свяжите настоящий EvidencePack направлением доказательство → решение через `informs`, заполните структурированные поля и изучите рекурсивную оценку. Не добавляйте случайные связи ради прохождения условия.

## Примеры

```bash
# After filling the existing PRD and linking real evidence:
forgeplan validate PRD-001
forgeplan score PRD-001
forgeplan review PRD-001
forgeplan activate PRD-001
```

## Force и облегчённые типы

`--force` обходит отказы методологических проверок и MUST-валидации, но не проверку перехода статуса и не отдельное правило состояний гипотезы. Принудительная активация без достаточных доказательств может оставить активное решение без поддержки. Это исключительное явное действие, не обычный путь завершения. Типы вне PRD/Epic/Spec/RFC/ADR пропускают эти проверки качества; гипотезы активируются через MCP `forgeplan_hypothesis_promote`. Активация не запускает тесты и не доказывает правильность решения.

## Статус и отказы

Используйте реальный ID или slug черновика и устраните причины отказа перед повтором. `--force` не позволяет активировать уже active или terminal-артефакт. Для пересмотренного устаревшего решения используйте документированный процесс продления; дефект renew в 0.38.0 нельзя считать способом обхода активации.
