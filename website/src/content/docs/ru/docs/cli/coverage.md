Сканирует код и показывает, какие исходные модули упомянуты в разделах Affected Files артефактов. Это покрытие документированными решениями, не тестовое покрытие и не доказательство соответствия реализации решению.

## Использование

```text
forgeplan coverage [OPTIONS]
```

## Опции

```text
      --backfill  Backfill "Affected Files" section into artifacts missing it
  -h, --help      Print help
  -V, --version   Print version
```

## Примеры

```bash
forgeplan coverage
forgeplan coverage --backfill
forgeplan drift
```

## Дополнение разделов и результат

Пути учитываются только из тел активных PRD/RFC/ADR. `--backfill` меняет
сохранённые тела без `## Affected Files` и `## Affected Scope`, добавляя
фиксированные примеры `crates/forgeplan-core/src/**` и
`crates/forgeplan-cli/src/**`, а не выведенные из проекта пути.
В совпадающем репозитории они могут завысить покрытие; замените их реальной областью.
В 0.38.0 backfill не перерисовывает Markdown-проекции: последующая синхронизация
из файлов может затереть обновление тела.

Обычный отчёт показывает непокрытые модули, покрытые модули с ID решений и процент.
Сопоставление удаляет ограниченный набор окончаний (`/*`, `/**`, `/*.rs`),
затем проверяет, содержит ли одна строка пути другую в любом направлении.
Это симметричная эвристика подстрок, не проверка префикса/границы каталога
и не glob-движок; она не доказывает применимость решения к каждому файлу.
Обязательного здорового процента нет.

## Различия CLI и MCP

`coverage` сам сканирует модули; `scan` полезен для изучения, но не обязателен заранее. В CLI 0.38.0 у coverage нет `--json`. Для структурированной интеграции используйте отдельно документированный MCP-инструмент `forgeplan_coverage` с его собственной схемой.
