Фиксирует решение из разговора с помощью настроенного LLM-провайдера. Простые решения становятся Notes, архитектурные могут стать ADRs. Результат — черновик уровня Tactical, а не автоматически проверенное или активированное решение.

## Использование

```text
forgeplan capture [OPTIONS] <DECISION>
```

## Аргументы

```text
  <DECISION>  The decision statement
```

## Опции

```text
      --context <CONTEXT>  Additional context (optional)
  -h, --help               Print help
  -V, --version            Print version
```

## Условия и ограничения

Настройте LLM-провайдер в `.forgeplan/config.yaml`. Без него команда завершается ошибкой, а не создаёт Note по фиксированному правилу. `--context` добавляет контекст. Capture не задаёт `valid_until`, поэтому сама команда не назначает срок в 90 дней. Для ручного выбора типа и заполнения шаблона используйте `new note` или `new adr`.

API-провайдерам нужны настроенные учётные данные; Ollama использует локальный HTTP без ключа, а явно выбранные профили официальных CLI — существующий вход. Это требования провайдера, не модели векторов. Capture печатает прогресс, путь проекции, назначенный ID, определённый тип, заголовок и подсказку; флага `--json` нет. Неверный префикс типа в ответе модели приводит к Note, а не ошибке.

## Примеры

```bash
forgeplan capture "Retry server failures, not malformed requests" --context "4xx responses need corrected input"
forgeplan capture "Markdown is authoritative; LanceDB is a derived index"
```

## Проверка результата

Прочитайте созданный артефакт, проверьте тип и обоснование; при необходимости уточните содержимое через `update --body @file`. Свяжите его с PRD или RFC отношением `informs`. Перед активацией выполните валидацию и рецензию: сгенерированный текст не доказывает правильность решения.
