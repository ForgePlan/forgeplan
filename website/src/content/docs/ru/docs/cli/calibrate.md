title: forgeplan calibrate
description: "Предлагает глубину Tactical, Standard или Deep по сохранённому содержимому и числу исходящих связей, не меняя артефакт."
---

`forgeplan calibrate` предлагает глубину существующего артефакта по сохранённому
содержимому и числу исходящих связей. В отличие от `route`, команда использует
детерминированную эвристику, а не вызов провайдера. Поле `depth` не меняется.

Эвристика релиза предлагает Tactical, Standard или Deep, но не Critical.
Сигналы: число чекбоксов, текст о безопасности и несовместимых изменениях,
число связей, `parent_epic`, число заголовков второго уровня и строк тела.

## Когда использовать

- В середине спринта: "этот PRD растёт - должен ли он всё ещё быть Standard?"
- После импорта артефактов извне (Brownfield) - чтобы проверить, соответствует ли роутинг реальности.
- Когда `forgeplan route` ошибся при создании, и вы хотите получить второе мнение.
- В рамках триажа `forgeplan gaps`: калибровать помеченные артефакты перед эскалацией глубины.

## Когда НЕ использовать

- Для доказательства правильности глубины: это эвристика, не семантический аудит и не проверка реализации.
- На каждом артефакте каждый день - это корректирующий инструмент, а не ежедневная проверка.

## Использование

```text
forgeplan calibrate [ID]
```

## Аргументы

```text
  [ID]  Artifact ID (checks all if omitted)
```

## Опции

```text
  -h, --help     Print help
  -V, --version  Print version
```

## Примеры

### Откалибровать один PRD после его роста

```bash
forgeplan calibrate PRD-001
```

Условный фрагмент для Standard-артефакта с разделом безопасности:

```text
PRD-001 "Auth System"
──────────────────────────────────────────────────
  Current:   "standard"
  Suggested: Deep ⬆ ESCALATION
  Signals:
    Deep → security_section (present)
```

### Сканировать каждый артефакт

```bash
forgeplan calibrate
```

Без ID выводит только рекомендации повысить глубину и итоговую сводку.
Если таких рекомендаций нет, пишет `All artifacts are at appropriate depth levels.`
Это не доказывает правильность глубины всех артефактов и не выявляет возможные понижения.

## Интерпретация вывода

| Сигнал | Минимальная рекомендуемая глубина |
|---|---|
| 4–10 строк с чекбоксами; больше 10 | Standard; Deep |
| Раздел security/compliance/authentication или `security considerations` | Deep |
| `breaking change`, `## migration` или `backwards compatibility` | Deep |
| 3–5 исходящих связей; больше 5 | Standard; Deep |
| Непустой `parent_epic` | Standard |
| 5–8 заголовков `## `; больше 8 | Standard; Deep |
| 51–200 строк тела; больше 200 | Standard; Deep |
| Нет сигналов | Tactical |

Если рекомендация выше текущей: либо обновите поле `depth` и добавьте недостающие этапы конвейера (Spec, ADR), либо разделите артефакт на более мелкие.

Если рекомендация ниже: рассмотрите возможность упрощения - возможно, вы излишне усложняете.

## Как это вписывается в рабочий процесс

```
route → new (depth=X) → code → calibrate → upgrade depth? → add Spec/ADR?
```

`calibrate` - это самокорректирующаяся петля. Роутинг - это предположение; калибровка - это аудит. Используйте его, когда что-то кажется неправильным, или в качестве запланированной ежемесячной проверки состояния.
