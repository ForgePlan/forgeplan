description: "Показывает оценки качества F-G-R - формальность, гранулярность, надёжность - ортогональные жизненному циклу."
---

`forgeplan fgr` выводит тройку качества **F-G-R** для артефакта:

- **F — Formality**: доля пройденных проверок валидации.
- **G — Granularity**: полнота пяти проверок содержимого — содержательные problem/goals/related, флажки требований и длина тела.
- **R — Reliability**: взвешенные R_eff, вклад связей и свежесть.

Все оси находятся в диапазоне **0–1**. Overall — **геометрическое среднее** `(F × G × R)^(1/3)`, не арифметическое. Это эвристики ForgePlan, не шкалы текущего upstream FPF и не калиброванные вероятности. F-G-R независим от жизненного цикла и не разрешает активацию.

## Когда использовать

- Быстрая оценка зрелости вместе с подробными находками валидатора.
- В начале сессии, после `health`, для сортировки артефактов по принципу "самый дешёвый для повышения уровня".
- При сравнении двух PRD-кандидатов перед фиксацией объёма работ.
- Изучение F-G-R перед применением соответствующих правил FPF.

## Когда НЕ использовать

- В качестве замены `validate` - FGR это сводка, а не отчёт о правилах.
- Для артефактов, не являющихся решениями, где оси не применимы в чистом виде (Notes, RefreshReports).

## Использование

```text
forgeplan fgr [OPTIONS] [ID]
```

## Аргументы

```text
  [ID]  ID артефакта (оценивает все, если пропущено)
```

## Опции

```text
      --json     Вывод в формате JSON для машинной обработки
  -h, --help     Вывести справку
  -V, --version  Вывести версию
```

## Примеры

### Проверить один PRD

```bash
forgeplan fgr PRD-001
```

Текстовый вывод содержит столбцы `ID`, `Title`, `F`, `G`, `R`, `Grade`.
Для иллюстрации, оси `1.0`, `0.8`, `0.7` дают overall около `0.824` и grade `A`.
Это пример арифметики, не измерение артефакта.

Границы строгие: A выше 0.8, B выше 0.6, C выше 0.4, D выше 0.2, иначе F.
Поля `exploit_fgr` эта команда не выводит.

### Ранжировать все артефакты по зрелости

```bash
forgeplan fgr --json | jq '.results | sort_by(.overall) | reverse | .[0:10]'
```

10 самых зрелых артефактов - полезно при принятии решения о том, что продвигать или цитировать.

### Найти самые "дешёвые победы"

```bash
forgeplan fgr --json | jq '.results[] | select(.formality == 1 and .granularity == 1 and .reliability < 0.6)'
```

Кандидаты на ревью надёжности: проверяйте доказательства, связи и свежесть, не предполагая, что один новый пакет завершит артефакт.

## Интерпретация вывода

| Поле | Значение |
|---|---|
| `formality` | Доля пройденных проверок валидации |
| `granularity` | Доля выполненных проверок полноты из пяти |
| `reliability` | Взвешенные R_eff, связи и свежесть, ограниченные 0–1 |
| `overall` | Геометрическое среднее трёх осей |
| `grade` | A/B/C/D/F по указанным границам |

Пороги правил FPF — отдельные настройки; команды `forgeplan fpf trust` нет.

## Как это вписывается в рабочий процесс

```
health → fgr → найти артефакты с низким R → добавить доказательства → оценить → fgr (перепроверить)
```

F и G оплачиваются во время Shape (`new → validate`). R оплачивается во время Evidence (`new evidence → link → score`). `fgr` - это линза, которая показывает, какая категория требует работы.
