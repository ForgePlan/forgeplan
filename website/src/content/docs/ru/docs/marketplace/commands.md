:::note[Требуется установка]
Эти точки входа поставляются внешними плагинами маркетплейса. В Claude Code сначала выполните `/plugin marketplace add ForgePlan/marketplace`, затем `/plugin install <name>@ForgePlan-marketplace`. Отдельная команда ядра `forgeplan setup-skill` устанавливает только встроенный навык `/forge`, а не эти плагины.
:::

Справочник охватывает **29 физических файлов `commands/*.md` в 10 плагинах**, а не все точки входа из чата. Публичный каталог **1.187.1** на [коммите `b4e8a1b`](https://github.com/ForgePlan/marketplace/tree/b4e8a1b9bfaa4c9c44e6f8dc1039e09fa1b193f7) поставляет **23 плагина, 99 навыков и 97 определений агентов**. Навыки тоже можно вызывать из чата; см. [Файлы команд и точки входа навыков](#файлы-команд-и-точки-входа-навыков).

В таблицах указаны короткие имена. При необходимости используйте имя с префиксом плагина, например `/forgeplan-workflow:forge-cycle` или `/dev-toolkit:sprint`. Доступность и написание зависят от среды исполнения; эти файлы используют формат команд Claude Code.

## forgeplan-workflow

Сам цикл методологии.

| Команда | Что делает |
|---|---|
| `/forge-cycle` | Запускает полный инженерный цикл forgeplan: проверка здоровья, роутинг, формирование, сборка, доказательства, активация, коммит. |
| `/forge-audit` | Запускает мультиэкспертный аудит текущей кодовой базы. |

## agents-canvas

Работа с дизайн-системой: от Pencil до нативных компонентов, с fail-closed гейтом токенов.

| Команда | Что делает |
|---|---|
| `/canvas-init` | Однократная настройка гейта токенов CANVAS для ветки. |
| `/canvas-audit` | Одноразовый аудит DS-конвенций (canvas-guardian как команда). |
| `/canvas-review` | Гейт кода + UX после экспорта CANVAS. |
| `/canvas-rule` | Поиск конвенции дизайн-системы CANVAS или UX-закона по имени. |

## forgeplan-map-pack

Составные карты кода+документации в `.forgeplan/map/`.

| Команда | Что делает |
|---|---|
| `/map-build` | Сканирует текущий репозиторий с включённым forgeplan и генерирует валидированный `.forgeplan/map/map.json`. |
| `/map-build-layer` | Генерирует детализированный слой одной зоны для уже построенной карты, по запросу и только с добавлением. |
| `/map-refresh` | Инкрементально обновляет уже построенную карту - перестраивает только слои, затронутые изменениями в git и документации. |
| `/map-doctor` | Быстрая проверка здоровья уже построенной карты и её слоёв в режиме только для чтения. |

## forgeplan-orchestra

Опубликованный плагин **3.6.0** по-прежнему содержит оба файла команд ниже. Он также поставляет навыки `task-cycle`, `unified-workflow` и `orchestra-mcp` и агентов `task-runner` и `orchestra-advisor`. Это отдельные компоненты, а не дополнительные файлы команд.

| Команда | Что делает |
|---|---|
| `/session` | Протокол начала сессии с паттерном Inbox - восстанавливает контекст из Orchestra, Git и Forgeplan. |
| `/sync` | Сравнивает артефакты Forgeplan с задачами Orchestra, показывает различия и ждёт подтверждения перед применением предложенных изменений. |

В этом релизе нет файлов `commands/task-cycle.md`, `commands/task-runner.md` и `commands/unified-workflow.md`. `task-cycle` — навык, `task-runner` — агент. Новый процесс работы с задачей не означает удаления `/session` или `/sync`. Для операций Orchestra нужны настроенный MCP-сервер и определение сервера и рабочего пространства по правилам плагина; автоматической синхронизации доски нет.

## fpf

Рассуждение First Principles Framework, основанное на базе знаний из 224 разделов.

| Команда | Что делает |
|---|---|
| `/fpf` | Универсальная команда мышления - направляет в режим декомпозиции, оценки или рассуждения в зависимости от вашего вопроса. |
| `/fpf-decompose` | Декомпозирует сложную проблему или систему на ограниченные части с использованием FPF. |
| `/fpf-evaluate` | Оценивает решение или сравнивает альтернативы с использованием Trust Calculus и F-G-R скоринга FPF. |
| `/fpf-reason` | Рассуждает над сложным вопросом с использованием структурированного цикла рассуждений FPF. |
| `/fpf-lookup` | Ищет концепцию FPF в базе знаний из 224 разделов. |

## laws-of-ux

30 законов UX как поверхность для ревью.

| Команда | Что делает |
|---|---|
| `/ux-review` | Проверяет фронтенд-код на соответствие принципам 30 законов UX. |
| `/ux-law` | Ищет конкретный UX-закон по имени. |

## slopocop

Обнаружение и переписывание AI-слопа в прозе.

| Команда | Что делает |
|---|---|
| `/slop-audit` | Обнаружение AI-слопа в тексте в режиме только для чтения. |
| `/slop-humanize` | Очеловечивает текст - удаляет AI-слоп и переписывает в конкретном человеческом голосе. |

## slopocop-code

Обнаружение и переписывание AI-слопа в исходном коде.

| Команда | Что делает |
|---|---|
| `/code-audit` | Обнаружение AI-слопа в исходном коде в режиме только для чтения. |
| `/code-deslop` | Переписывание с сохранением поведения, которое удаляет слой AI-слопа из исходного кода. |

## slopocop-design

Обнаружение и переписывание AI-слопа в UI.

| Команда | Что делает |
|---|---|
| `/design-audit` | Аудит UI и фронтенд-кода на наличие AI-слоп дизайна. |
| `/design-redesign` | Редизайн страницы или компонента, чтобы он перестал выглядеть сгенерированным AI. |

## dev-toolkit (устарел)

:::caution[Устарел]
`dev-toolkit` **1.9.1** помечен в каталоге как `deprecated`, но по-прежнему опубликован со всеми четырьмя файлами команд. Новым пользователям рекомендуется **fpl-skills 1.75.1**. Структурированное поле `supersedes` в каталоге указывает именно диапазон `dev-toolkit <=1.6.1`; этот диапазон и статус текущего плагина — разные сведения.
:::

| Команда | Что делает |
|---|---|
| `/audit` | Мультиэкспертный аудит кода - запускает 4 параллельных агента ревью (Logic, Architecture, Security, Tests) и сообщает о находках по степени серьёзности. |
| `/sprint` | Адаптивный спринт - масштабируется от быстрого фикса до полного цикла релиза. |
| `/recall` | Восстановление контекста сессии - читает состояние проекта, недавнюю историю git и доступные источники памяти для брифинга начала сессии. |
| `/report` | Генерирует структурированный отчёт о недавней работе: выбирает шаблон, выводит TL;DR, что сделано, что нет, обратимость, риски дрейфа и следующие шаги. |

## Замещённые команды

При переходе на `fpl-skills` используйте следующие точки входа навыков. Это не новые файлы в `commands/` взамен старых.

| Устаревшая команда | Преемник в fpl-skills |
|---|---|
| `/dev-toolkit:audit` | Навык `/fpl-skills:audit` |
| `/dev-toolkit:sprint` | Навык `/fpl-skills:sprint` |
| `/dev-toolkit:recall` | Навык `/fpl-skills:restore` |
| `/dev-toolkit:report` | Навык `forge-report`, вызываемый как `/fpl-skills:forge-report`; навыка или команды `report` в fpl-skills нет |

Каталог отдельно объявляет два расширения команд, а не псевдонимы или удаления:

| Существующая команда | Расширение | Отличие |
|---|---|---|
| `/dev-toolkit:audit` | `/forgeplan-workflow:forge-audit` | Добавляет ревьюеров Performance и Documentation. Процедура требует создать Evidence и освободить claim; старое вводное описание о необязательности Evidence устарело. |
| `/dev-toolkit:recall` | `/forgeplan-orchestra:session` | Добавляет inbox Orchestra и проверку здоровья Forgeplan к восстановлению. |

## Файлы команд и точки входа навыков

**Файл команды** находится в `plugins/<plugin>/commands/<name>.md`. **Навык** — в `plugins/<plugin>/skills/<name>/SKILL.md`; YAML-фронтматтер задаёт `name`, `description` и ограничения вызова. Claude Code может предоставлять доступный пользователю навык как `/plugin:skill`, даже если у плагина нет каталога `commands/`. Например, `/fpl-skills:shape`, `/fpl-skills:spec-author`, `/fpl-skills:estimate`, `/fpl-skills:gate-check`, `/fpl-skills:refine`, `/fpl-skills:sprint` и `/fpl-skills:wrap` — точки входа навыков.

`disable-model-invocation: true` означает явный вызов вместо автоматического выбора моделью, а **не** недоступность навыка из чата. Опубликованный навык `shape` использует этот флаг и явно документирует `/shape`. Совпадение описания с задачей само по себе не гарантирует автозагрузку. Способ вызова определяют поддержка среды исполнения и фронтматтер.

Отсутствие в списке из 29 файлов не означает «нельзя вызвать» или «не установлено». Другие среды находят переносимые навыки по своим путям и не обязательно регистрируют команды Claude Code или применяют его ограничения инструментов. Границы совместимости описаны в [Разработке плагинов](/ru/docs/marketplace/development/).

## Когда что использовать

| Ситуация | Команда |
|---|---|
| Начало новой фичи | `/forge-cycle` |
| Ревью кода перед PR | `/forge-audit` |
| Комплексный спринт | Навык `/fpl-skills:sprint` (рекомендуется); `/dev-toolkit:sprint` устарел |
| Архитектурное решение | `/fpf-evaluate` |
| Понимание системы | `/fpf-decompose` |
| Отладка аргумента | `/fpf-reason` |
| Поиск концепции FPF | `/fpf-lookup` |
| Восстановление контекста сессии | `/session` |
| Синхронизация с доской задач | `/sync` |
| Качество фронтенда | `/ux-review` |
| Текст читается как написанный AI | `/slop-audit` → `/slop-humanize` |
| Код читается как написанный AI | `/code-audit` → `/code-deslop` |
| UI выглядит сгенерированным AI | `/design-audit` → `/design-redesign` |

## Цепочки рабочего процесса

```
Поставка фичи:
  /forgeplan-workflow:forge-cycle  →  /forgeplan-workflow:forge-audit  →  исправление при необходимости

Архитектурное решение:
  /fpf-evaluate "варианты"  →  /forge-cycle "реализовать победителя"

Очистка кодовой базы от слопа:
  /code-audit  →  /code-deslop  →  /code-audit

Начало сессии:
  /session  →  работа  →  /sync
```
