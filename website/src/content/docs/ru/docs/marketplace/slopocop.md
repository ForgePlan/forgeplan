**Slopocop — коммуникационный слой**, который делает ответы, вопросы и сообщения о ходе работы краткими и технически точными. Он дополняет существующие инструкции, не заменяет их и не запускает отдельного редактора или оценщика на каждый ответ. Документы и другие запрошенные материалы сохраняют нужный жанр, стиль и объём.

**Humanizer — отдельная задача редактирования целевого текста.** `humanizer-ru` работает с русской прозой, `slop-humanizer` — с английской. Их правила не превращают рабочий голос coding-агента в постоянное художественное переписывание. Очистка дизайна и исходного кода относится к отдельным пакетам.

**Стоимость**: лёгкая | **Стабильность**: стабильная | **Версия**: 2.0.0 | **Категория**: качество

**Клиенты**: штатные пути для Claude Code, Codex и OMP; переносимый вариант через явно выбранный файл стартовых инструкций другого агента.

## Команды

| Команда | Что делает |
|---|---|
| `/slop-audit <file-or-paste>` | Аудит прозы без правок. Определяет RU/EN, для русского пытается запустить сканер; английская оценка эвристическая. |
| `/slop-humanize <file-or-paste>` | Переписывает целевой текст, сохраняя факты, числа, даты, имена и ссылки. Не записывает результат обратно в файл без запроса пользователя. Необязательный тон: `casual` или `professional`. |

## Агенты

| Агент | Что делает |
|---|---|
| `slop-cop` | Проверяет прозу по запросу, отмечает конкретные находки; не должен молча переписывать текст. |

## Скиллы

- `slopocop` — коммуникация агента на RU/EN, без обязательного брендированного префикса ответа.
- `humanizer-ru` — 54 паттерна, HARD BANS, сохранение фактов и русский сканер 0–100.
- `slop-humanizer` — английская проза: языковые и структурные признаки AI-слопа, без отдельного детерминированного сканера.

Поставляются **2 файла команд, 1 агент и 3 навыка**. Обнаруживаемый клиентом навык сам по себе не означает постоянное включение коммуникационного слоя.

## Установка

Выберите **один** способ автоматической загрузки. Не объединяйте нативные хуки с дублирующим глобальным блоком инструкций.

### Claude Code

```text
/plugin marketplace add ForgePlan/marketplace
/plugin install slopocop@ForgePlan-marketplace
```

Для нативных хуков нужны POSIX и Python >=3.9 во время работы, только стандартная библиотека. Слой загружается в следующей сессии, если клиент выполняет хуки плагина. Состояние адаптера хранится в `~/.local/state/slopocop/claude-code/state.json`; ошибка хука не подтверждает включение.

### Codex

```text
codex plugin marketplace add ForgePlan/marketplace
codex plugin add slopocop@ForgePlan-marketplace
```

Просмотрите и разрешите хуки через Codex `/hooks`, затем начните новую сессию. Одна установка без доверия к хукам не включает автозагрузку. Имя `ForgePlan-marketplace` регистрозависимо; каталог OMP с именем `forgeplan-marketplace` — другой путь установки.

Адаптер использует `hooks/codex-hooks.json` и отдельное состояние `~/.local/state/slopocop/codex/state.json`. Нужны POSIX и Python >=3.9 во время работы. Если клиент не предоставляет нужные события или доверие к хукам, используйте стартовые инструкции, не обходите механизм доверия.

### OMP

```bash
omp plugin marketplace add ForgePlan/marketplace
omp plugin install slopocop@forgeplan-marketplace
```

Пакет объявляет расширение `omp/slopocop.mjs`, которое загружает тот же коммуникационный слой без ручного вызова навыка. Оно не делает аудит или сетевой вызов. Новые сессии по умолчанию включены; ON/OFF относится к активной ветке сессии OMP, а не к личным настройкам.

**API расширения не подтверждает долговечную запись на диск.** Наличие имени файла сессии не даёт оснований сообщать «настройка сохранена». `--no-extensions` или отключённое расширение предотвращают нативную загрузку. Для OMP 18.11.1 одного `--plugin-dir` недостаточно, чтобы загрузить entrypoint расширения; для локального пакета используйте `omp plugin link` или явно переданный `--extension` согласно исходной инструкции.

### Любой агент со стартовыми инструкциями

После получения файлов плагина укажите путь к нему и файл, который ваш агент действительно загружает:

```bash
SLOPOCOP_PLUGIN=/path/to/installed/slopocop
python3 "$SLOPOCOP_PLUGIN/scripts/activate.py" install --instructions ./AGENTS.md
python3 "$SLOPOCOP_PLUGIN/scripts/activate.py" check --instructions ./AGENTS.md
```

`/path/to/installed/slopocop` замените фактическим путём. `AGENTS.md` — пример, не автоматически найденная цель: можно явно выбрать `CLAUDE.md`, `GEMINI.md` или другой поддерживаемый клиентом Markdown-файл. Учитывайте более приоритетный `AGENTS.override.md`, если клиент его использует.

Установщику нужны POSIX и Python >=3.9 только на этапе установки. Он сохраняет остальное содержимое и права файла, создаёт резервную копию существующего файла в `.slopocop-backups/` и отказывается перезаписывать изменённый управляемый блок или связанные файлы. После установки начните новую беседу. Во время её работы Python и обнаружение навыков уже не нужны, но клиент должен действительно читать выбранный файл.

После обновления плагина повторите `install`; `check` обнаруживает устаревший блок. Для отключения этого способа в будущих беседах:

```bash
python3 "$SLOPOCOP_PLUGIN/scripts/activate.py" uninstall --instructions ./AGENTS.md
```

Удаляется только управляемый блок. Этот способ не реализует нативное хранилище режима: разговорная команда отключает слой в текущей беседе, но не редактирует файл стартовых инструкций.

## Режим беседы и сохранённый режим

| Запрос | Область действия |
|---|---|
| `Отключи Slopocop` / `Turn off Slopocop` | Текущая беседа; в OMP — активная ветка сессии. |
| `Включи Slopocop` / `Enable Slopocop` | Та же область, не обещание изменения будущих сессий. |
| `Отключи постоянное включение Slopocop` / `Disable Slopocop always-on` | Дефолт новых бесед в нативных Claude/Codex hook-адаптерах. |
| `Включи Slopocop всегда` / `Enable Slopocop always` | Дефолт новых бесед в тех же адаптерах. |

Сессионные исключения Claude/Codex сохраняются при смене дефолта. Цитаты и данные задачи не считаются командами переключения. Команды изменения дефолта не являются API сохранения для OMP или способа со стартовыми инструкциями. Без подтверждения доверенного адаптера можно подтвердить только применение режима в беседе, не запись настройки на диск.

При ручной загрузке навыка явно задайте область: «Загрузи slopocop и применяй к ответам, вопросам и сообщениям о ходе работы до моего отключения; документы оставляй в запрошенном стиле». Это не включает будущие сессии автоматически.

## Хуки

В Claude Code `hooks/hooks.json` регистрирует **3 события**:

| Событие | Matcher и назначение |
|---|---|
| `SessionStart` | `^(startup\|resume\|clear\|compact\|fork)$`: загрузка/восстановление ядра коммуникации через Python-адаптер. |
| `UserPromptSubmit` | Обработка явных команд режима тем же адаптером; обычные запросы не меняют сохранённый режим. |
| `PostToolUse` | `Write\|Edit\|MultiEdit`: `slop-hint.sh` может выдать подсказку об аудите прозы. |

В Codex отдельный `hooks/codex-hooks.json` регистрирует **`SessionStart` и `UserPromptSubmit`**, без `PostToolUse`. В OMP используется расширение, а не исполнение Claude-hook JSON.

`PostToolUse` — **рекомендательная подсказка после записи, не fail-closed гейт и не автоматический запуск `slop-cop`**. Скрипт лишь печатает предложение вызвать `/slop-audit` или `/slop-humanize`, если получил подходящий путь; типовые README/CHANGELOG/LICENSE и код пропускаются. Регистрация событий не доказывает, что клиент разрешил хуки, выполнил их или сохранил режим.

## Сканер прозы и модели

Русскому `skills/humanizer-ru/scripts/scan.py` нужны дополнительные пакеты `razdel` и `pymorphy3`; без них остаётся аудит по каталогу, без машинных метрик. Для английского отдельного сканера нет: оценка 0–100 эвристическая. Ни одна оценка не проверяет достоверность фактов вместо автора.

`slop-cop` требует уровня **B**; `model: sonnet` — привязка Claude Code. В OMP, OpenCode, Codex и Gemini CLI сопоставьте уровень с моделью своей конфигурации, при сомнении — выше. Коммуникационное ядро переносимо, но выбор модели, доверие к хукам и поддержка расширений остаются обязанностью клиента.

## Обновление до 2.0.0

Публичный навык называется `slopocop`, entrypoint OMP — `omp/slopocop.mjs`; старые публичные имена не являются алиасами. Claude/Codex адаптеры однократно импортируют проверенные данные режима до 2.0 только при отсутствии нового состояния, сохраняя OFF и явные сессионные исключения. Явный `--state-dir` изолирован от этой миграции.

Для стартовых инструкций повторите `install --instructions FILE`: установщик заменяет один целый проверенный старый блок, а не дублирует его. Изменённый или неоднозначный блок отклоняется; личные инструкции не мигрируются неявно.
