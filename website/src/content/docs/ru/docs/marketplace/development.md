Руководство соответствует публичному маркетплейсу на [коммите `b4e8a1b`](https://github.com/ForgePlan/marketplace/tree/b4e8a1b9bfaa4c9c44e6f8dc1039e09fa1b193f7), каталог **1.187.1**. Работайте в клоне [ForgePlan/marketplace](https://github.com/ForgePlan/marketplace); пути ниже указаны относительно его корня. Плагин не входит в релиз CLI ядра Forgeplan.

## Структура плагина

```text
plugins/my-plugin/
├── .claude-plugin/plugin.json    # name, version, description
├── commands/                     # Необязательные файлы команд Claude Code
│   └── my-command.md             # YAML: name, description
├── agents/                       # Необязательные определения субагентов Claude Code
│   └── my-agent.md               # YAML: name, description, model, color
├── skills/
│   └── my-skill/
│       ├── SKILL.md              # YAML: name, description; инструкции или роутер
│       └── sections/             # Необязательные тематические файлы и индексы
├── .agents/skills/               # Относительные ссылки для совместимости, не копии
│   └── my-skill -> ../../skills/my-skill
├── hooks/
│   └── hooks.json                # Необязательная автоматизация для конкретной среды
└── README.md
```

Добавляйте только нужные плагину компоненты. Обычную документацию храните вне `agents/`: среда исполнения считает Markdown в этом каталоге определениями агентов. Имя во фронтматтере должно совпадать с каталогом навыка или именем файла команды/агента. Описания с чувствительным для YAML текстом, например `: `, заключайте в кавычки.

Минимальный манифест плагина:

```json
{
  "name": "my-plugin",
  "version": "1.0.0",
  "description": "A focused description of the plugin.",
  "author": { "name": "Your Name" },
  "license": "MIT"
}
```

Claude Code находит стандартные каталоги компонентов; не добавляйте выдуманное поле регистрации `components`. Поля ForgePlan — `cost`, `stability`, `targets`, `requires` и `supersedes` — относятся к **записи каталога**, а не к манифесту плагина. Имена плагинов используют строчные латинские буквы, цифры, точки и дефисы, без разделителя в начале или конце, длиной не более 64 символов; OMP может отклонить каталог из-за некорректного имени.

### Команды, навыки и агенты

Файл команды и навык, вызываемый из чата, — разные ресурсы. Например, `fpl-skills` публикует 46 навыков и **ни одного** файла `commands/`, но Claude Code может предоставлять точки входа вроде `/fpl-skills:shape` через фронтматтер навыка. `disable-model-invocation: true` оставляет явный вызов, а не запрещает вызов из чата. Список из 29 файлов и имена для миграции приведены в [Справочнике команд](/ru/docs/marketplace/commands/).

Значения `model: opus|sonnet|haiku` в определении агента — привязки Claude Code, а не переносимые требования к модели. Следуйте [руководству по созданию агентов](https://github.com/ForgePlan/marketplace/blob/b4e8a1b9bfaa4c9c44e6f8dc1039e09fa1b193f7/plugins/fpl-skills/AGENT-AUTHORING-GUIDE.md) для выбора роли, границ изменений, описания и яруса модели. В другой среде нужны своя модель соответствующего яруса и собственное применение разрешений; копирование `disallowedTools` не создаёт там такую границу.

Claude Code [загружает файлы агентов в `agents/` рекурсивно](https://code.claude.com/docs/en/plugins/components#agents); явная регистрация стандартного каталога в манифесте не нужна. Имена подкаталогов входят в имя агента с учётом области видимости: опубликованный `forgeplan-brownfield-pack/agents/discover/discover.md` — это `forgeplan-brownfield-pack:discover:discover`. В подсчёт определений включайте вложенные файлы: в этой публичной поставке **97 агентов**, а не только 96 прямых файлов `agents/*.md`.

## Паттерн агентского RAG

Для большой базы знаний **агентский RAG** означает переход от небольшого роутера к нужным файлам вместо загрузки всего содержимого. Это способ организации контента, а не ограничение среды исполнения в 300 строк. Небольшой навык может хранить все инструкции в одном `SKILL.md`; многие навыки оркестрации значительно длиннее.

### Как это работает:

1. `SKILL.md` сопоставляет задачи с тематическими каталогами.
2. `sections/<topic>/_index.md` перечисляет файлы темы и их назначение.
3. Агент читает нужные файлы по мере необходимости.

```markdown
| Что нужно | С чего начать |
|---|---|
| Выбрать декомпозицию | sections/decomposition/_index.md |
| Сравнить альтернативы | sections/evaluation/_index.md |
```

Плагин `agentic-rag` рекомендует 30–50 строк на файл контента (максимум 70), 15–30 на индекс (максимум 40) и 60–100 на роутер (максимум 150). Это ограничения авторского паттерна, **а не универсальный размер или гарантия загрузки для всех навыков маркетплейса**. См. его [рекомендации по размеру файлов](https://github.com/ForgePlan/marketplace/blob/b4e8a1b9bfaa4c9c44e6f8dc1039e09fa1b193f7/plugins/agentic-rag/skills/agentic-rag/sections/structure/file-budget.md) и [плагин Forgeplan Workflow](/ru/docs/marketplace/forgeplan-workflow/) как пример другого, инструктивного навыка.

## Автономные навыки (npx)

Автономная установка распространяет **навыки**, а не команды, агентов или хуки плагина. Используйте реально опубликованный источник, например:

```bash
npx skills add ForgePlan/fpf -g
npx skills add ForgePlan/loux -g
```

Эти репозитории предоставляют `fpf-knowledge` и `ux-laws` соответственно. Общего правила «навыку `X` соответствует репозиторий `ForgePlan/X`» нет. Источник списка зеркал — [`scripts/standalone-mirrors.json`](https://github.com/ForgePlan/marketplace/blob/b4e8a1b9bfaa4c9c44e6f8dc1039e09fa1b193f7/scripts/standalone-mirrors.json); автономное зеркало есть не у каждого плагина или навыка. Для нового зеркала также нужно обновить процесс синхронизации и проверки зеркал в репозитории, а не придумывать адрес установки.

## Публикация на маркетплейсе

Выполняйте эти шаги в клоне маркетплейса, а не в проекте, использующем плагины:

1. Добавьте плагин в `plugins/my-plugin/` с манифестом, компонентами и README.
2. Зарегистрируйте его в `.claude-plugin/marketplace.json` → `plugins[]` с `"source": "./plugins/my-plugin"` и совпадающими именем, описанием и версией. Требования для установки и сведения о замещении объявляйте там. Изменяйте именованный профиль, только если плагин относится к этому набору.
3. При обновлении повысьте версию плагина в **обоих** манифестах. Также повысьте `metadata.version` каталога: это ключ кеша обновлений маркетплейса.
4. Пересоздайте каталог OMP и ссылки для обнаружения навыков:

   ```bash
   node scripts/gen-omp-catalog.js
   node scripts/gen-interop-skills.js
   ```

   Включите полученный `.omp-plugin/marketplace.json` и относительные ссылки `.agents/skills/` в тот же коммит, что и исходное изменение. Имя маркетплейса в каталоге OMP записано строчными буквами; это не отдельно поддерживаемый реестр. Если созданию ссылки мешает реальный каталог, разберите конфликт вручную: генератор его не трогает.

5. Выполните проверки через интерфейсы ниже и отправьте PR по правилам [CONTRIBUTING.md](https://github.com/ForgePlan/marketplace/blob/b4e8a1b9bfaa4c9c44e6f8dc1039e09fa1b193f7/CONTRIBUTING.md). Локальная правка или открытый PR ещё не опубликованы: объединённые каталог и файлы плагина должны попасть в публичный маркетплейс.

### Команды проверки и их область действия

```bash
# Имя плагина, НЕ plugins/my-plugin и не путь к манифесту
./scripts/validate-all-plugins.sh my-plugin

# Также считать ошибками предупреждения о старом формате агентов
./scripts/validate-all-plugins.sh my-plugin --strict-agents

# Все плагины
./scripts/validate-all-plugins.sh

# Валидатор Claude Code принимает КАТАЛОГ плагина
claude plugin validate plugins/my-plugin/ --strict

# Для каталога маркетплейса передайте ФАЙЛ, без --strict
claude plugin validate .claude-plugin/marketplace.json
```

Валидатор репозитория принимает `[plugin-name] [--strict-agents]`. Аргумент плагина сужает проверки структуры и формата агентов, но **не изолирует весь запуск**. Проверки конфликтов команд, общие проверки CI, обёртка валидатора среды исполнения и все наборы `plugins/*/tests/test-*.sh` по-прежнему выполняются. Это не быстрая проверка одного плагина.

Скрипту нужны Bash, Python 3 с PyYAML для проверки агентов, Node.js для проверок CI и зависимости наборов тестов плагинов. Если `claude` отсутствует, обёртка официального валидатора сообщает **SKIPPED**, а не успешное прохождение. Манифесты плагинов проверяются строго; каталог намеренно проверяется без строгого режима, поскольку содержит метаданные ForgePlan, неизвестные Claude Code. Проверки оценивают текущие файлы и не пересоздают устаревшие каталоги или ссылки. Читайте фактический вывод: наличие файла само по себе не доказывает, что он загружается.

## Хуки для конкретной среды и совместимость

Для автоматизации Claude Code используйте его схему `hooks/hooks.json`, `type: "command"` и пути от `${CLAUDE_PLUGIN_ROOT}`. Политика репозитория запрещает хуки `type: "prompt"`. Набор событий зависит от плагина: в публичной поставке встречаются `PreToolUse`, `PostToolUse`, `SessionStart`, `UserPromptSubmit`, `Stop` и `SessionEnd`; не считайте, что каждый плагин реализует все события.

Переносимое тело навыка не преобразует API среды. Публикуемые ссылки `plugins/<plugin>/.agents/skills/` позволяют обнаружить единое исходное тело навыка; они не регистрируют команды Claude, не переносят субагентов, разрешения инструментов, хуки или учётные данные MCP. В проекте-потребителе отдельный `scripts/cross-runtime.mjs` навыка `cross-runtime` сообщает о пробелах обнаружения и может создать ссылки проекта с `--fix`; он не заменяет регистрацию плагина при публикации и не настраивает автоматически все среды.

Большинство хуков остаются специфичными для Claude. `slopocop` **2.0.0** — явно реализованное исключение: хуки Claude, доверенные хуки Codex, расширение OMP и независимый от среды установщик стартовых инструкций. Его редакторские команды и агент-ревьюер всё ещё используют форматы Claude. Границы поддержки описаны в опубликованном [контракте совместимости CLI](https://github.com/ForgePlan/marketplace/blob/b4e8a1b9bfaa4c9c44e6f8dc1039e09fa1b193f7/docs/CROSS-CLI.md).

Для интеграции памяти `fpl-hsmem` **3.7.0** требует явного подключения проекта через `.hindsight.json` с полями `url`, `banks` и `defaultBank`; выбранные банки должны уже существовать на совместимом сервере Hindsight API (`>=0.10.2`, `<0.11.0`). Хуки по умолчанию выключены. Одни переменные окружения не заменяют конфигурацию проекта, а BankGate — защита клиента, не авторизация сервера. Используйте [fpl-hsmem](/ru/docs/marketplace/fpl-hsmem/), а не старые инструкции настройки только через окружение.

## Примеры плагинов

Используйте [forgeplan-workflow](/ru/docs/marketplace/forgeplan-workflow/) как пример команд, навыка, агента и хука; [fpl-skills](/ru/docs/marketplace/fpl-skills/) — точек входа через навыки; [slopocop](/ru/docs/marketplace/slopocop/) — явно поддерживаемых адаптеров сред. `dev-toolkit` остаётся опубликованным, но устарел; это не основной шаблон для нового плагина.

## Рекомендации по внесению вклада

См. [CONTRIBUTING.md](https://github.com/ForgePlan/marketplace/blob/b4e8a1b9bfaa4c9c44e6f8dc1039e09fa1b193f7/CONTRIBUTING.md) и исходные скрипты на зафиксированной публичной ревизии.

### Требования к PR:

- Корректные манифест плагина и фронтматтер компонентов, README с реальными инструкциями установки.
- Совпадающие версии плагина в манифесте и каталоге, повышенный `metadata.version` каталога при обновлении.
- Пересозданные каталог OMP и ссылки совместимости при изменении их источников.
- Вывод проверок, различающий успешное прохождение, ошибку и пропуск проверки среды исполнения.
- Отсутствие секретов, персональных путей и учётных данных; соблюдение модели разрешений и конфигурации каждой среды.
