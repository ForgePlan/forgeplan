Плагин подключает проект к серверу Hindsight для поиска решений, истории экспериментов и других знаний между сессиями. В версии 3.7.0 поставляются 28 MCP-инструментов, 10 навыков и агент `memory-curator`. Инструменты позволяют искать и просматривать записи, исправлять неверные факты через вывод из обращения и новую запись, а также проверять фоновые операции. Записанные в репозитории решения остаются первичным источником; память помогает найти их и восстановить контекст.

**Стоимость**: лёгкая | **Стабильность**: стабильный | **Версия**: 3.7.0 | **Категория**: память

**Цели**: claude-code

**Требует**: Node.js >=20, доступный сервер Hindsight API >=0.10.2 и <0.11.0 и проектный `.hindsight.json` с явными `url`, непустым списком `banks` и `defaultBank` из этого списка. URL по умолчанию нет. Все выбранные банки должны уже существовать на сервере: плагин их не создаёт. Без конфигурации сервер завершает MCP-рукопожатие, но не публикует инструменты; хуки ничего не делают.

Аутентификация зависит от сервера. Для локального сервера без аутентификации токен не нужен. Если сервер требует Bearer-токен, используйте существующий `tokenFile` внутри каталога с конфигурацией и исключите его из git либо `tokenCommand` с отдельным разрешением `HINDSIGHT_ALLOW_TOKEN_COMMAND=1`. Переменная `HINDSIGHT_API_KEY` учитывается только вместе с `HINDSIGHT_URL`; переменные окружения сами по себе не включают плагин. Старый `HINDSIGHT_BANK_ID` игнорируется.

Минимальная конфигурация для локального сервера без аутентификации; банк `team` нужно заранее создать на сервере:

```json
{
  "url": "http://127.0.0.1:8888",
  "banks": ["team"],
  "defaultBank": "team",
  "autoRecall": false,
  "autoRetain": false
}
```

Без `allowTools`/`denyTools` активная конфигурация открывает все 28 инструментов, в том числе изменяющие данные. Для первого подключения можно ограничить `allowTools`, например до `["memory_get_current_bank", "memory_status", "memory_recall"]`.

Большинство инструментов принимают необязательный `bank`; без него используется `defaultBank`. Исключения: `memory_get_current_bank` и пакетный планировщик `memory_retain_batch`. Межбанкового поиска нет. Проверка BankGate ограничивает вызовы этого клиента, но не заменяет авторизацию сервера и не защищает от других клиентов.

## Агенты

| Агент | Что делает |
|---|---|
| `memory-curator` | Помогает выбрать инструмент чтения, диагностировать память и исправить неверный факт. Удаление документов и изменение конфигурации банка не входят в его разрешения. |

## Навыки

- `audit-bank` - Аудит банка только для чтения в шесть вызовов, заканчивающийся письменным вердиктом, а не числом.
- `bootstrap` - Однократное заполнение банка для проекта, который только что был активирован: установить персону банка, проиндексировать формальные артефакты, которые уже существуют, и создать небольшой стартовый набор страниц знаний.
- `correct-memory` - Рабочий процесс, который делает банк исправляемым вместо накопительного: найти точную сохранённую строку, вывести её из обращения с указанной причиной, записать исправление полностью, перестроить убеждения, которые на ней основывались, и проверить, что фоновая задача завершилась.
- `diagnose` - Полная диагностика, когда память не делает то, что должна: сервер доступен, банк разрешён как задумано, хуки действительно срабатывают, конфиг не переопределён где-то, где вы забыли, и задачи завершаются.
- `directives` - Постоянные правила, которым банк следует при синтезе ответа - приоритет между конфликтующими решениями, что ответ всегда должен называть, что оставлять за бортом.
- `enrich` - Выделяет из источников короткие записи со ссылками, сохраняет локальный JSONL и готовит план через `memory_retain_batch` без записи в банк. Применение выполняет отдельно уполномоченный оператор через CLI; digest подтверждает свежесть плана, а не право записи.
- `export-bank` - Читаемый markdown-снимок банка для резервного копирования, аудита или передачи контекста человеку.
- `memory-setup` - Посмотреть на проект и предложить слои извлечения и памяти, которые он должен иметь - что установить, на какие вопросы отвечает каждый слой и на какие он никогда не ответит.
- `mental-model` - Управляемое создание живой страницы знаний - постоянного ответа на повторяющийся вопрос, перестраиваемого из воспоминаний после каждой консолидации.
- `status` - Тридцатисекундное чтение одного банка памяти: какой банк, кто его выбрал, сколько в нём хранится и не сломано ли что-то молча.

## Хуки

В `hooks/hooks.json` зарегистрированы события Claude Code:

| Событие | Действие при включённой настройке |
|---|---|
| `UserPromptSubmit` | Поиск в `defaultBank` и добавление контекста при `autoRecall: true`. |
| `Stop` | Сохранение транскрипта с учётом порога частоты при `autoRetain: true`. |
| `SessionEnd` | Сохранение транскрипта при завершении сессии, если `autoRetain: true`. |

Обе настройки по умолчанию выключены. Конфигурация, полученная с репозиторием, сама по себе не означает согласия на автоматическое чтение или сохранение транскриптов. Это регистрация хуков в Claude Code, а не универсальная автоактивация в других средах. Прямое подключение MCP в Codex или OMP не устанавливает навыки и хуки.
