Плагин содержит 46 навыков, шаблоны и руководство по созданию агентов для работы с Forgeplan. Семейство `smith` помогает выбрать методологию по 14 контекстам, другие навыки ведут исследование, реализацию, аудит и проверку качества. Это инструкции для агента и оркестратора, а не новые встроенные команды CLI. Плагин заменяет устаревший `dev-toolkit`.

**Стоимость**: тяжёлый | **Стабильность**: стабильный | **Версия**: 1.75.1 | **Категория**: developer-tools

**Целевые платформы**: claude-code

**Требует**: `forgeplan` в `PATH`. Для вызова агента `smith` нужен также плагин `agents-pro`: его определение не входит в `fpl-skills`. Интеграции с памятью, трекерами и дополнительные специалисты требуют отдельного подключения; `/fpl-init` не устанавливает плагины-спутники.

## Агенты

| Агент | Что делает |
|---|---|
| `dev-advisor` | Предлагает аудит, тесты и другие подходящие шаги разработки; рекомендации не означают, что проверки уже выполнены. |

## Навыки

- `agent-advisor` - Рекомендует правильного канонического агента (или набор агентов) для описанной инженерной задачи.
- `agent-fetcher` - Предлагает агентов и навыки из других маркетплейсов, но не устанавливает их автоматически.
- `audit` - Мультиэкспертный аудит кода, архитектуры или завершённой функции - минимум 4 параллельных агента-ревьюера, каждый со специализацией (логика, архитектура/SOLID, типизация, безопасность; опционально тесты, бэкенд-паттерны, фронтенд, завершённость задачи).
- `autorun` - Выполняет согласованный цикл исследования, реализации, аудита и отчёта без промежуточных точек одобрения; требует явно заданных границ работы.
- `bootstrap` - Создаёт `CLAUDE.md` по шаблону и каталог руководств с учётом стека проекта.
- `briefing` - Утренний брифинг по задачам и сообщениям - собирает просроченные, на сегодня, @упоминания, непрочитанные чаты и статистику проекта из любого доступного трекера задач (Orchestra MCP, Linear MCP, Jira MCP, GitHub Issues) или из локальных TODO-файлов.
- `build` - Выполняет готовый `IMPLEMENTATION-PLAN.md`: читает фазы, владение файлами и критерии приёмки, распределяет работу и проверяет результат доступными средствами проекта.
- `c4-diagram` - Интерактивный генератор C4-диаграмм архитектуры.
- `conformance-vectors` - Помогает подготовить необязательный замороженный корпус примеров поведения с закреплённым хешем, проверки для каждого языка и сравнение результатов реализаций.
- `cross-runtime` - Помогает подключить навыки и команды проекта к другим установленным средам. Перенос инструкций не означает переноса механизмов разрешений, хуков и автоматического вызова.
- `ddd-decompose` - Навык декомпозиции Domain-Driven Design через интервью.
- `decay-watch` - Проверяет условия пересмотра активных ADR и сообщает о сработавших триггерах.
- `decision` - Записывает рутинное решение как короткий ADR из шести разделов.
- `diagnose` - Дисциплинированный цикл диагностики для сложных багов и регрессий производительности.
- `discover-product` - Проводит интервью о продукте по JTBD, Lean Startup или Double Diamond и связывает выводы с артефактами Forgeplan.
- `do` - Классифицирует задачу, составляет план из подходящих навыков и выполняет его с точками согласования.
- `estimate` - Оценивает сложность и риск именованного артефакта через `forgeplan estimate`, объясняет уверенность оценки и сопоставляет её с текущим R_eff.
- `forge-cleanup` - Разбирает черновики и аномалии, распределяет действия по уровням AUTO/ADI/USER. Пакетная активация готовых Evidence требует подтверждения; неоднозначные случаи требуют разбора или решения пользователя.
- `forge-heal` - Предлагает действия по уже найденным проблемам. По умолчанию ждёт подтверждения; молчаливое применение возможно только при отдельном разрешении для указанных обратимых действий.
- `forge-insight` - Собирает сводку аномалий Forgeplan и ведёт учёт находок для последующего разбора.
- `forge-report` - Структурированные форматы отчётов для Claude - на основе карточек, читаемые человеком, без ASCII-шума рамок.
- `forgeplan-cookbook` - Справочник выбора CLI/MCP-инструмента по задаче. Поставляемый текст описывает Forgeplan 0.32.1; параметры для 0.38.0 сверяйте с текущим `--help` и схемой MCP, а не со старыми числами в навыке.
- `fpl-init` - Готовит проект к работе с Forgeplan: инициализация workspace, подключение MCP и настройка инструкций проекта после согласования плана.
- `gate-check` - Читает глубину и пороги качества, проверяет артефакт через `validate`, `score` и F-G-R, а `gaps` и `blindspots` выводит как рекомендации по всему workspace. Возвращает PASS/FAIL вызывающему оркестратору; сам артефакт не активирует.
- `gh-project` - Проект-агностическая интеграция с GitHub Projects v2.
- `incident` - Ведёт активный инцидент через аварийную фазу и последующий разбор без поиска виноватых: post-mortem, запись проблемы, план исправлений и проверка закрытия инцидента.
- `methodology-check` - Проверяет, какие требования четырёх слоёв процесса выполнены для артефакта: FPF, BMAD, OpenSpec и автоматизация Forgeplan.
- `migrate-from-dev-toolkit` - Предлагает и выполняет согласованную миграцию настроек и ссылок с `dev-toolkit` на `fpl-skills`, сохраняя резервные копии.
- `progress-dashboard` - Показывает снимок текущего состояния проекта без отдельной системы событий.
- `project-agent-scaffold` - Готовит определение агента для конкретного проекта с учётом обнаруженного стека.
- `refine` - Уточнение плана, дизайна или предложения через интервью.
- `research` - Исследует тему несколькими агентами: исходники, проектные решения, состояние работ, внешние примеры и доступная долговременная память.
- `restore` - Восстанавливает контекст по Git и рабочей копии; при наличии подключённой памяти читает предыдущие решения.
- `rfc` - Создаёт, читает и обновляет RFC и другие проектные документы через MCP, затем CLI, а при отсутствии обоих предлагает обычный Markdown.
- `riper` - Проводит сложную диагностику и исправление через Research → Innovate → Plan → Execute → Review. Для продолжающегося пользовательского сбоя предназначен `incident`.
- `setup` - Интерактивный визард, который настраивает CC-templates для текущего проекта.
- `shape` - Навык интервью с нуля, который превращает сырую идею в структурированный черновик PRD.
- `smith` - Мастер-оркестратор, точка входа.
- `smith-bootstrap` - Выполняет начальную настройку нового проекта через оркестратора: проверяет предпосылки, подключает инструменты, создаёт структуру и первые Brief/PRD. Останавливается на обязательных проверках и запросах согласования.
- `smith-plan` - Готовит план для конкретной задачи и рекомендует последовательность агентов. Сам эту последовательность не выполняет.
- `smith-routing` - Объясняет выбор методологии по таблице контекстов.
- `spec-author` - Готовит SPEC с проверяемым поведением и фиксирует согласованную спецификацию перед реализацией.
- `sprint` - Выполняет задачу волнами после согласования плана, закрепляет файлы за исполнителями и записывает Evidence по затронутым артефактам. Активация собранных Evidence согласуется отдельно.
- `supersede` - Заменяет ADR с фиксацией изменений требований и связей с предыдущим решением.
- `team` - Описывает создание команд и отдельных субагентов, роли координатора и исполнителей, владение файлами и завершение командной работы.
- `wrap` - Закрывает цикл forgeplan на стадии `wrap`.

Отдельных файлов команд в `commands/` у этой версии нет. Записи вида `/research` и `/smith-plan` обозначают вызов навыков через поддерживающую их среду, а не подкоманды `forgeplan`.

## Хуки

`hooks/hooks.json` регистрирует в Claude Code:

- `SessionStart`: подсказки по началу работы, сброс счётчика отчёта, напоминания о пересмотре решений и состоянии конвейера.
- `PreToolUse` с `Bash`: проверку опасных команд.
- `PostToolUse` с `Write|Edit|MultiEdit`: напоминания о тестах; отдельный обработчик учитывает вызовы для отчёта.
- `UserPromptSubmit`: маршрутизационную подсказку по запросу.

Регистрация относится к Claude Code. Она не гарантирует автоматический вызов навыка или агента и не переносит хуки и ограничения инструментов в другие среды.
