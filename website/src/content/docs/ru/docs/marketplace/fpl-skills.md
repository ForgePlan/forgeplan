Флагманский плагин рабочего процесса экосистемы ForgePlan - навыки, шаблоны и контракт авторства, на которых построен весь остальной маркетплейс: роутер методологии smith (14 контекстов), руководство по созданию агентов, которому следует каждый forgeplan-aware агент, и навыки гейтов, очистки и инсайтов, которые поддерживают честность конвейера. Используйте, когда вам нужна сама методология, а не один специалист - решение, как подойти к задаче, гейтинг артефакта перед активацией или создание нового агента по каноническим правилам. Полная история в CHANGELOG.md.

**Стоимость**: тяжёлый | **Стабильность**: стабильный | **Версия**: 1.75.1 | **Категория**: developer-tools

**Целевые платформы**: claude-code

**Требует**: CLI: forgeplan

## Агенты

| Агент | Что делает |
|---|---|
| `dev-advisor` | Проактивный советник по разработке, который отслеживает ваш рабочий процесс и предлагает лучшие практики. |

## Навыки

- `agent-advisor` - Рекомендует правильного канонического агента (или набор агентов) для описанной инженерной задачи.
- `agent-fetcher` - Методология: Кросс-маркетплейс предложение агентов/навыков (только предложение, БЕЗ автоустановки).
- `audit` - Мультиэкспертный аудит кода, архитектуры или завершённой функции - минимум 4 параллельных агента-ревьюера, каждый со специализацией (логика, архитектура/SOLID, типизация, безопасность; опционально тесты, бэкенд-паттерны, фронтенд, завершённость задачи).
- `autorun` - Автономный оркестратор для выполнения по зелёному свету / в ночное время.
- `bootstrap` - Разворачивает стартовый скаффолд Claude Code автора в новый или существующий проект - создаёт CLAUDE.md из шаблона, папку guides/ с руководствами автора (Git Flow, лучшие практики CLAUDE.md) и guides/INDEX.md.
- `briefing` - Утренний брифинг по задачам и сообщениям - собирает просроченные, на сегодня, @упоминания, непрочитанные чаты и статистику проекта из любого доступного трекера задач (Orchestra MCP, Linear MCP, Jira MCP, GitHub Issues) или из локальных TODO-файлов.
- `build` - Запускает команду реализации из готового исследовательского отчёта - читает IMPLEMENTATION-PLAN.md (фазы, владение файлами, критерии приёмки) и SUMMARY с ADR, порождает тиммейтов по фазам (последовательно или параллельно) и верифицирует результат через build/typecheck/tests.
- `c4-diagram` - Интерактивный генератор C4-диаграмм архитектуры.
- `conformance-vectors` - ОПЦИОНАЛЬНОЕ обогащение `## Conformance Vectors` для spec-driven разработки (ADR-008): замороженный, хеш-закреплённый, языково-нейтральный корпус конформности, который является ЕДИНСТВЕННЫМ поведенческим оракулом для реализации, плюс хранесс для каждого языка и гейт кросс-языковой эквивалентности.
- `cross-runtime` - Подключает навыки и команды Claude Code этого проекта во все другие AI-рантаймы, установленные на машине - Codex, OpenCode, OMP и любые agents.md клиенты.
- `ddd-decompose` - Навык декомпозиции Domain-Driven Design через интервью.
- `decay-watch` - Сканирует все активные ADR-артефакты на сработавшие Revisit Triggers (Evidence Decay).
- `decision` - Быстрый путь для записи рутинного решения как лёгкого ADR (200-400 слов, 6-секционная DDR-форма).
- `diagnose` - Дисциплинированный цикл диагностики для сложных багов и регрессий производительности.
- `discover-product` - Навык product-discovery через интервью, который соединяет JTBD / Lean Startup / Double Diamond discovery с графом артефактов forgeplan (ADR-023 D2, строка 10 routing-map).
- `do` - Мета-оркестратор - принимает задачу на естественном языке, классифицирует её (research / docs / feature / review / bug / refactor / status), строит конвейер из других навыков (research → write-doc → wave-sprint → audit), показывает план и выполняет с чекпоинтами одобрения.
- `estimate` - Оценивает усилия и риск для именованного артефакта на стадии `estimate` канонического конвейера: запускает forgeplan estimate для сложности и часов по грейду на элемент, сообщает цифру уверенности с причинами, и связывает число с текущим снимком R_eff, чтобы оценка читалась вместе с тем, сколько реально известно.
- `forge-cleanup` - Методология: 3-уровневое самовосстановление конвейера (классификация AUTO / ADI / USER по PRD-032 Sprint D; расширена 4 видами аномалий в Sprint F PRD-034 + 1 вид аномалии в Sprint M PRD-039 = 9 всего).
- `forge-heal` - Методология: Цикл heal-or-task уровня 4 (PRD-074 brick 2 / RFC-020) - propose-not-silent 3-уровневая диспетчеризация (AUTO / ADI / USER по PRD-032) Finding[], которые уже обнаружили /forge-insight + insight-watchdog.
- `forge-insight` - Методология: слой инсайтов над обнаружением аномалий forgeplan (PRD-074 Layer 2 + don't-forget ledger; RFC-019 brick 1).
- `forge-report` - Структурированные форматы отчётов для Claude - на основе карточек, читаемые человеком, без ASCII-шума рамок.
- `forgeplan-cookbook` - Живой справочник по 66 MCP-инструментам mcp__forgeplan__* и 82 подкомандам CLI forgeplan, поставляемым в forgeplan 0.32.1.
- `fpl-init` - Одна команда для бутстрапа проекта в экосистеме ForgePlan.
- `gate-check` - Запускает гейт качества между стадиями конвейера для именованного артефакта: читает глубину, загружает пороги из .forgeplan/quality-gates.yaml (с откатом на поставляемый шаблон), выполняет validate + score + fgr для артефакта, запускает gaps + blindspots как workspace-рекомендации и возвращает PASS или FAIL с именованными проваленными проверками и конкретным фиксом для каждой.
- `gh-project` - Проект-агностическая интеграция с GitHub Projects v2.
- `incident` - Проводит живой инцидент от начала до конца в две фазы (ADR-024 wave 2, smith строка 12): Фаза 1 - пожар, цепочка Incident Command System с приостановленными методологическими накладными расходами, хотфикс под авторитетом ICS, smoke перед ship; Фаза 2 - blameless post-mortem, PROBLEM-артефакт из шаблона post-mortem, post-incident PRD и гейт цикла incident_close.
- `methodology-check` - Для любого ID артефакта сообщает, какие из 4 слоёв конвейера EPIC-001 (S10 FPF design, S11 BMAD quality gate, S12 OpenSpec structure, S13 Forgeplan automation) удовлетворены, а какие требуют работы.
- `migrate-from-dev-toolkit` - Одна команда для миграции с dev-toolkit на fpl-skills.
- `progress-dashboard` - Методология: Рендерер живого состояния (read-only снимок, без новой системы событий).
- `project-agent-scaffold` - Методология: Генерация агента с областью видимости проекта через обнаружение tech-stack.
- `refine` - Уточнение плана, дизайна или предложения через интервью.
- `research` - Глубокое мультиагентное исследование темы - параллельные scout-агенты покрывают исходный код, design docs/RFCs, TODO/status файлы, референсные реализации, персистентную память.
- `restore` - Восстанавливает контекст рабочей сессии - собирает свежую информацию о текущей ветке, недавних коммитах, незакоммиченных изменениях, стешах и (если доступно) решениях из системы памяти.
- `rfc` - Создаёт, читает и обновляет RFCs (Request for Comments) / design docs - структурированные документы для архитектурных решений через **MCP-first** путь (`mcp__forgeplan__forgeplan_new` + `forgeplan_update` + `forgeplan_link` + `forgeplan_validate`) с откатом на CLI, когда MCP не подключён, или plain markdown, когда недоступно ни то, ни другое.
- `riper` - Оркестратор методологии RIPER - Research → Innovate → Plan → Execute → Review - ЧЕТВЁРТЫЙ экземпляр контракта AD/AID-PDLC sub-cycle (ADR-010 / RFC-018).
- `setup` - Интерактивный визард, который настраивает CC-templates для текущего проекта.
- `shape` - Навык интервью с нуля, который превращает сырую идею в структурированный черновик PRD.
- `smith` - Мастер-оркестратор, точка входа.
- `smith-bootstrap` - Навык онбординга greenfield-проекта.
- `smith-plan` - Навык планирования задач.
- `smith-routing` - Образовательный навык роутинга.
- `spec-author` - Создаёт forgeplan SPEC в spec-driven LIGHT конвейере (OpenSpec/SpecKit-стиль на SPEC kind) - итерирует до "идеального", затем замораживает для реализации.
- `sprint` - Wave-based выполнение функции/задачи мультиагентной командой - research → wave plan (5-8 агентов в 2-5 волнах) → одобрение → порождение тиммейтов волна за волной через TeamCreate.
- `supersede` - Проводит полный рабочий процесс supersede-ADR с обязательной дисциплиной OpenSpec delta-spec.
- `team` - Фундаментальный навык для запуска мультиагентных команд - TeamCreate vs параллельные Task() (суб-агенты), роли team-lead vs teammate, владение файлами, динамическое порождение новых агентов для дополнительной работы, очистка.
- `wrap` - Закрывает цикл forgeplan на стадии `wrap`.
