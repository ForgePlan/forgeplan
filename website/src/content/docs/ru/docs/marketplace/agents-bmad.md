Методология BMAD для greenfield-проектов: мастер-оркестратор проходит по дуге персон - Аналитик, PM, Архитектор, Scrum-Master, Dev, QA - как отдельные изолированные контексты, с блокирующим гейтом качества между каждой персоной и fail-closed хуком no-code-before-plan. Используется при создании нового продукта или сервиса с нуля; не для одной фичи в существующей системе (это SPARC) и не для модернизации легаси (это Strangler Fig). Полная история в CHANGELOG.md.

**Стоимость**: лёгкая | **Стабильность**: beta | **Версия**: 0.6.0 | **Категория**: workflow

**Целевые платформы**: claude-code

**Требования**: Ничего, кроме Claude Code

## Агенты

| Агент | Что делает |
|---|---|
| `bmad-orchestrator` | Мастер-оркестратор для конвейера BMAD greenfield. |

## Навыки

- `bmad` - Точка входа для конвейера BMAD greenfield - координируемый мастером проход по персонам от сырой идеи до отгруженной, проверенной QA фичи (Аналитик → PM → Архитектор → Scrum-Master → Dev → QA), ВТОРАЯ инстанция контракта подцикла AD/AID-PDLC (ADR-010 / RFC-013).
- `bmad-init` - Однократная настройка проекта для конвейера BMAD - генерирует языковую привязку `.forgeplan/bmad/stack.json`, которую читает хук `bmad-gate.sh` (команда тестирования, глобы тестовых/исходных файлов, маркер провала утверждений, команда линтинга), и инициализирует файл состояния для каждой ветки.

## Установка

```bash
/plugin marketplace add ForgePlan/marketplace
/plugin install agents-bmad@ForgePlan-marketplace
```
