## Что такое CLAUDE.md?

`CLAUDE.md` - это память проекта Claude Code, файл в корневом каталоге вашего репозитория, который сообщает Claude о вашем проекте, соглашениях и рабочих процессах. Claude читает его при каждом запуске сессии.

## Рекомендуемая структура CLAUDE.md

Используйте этот план, адаптируя команды и правила к репозиторию. Сами
разделы не устанавливают хуки, MCP-серверы или память:

```markdown
# CLAUDE.md

## Быстрый старт
- Настройка среды разработки
- Ключевые команды
- Где что найти

## Методология (Forgeplan)
- Route → Shape → Validate → Code → Evidence → Activate
- Таблица калибровки глубины
- Поток создания артефактов

## Рабочий процесс Git
- Стратегия ветвления (main ← dev ← feat/*)
- Формат коммитов (conventional commits + Refs)
- Конвейер PR: Code → Audit → Fix → Test → PR

## Хуки проверок
- Пути установленных хуков и их реальные trigger/matcher
- Что проверяет каждый хук, какие есть обходы и неподдерживаемые операции
- Команды тестирования и форматирования проекта

## Память (Hindsight)
- Явный .hindsight.json: url, banks, defaultBank
- Сначала memory_get_current_bank и memory_status
- Поиск существующих знаний; запись включается отдельно с разрешением

## Жесткие требования
- Правила для конкретного языка
- Архитектурные ограничения
- Стандарты тестирования
```

## Раздел Forgeplan

Добавьте это в CLAUDE.md любого проекта для интеграции Forgeplan:

```markdown
## Forgeplan

### Начало сессии
forgeplan health   # слепые пятна, сироты (артефакт без связей) - исправить В ПЕРВУЮ ОЧЕРЕДЬ

### Перед любой задачей
forgeplan route "task description"   # определяет глубину

### Полный цикл (Standard+)
1. forgeplan new prd "Title"         # создать артефакт
2. Заполнить MUST-разделы через forgeplan update --body @file
3. forgeplan validate PRD-XXX        # проверки структуры и содержимого
4. forgeplan reason PRD-XXX --save   # нужна LLM; сохранить Note с ADI
5. Реализовать и протестировать согласованный объём
6. Независимое ревью + реальные доказательства; задать verdict/congruence/type
7. forgeplan link EVID-XXX PRD-XXX --relation informs
8. forgeplan score PRD-XXX           # разобрать самое слабое текущее доказательство
9. forgeplan review PRD-XXX
10. forgeplan activate PRD-XXX       # главный оркестратор, не автор

### Тактическая глубина
Артефакт планирования не нужен; правила кода, ревью и тестов проекта действуют.
```

`reason` требует настроенного провайдера LLM и аутентификации; установка
`/forge` их не обеспечивает. Базовым операциям с артефактами и валидации LLM
не нужна. Контекст корпуса FPF в CLI запрашивается через `--fpf`; публичная
обвязка требует FPF/ADI для Standard+. Настройка провайдера — в
[Конфигурации](/ru/docs/getting-started/configuration/).

### Выбор процесса и разделение ролей

`forgeplan setup-skill` записывает только встроенный навык `/forge` для
Claude Code. Полный набор плагинов описан в
[Установке](/ru/docs/getting-started/installation/#полный-harness-комплект-claude-code).
Для публичных процессов:

| Процесс | Контекст и условие входа |
|---|---|
| `/bmad` (`agents-bmad`) | Новый продукт/сервис от идеи до поставки; перед первым циклом `/bmad-init` |
| `/sparc` (`agents-sparc`) | Одна ограниченная фича в существующей активной системе; отдельного хука инициализации SPARC нет |
| `/tdd` (`agents-tdd`) | Реализация при активных PRD и SPEC с блоками `#### Scenario`; сначала `/tdd-init` |

Bootstrap использует `agents-sparc:specification` для первого PRD, но это
не делает конвейер SPARC процессом для greenfield.

| Профиль | Ответственность |
|---|---|
| A | Создать черновик артефакта; не активировать свою работу |
| B / B-gate | Независимое ревью и доказательства / вердикт готовности guardian |
| C | Исследование без записи |
| C-coder | Изменение исходников, но не артефактов Forgeplan |
| D | Поддержка существующих метаданных и связей с использованием нужных команд жизненного цикла |

Генератор и верификатор работают в разных контекстах. Уровень модели
верификатора не должен быть ниже уровня генератора. `opus`/`sonnet`/`haiku`
в frontmatter — привязки Claude Code, а не переносимая гарантия модели.
Другим средам нужны собственные соответствия уровней и ограничения;
denylist Claude Code не становится серверной авторизацией. После ревью
активирует главный оркестратор; автор и guardian не активируют свой результат.

## Хуки принудительного исполнения

Публичный `fpl-skills` содержит хуки плагина и опциональные шаблоны
локальных хуков в `templates/hooks/`:

| Шаблон | Что проверяет |
|---|---|
| `safety-hook.sh` | Отдельные разрушительные шаблоны команд git/rm |
| `pre-pr-evidence-check.sh` | Связанные доказательства для ID из ветки/коммитов перед `gh pr create`; есть задокументированные исключения и обход |
| `forge-safety-hook.sh` | Отдельные разрушительные операции CLI Forgeplan |

`/smith-bootstrap` предлагает с разрешения пользователя скопировать шаблоны
в пустой `.claude/hooks/` и объединить настройки. `setup-skill` их не
устанавливает. Эти проверки по шаблонам — дополнительный защитный слой,
а не универсальная песочница, запуск всех тестов или доказательство готовности.

### Настройка хуков

После размещения опубликованного шаблона `safety-hook.sh` в
`.claude/hooks/safety-hook.sh` зарегистрируйте его объектом command-hook.
Объедините запись с существующими настройками, не заменяя остальные хуки:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "bash .claude/hooks/safety-hook.sh"
          }
        ]
      }
    ]
  }
}
```

Git-хуки от `forgeplan setup` — другие: `post-merge` и `post-checkout`
вызывают `git-sync` для обновления производного индекса. Они не устанавливают
эти хуки Claude и не пересчитывают эмбеддинги.

## Конфигурация MCP сервера

Из каталога проекта лучше выполнить:

```bash
forgeplan mcp install --client claude --scope project
```

Команда записывает абсолютный путь найденного бинарника и сохраняет другие
серверы и `env`. При ручной настройке убедитесь, что MCP-клиент находит
`forgeplan` через свой PATH:

```json
{
  "mcpServers": {
    "forgeplan": {
      "command": "forgeplan",
      "args": ["serve"]
    }
  }
}
```

Опубликованный stdio-сервер 0.38.0 предоставляет 73 инструмента.
Перезапустите клиента и убедитесь, что `forgeplan_health` читает нужный
workspace. Project scope сам по себе не закрепляет рабочий каталог сервера.
Пути и границы workspace — в [Настройке MCP](/ru/docs/guides/mcp-setup/).

## Интеграция памяти (Hindsight)

Hindsight — отдельный опциональный плагин и сервис, а не часть 73 инструментов
Forgeplan. Публичный `fpl-hsmem` 3.7.0 требует Hindsight API **>=0.10.2 и
<0.11.0** и явный `.hindsight.json` проекта с `url`, `banks` и `defaultBank`.
Выбранный банк должен уже существовать на сервере. Неявного URL и банка,
вычисленного из имени каталога, нет.

Начните с политики пилота плагина только для чтения: вызовите
`memory_get_current_bank`, затем `memory_status`. Для поиска фактов используйте
`memory_recall`. Ручное сохранение, reflection, bootstrap и автоматические
хуки — отдельные решения о записи/автоматизации, а не предпосылки Forgeplan.
`autoRecall` и `autoRetain` по умолчанию выключены. Allowlist BankGate —
клиентская защита, а не серверная авторизация. Не коммитьте учётные данные.

## Рекомендуемые разрешения

Используйте узкую политику проекта. Пример разрешает только просмотр;
он не одобряет заранее все операции `forgeplan`, пакетных менеджеров или git:

```json
{
  "permissions": {
    "allow": [
      "Bash(forgeplan --version)",
      "Bash(forgeplan health)",
      "Bash(git status:*)",
      "Bash(git diff:*)",
      "Bash(git log:*)",
      "Read",
      "Glob",
      "Grep"
    ],
    "deny": [
      "Bash(git push --force*)",
      "Bash(rm -rf /*)",
      "Bash(cargo publish*)"
    ]
  }
}
```

## Настройка нескольких проектов

Для монорепозитория или настройки с несколькими проектами каждая поддиректория может иметь свой собственный CLAUDE.md:

```
project/
├── CLAUDE.md          ← корневая конфигурация (git, методология)
├── packages/
│   ├── core/
│   │   └── CLAUDE.md  ← правила для конкретного пакета
│   └── web/
│       └── CLAUDE.md  ← правила для фронтенда
└── .claude/
    ├── hooks/         ← общие хуки
    └── settings.json  ← разрешения
```

## Лучшие практики

1.  **Держите CLAUDE.md менее 500 строк** - Claude читает его каждую сессию. Слишком длинный = потерянный контекст.
2.  **Размещайте детали в docs/, а не в CLAUDE.md** - ссылайтесь на `docs/guides/X.md` для глубокого контента.
3.  **Обновляйте после решений** - новая конвенция? Немедленно добавьте ее в CLAUDE.md.
4.  **Хуки для конкретных проверок** — фиксируйте matcher и ограничения; ни инструкции, ни хуки по шаблонам не дают универсальной границы безопасности.
5.  **Здоровье Forgeplan в первую очередь** - всегда начинайте сессию с `forgeplan health`, чтобы выявить слепые пятна.
