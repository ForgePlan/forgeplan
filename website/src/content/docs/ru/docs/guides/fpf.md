## Что такое FPF?

First Principles Framework (FPF) - это «Операционная система для мышления» - трансдисциплинарная архитектура для рассуждений. Она превращает необработанный интеллект (человеческий или машинный) в пригодные для использования в организации рассуждения.

Forgeplan 0.38 предоставляет CLI базы знаний `forgeplan fpf`. Команда `/fpf` —
отдельный плагин публичного маркетплейса (`fpf` 1.7.1), который исполняет
ИИ-среда, например Claude Code. Установка CLI сама по себе не устанавливает плагин.

## Режимы рассуждения

### /fpf decompose - Декомпозиция

Когда у вас есть сложная система и вам нужно понять её части.

```
/fpf decompose our authentication system
```

Вывод:
- Таблица: Контекст | Ответственность | Ключевые роли | Интерфейсы
- Диаграмма Mermaid с границами и связями
- Проверка на ошибку категории (роль против функции?)

**Когда использовать:** Начало новой функции, понимание существующей системы, планирование архитектуры.

### /fpf evaluate - Сравнение вариантов

Когда вам нужно выбрать между альтернативами с оценкой доказательств.

```
/fpf evaluate React vs Vue vs Svelte for our SPA
```

Вывод:
- Сильные стороны, слабые стороны, доказательства, отсутствующие доказательства для каждого варианта
- Баллы F-G-R: Формальность (0-3), Гранулярность (0-3), Надёжность (0-3)
- Матрица решений с рекомендацией
- Цикл ADI: гипотезы → предсказания → проверка доказательств

**Когда использовать:** Выбор технологии, архитектурные решения, анализ компромиссов.

### /fpf reason - Продумать

Когда вам нужно понять, почему что-то произошло, или как подойти к проблеме.

```
/fpf reason why our API response times degraded
```

Вывод:
- **Абдукция**: 3+ гипотезы
- **Дедукция**: Проверяемые предсказания для каждой гипотезы
- **Индукция**: Проверка по имеющимся доказательствам
- Оценённые гипотезы: подтверждены / ослаблены / опровергнуты
- Заключение с оставшимися неопределённостями

**Когда использовать:** Отладка, реагирование на инциденты, анализ проблем, обоснование архитектуры.

### /fpf lookup — Объяснение понятия

```text
/fpf lookup bounded context
```

Плагин читает нужный раздел спецификации и объясняет понятие, его применение,
связанные понятия и практический пример. Если среда может читать установленный
навык, для этого не требуется импортировать базу знаний в CLI.

## База знаний FPF

CLI ищет по **предварительно загруженному локальному корпусу**; полная
спецификация не встроена в исполняемый файл. Выполняйте команды внутри
инициализированного рабочего пространства. Установите плагин FPF или получите
его каталог `skills/fpf-knowledge/sections`.

```bash
# Путь по умолчанию: ~/.claude/skills/fpf-knowledge/sections (затем старые имена)
forgeplan fpf ingest

# Для кэша marketplace-плагина или другого места укажите реальный путь:
forgeplan fpf ingest --path /absolute/path/to/fpf/skills/fpf-knowledge/sections

forgeplan fpf status
forgeplan fpf list
forgeplan fpf search "bounded context" --limit 5
forgeplan fpf search "trust assurance" --semantic --limit 5
forgeplan fpf section B.3
forgeplan fpf rules
forgeplan fpf check PRD-001
```

Выполните **одну** команду ingest с вашим реальным путём. Импорт заменяет
существующий корпус FPF рабочего пространства. Опубликованные бинарные файлы
0.38 включают семантическую поддержку: импорт кодирует разделы и может загрузить
**модель BGE-M3 объёмом ~2.1 ГБ**. Для операции нужны сеть, место на диске и время.
Сборка из исходников без `semantic-search` импортирует разделы только для
поиска по словам.

`fpf search` по умолчанию ищет по словам. При `--semantic` отсутствие функции
или ошибка модели/векторного поиска приводит к предупреждению и переходу
к поиску по словам. Проверьте предупреждения и заголовок семантического
режима, прежде чем считать результат векторным. Этот переход не означает,
что `fpf ingest` выполнится без доступного корпуса или модели.

Чтобы добавить подходящие разделы в ADI:

```bash
forgeplan reason PRD-001 --fpf
```

`reason` требует настроенного провайдера LLM. HTTP-провайдеры читают ключ
из переменной окружения, указанной в `llm.api_key_env`; поддерживаемые локальные
CLI-провайдеры используют существующий вход и подключаются явно для личной
разработки, а не общей среды/CI. Без провайдера команда возвращает ошибку,
**а не** локальный шаблон рассуждения. Для `--fpf` нужны импортированные
подходящие разделы; без них команда сообщает, что контекст FPF не добавлен.

## Ключевые концепции FPF

| Концепция | Что это значит |
|---------|--------------|
| **Ограниченный контекст** | Часть системы с чёткими границами и собственным словарём |
| **Trust Calculus** | Оценка уверенности: насколько вы можете доверять утверждению? |
| **F-G-R** | Формальность × Гранулярность × Надёжность - измерения качества |
| **Цикл ADI** | Абдукция → Дедукция → Индукция - структурированный цикл рассуждений |
| **Ошибка категории** | Путаница роли и функции, метода и работы |
| **Гамма-алгебра** | Как части объединяются в целое, сохраняя свойства |

Шкала F-G-R плагина от 0 до 3 не совпадает с числовой оценкой артефакта в CLI.
`forgeplan fgr ID` вычисляет F/G/R по шкалам 0–1 и объединяет их средним
геометрическим. Ни одна из оценок не проверяет истинность утверждений модели.

## Установка

В Claude Code:

```text
/plugin marketplace add ForgePlan/marketplace
/plugin install fpf@ForgePlan-marketplace
```

Команды CLI доступны независимо. Установка плагина не импортирует корпус
автоматически в каждое рабочее пространство; передайте реальный каталог
разделов в `fpf ingest --path`, если он не находится в каталоге навыка по умолчанию.

Полный каталог и инструкции по установке см. в
[Обзоре Marketplace](/ru/docs/marketplace/overview/).

:::tip
FPF наиболее эффективен в сочетании с системой артефактов Forgeplan. Используйте `/fpf decompose` для планирования, затем `forgeplan new prd` для сохранения результата в виде структурированного артефакта.
:::
