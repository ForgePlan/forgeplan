Оценивает трудозатраты (в часах) для артефакта путем анализа его чекбоксов функциональных требований и этапов реализации, затем применяя профиль с несколькими грейдами (Junior / Middle / Senior / Principal / AI). Возвращает разбивку по грейдам с оценкой достоверности, опционально используя оценку сложности на основе LLM или ручные переопределения.

**Категория**: Качество

## Когда агент вызывает её

-   **Планирование спринта** - получить часы для каждого PRD / RFC до фиксации объема работ.
-   **Сопоставление грейдов** - посмотреть, сколько часов занимает задача для вашего собственного грейда с помощью `my_grade`.
- **Планы с помощью ИИ** — выделить часы AI, рассчитанные по множителям типа задачи с накладными расходами на ревью, а не универсальному ускорению.
-   **Цикл обратной связи для калибровки** - сравнить фактические и оценочные значения после спринта, чтобы настроить профиль.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `complexity` | `string \| null` | нет | Ручные оценки сложности: `"FR-001=5,FR-002=3"`. По умолчанию в схеме: `null`. |
| `grade` | `string \| null` | нет | Уровень исполнителя для всех элементов. string: Значения enum: `"junior"`, `"middle"`, `"senior"`, `"principal"`, `"ai"`. |
| `id` | `string` | да | ID артефакта для оценки трудозатрат. |
| `llm_score` | `boolean \| null` | нет | Оценивать сложность с помощью LLM вместо эвристик на основе правил. По умолчанию в схеме: `null`. |
| `my_grade` | `boolean \| null` | нет | Определить уровень исполнителя из `grade_profile` с учётом предметной области артефакта. По умолчанию в схеме: `null`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в текстовом содержимом MCP. Верхний уровень: `artifact_id`, `artifact_title`, `items`, `totals` (грейд → число часов), `total_score`, `confidence`, `confidence_reasons`, необязательный непустой `hints` и `_next_action`. Полей `by_grade`, `breakdown`, `total_items` нет.

Элемент содержит `id`, `description`, `complexity` (имя enum, например `"Medium"`, а не число Фибоначчи), `task_type` (например `"pure_coding"`), `hours` (грейд → часы) и `score`. Уверенность одна для всей оценки, а не по грейдам. Подсказки содержат `level`, `message` и необязательное `action`.

`grade` лишь добавляет `highlighted_grade`; вычисляются все грейды. Без явного `grade` параметр `my_grade: true` добавляет `highlighted_grade` и `inferred_domain` из настроенного профиля. Ручная сложность принимает `1,2,3,5,8,13` и имеет приоритет над эвристиками/LLM; неверный формат даёт ошибку MCP, ID без совпадения не действует.

`llm_score` по умолчанию false. Без конфигурации LLM или при сбое провайдера используются эвристики; ответ не подтверждает, что LLM выполнялась. Отсутствие FR/Phase даёт успешную пустую оценку (`items: []`, `totals: {}`, score/confidence равны нулю), без выделения грейда. Инструмент не сохраняет оценку и не настраивает профиль автоматически; отсутствующий артефакт возвращает ошибку MCP.

Условный фрагмент элемента Medium для pure coding с множителями по умолчанию:

```json
{
  "id": "FR-001",
  "description": "Implement the parser",
  "complexity": "Medium",
  "task_type": "pure_coding",
  "hours": {"junior": 16.0, "middle": 12.0, "senior": 8.0, "principal": 5.6, "ai": 1.04},
  "score": 24.0
}
```

Это модельные оценки, не измеренное время выполнения. Часы AI включают настроенные расходы на ревью; координационные задачи не получают множитель pure coding.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "id": "PRD-001",
  "grade": "senior"
}
```

## Типичная последовательность

1.  `forgeplan_estimate` с `my_grade: true` - получить личные часы.
2.  Сравнить с пропускной способностью спринта - при необходимости уменьшить объем работ.
3.  После спринта: внести фактические данные и оценки обратно в конфигурацию `grade_profile`.

## Эквивалент CLI

```bash
forgeplan estimate PRD-039 --my-grade
forgeplan estimate PRD-039 --grade ai
```
