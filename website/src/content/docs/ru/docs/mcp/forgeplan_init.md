Создаёт новое рабочее пространство в каталоге запуска MCP-сервера без интерактивных вопросов. Принимает только `force`: полей `scan` и `workspace` у этого инструмента нет. Если после клонирования уже есть отслеживаемые Markdown-файлы `.forgeplan/`, для пересборки производного индекса обычно нужен CLI [`forgeplan reindex`](/ru/docs/cli/reindex/), а не повторная инициализация.

**Категория**: Рабочее пространство и данные

## Когда агент вызывает эту команду

- При первой настройке проекта, в котором нет `.forgeplan/`.
- При создании нового проекта: init → new → заполнение артефакта → validate.
- При восстановлении в пустой проект из сохранённого экспорта, затем `forgeplan_import`.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `force` | `boolean \| null` | нет | Принудительная повторная инициализация, даже если рабочее пространство уже существует. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

`workspace` указывает каталог `.forgeplan/`, `message` описывает результат, `_next_action` предлагает следующий вызов. При существующем пространстве и `force` false или без значения возвращает «Already initialized», не пересобирая индекс.

`force: true` удаляет существующий `.forgeplan/`, найденный подъёмом от каталога запуска сервера, затем создаёт пространство в каталоге запуска. Поэтому удалить можно пространство предка, не только каталог внутри CWD. Уничтожаются артефакты, производный индекс и локальные данные. Заранее сохраните экспорт и конфигурацию отдельно; это не операция обновления индекса.

Инициализация создаёт каталоги артефактов с `.gitkeep`, `config.yaml`,
шаблон `secrets.env` и таблицы LanceDB. Forgeplan не загружает `secrets.env`
автоматически. Этот MCP-обработчик не запускает CLI-onboarding, не импортирует
документы, не устанавливает навыки/агентов marketplace, не настраивает хост,
не скачивает модель эмбеддингов и не вызывает LLM. Установка дистрибутива
и настройка модели/провайдера для нуждающихся в них функций выполняются отдельно.
Успех — JSON в текстовом содержимом MCP (`workspace`, `message`, `_next_action`),
без `resolved_via` / `resolved_workspace`. Ошибки удаления, создания файлов и
LanceDB возвращаются на уровне JSON-RPC; при неудачной повторной инициализации
удалённый каталог не восстанавливается.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "force": false
}
```

## Типичная последовательность

Используйте `forgeplan_init` для нового пространства, затем `forgeplan_status` или `forgeplan_health` для просмотра. В существующем пространстве начинайте с этих инструментов чтения. Перед намеренно деструктивной повторной инициализацией получите согласие, сохраните JSON `forgeplan_export` и отдельно локальные файлы, не включённые в экспорт.

## Эквивалент CLI

- [`forgeplan init`](/ru/docs/cli/init/) — первая инициализация; `-y` / `--yes` выбирает неинтерактивные дефолты. **Force работает по-разному:** CLI `--force` сохраняет тела артефактов и делает автобэкап, если не указан `--no-backup`; MCP `force: true` удаляет пространство. Аналогов CLI `--scan` и `--with-model` здесь нет; один CLI `--yes` модель не скачивает.
