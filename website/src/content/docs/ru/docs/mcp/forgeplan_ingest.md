Планирование запуска инжеста (YAML-маппинг × исходный файл). Волна 3: только dry-run - возвращает черновики без записи артефактов. Установите `dry_run: false`, чтобы указать намерение записать, но поверхность MCP всё равно делегирует фактическую запись CLI `forgeplan ingest` (Волна 4 подключит artifact::Store). PRD-066 AC-1.

**Категория**: Прочее

Этот инструмент - **планировщик, а не исполнитель**. Он валидирует, что оба пути существуют, находятся внутри рабочего пространства и укладываются в бюджет размера, который сервер готов обработать. Затем он передаёт агенту точную командную строку `forgeplan ingest`, которая выполнит запуск. Ничего не записывается в `.forgeplan/`, даже при `dry_run: false`.

## Что он делает

1. **Канонизирует путь к маппингу.** Файл должен существовать, быть обычным файлом и разрешаться под разрешённым корнем: корнем рабочего пространства (родителем `.forgeplan/`) или деревом `~/.claude/plugins/`, куда пакеты плагинов устанавливают свои бандлы. Побеги через симлинки разрешаются перед проверкой, поэтому безобидный на вид относительный путь не может указывать наружу.
2. **Канонизирует путь к источнику** по тем же правилам.
3. **Проверяет бюджет размера.** Маппинг отклоняется при превышении 1 МиБ, источник - при превышении 10 МиБ. Проверка читает только метаданные файла - сервер никогда не загружает ни один из файлов в память здесь.
4. **Эхо плана.** Ответ повторяет оба пути (редактированные до относительных от рабочего пространства, где возможно), оба флага и `wave3_status: "planned"` с пустыми списками `drafts`, `skipped` и `errors`.
5. **Подсказывает реальную команду.** `_next_action` содержит готовую к вставке строку `forgeplan ingest --mapping ... --source ...`, с добавленными `--dry-run` и/или `--update` в соответствии с переданными флагами.

Поскольку шаг 3 - единственное, что касается файлов, маппинг, нарушающий схему SPEC-004, **проходит** валидацию MCP и отклоняется только CLI:

```text
# MCP: принимает и возвращает план
{ "wave3_status": "planned", "mapping": "bad.yaml", ... }

# CLI: отказывается выполнять
Error: invalid mapping YAML: source_kind: unknown variant `markdown`, expected one of
`c4-documentation`, `autoresearch`, `git-log`, `ddd-model`, `sparc-spec` at line 2 column 14
Fix: edit bad.yaml to match SPEC-004 schema
```

## Когда агент вызывает это

- **Предварительная проверка маппинга** перед тратой запуска CLI: раннее обнаружение неверного пути или слишком большого источника.
- **Dry-run планируемого инжеста** и показ пользователю, какое правило сработает, без касания хранилища артефактов.
- **Вопрос "какой будет эта команда?"** - подсказанная командная строка и есть ответ, и её безопасно передать человеку.
- **Проверка ограничения рабочим пространством** - отказ сигнализирует, что путь, данный агенту, находится вне проекта.

## Входные параметры

| Имя | Тип | Обязательный | Описание |
|---|---|---|---|
| `mapping` | `string` (путь) | да | Путь к YAML-маппингу, описывающему трансформацию (схема SPEC-004). Должен быть существующим обычным файлом внутри разрешённого корня. По соглашению они находятся в `.forgeplan/mappings/`. |
| `source` | `string` (путь) | да | Путь к файлу, который потребляет маппинг. Должен быть существующим обычным файлом - **директория отклоняется**, хотя CLI принимает её. |
| `dry_run` | `boolean` | нет (по умолчанию: `true`) | Только планирование. Эхом возвращается в ответе и добавляется к подсказанной команде. Поверхность MCP никогда не пишет в любом случае. |
| `update` | `boolean` | нет (по умолчанию: `false`) | Разрешить обновление существующих артефактов при идемпотентном повторном инжесте. Эхом возвращается и добавляется к подсказанной команде. |
| `workspace` | `string` | нет | Явная директория рабочего пространства. Когда установлена, сервер разрешает `.forgeplan/` от этого пути вместо своего стартового CWD. PRD-078 / ADR-015. |

_Источник схемы: `crates/forgeplan-mcp/src/types.rs::IngestParams`_

## Возвращает

```json
{
  "_next_action": "forgeplan ingest --mapping map.yaml --source docs/comp.md --dry-run",
  "drafts": [],
  "dry_run": true,
  "errors": [],
  "mapping": "map.yaml",
  "skipped": [],
  "source": "docs/comp.md",
  "update": false,
  "wave3_note": "Wave 3 MCP surface validates inputs only; full ingest execution available via the `forgeplan ingest` CLI. Wave 4 will wire IngestEngine + artifact::Store directly.",
  "wave3_status": "planned"
}
```

`drafts`, `skipped` и `errors` всегда пусты на этой поверхности - это поля, которые заполнит исполнитель Волны 4. Рассматривайте непустой `_next_action` как результат вызова.

## Отказы

Каждый отказ - это ошибка инструмента, текст которой содержит причину плюс строку `_next_action:`:

| Отказ | Сообщение | Подсказка |
|---|---|---|
| Маппинг отсутствует или вне рабочего пространства | `mapping file not found or outside workspace` | Проверьте путь к маппингу. Маппинги SPEC-004 по соглашению находятся в `.forgeplan/mappings/*.yaml`. |
| Источник отсутствует, вне рабочего пространства или является директорией | `source path not found or outside workspace` | Проверьте, что путь к источнику существует под рабочим пространством. |
| Маппинг превышает 1 МиБ | `mapping exceeds 1048576-byte size limit` | Обрежьте маппинг или разделите на несколько файлов SPEC-004. |
| Источник превышает 10 МиБ | `source exceeds 10485760-byte size limit` | Разделите исходный файл перед инжестом. |

Отказы по путям намеренно общие: сервер никогда не эхом возвращает абсолютный путь клиенту, поэтому проба не может быть использована для картирования файловой системы хоста.

## Примеры

Планирование запуска с настройками по умолчанию (`dry_run` true, `update` false):

```json
{ "mapping": "map.yaml", "source": "docs/comp.md" }
```

Указание намерения записать и разрешить обновления - подсказка получает `--update` и теряет `--dry-run`:

```json
{ "mapping": "map.yaml", "source": "docs/comp.md", "dry_run": false, "update": true }
```

```json
{
  "_next_action": "forgeplan ingest --mapping map.yaml --source docs/comp.md --update",
  "dry_run": false,
  "update": true,
  "wave3_status": "planned"
}
```

Указание на директорию вместо файла:

```json
{ "mapping": "map.yaml", "source": "docs" }
```

```text
source path not found or outside workspace

_next_action: Verify the source path exists under the workspace.
```

## Примечания

- Инструмент аннотирован как read-only, неразрушающий и идемпотентный. Повторные вызовы не влияют на рабочее пространство.
- Оба пути редактируются до формы относительно рабочего пространства, когда они находятся под CWD сервера, и экранируются в подсказке, чтобы путь с пробелом всё равно вставлялся чисто.
- Лимиты размера существуют, чтобы предотвратить исчерпание сервера враждебным маппингом или источником: они проверяются перед любым чтением, поэтому файл сверх размера отклоняется, а не обрезается.

## Эквивалент в CLI

- [`forgeplan ingest`](/ru/docs/cli/ingest/) - реальный исполнитель. Те же флаги `--mapping` / `--source` плюс `--dry-run`, `--update` и `--json`, и это единственный путь, который парсит маппинг и пишет артефакты.
