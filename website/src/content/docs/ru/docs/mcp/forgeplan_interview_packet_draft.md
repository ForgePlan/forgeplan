**Этот инструмент - экспериментальная заглушка.** Он зарегистрирован на поверхности MCP, его схема параметров
финальна, и пока он ничего не делает: реальная реализация поставляется с плагином
[`forgeplan-brownfield-pack`](/ru/docs/marketplace/forgeplan-brownfield-pack/) (marketplace
issue #79). Вызов сегодня возвращает конверт `not_implemented`, чтобы агент мог обнаружить пробел и
показать подсказку об установке вместо молчаливого получения пустого ответа.

Не стройте рабочий процесс, зависящий от возврата пакета. Рассматривайте это как проверку возможности и
фиксированный контракт для будущей реализации.

**Категория**: Прочее

## Что он делает сегодня

Ровно следующее:

1. Разрешает рабочее пространство через путь записи, что также валидирует существование рабочего пространства
   и выдаёт ту же ошибку "нет рабочего пространства", что и все остальные инструменты.
2. Захватывает блокировку рабочего пространства.
3. Возвращает конверт-заглушку с внедрённой трассировкой разрешённого рабочего пространства и добавленной подсказкой `_next_action`:

```json
{
  "_next_action": "Fix: install plugin — see marketplace issue #79 (`forgeplan-brownfield-pack`).",
  "marketplace_issue": 79,
  "message": "Install forgeplan-brownfield-pack plugin to enable; or invoke via shell pipeline temporarily.",
  "resolved_via": "param",
  "resolved_workspace": "/private/tmp/agent-enrichmcpf/.forgeplan",
  "status": "not_implemented"
}
```

Он не читает артефакты, не записывает артефакты и не генерирует вопросы.

## Что он будет делать

Навык `interview-packager` плагина группирует отложенные гипотезы и открытые вопросы в
структурированные пакеты интервью для Domain Owner - документ, на который отвечает человек, чтобы агент мог преобразовать
выведенные утверждения в проверенные или опровергнутые. Параметры ниже существуют для управления этим пакетом:
`domain` ограничивает генерацию вопросов, `seed_ids` задаёт повестку из артефактов, которые уже есть в рабочем пространстве.

Схема зафиксирована сейчас, до реализации, чтобы агенты, принимающие brownfield-рабочий процесс,
не переучивались при появлении плагина. Поэтому поля документированы как принимаемые, хотя заглушка их не читает.

## Входные параметры

| Имя | Тип | Обязательный | Описание |
|---|---|---|---|
| `domain` | `string` | нет | Целевой домен или функциональная область, которую должен охватывать пакет. Используется плагином для ограничения генерации вопросов. Заглушкой не читается. |
| `seed_ids` | `string[]` | нет | Существующие идентификаторы артефактов (HYP / UC / INV), которые задают повестку интервью. По умолчанию пустой список, что означает "обнаружить с нуля". Заглушкой не читается. |
| `workspace` | `string` | нет | Явный каталог рабочего пространства для этого вызова, чтобы агент в git worktree мог обратиться к своему `.forgeplan/` вместо каталога запуска сервера. Абсолютный путь или с тильдой. Читается заглушкой. |

_Источник схемы: `crates/forgeplan-mcp/src/server.rs::InterviewPacketDraftParams`_

## Пример вызова

Как будет выглядеть реальный вызов:

```json
{
  "domain": "billing",
  "seed_ids": ["HYP-001", "HYP-004"]
}
```

Что сегодня возвращает конверт `not_implemented` выше, с `"marketplace_issue": 79`.

## Примечания

- **Схема - это контракт, а не подсказка.** Имена полей и опциональность зафиксированы замороженной wire-схемой,
  поэтому интеграция, написанная по этой странице, продолжит работать, когда заглушка будет заменена реальной реализацией.
- **Заглушка захватывает блокировку рабочего пространства**, хотя ничего не записывает. Это намеренное
  упреждение, чтобы реализация плагина унаследовала корректную блокировку, а не добавляла её позже.
- **Заглушка возвращает разрешённое рабочее пространство** (`resolved_via`, `resolved_workspace`). Мало инструментов делают
  это; здесь это самый дешёвый способ для агента доказать, в какое рабочее пространство был направлен вызов,
  прежде чем он зафиксируется на brownfield-сессии.
- **Схема MCP объявляет его идемпотентным и не read-only.** Повторные вызовы безвредны, и это не инструмент чтения в смысле аннотации.
- **Что использовать вместо этого сегодня:** протокол brownfield-обнаружения
  ([`forgeplan_discover_start`](/ru/docs/mcp/forgeplan_discover_start/)) - это живой путь для картирования существующей
  кодовой базы, и навыки плагина можно вызывать напрямую, как предлагает сообщение конверта.
