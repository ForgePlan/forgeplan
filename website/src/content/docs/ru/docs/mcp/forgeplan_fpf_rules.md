Возвращает активный **набор правил FPF** - деревья условий, которые определяют рекомендации Forgeplan по действиям. Каждое правило имеет имя, приоритет, категорию действия (`EXPLORE` / `INVESTIGATE` / `EXPLOIT`), условие, которое оценивается по состоянию артефакта, и сообщение, объясняющее результирующее действие. Правила загружаются из `.forgeplan/config.yaml` (`fpf.rules`), если он присутствует, в противном случае - из встроенных значений по умолчанию (PRD-041).

**Категория**: База знаний FPF

## Когда агент вызывает это

- "Какие правила действуют в этом рабочем пространстве?" - агент хочет получить список перед отладкой неожиданного действия.
- "Покажи мне только правила EXPLORE" - сузить область просмотра при работе с артефактами с низким уровнем доверия.
- "Правило X из конфигурации или из значений по умолчанию?" - используйте `source`, чтобы определить, загружено ли пользовательское переопределение.
- "Дай мне однострочное резюме каждого правила" - передайте `summary: true`, чтобы пропустить полные деревья условий.

## Категории действий

Правила оцениваются по возрастанию приоритета; первое совпадение выигрывает. Встроенный набор:

| Приоритет / имя | Условие (должны выполняться все перечисленные проверки) | Действие |
|---|---|---|
| 1 / `blind-spot` | `status=draft`, `r_eff < 0.01` | EXPLORE |
| 2 / `weak-evidence` | `status` равен `active` или `stale`, `r_eff < 0.5` | INVESTIGATE |
| 3 / `orphan-active` | `status=active`, `link_count == 0` | EXPLORE |
| 4 / `medium-quality` | `r_eff` соответствует `0.5..0.7` | INVESTIGATE |
| 5 / `ready-to-build` | `r_eff >= 0.7`, `overall >= 0.6` | EXPLOIT |

Это рекомендации, а не разрешения на активацию. В этих правилах нет универсального разбиения на три интервала или автоматического повышения порогов по глубине. Непустой `fpf.rules` целиком заменяет встроенный набор; поведение пользовательских правил определяют возвращаемые деревья условий.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `action` | `string \| null` | нет | Фильтр по действию: `"EXPLORE"`, `"INVESTIGATE"` или `"EXPLOIT"`. Без фильтра возвращаются все категории. По умолчанию в схеме: `null`. |
| `name` | `string \| null` | нет | Получить одно правило по имени. Возвращает правило или ошибку, если оно не найдено. По умолчанию в схеме: `null`. |
| `source` | `string \| null` | нет | Фильтр по источнику: `"config"` или `"default"`. Для диагностики правил рабочего пространства. По умолчанию в схеме: `null`. |
| `summary` | `boolean \| null` | нет | При true возвращаются только `name`, `priority`, `action`, без подробностей условий. По умолчанию в схеме: `null`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Полный режим включает `name`, `priority`, `action`, сериализованное `condition`, его читаемое описание `condition_summary` и `message`, допускающее `null`. Поле `source` находится на верхнем уровне (`config` или `default`), а не внутри каждого правила. `count` — число правил после фильтрации. Оба режима добавляют `_next_action`.

Условный объект правила `blind-spot` полного режима (внутри `rules`; остальные поля ответа те же, что в режиме сводки):

```json
{
  "name": "blind-spot",
  "priority": 1,
  "action": "EXPLORE",
  "condition": {
    "status": "draft",
    "kind": null,
    "depth": null,
    "r_eff": "< 0.01",
    "overall": null,
    "link_count": null,
    "is_stale": null,
    "links_missing": null,
    "days_until_expiry": null
  },
  "condition_summary": "status=draft AND r_eff<0.01",
  "message": "Draft with no evidence (R_eff < 0.01). Needs evidence to validate."
}
```

Поля условий объединяются неявным AND. Числовые выражения сериализуются строками; массива `all` из узлов `{field,op,value}` нет.

Условный ответ в режиме сводки для `{"name":"blind-spot","summary":true}` со встроенными правилами:

```json
{
  "source": "default",
  "count": 1,
  "rules": [
    { "name": "blind-spot", "priority": 1, "action": "EXPLORE" }
  ],
  "_next_action": "Illustrative guidance to check an artifact."
}
```

Успешный ответ содержит JSON в текстовом содержимом MCP. Если точное `name` не найдено, возвращается JSON с `error: "rule not found"`, `name` и `available` (без флага ошибки MCP). Несовпавшие `action` или `source` обычно дают пустой массив. `source` и `action` сравниваются без учёта регистра, `name` — точно. Ограничения длины: 64 байта для `action`, 128 для `name`, 16 для `source`; превышение возвращает ошибку MCP с обычным текстом.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{}
```
