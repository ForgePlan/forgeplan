Превращает контекст свободного разговора в постоянный артефакт - либо `Note` (тактическое микро-решение), либо `ADR` (запись архитектурного решения) на основе автоматического определения. Агент вызывает это, когда понимает, что в чате только что было принято реальное решение, но никто его ещё не записал. Захват - это то, как Forgeplan восстанавливает «племенные знания», которые иначе были бы потеряны в истории чата.

**Категория**: Создание артефактов

## Когда агент вызывает это

- После обсуждения, в котором принято конкретное решение, ещё не записанное в артефактах.
- В конце сессии — сохранить решения с обоснованием, пока контекст доступен.

Требуется настроенный LLM-провайдер. Входного поля, принудительно задающего тип результата, нет.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `context` | `string \| null` | нет | Дополнительный контекст, необязателен. По умолчанию в схеме: `null`. |
| `decision` | `string` | да | Формулировка решения, которое нужно сохранить. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Поля `id`, `kind`, `title`, `filepath`, `auto_detected_type`, `provider`, `model`, `_next_action`. Артефакт создаётся черновиком: проверьте выбранный `kind`, прочитайте тело через `forgeplan_get`, затем валидируйте, связывайте или активируйте.

В ответе нет булева `auto_detected` и поля `path`. Во входе обязателен `decision`; `context` дополняет формулировку решения, не заменяет её.

Обработчик сохраняет `draft` с глубиной `tactical`: сначала пишет Markdown-проекцию, затем синхронизирует хранилище. Заголовок — первая строка `decision`, обрезанная до 80 символов. Тип определяется строкой `KIND:` в ответе LLM; неверный или отсутствующий выбор даёт `note`. Успешный ответ — JSON в текстовом содержимом MCP, без полей трассировки рабочего пространства в этом релизе. Сбой провайдера возвращает `isError` с текстом и подсказкой по настройке/входу; до успешной генерации артефакт не создаётся.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "decision": "Use PostgreSQL for transactional storage.",
  "context": "The service needs multi-row transactions."
}
```

## Типичная последовательность

Conversation → `forgeplan_capture` → `forgeplan_validate` (для ADR) → `forgeplan_link` (к любым связанным PRD/RFC) → `forgeplan_activate`. Захват часто используется в паре с `forgeplan_link relation=informs`, чтобы новая запись не оставалась сиротой (артефакт без связей).
