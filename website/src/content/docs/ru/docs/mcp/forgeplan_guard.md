title: forgeplan_guard
description: "Проверить переход фазы сессии методологии, не изменяя её и не записывая фазу артефакта."
---

Проверяет, разрешён ли переход **сессии методологии** к `target_session_phase` (`idle`, `routing`, `shaping`, `coding`, `evidence`, `pr`). Это проверка сохранённого состояния только для чтения: она не меняет сессию, не блокирует произвольное редактирование файлов и не записывает фазу артефакта. Для отдельного маркера фазы артефакта (`shape`…`done`) используйте [`forgeplan_phase_advance`](/ru/docs/mcp/forgeplan_phase_advance/).

**Категория**: Качество

## Когда агент вызывает его

- Перед работой над кодом или PR — проверить, допускает ли сессия следующий переход.
- Перед операцией, которую контролирует клиент или установленный хук. Сам вызов инструмента не устанавливает механизм блокировки.
- После отказа — прочитать, какое условие не выполнено.

Каноническое входное поле — `target_session_phase`. `target_phase` остаётся совместимым псевдонимом, но новым клиентам следует использовать имя из схемы.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `target_session_phase` | `string` | да | Целевая фаза **сессии методологии**: `idle`, `routing`, `shaping`, `coding`, `evidence`, `pr`. Не путать с фазой жизненного цикла артефакта (`shape`…`done`) в `forgeplan_phase_advance`. Старое имя `target_phase` принимается как совместимый псевдоним, но новым клиентам следует передавать `target_session_phase` (PROB-065). Значения enum: `"idle"`, `"routing"`, `"shaping"`, `"coding"`, `"evidence"`, `"pr"`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Поля `current_phase`, `target_phase`, `allowed`, `reason`, `next_action`, `_next_action`. В ответе имя `target_phase` сохранилось, хотя входное поле называется `target_session_phase`.

При `allowed: false` прочитайте причину и подсказку, выполните недостающее условие и проверьте снова. Вызов не переводит ни один из двух автоматов состояний.

Успешный ответ, включая `allowed: false`, — JSON в текстовом содержимом MCP, а не ошибка MCP. Проверка использует только сохранённую фазу и `route_depth`: не загружает результаты валидации артефакта, доказательства или ADI. Глубина tactical разрешает любые переходы; иначе разрешены та же фаза/сброс в idle, обычная последовательность и явные пропуски (`idle→shaping`, `idle→coding`, `shaping→evidence`, `coding→pr`). Даже `enforced: false` при незаданной глубине не означает, что разрешены все переходы.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "target_session_phase": "coding"
}
```

## Типичная последовательность

1. `forgeplan_session` — прочитать текущую фазу сессии.
2. `forgeplan_guard` с `target_session_phase` — проверить переход.
3. При отказе прочитать `reason` и `_next_action`.
4. После устранения причины повторить проверку.

## Эквивалент CLI

Отдельной CLI-команды для гарда нет - это совещательная проверка только на
MCP-поверхности. Доступны связанные CLI-операции:

```bash
forgeplan session           # фаза, в которой вы находитесь
forgeplan validate PRD-001  # отдельная валидация артефакта; guard её не выполняет
```
