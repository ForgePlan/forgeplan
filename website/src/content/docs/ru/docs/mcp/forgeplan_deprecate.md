---

Перемещает артефакт в конечное состояние `deprecated` (отменённый) без замены. В отличие от `supersede` (заместить), что подразумевает «используйте вместо этого новую вещь», `deprecate` (отменить) означает «мы больше этим не занимаемся». Обязательная `reason` (причина) сохраняется в артефакте и отображается при каждом последующем вызове `forgeplan_get`, чтобы будущие читатели понимали, почему он был выведен из эксплуатации.

**Категория**: Жизненный цикл

## Когда агент вызывает эту команду

- Вывод функции из эксплуатации: «мы убираем ограничение скорости из v3, отмените PRD-020».
- Отменённое направление: исследовательский PRD в `active` или `stale`, который оказался невыполнимым.
- Очистка в ходе устранения проблем `forgeplan_health`: просроченные артефакты, которые никто не будет продлевать.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `id` | `string` | да | ID артефакта для перевода в deprecated. |
| `reason` | `string` | да | Причина перевода в deprecated. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Подтверждение содержит `deprecated`, `reason`, `dependents_affected`, `receipt_id`, `resolved_workspace`, `resolved_via` и `_next_action`. `dependents_affected` перечисляет входящие ссылки, а не автоматически перенесённые артефакты или уведомления.

Причина вместе с датой добавляется в раздел тела `## Deprecation`, а не в новое поле frontmatter.

## Проверки и побочные эффекты

- Допустим только переход `active` или `stale` → `deprecated`. Черновик, уже отменённый или замещённый артефакт отклоняются; соответствия схеме недостаточно.
- Обработчик блокирует пространство, сохраняет запись восстановления до изменения и синхронизирует проекцию. Сбой записи отменяет вывод из использования. Более поздний отказ гейта может оставить неиспользованную запись; это не доказательство завершённого перехода.
- Успех меняет статус и добавляет причину. Перерисовка проекции, продвижение рекомендательной фазы в `done` и пересчёт зависимых оценок при вытеснении доказательства выполняются best-effort; сбой в журнале не обязательно приводит к ошибке вызова.
- Инструмент MCP не запрашивает подтверждение. Выводите из использования только согласованный пользователем или процессом артефакт и изучайте зависимости. Доступная запись позволяет восстановление, но оно само меняет состояние и имеет [ограничения 0.38.0](/ru/docs/mcp/forgeplan_restore/).

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "id": "PRD-001",
  "reason": "Feature cancelled; no replacement."
}
```

## Типичная последовательность

Прочитать цель через `forgeplan_get` или `forgeplan_list` → подтвердить вывод из использования → вызвать `forgeplan_deprecate` с `id` и `reason` → изучить зависимые артефакты → `forgeplan_health`. Для просроченного, но ещё верного решения CLI [`forgeplan renew`](/ru/docs/cli/renew/) продлевает срок; это не MCP-инструмент.
