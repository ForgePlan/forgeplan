Применяет изменения к телу и/или метаданным frontmatter существующего артефакта прямо в файле. Это путь прямого редактирования - агент использует его, чтобы заполнить только что созданную заглушку, переписать раздел после обратной связи от пользователя или переименовать артефакт. Для переходов жизненного цикла (draft → active → superseded) агент должен использовать специализированные инструменты `forgeplan_activate` / `forgeplan_supersede` / `forgeplan_deprecate` вместо этого - они обеспечивают гейты валидации.

**Категория**: Редактирование артефактов

## Когда агент вызывает это

- Сразу после `forgeplan_new` для заполнения ОБЯЗАТЕЛЬНЫХ разделов (Problem, Goals, Non-Goals, FR).
- Применение запрошенного пользователем изменения: "добавить раздел о наблюдаемости в RFC-007".
- Исправление обнаружения валидатора: `forgeplan_validate` сообщает об отсутствующем разделе, агент записывает его и повторно валидирует.

Хотя схема перечисляет все статусы жизненного цикла, обработчик допускает прямую запись только `draft`. Для `active`, `superseded`, `deprecated` нужны специализированные инструменты жизненного цикла. Кроме `id` необходимо передать хотя бы одно ненулевое значение `title`, `body` или `status`. Значение `body` заменяет всё тело, а не один раздел; пустая строка очищает его.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `body` | `string \| null` | нет | Новое содержимое тела. По умолчанию в схеме: `null`. |
| `id` | `string` | да | ID обновляемого артефакта. |
| `status` | `string \| null` | нет | Новый статус. Ограничения обработчика на переходы жизненного цикла описаны в разделе использования. string: Значения enum: `"draft"`, `"active"`, `"superseded"`, `"deprecated"`. |
| `title` | `string \| null` | нет | Новый заголовок. По умолчанию в схеме: `null`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ содержит `id` (разрешённый канонический ID), `message: "Updated successfully"`, итоговые `status` и `title`, `resolved_workspace`, `resolved_via` и `_next_action`. Это не полная запись артефакта; полей `ok`, `changed`, `updated_at` нет.

Если нужно итоговое тело или другие метаданные, прочитайте артефакт через `forgeplan_get`. Подсказки — текстовые рекомендации, а не готовый синтаксис аргументов MCP.

## Проверки и побочные эффекты

- Перед проверкой существования разрешаются ID и slug. Неизвестный артефакт и вызов только с `id` (или только с null вместо изменений) отклоняются.
- Прямые записи статуса `active`, `superseded`, `deprecated` запрещены. Их наличие в enum схемы не разрешает обходить инструменты жизненного цикла.
- Применяются проверка заголовка и настраиваемые ограничения размера заголовка и тела в байтах. Если `body` начинается с `@`, читается файл UTF-8 на машине сервера; относительный путь считается от каталога процесса сервера, а не от файловой системы клиента или аргумента `workspace`. Распознанный YAML frontmatter из файла удаляется перед сохранением тела.
- Метаданные и тело записываются отдельными хелперами проекции под блокировкой пространства. Это не транзакционный JSON patch: ошибка позднего шага возможна после успешного изменения метаданных.
- Смена заголовка создаёт новую проекцию и запускает удаление старого файла по точному пути. Очистка старого пути и запись идентификации выполняются best-effort. Обработчик сам не запускает валидацию и пересчёт оценки изменённого артефакта.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "id": "PRD-001",
  "title": "Authentication and sessions"
}
```

## Типичная последовательность

`forgeplan_new` → `forgeplan_update` (заполнение заглушки) → `forgeplan_validate` → цикл по любым обнаружениям → `forgeplan_activate`. Для поздних изменений активного артефакта шаблон такой: `forgeplan_get` → вычислить патч → `forgeplan_update`.

## Эквивалент CLI

- [`forgeplan update`](/ru/docs/cli/update/) — обновление через CLI, включая `--body @file.md`. Не редактируйте проекции `.forgeplan/` напрямую. Для пересборки производного индекса после получения отслеживаемого Markdown используйте `forgeplan reindex`.
