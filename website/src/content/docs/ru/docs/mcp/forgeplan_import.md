Воспроизводит записи артефактов и связи из JSON-строки экспорта в выбранном пространстве. Подходит для нового каталога назначения, заполнения CI и восстановления из сохранённого экспорта. Не восстанавливает все файлы пространства и не гарантирует запись каждой переданной связи; изучите счётчики и итоговый граф.

**Категория**: Рабочее пространство и данные

## Когда агент вызывает это

- После `forgeplan init -y` в новом рабочем пространстве - заполните его из резервной копии или общего пакета.
- На новой машине с пустым пространством — инициализировать его и импортировать сохранённый экспорт. Если в клоне уже есть отслеживаемые проекции, вместо переинициализации использовать CLI `forgeplan reindex`.
- В CI - воспроизведите детерминированный набор артефактов перед запуском интеграционных тестов против сервера MCP.
- Аварийное восстановление - рабочее пространство было стёрто, но у вас есть недавний JSON-файл `forgeplan_export`.

## Коллизии и частичные изменения

- `force` по умолчанию равен `false`, в том числе при отсутствии или null. Существующие ID артефактов пропускаются, но **связи применяются всё равно**, включая связи между существующими артефактами.
- При `force: true` существующий артефакт удаляется хелпером проекции и создаётся заново. Это может удалить старую проекцию и связи. Интерактивного подтверждения перезаписи нет; сначала получите согласие и экспортируйте пространство назначения.
- Пакет не является транзакцией. Ранние записи остаются после ошибки более позднего артефакта; при перезаписи старый артефакт уже может быть удалён до сбоя повторного создания.
- ID сохраняются. Обработчик не воспроизводит поля экспорта `created_at`, `updated_at`, `r_eff_score`; это не побайтовое восстановление с сохранением времён.

## Примечания по безопасности

- Импорт меняет индекс, проекции и связи под блокировкой записи пространства. Рекомендательная подсказка не означает согласия на `force: true`.
- Локальной конфигурации, корзины восстановления, состояний фаз и захватов в экспорте нет. Тела артефактов передаются дословно и могут содержать чувствительные данные.
- Для клона с отслеживаемыми проекциями используйте CLI `forgeplan reindex`; `scan-import` не является обновлением индекса после импорта. Не удаляйте и не переинициализируйте сохранившееся пространство только ради пакета.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `data` | `string` | да | Данные JSON-экспорта в виде строки. |
| `force` | `boolean \| null` | нет | Перезаписывать существующие артефакты. По умолчанию false. По умолчанию в схеме: `null`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Ответ содержит `imported`, `skipped`, `relations_imported` и `_next_action`, без трассировки рабочего пространства. Перезаписи входят в `imported`; отдельных счётчиков `artifacts_inserted` / `artifacts_overwritten` нет.

Передавайте реальный JSON экспорта строкой `data`, а не именем файла. После разбора пакет должен содержать массив `artifacts`. Поле `version` этот обработчик не проверяет. Артефакты без строкового непустого ID игнорируются без увеличения `skipped`; для отсутствующих полей используются, например, `kind: "note"`, `status: "draft"`, `depth: "standard"` до последующих проверок создания.

Связи используют `source`, `target`, `relation`; без `relation` применяется `informs`. Записи без пригодных концов игнорируются. Точные дубликаты и неудачные записи связей не учитываются счётчиком; ошибки пакета могут попасть только в журнал или свестись к `relations_imported: 0`, не вызывая ошибки MCP. Поэтому успех не доказывает восстановление всего графа.

Некорректный JSON и отсутствие массива `artifacts` дают текст ошибки MCP. Пустой массив допустим и не создаёт артефактов, но переданный массив `relations` всё ещё может изменить граф.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "data": "{\"version\":1,\"artifacts\":[{\"id\":\"NOTE-001\",\"kind\":\"note\",\"status\":\"draft\",\"title\":\"Storage decision\",\"body\":\"## Decision\\nUse PostgreSQL for transactional storage.\"}],\"relations\":[]}"
}
```

## Типичная последовательность

В пустом проекте: `forgeplan_init` → `forgeplan_import` со строкой полного экспорта → `forgeplan_list` → `forgeplan_health`.

Если клон уже содержит отслеживаемые проекции артефактов, пересоберите индекс через CLI `forgeplan reindex`, не переинициализируйте пространство.

После случайного удаления сначала попробуйте [`forgeplan_restore`](/ru/docs/mcp/forgeplan_restore/) или [`forgeplan_undo_last`](/ru/docs/mcp/forgeplan_undo_last/), пока доступна запись восстановления. Сохранённый экспорт — долгосрочный запасной вариант. Не удаляйте сохранившееся пространство только ради импорта: сначала сохраните его состояние и решите, пропускать существующие ID или явно перезаписывать.
