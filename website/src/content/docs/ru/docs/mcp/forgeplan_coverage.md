Показывает связи обнаруженных каталогов исходников с **активными** ADR/RFC/PRD. Пути извлекаются из Markdown-секций `Affected Files`, `Affected Scope` или `affected_files`, не из одного YAML frontmatter. Пустой `decisions` означает отсутствие учтённой связи, но не доказывает отсутствие архитектурной документации в других местах.

**Категория**: Качество

## Когда агент вызывает инструмент

- **Архитектурный аудит** — найти обнаруженные модули без учтённой связи с активным решением.
- **Онбординг** - новые инженеры могут быстро найти задокументированные части системы.
- **Перед рефакторингом** - убедиться, что модуль, который вы собираетесь изменить, имеет (или нуждается в) ADR.
- **Готовность к релизу** - ни один высоконагруженный модуль не должен иметь нулевое количество решений.

Используйте вместе с `forgeplan_drift`: drift сопоставляет объявленные решения с изменениями файлов, coverage учитывает объявленные связи обнаруженных модулей. Ни один результат не доказывает, что других решений никогда не записывали.

## Входные параметры

_Без входных параметров. Вызовите этот инструмент с пустым объектом `{}`._

## Возвращает

Payload содержит `total_modules`, `covered_modules`, `uncovered_modules`,
`coverage_percent`, `modules`, `_next_action`. У каждого модуля есть `path`,
`file_count`, `line_count`, `decisions` (ID артефактов). Пустой массив
`decisions` указывает на пробел; полей `count`/`blind_spot` у модуля
и `covered`/`blind_spots` верхнего уровня нет.

Это учёт объявленных связей решений с модулями, не покрытие тестами
и не смысловой обзор документации или кода.

## Типичная последовательность

1. `forgeplan_coverage` - перечислить модули со слепыми пятнами.
2. Для каждого: определить, заслуживает ли он ADR (нетривиальные дизайнерские решения).
3. `forgeplan_new adr` → задокументировать решение.
4. Через `forgeplan_update` укажите совпадающие пути в секции тела `## Affected Files` и выполните условия активации решения: считаются только активные записи. `forgeplan_link` связывает артефакты, не файлы.
5. Снова вызовите `forgeplan_coverage` и проверьте, учитывается ли объявленная связь.

## Эквивалент CLI

```bash
forgeplan coverage
```
