Показывает покрытие архитектурными решениями каталогов с распознанными исходными файлами. Сопоставляет **активные** PRD/RFC/ADR с путями модулей по разделам тела Markdown `## Affected Files`, `## Affected Scope` или `## affected_files`, а не списку фронтматтера или графовой связи артефакта с файлом. Модуль без совпавшего решения — пробел измеряемого покрытия, но не доказательство отсутствия документации где-либо ещё.

**Категория**: Качество

## Когда агент вызывает инструмент

- **Архитектурный аудит** - найти модули, для которых никто никогда не писал ADR.
- **Онбординг** - новые инженеры могут быстро найти задокументированные части системы.
- **Перед рефакторингом** - убедиться, что модуль, который вы собираетесь изменить, имеет (или нуждается в) ADR.
- **Готовность к релизу** - ни один высоконагруженный модуль не должен иметь нулевое количество решений.

Покрытие дополняет `forgeplan_drift`: `drift` говорит: «решения существуют, но код изменился», а покрытие говорит: «код существует, но решение никогда не было зафиксировано».

## Входные параметры

_Объявленных входных полей нет. Вызывайте инструмент с пустым объектом `{}`._

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в MCP `content[0].text`: `total_modules`, `covered_modules`, `uncovered_modules`, `coverage_percent`, `modules`, `_next_action`. Модуль содержит `path`, `file_count`, `line_count`, `decisions`. Нет полей модуля `count`/`blind_spot` и верхнеуровневых `covered`/`blind_spots`.

Условный фрагмент ответа (`_next_action` опущен):

```json
{
  "total_modules": 2,
  "covered_modules": 1,
  "uncovered_modules": 1,
  "coverage_percent": 50.0,
  "modules": [
    {"path": "src/auth", "file_count": 2, "line_count": 120, "decisions": ["ADR-002"]},
    {"path": "src/cache", "file_count": 1, "line_count": 40, "decisions": []}
  ]
}
```

Сканер распознаёт rs, ts, tsx, js, jsx, py, go, java, kt, swift, c, cpp, h; считает файлы непосредственно в каталоге и пропускает скрытые и известные каталоги генерации/документации/зависимостей. Сопоставление удаляет некоторые суффиксы масок и проверяет вхождение строк в обоих направлениях, а не полностью раскрывает glob. Покрытие не проверяет точность решения или тесты и не дописывает разделы.

Ошибка разрешения пространства возвращается как текстовая ошибка инструмента. Сбои сканирования/построения обработчик подавляет до пустого/нулевого отчёта, поэтому ноль модулей не доказывает отсутствия исходников.

## Типичная последовательность

1. `forgeplan_coverage` - перечислить модули со слепыми пятнами.
2. Для каждого: определить, заслуживает ли он ADR (нетривиальные дизайнерские решения).
3. Создайте и заполните подходящее решение через `forgeplan_new` / `forgeplan_update`.
4. Добавьте точные пути в Markdown-раздел `## Affected Files` и активируйте решение после прохождения гейтов. `forgeplan_link` связывает артефакты, а не файлы.
5. `forgeplan_coverage` снова - подтвердить устранение слепого пятна.

## Эквивалент CLI

```bash
forgeplan coverage
```
