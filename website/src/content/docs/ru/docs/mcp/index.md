---
title: Инструменты MCP
description: "Справочник по всем 73 инструментам Model Context Protocol, предоставляемым командой `forgeplan serve`."
---

Forgeplan поставляется с **73 MCP инструментами**, которые AI-агент может вызывать через Model Context Protocol (транспорт stdio).

Запустите MCP-сервер:

```bash
forgeplan serve
```

Настройте ваш агент (Claude Code, Cursor и т. д.) на подключение, затем вызовите любой из инструментов, перечисленных ниже.

### Рабочее пространство и данные

| Инструмент | Описание |
|---|---|
| [`forgeplan_export`](/ru/docs/mcp/forgeplan_export/) | Экспортировать все артефакты и связи в JSON-пакет. Возвращает экспортированные данные напрямую для программного использования или записывает в путь файла. |
| [`forgeplan_import`](/ru/docs/mcp/forgeplan_import/) | Импортировать артефакты и связи из JSON-пакета экспорта. Установите force=true для перезаписи существующих артефактов. |
| [`forgeplan_init`](/ru/docs/mcp/forgeplan_init/) | Инициализировать новое рабочее пространство .forgeplan/. Создаёт таблицы LanceDB, конфиг и подпапки артефактов. |

### Создание артефактов

| Инструмент | Описание |
|---|---|
| [`forgeplan_capture`](/ru/docs/mcp/forgeplan_capture/) | Захватить решение из диалога в артефакт Note или ADR. Автоматически определяет тип: простые решения становятся Notes, архитектурные решения становятся ADRs. Требует поставщика LLM. |
| [`forgeplan_generate`](/ru/docs/mcp/forgeplan_generate/) | Сгенерировать артефакт с помощью AI из описания на естественном языке. Требует поставщика LLM, настроенного в .forgeplan/config.yaml. Поддерживает OpenAI, Claude, Gemini, Ollama и любую совместимую с OpenAI конечную точку. |
| [`forgeplan_new`](/ru/docs/mcp/forgeplan_new/) | Создать новый артефакт из шаблона. Генерирует последовательный ID (например, PRD-001), отрисовывает шаблон, сохраняет в LanceDB и записывает проекцию markdown. |

### Чтение артефактов

| Инструмент | Описание |
|---|---|
| [`forgeplan_blocked`](/ru/docs/mcp/forgeplan_blocked/) | Показать заблокированные артефакты и их неудовлетворённые зависимости. Только черновики блокируют - устаревшие и замещённые считаются разрешёнными. Использует только структурные связи (based_on, refines, supersedes, contradicts). |
| [`forgeplan_get`](/ru/docs/mcp/forgeplan_get/) | Прочитать полный артефакт по ID. Возвращает все метаданные и содержимое тела. |
| [`forgeplan_graph`](/ru/docs/mcp/forgeplan_graph/) | Сгенерировать граф зависимостей mermaid всех связанных артефактов. Включает явные связи и рёбра parent_epic belongs_to. Issue #287 Phase F: передайте `brownfield_only: true` для фильтрации только по рёбрам UC/GLOS/INV/SCEN/HYP/DM. |
| [`forgeplan_journal`](/ru/docs/mcp/forgeplan_journal/) | Показать журнал решений - хронологическую временную шкалу артефактов ADR, Note, Problem, Solution с оценками R_eff и статусом доказательств. |
| [`forgeplan_list`](/ru/docs/mcp/forgeplan_list/) | Список артефактов с опциональными фильтрами kind/status. Возвращает ID, kind, status и title для каждого артефакта. |
| [`forgeplan_order`](/ru/docs/mcp/forgeplan_order/) | Показать артефакты в топологическом порядке (порядок зависимостей). Возвращает упорядоченный список, классификацию ready/blocked и обнаружение циклов. Использует только структурные связи. |
| [`forgeplan_progress`](/ru/docs/mcp/forgeplan_progress/) | Показать прогресс чекбоксов для артефактов. Парсит markdown-чекбоксы (- [ ] / - [x]) и вычисляет процент завершения. |
| [`forgeplan_search`](/ru/docs/mcp/forgeplan_search/) | Умный поиск по артефактам: BM25 поиск по ключевым словам + опциональный семантический + расширение графа. Поддерживает фильтры по kind/status/depth/evidence/since и переключение расширения графа. |
| [`forgeplan_session`](/ru/docs/mcp/forgeplan_session/) | Показать текущее состояние сессии методологии - фаза (idle/routing/shaping/coding/evidence/pr), активный артефакт, глубина, статус принудительного применения. Используйте это, чтобы узнать, где вы находитесь в рабочем процессе. |

### Редактирование артефактов

| Инструмент | Описание |
|---|---|
| [`forgeplan_delete`](/ru/docs/mcp/forgeplan_delete/) | Удалить артефакт из LanceDB и удалить его файл markdown-проекции. |
| [`forgeplan_link`](/ru/docs/mcp/forgeplan_link/) | Связать два артефакта типизированным отношением. Допустимые типы: informs, based_on, supersedes, contradicts, refines. |
| [`forgeplan_unlink`](/ru/docs/mcp/forgeplan_unlink/) | Удалить типизированное отношение между двумя артефактами. Зеркало `forgeplan_link` для отмены или исправления неправильно типизированных рёбер. Issue #286. |
| [`forgeplan_update`](/ru/docs/mcp/forgeplan_update/) | Обновить метаданные артефакта (статус, название) и/или содержимое. Перерендеривает markdown-проекцию после обновления. |

### Качество и валидация

| Инструмент | Описание |
|---|---|
| [`forgeplan_calibrate`](/ru/docs/mcp/forgeplan_calibrate/) | Предложить уровень глубины (Tactical/Standard/Deep/Critical) для артефактов на основе анализа содержимого. Обнаруживает разделы безопасности, критические изменения, количество связей, сложность содержимого. |
| [`forgeplan_coverage`](/ru/docs/mcp/forgeplan_coverage/) | Показать покрытие решений по модулям кода - какие модули имеют архитектурные решения, а какие являются слепыми пятнами. |
| [`forgeplan_coverage_business`](/ru/docs/mcp/forgeplan_coverage_business/) | Issue #287 Phase C - вычислить extract_score (0.0-1.0) для Domain Model. Читает раздел ## Composition модели DM для получения ожидаемых количеств глоссария / use_cases / инвариантов / сценариев / гипотез; подсчитывает фактические значения по рабочему пространству; возвращает взвешенный extract_score. Канонические поля (DDL/SDL/pseudo-code) по умолчанию имеют значение 0/false до момента, когда будет выпущена marketplace#79 Phase E. |
| [`forgeplan_decay`](/ru/docs/mcp/forgeplan_decay/) | Показать влияние распада доказательств на оценки R_eff. Перечисляет артефакты, где истёкшие доказательства снизили оценки качества, с сравнением текущего и свежего R_eff. |
| [`forgeplan_drift`](/ru/docs/mcp/forgeplan_drift/) | Проверить дрейф решений - затронутые файлы, которые изменились после создания ADR/RFC. |
| [`forgeplan_estimate`](/ru/docs/mcp/forgeplan_estimate/) | Оценить усилия для артефакта на основе FR и Phase элементов. Возвращает многоуровневую разбивку (Junior/Middle/Senior/Principal/AI) с оценкой уверенности. |
| [`forgeplan_guard`](/ru/docs/mcp/forgeplan_guard/) | Проверить, разрешен ли переход **фазы сессии** методологии (idle → routing → shaping → coding → evidence → pr). Используйте перед выполнением действий на уровне сессии, чтобы избежать заблокированных операций. Пример: могу ли я перейти из 'shaping' в 'coding'? Возвращает allowed=true/false с причиной. ПРИМЕЧАНИЕ: это охраняет машину состояний фазы методологической сессии, НЕ машину жизненного цикла артефакта (shape/validate/adi/code/test/audit/evidence/done) - для этого используйте `forgeplan_phase_advance`. Аргумент `target_session_phase` - это каноническое имя; `target_phase` принимается как устаревший псевдоним для обратной совместимости (PROB-065). |
| [`forgeplan_review`](/ru/docs/mcp/forgeplan_review/) | Проверить артефакт - запустить валидацию и показать контрольный список жизненного цикла. Показывает MUST/SHOULD находки и может ли артефакт быть активирован. |
| [`forgeplan_score`](/ru/docs/mcp/forgeplan_score/) | Вычислить оценку качества R_eff для артефакта на основе связанных доказательств. R_eff использует принцип слабого звена: score = min(evidence_scores) по ТЕКУЩИМ доказательствам артефакта - пакеты с терминальным статусом (superseded/deprecated) исключаются из min (ADR-020), но остаются в списке с `excluded: true`. Активный пакет refutes всё ещё обнуляет оценку. |
| [`forgeplan_stale`](/ru/docs/mcp/forgeplan_stale/) | Обнаружить просроченные артефакты с истёкшими датами valid_until. Возвращает список истёкших артефактов с количеством дней с момента истечения. |
| [`forgeplan_validate`](/ru/docs/mcp/forgeplan_validate/) | Валидировать полноту артефакта по правилам схемы. Проверяет обязательные разделы по типу артефакта и уровню глубины. Возвращает структурированные находки с серьёзностью (MUST/SHOULD/COULD). |

### Жизненный цикл

| Инструмент | Описание |
|---|---|
| [`forgeplan_activate`](/ru/docs/mcp/forgeplan_activate/) | Активировать артефакт (черновик → активный). Требует прохождения всех правил валидации MUST. |

| [`forgeplan_supersede`](/ru/docs/mcp/forgeplan_supersede/) | Заместить артефакт (активный → замещённый). Создаёт связь с заменой и уведомляет зависимые артефакты. |

### Рассуждения и ИИ

| Инструмент | Описание |
|---|---|
| [`forgeplan_decompose`](/ru/docs/mcp/forgeplan_decompose/) | Разложить PRD на RFC задачи с помощью ИИ. Анализирует функциональные требования и предлагает 3-7 RFC с названиями, описаниями, областью действия и зависимостями. Требует провайдера LLM. |
| [`forgeplan_reason`](/ru/docs/mcp/forgeplan_reason/) | Анализировать артефакт, используя цикл рассуждений FPF ADI: абдукция (3+ гипотезы) → дедукция (оценить каждую) → индукция (синтезировать рекомендацию). Требует провайдера LLM. |
| [`forgeplan_route`](/ru/docs/mcp/forgeplan_route/) | Предложить уровень глубины (Tactical/Standard/Deep/Critical) и конвейер артефактов для описания задачи. Использует классификацию LLM (Level 1) при настройке API ключа, откатывается на правила на основе ключевых слов (Level 0). |

### Панели управления

| Инструмент | Описание |
|---|---|
| [`forgeplan_blindspots`](/ru/docs/mcp/forgeplan_blindspots/) | Показать слепые пятна - решения (PRD/RFC/ADR/Epic) без связанных доказательств и сироты артефактов без связей. |
| [`forgeplan_health`](/ru/docs/mcp/forgeplan_health/) | Показать панель здоровья проекта - пробелы, риски, слепые пятна, сироты, просроченные доказательства и рекомендуемые следующие действия. Возвращает агрегированное поле `verdict` ("healthy" \| "needs_attention" \| "unhealthy") + `verdict_summary` для однострочного отображения человеком. Ветвление по `verdict` для гейтов качества CI и логики принятия решений агентом. LLM не требуется. |
| [`forgeplan_status`](/ru/docs/mcp/forgeplan_status/) | Показать панель статуса проекта - всего артефактов, подсчёты по типам и статусам. |

### База знаний FPF

| Инструмент | Описание |
|---|---|
| [`forgeplan_fpf_check`](/ru/docs/mcp/forgeplan_fpf_check/) | Проверить, какие правила FPF совпадают с заданным артефактом, показав все совпадающие правила, выигрывающее правило (первое в порядке приоритета, как во время выполнения) и правила, которые не совпали. Используйте это, чтобы понять поведение механизма FPF для конкретного артефакта перед действием. |
| [`forgeplan_fpf_list`](/ru/docs/mcp/forgeplan_fpf_list/) | Список всех доступных разделов FPF (First Principles Framework) в базе знаний. |
| [`forgeplan_fpf_rules`](/ru/docs/mcp/forgeplan_fpf_rules/) | Список активных правил FPF из рабочего пространства. По умолчанию возвращает все правила с полными деревьями условий и сообщениями. Параметры позволяют фильтровать: `action` (EXPLORE/INVESTIGATE/EXPLOIT) для отображения только правил этой категории действий; `name` для получения одного правила по имени; `summary: true` для возврата только имени/приоритета/действия без деталей условий (полезно для быстрых обзоров); `source` (config/default) для отладки, какой источник правил активен. Если рабочее пространство имеет определённые пользователем правила в .forgeplan/config.yaml под fpf.rules, они имеют приоритет; в противном случае возвращаются встроенные значения по умолчанию. |
| [`forgeplan_fpf_search`](/ru/docs/mcp/forgeplan_fpf_search/) | Поиск в базе знаний FPF (First Principles Framework). По умолчанию используется поиск по ключевым словам. Передайте `semantic: true` для поиска по сходству векторов через эмбеддинги BGE-M3 (требует функцию сборки `semantic-search`). Когда `semantic: true`, но функция не скомпилирована, запрос корректно переходит на поиск по ключевым словам и ответ включает поле `warning`. Примечание: первый вызов с `semantic: true` может занять несколько минут, если модель BGE-M3 требует загрузки (~2,1 ГБ). Параметры: query (обязательно, 1..=8192 символов), limit (по умолчанию 5, макс 50), semantic (по умолчанию false). |
| [`forgeplan_fpf_section`](/ru/docs/mcp/forgeplan_fpf_section/) | Получить полное содержимое конкретного раздела FPF по ID (например 'B.3', 'C.2.2', 'A.1'). |

### Обнаружение в существующем коде

| Инструмент | Описание |
|---|---|
| [`forgeplan_discover_complete`](/ru/docs/mcp/forgeplan_discover_complete/) | Завершить сеанс обнаружения. Генерирует отчёт с выводами по фазам/уровням, запускает forgeplan health и отмечает сеанс как завершённый. |
| [`forgeplan_discover_finding`](/ru/docs/mcp/forgeplan_discover_finding/) | Сообщить о находке при обнаружении. Агент вызывает это после анализа файла/модуля/git-лога во время фазы. ForgePlan создаёт артефакт (note/prd/rfc/problem/evidence) с содержимым находки, помечает его исходным уровнем и связывает с сеансом обнаружения. |
| [`forgeplan_discover_start`](/ru/docs/mcp/forgeplan_discover_start/) | Начать сеанс обнаружения в существующем коде. Возвращает структурированный протокол (7 фаз: detect/structure/code/git/tests/docs/synthesize), который следует AI-агент для отображения существующей кодовой базы. ForgePlan предоставляет протокол; агент анализирует код и сообщает о находках через forgeplan_discover_finding. |

### Прочее

| Инструмент | Описание |
|---|---|
| [`forgeplan_activity`](/ru/docs/mcp/forgeplan_activity/) | Запросить журнал активности - добавляемую только JSONL-запись каждого вызова инструмента MCP в .forgeplan/logs/tools-YYYY-MM-DD.jsonl. Используйте это для восстановления того, что делал агент за временной промежуток, атрибуции затрат LLM-токенов или аудита деструктивных операций. Параметры: since_hours (по умолчанию 24, макс 720), tool (имена через запятую для фильтрации), status (ok/tool_err/rpc_err), limit (по умолчанию 500, макс 5000 - сохраняет самые свежие). |
| [`forgeplan_activity_stats`](/ru/docs/mcp/forgeplan_activity_stats/) | Агрегированная статистика из журнала активности, сгруппированная по имени инструмента: количество, количество ошибок, p50/p95 длительность, общее время. Используйте для атрибуции затрат LLM-токенов и выявления медленных инструментов. Параметры: since_hours (по умолчанию 24, макс 720). |
| [`forgeplan_anomalies`](/ru/docs/mcp/forgeplan_anomalies/) | Issue #289 - обнаружить аномалии конвейера (застрявшие черновики, потерянные связи, неправильно набранные based_on, отсутствующие MUST-разделы, истёкшие доказательства, циклы, дубликаты и т.д.). Возвращает структурированный список с серьёзностью + уровнем + suggested_resolution, чтобы оркестраторы (`/forge-cycle`, `/forge-cleanup`) могли отправлять уровни auto/adi/user без переклассификации. |
| [`forgeplan_claim`](/ru/docs/mcp/forgeplan_claim/) | Заявить артефакт для эксклюзивной работы. Записывает .forgeplan/claims/<id>.yaml с идентификатором агента вызывающей стороны, временной меткой и TTL. Не удаётся, если существует активное заявление другого агента - вызовы того же агента продлевают TTL. Рекомендация: другие инструменты не блокируют заявления, но оркестраторы должны использовать `forgeplan_claims --active` для избежания двойного назначения работы. |
| [`forgeplan_claims`](/ru/docs/mcp/forgeplan_claims/) | Список активных заявлений в рабочем пространстве, отсортированный по истечению по возрастанию. Пропускает истёкшие заявления (они считаются практически освобождёнными). Используется оркестраторами для построения планов отправки и под-агентами для избежания двойного заявления. |
| [`forgeplan_contradictions`](/ru/docs/mcp/forgeplan_contradictions/) | Issue #287 Phase C - обнаружить противоречия между артефактами (v1: hypothesis_duplicate через Jaccard ≥ 0,6 по названиям). Три других класса (invariant_conflict, glossary_divergence, scenario_vs_invariant) требуют суждения LLM и отложены - корзины включены в ответ с пустыми массивами + список ограничений. |
| [`forgeplan_dispatch`](/ru/docs/mcp/forgeplan_dispatch/) | Вычислить параллельно-безопасный план работы для N под-агентов. Возвращает корзины (по одной на агента), последовательную очередь для оставшейся работы и понятное человеку обоснование для каждого решения размещения. Пропускает артефакты, уже заявленные, откладывает артефакты с перекрытием файлов >= порога (по умолчанию Jaccard 0,3), и при предоставлении agent_skills маршрутизирует по совпадению домена. Только для чтения - не мутирует состояние рабочего пространства. |
| [`forgeplan_hypothesis_promote`](/ru/docs/mcp/forgeplan_hypothesis_promote/) | Повысить гипотезу вдоль машины состояния верификации (parked → inferred → strong-inferred → verified; или любое → refuted; или любое → parked). Мутирует тело артефакта через проекцию файла-первого: обновляет поле frontmatter `hypothesis_state:` и добавляет запись аудита в раздел `## Lifecycle State`. Возвращает список артефактов, которые информируют / основаны на гипотезе (каскад) - только информационно, не автоматически повышаются.
