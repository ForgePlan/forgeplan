---

Возвращает полное тело артефакта в формате Markdown, а также метаданные фронтматтера. Это каноническая операция "чтения" - агент вызывает её, когда ему требуется фактическое содержимое PRD/RFC/ADR, чтобы рассуждать о нём, цитировать или обновлять. В отличие от `forgeplan_list`, ответ содержит всё, что нужно агенту для понимания артефакта.

**Категория**: Чтение артефактов

## Когда агент вызывает эту операцию

- Пользователь спрашивает: "Что PRD-042 говорит об ограничениях скорости?" - агент извлекает, затем цитирует соответствующий раздел.
- Перед вызовом `forgeplan_update` - агенту требуется текущее тело, чтобы создать патч с учётом различий.
- Перед `forgeplan_reason` - агент предварительно считывает данные, чтобы описать контекст пользователю, если вызов LLM происходит медленно.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `id` | `string` | да | ID артефакта для чтения. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в MCP `content[0].text`, а не объект `structuredContent`. Фиксированные поля записи: `id`, `kind`, `status`, `title`, `body`, `depth`, `author`, `parent_epic`, `r_eff_score`, `valid_until`, `created_at`, `updated_at`, `id_canonical`, `id_display` и `links`. `author`, `parent_epic` и `valid_until` могут быть null. Необязательные поля идентификации `slug`, `predicted_number` и `assigned_number` отсутствуют, если не заданы. Верхнеуровневого поля `tags` нет; произвольный фронтматтер остаётся в `body`.

`links.outbound` содержит объекты `{target, relation}`, а `links.inbound` — `{source, relation}`. При ошибке чтения связей возвращаются пустые массивы. `_next_action` — подсказка по статусу, иногда с фазой или действующей заявкой на работу; это не автоматическое действие и не блокировка записи. Поддерживаются отображаемый ID и канонический slug. Отсутствующий артефакт возвращает ошибку инструмента MCP (`isError: true`) с обычным текстом, а не этот JSON.

Условный пример ответа (значения не получены из реального рабочего пространства):

```json
{
  "id": "PRD-042",
  "kind": "prd",
  "status": "active",
  "depth": "standard",
  "title": "Authentication system",
  "author": null,
  "parent_epic": null,
  "r_eff_score": 0.0,
  "valid_until": null,
  "created_at": "2026-04-10T09:31:00Z",
  "updated_at": "2026-04-11T09:31:00Z",
  "id_canonical": "prd-042",
  "id_display": "PRD-042",
  "links": {"outbound": [], "inbound": []},
  "_next_action": "Active. Verify trust: `forgeplan_score prd-042`.",
  "body": "# PRD-042: Authentication system\n\n## Problem\nUsers currently..."
}
```

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "id": "PRD-001"
}
```

## Типичная последовательность

`forgeplan_list` или `forgeplan_search` возвращает ID → `forgeplan_get` читает тело → агент цитирует, анализирует или обновляет. Поиск находит кандидатов; результаты smart-поиска не содержат фрагментов тела, поэтому сам текст читайте через `get`.
