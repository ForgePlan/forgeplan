---

Показывает, как устаревшие/просроченные доказательства снизили оценки R_eff по всему рабочему пространству. Для каждого затронутого решения он сообщает **текущий** R_eff (с учётом штрафов за устаревание) по сравнению с гипотетическим **обновлённым** R_eff (если бы срок действия просроченных доказательств был продлён). Это позволяет количественно оценить «скрытую потерю качества», вызванную устареванием доказательств.

**Категория**: Качество

## Когда агент вызывает его

- **Аудит качества** - чтобы увидеть, какие решения незаметно теряют доверие из-за старых доказательств.
- **Приоритизация работы по обновлению** - наибольшие дельты между текущим и обновлённым R_eff указывают на обновления с наибольшим влиянием.
- **Перед релизом** - чтобы убедиться, что выпущенные решения не опираются на устаревшие доказательства.
- **Объяснение падения R_eff** пользователю («почему оценка PRD-039 изменилась с 0.85 на 0.41?»).

Отчёт использует **плоский** минимум доказательств, а не рекурсивный движок `forgeplan_score`: обхода зависимостей и штрафа типа доказательства нет. Просрочка заменяет оценку на 0.1 без изменения CL и удаления пакета. Терминальные доказательства исключены; черновики учитываются. Отчёт включает не-доказательства со связанными просроченными допустимыми доказательствами, даже если гипотетическая свежая оценка такая же или ниже.

## Входные параметры

_Объявленных входных полей нет. Вызывайте инструмент с пустым объектом `{}`._

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в MCP `content[0].text` с `entries`, `total_affected` и `_next_action`. Элемент содержит `artifact_id`, `artifact_title`, `current_r_eff`, `fresh_r_eff`, `r_eff_drop` (`fresh - current`), `expired_evidence`. Просроченный элемент содержит `id`, `valid_until`, `days_expired`, `score` (обычно 0.1). Нет `decayed`, `delta`, `kind` и `total_impacted`.

Условный фрагмент ответа (динамический `_next_action` опущен):

```json
{
  "entries": [
    {
      "artifact_id": "PRD-039",
      "artifact_title": "Auth system",
      "current_r_eff": 0.1,
      "fresh_r_eff": 0.9,
      "r_eff_drop": 0.8,
      "expired_evidence": [
        {"id": "EVID-047", "valid_until": "2026-03-30", "days_expired": 12, "score": 0.1}
      ]
    }
  ],
  "total_affected": 1
}
```

Значения предполагают один поддерживающий пакет CL2 и дату UTC 2026-04-11. Это только отчёт: он не продлевает доказательства, не обновляет оценки и не меняет статус. Ошибки пространства возвращаются текстом, сбои отчёта могут быть JSON-RPC ошибками. При сбое чтения связей используются пустые связи, поэтому часть затронутых записей может не попасть в отчёт.

## Пример вызова

## Типичная последовательность

1. `forgeplan_stale` - найти просроченные артефакты.
2. `forgeplan_decay` - посмотреть, каким решениям они нанесли ущерб.
3. Прочитайте `r_eff_drop` (уже отсортирован по убыванию): наибольшие положительные падения — приоритетные кандидаты на обновление.
4. `forgeplan_renew` или создать новый `EvidencePack` → `forgeplan_link`.
5. `forgeplan_score` - подтвердить восстановление R_eff.

## Эквивалент CLI

```bash
forgeplan decay
```
