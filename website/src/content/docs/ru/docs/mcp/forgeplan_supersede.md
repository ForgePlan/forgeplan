Помечает активный артефакт как замещённый новым и создаёт связь `supersedes`, сохраняя историю решений. `superseded` — конечный статус жизненного цикла, но ошибочную операцию можно отменить через [`forgeplan_restore`](/ru/docs/mcp/forgeplan_restore/), пока доступна пригодная запись восстановления (по умолчанию 30 дней, с проверкой конфликта ID). Это не прямая запись статуса через `forgeplan_update`.

**Категория**: Жизненный цикл

## Когда агент вызывает это

- Чтобы вытеснить устаревший EvidencePack после ре-верификации (сначала слинкуйте пакет-наследник): superseded-пакет исключается из R_eff min родительского артефакта, информируемые артефакты рескорятся автоматически.

- Редизайн: новый RFC-019 замещает RFC-018 - агент вызывает `supersede RFC-018 --by RFC-019`.
- Вторая итерация решения после того, как новые доказательства противоречат старым.
- Переименование/реструктуризация: создать новый артефакт, затем заместить старый, чтобы история оставалась связанной.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `by` | `string` | да | ID замещающего артефакта. |
| `id` | `string` | да | ID артефакта, который нужно заменить. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Ответ содержит `superseded` (старый ID), `replacement`, `dependents_affected`, `warnings`, `receipt_id`, `resolved_workspace`, `resolved_via` и `_next_action`. Полей `ok`, `from`, `to`, `link` в ответе нет.

Сохранённое ребро направлено **от старого артефакта к замене**: вызов с `id: "ADR-001", by: "ADR-002"` создаёт `ADR-001 --supersedes--> ADR-002`. Не выводите обратное направление из английского названия отношения или подсказки.

`dependents_affected` перечисляет артефакты, которые ещё ссылаются на старый. Это не означает автоматический перенос ссылок на замену или отправку внешнего уведомления.

## Проверки и побочные эффекты

- Старый артефакт должен существовать и иметь статус `active`. Если замены нет, возвращается `Replacement not found: <id>`.
- Замена в `draft` принимается с предупреждением. Активировать её заранее рекомендуется, но это не обязательный гейт обработчика. Замена со статусом `superseded` или `deprecated` отклоняется. Ошибку также могут вызвать ссылка на себя или уже существующее такое ребро.
- Обработчик блокирует пространство, сохраняет запись восстановления до перехода, затем синхронизирует старую проекцию. Сбой создания записи отменяет переход. Поздний отказ может оставить заранее созданную, неиспользованную запись; изучите её до восстановления.
- Успех добавляет связь от старого к замене и меняет статус старого. Перерисовка обоих артефактов, продвижение фазы в `done` и пересчёт зависимых оценок при вытеснении доказательства выполняются best-effort. Замена и зависимые артефакты автоматически не активируются, их ссылки не перенаправляются.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "id": "ADR-001",
  "by": "ADR-002"
}
```

## Типичная последовательность

`forgeplan_new` (замена) → `forgeplan_update` → `forgeplan_validate` PASS → `forgeplan_activate` замену → `forgeplan_supersede` старый. Предпочитайте активную замену. Если намеренно выбрана замена-черновик, изучите `warnings` и явно учитывайте, что она ещё не завершена.
