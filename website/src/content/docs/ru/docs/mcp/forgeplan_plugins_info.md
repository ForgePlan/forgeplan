Показать детали одного плагина из расширенного реестра. Возвращает статический PluginInfo плюс, если установлен, runtime-запись InstalledPlugin (обнаруженный путь + версия). PRD-067.

**Категория**: Прочее

Одна запись реестра, полностью разрешённая. Ответ объединяет два источника: **статическую** запись, которая идентична на каждой машине, и **runtime** запись, которая отражает то, что фактически есть на этой машине. Плагин, который зарегистрирован, но не обнаружен, возвращается с полной статической записью и null в runtime-половине - это нормальный ответ, а не ошибка.

## Что делает

1. **Ищет имя в расширенном реестре.** Поиск точный и чувствителен к регистру по ключу реестра, то есть это имя плагина в kebab-case. Имя, которое не зарегистрировано, отклоняется до начала любой работы с файловой системой.
2. **Возвращает статическую запись `info`**: имя, источник распространения, требование к версии, ожидаемые пути, команду установки и описание.
3. **Сканирует этот плагин на диске** и, когда путь совпадает, добавляет запись `installed` с путём, который разрешился, и версией, прочитанной из его манифеста.
4. **Проверяет совместимость**, чтобы выбрать подсказку: обнаруженная версия, удовлетворяющая требованию, завершает вызов с `Done.`, всё остальное запрашивает установку или обновление, используя команду установки из самого реестра.

## Входные параметры

| Имя | Тип | Обязательный | Описание |
|---|---|---|---|
| `name` | `string` | да | Имя плагина в kebab-case, точно как зарегистрировано. Например `c4-architecture`, `agents-pro`, `forgeplan`. |

_Источник схемы: `crates/forgeplan-core/src/plugins/types.rs::PluginsInfoParams`_

## Возвращает

Зарегистрирован и обнаружен на этой машине:

```json
{
  "_next_action": "Done.",
  "info": {
    "description": "Forgeplan core methodology engine (always present)",
    "expected_paths": [],
    "install_command": "(built-in)",
    "name": "forgeplan",
    "source": "forgeplan",
    "version_req": "*"
  },
  "installed": {
    "detected_path": "(built-in)",
    "detected_version": "0.37.0",
    "info": { "name": "forgeplan", "source": "forgeplan", "version_req": "*" }
  }
}
```

Зарегистрирован, но не обнаружен - статическая запись полная, а `installed` равен null:

```json
{
  "_next_action": "Install: `/plugin install c4-architecture@claude-code-workflows`.",
  "info": {
    "description": "C4 model diagrams (context/container/component/code) generator",
    "expected_paths": ["c4-architecture"],
    "install_command": "/plugin install c4-architecture@claude-code-workflows",
    "name": "c4-architecture",
    "source": "claude-plugin",
    "version_req": ">=1.0"
  },
  "installed": null
}
```

Статический `info` вложен также внутри `installed`, поэтому потребитель, имеющий только runtime-половину, всё равно видит требование, по которому она была измерена.

## Как выбирается подсказка

| Состояние | `_next_action` |
|---|---|
| Обнаружен и версия удовлетворяет требованию | `Done.` |
| Обнаружен, но версия не соответствует требованию, или версию не удалось прочитать | `Update plugin: <install command>.` |
| Не обнаружен | `Install: <install command>.` |

Поскольку отсутствующая версия считается как "невозможно доказать совместимость", директория плагина без парсируемого манифеста попадает в ветку обновления, даже если она только что установлена. Прочитайте `installed.detected_version` перед тем, как действовать по этой подсказке.

## Отказы

Имя, которого нет в реестре, является ошибкой инструмента с указателем на полный список:

```text
plugin `nope-not-real` not in registry

_next_action: List all known plugins: `forgeplan_plugins_list`.
```

Отказ происходит до сканирования файловой системы, поэтому опечатка ничего не стоит и никогда не возвращает частичный ответ.

## Когда агент вызывает это

- **Подтверждение команды установки** перед показом её пользователю, вместо угадывания имени в маркетплейсе.
- **Проверка требования к версии** перед зависимостью от возможности плагина.
- **После установки**, чтобы проверить, что обнаруженная версия удовлетворяет тому, что ожидает forgeplan.

## Примеры

Прочитать один зарегистрированный плагин:

```json
{ "name": "c4-architecture" }
```

Прочитать встроенную запись, чтобы узнать запущенную версию:

```json
{ "name": "forgeplan" }
```

## Примечания

- Только для чтения, неразрушающий и идемпотентный.
- Обнаружение - это проверка пути, а не выполнение: плагин никогда не загружается, не импортируется и не запускается для ответа на этот вызов.
- Реестр скомпилирован в бинарный файл, поэтому запись может быть зарегистрирована, пока сам плагин опубликован в другом месте - что именно и сообщает `missing` в [`forgeplan_plugins_list`](/ru/docs/mcp/forgeplan_plugins_list/).

## Эквивалент в CLI

- [`forgeplan plugins info`](/ru/docs/cli/plugins-info/) - тот же поиск, напечатанный как блок полей, с явной строкой `Installed: yes` / `no`.
