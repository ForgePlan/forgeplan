---

Добавляет одно **наблюдение** в сессию исследования. После получения протокола агент проходит фазы detect / structure / code / git / tests / docs / synthesize, читает источники в предписанном порядке и вызывает инструмент для каждого наблюдения, которое стоит сохранить. Forgeplan создаёт настоящий черновик артефакта. Обычно используют `note`, `prd`, `rfc`, `problem` и `evidence`, но обработчик применяет общий парсер типов артефактов, не ограничивая выбор этими пятью.

**Категория**: Обнаружение в Brownfield

> **Только MCP по замыслу.** Этот инструмент не имеет эквивалента в `forgeplan` CLI. Протокол исследования *управляется агентом* - ForgePlan не читает исходные файлы самостоятельно. Оператор-человек, используя CLI, запускает сессию, а затем запускает агента; обнаруженные факты возвращаются только через MCP.

## Уровни источников (напоминание)

Каждое наблюдение должно указывать уровень источника.

| Уровень | Источники | Типичные kind |
|---|---|---|
| 1 | Код, git-история, манифесты | `note`, `rfc`, `problem`, `evidence` |
| 2 | Тесты, JSDoc-комментарии, конфигурация CI | `evidence`, `note` |
| 3 | Документация | `note`, `problem` |

## Когда агент вызывает этот инструмент

- После прочтения исходного файла и выявления шаблона, зависимости, границы или странности, которые стоит зафиксировать.
- После анализа `git log` и обнаружения отката, коммита с решением или заброшенной ветки.
- После запуска тестов и обнаружения поведенческого контракта, который не был явно выражен в самом коде.
- После сверки `README.md` с кодом и обнаружения расхождений (обнаруженный факт становится артефактом `ProblemCard`).

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `body` | `string` | да | Тело артефакта в Markdown. |
| `kind` | `string` | да | Тип создаваемого артефакта: `note`, `prd`, `rfc`, `problem` или `evidence`. |
| `phase` | `string` | да | Фаза: `detect`, `structure`, `code`, `git`, `tests`, `docs` или `synthesize`. |
| `session_id` | `string` | да | ID сессии, возвращённый `discover_start`. |
| `source_files` | `array<string>` | нет | Пути исходных файлов, на которых основано наблюдение. По умолчанию в схеме: `[]`. |
| `tier` | `integer` | да | Уровень источника: 1, 2 или 3. `format`: `uint8`. `minimum`: `0`. `maximum`: `255`. |
| `title` | `string` | да | Заголовок артефакта. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Поля `artifact_id`, `session_id`, `phase`, `tier`, `total_findings`, `session_status`, `artifact_status`. Созданный артефакт всегда имеет `artifact_status: "draft"`; активность сессии не активирует артефакт. `status` — устаревший псевдоним статуса сессии, о чём сообщает `_field_warnings`.

Артефакт получает теги `discover-session=<session_id>`, `source=tier<N>`, `phase=<phase>`, а при tier 3 также `source=legacy-doc`. Это теги принадлежности наблюдения сессии, не типизированная связь с артефактом сессии. `_next_action` предлагает завершить сессию, когда все фазы пройдены.

`body` принимает Markdown или `@path` для чтения локального файла. Непустой список
`source_files` дописывается в тело артефакта под `## Source Files`; это ссылки
вызывающего, а не файлы, которые инструмент исследует самостоятельно.
Артефакт создаётся с глубиной `standard`; тип `kind` не создаёт пакет доказательств
и не задаёт `valid_until`. Поэтому наблюдение типа evidence само по себе не
подтверждает утверждение и не даёт ему оценку.

Первое наблюдение переводит сессию из `started` в `active`. Порядок фаз и завершение
сессии не проверяются как запреты: обработчик принимает наблюдения и после завершения,
не открывая сессию заново. Соблюдайте протокол на стороне вызывающего; для нового
исследования начинайте новую сессию, не опирайтесь на этот пробел проверки.

Успех — JSON в текстовом содержимом MCP без трассировки пространства.
Неизвестная фаза, tier вне 1–3, отсутствующая сессия, неверный kind, ошибки выделения
ID и сохранения дают ошибки инструмента. Выбор пространства и раскрытие `@path`
могут завершиться ошибкой JSON-RPC. Артефакт создаётся до сохранения сессии:
при ошибке сохранения он уже может существовать; проверьте пространство перед повтором.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "session_id": "disc-20261023-120000",
  "phase": "code",
  "tier": 1,
  "kind": "note",
  "title": "Billing entry point",
  "body": "The billing module handles invoice creation.",
  "source_files": [
    "src/billing.rs"
  ]
}
```

## Типичная последовательность

`forgeplan_discover_start` → повторные вызовы `forgeplan_discover_finding` → `forgeplan_discover_complete`.

Сообщайте одно конкретное наблюдение за вызов и используйте действительный ID, полученный от `forgeplan_discover_start`.

## Эквивалент CLI

Нет - намеренно. Обнаруженные факты исследования передаются только через путь MCP.
