Возвращает полный каталог разделов базы знаний FPF - иерархическую таксономию, лежащую в основе механизма рассуждений Forgeplan. Каждый раздел представляет собой небольшую, самодостаточную часть First Principles Framework (цикл ADI, Trust Calculus, ограниченный контекст, explore/investigate/exploit и т.д.). `forgeplan_fpf_list` - это индекс агента: просматривайте его, решайте, какие разделы кажутся релевантными, затем получайте полное содержимое через `forgeplan_fpf_section` или ищите содержимое через `forgeplan_fpf_search`.

**Категория**: База знаний FPF

## Когда агент вызывает этот инструмент

- В начале работы с FPF — вспомнить, какие темы доступны в загруженной базе.
- Перед `forgeplan_fpf_section` — узнать действительный ID раздела.
- Для вопроса о существовании конкретной темы — просмотреть заголовки перед поиском.
- После CLI `forgeplan fpf ingest` — проверить фактический каталог. Его размер зависит от корпуса.

## Что вы получаете в ответ

`sections` — массив объектов с `section_id`, `title`, `line_count`. `total` — его длина. `_next_action` указывает реальный раздел либо предлагает CLI `forgeplan fpf ingest`, если база пуста.

Это не массив объектов `{id, summary, chapter}`. Фиксированное число разделов не гарантируется.

## Входные параметры

_Объявленных входных полей нет. Вызывайте инструмент с пустым объектом `{}`._

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Передавайте полученный `section_id` во **входное** поле `id` инструмента `forgeplan_fpf_section`. `line_count` описывает размер раздела, а не уверенность. Полные тексты в каталоге отсутствуют; читайте их по необходимости.

Успешный ответ — JSON в текстовом содержимом MCP. Инструмент без параметров читает рабочее пространство сервера по умолчанию, а не явно выбранный worktree отдельного вызова. Отсутствующая таблица FPF или сбой запроса журналируется и может дать `sections: []`, `total: 0` с подсказкой загрузки; пустой ответ не доказывает, что загрузка никогда не выполнялась. Порядок сортировки и вложенная иерархия не гарантируются, изменений нет.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

## Типичная последовательность

```
forgeplan_fpf_list
   ↓ выбрать интересные ID
forgeplan_fpf_section { id: "B.3" }    ← полное содержимое одного раздела
   или
forgeplan_fpf_search  { query: "…" }   ← поиск на уровне содержимого (по ключевым словам или BGE-M3)
```
