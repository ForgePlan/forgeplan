title: forgeplan_claim
description: "Захватить артефакт для работы одного агента с ограниченным сроком. Захват рекомендательный и не блокирует другие инструменты."
---

Записывает `.forgeplan/claims/<id>.yaml`, отмечая намерение агента работать над артефактом. Блокировка записи пространства упорядочивает вызовы claim/release, но сам захват рекомендательный: он не блокирует исходные файлы и другие инструменты. Действующий захват другого агента вызывает отказ. Повторный вызов того же агента перезаписывает время, TTL и заметку; это продление, а не идемпотентная операция без записи. Перед распределением работы проверьте [`forgeplan_claims`](/ru/docs/mcp/forgeplan_claims/).

**Категория**: Совместная работа агентов

## Когда агент вызывает

- Суб-агент берёт артефакт из бакета `forgeplan_dispatch` и клеймит его перед
  тем, как трогать файлы.
- Долгая работа (R3-grade рефакторинг, multi-PR feature): продлевает клейм тем же
  вызовом до истечения TTL.
- Оркестратор клеймит от имени работника, явно передавая `agent: "worker-1"`.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `agent` | `string \| null` | нет | Agent identity ("name/version" or free-form). Optional - defaults to the MCP caller's clientInfo when omitted. Providing this explicitly lets an orchestrator claim on behalf of a sub-agent. |
| `id` | `string` | да | ID артефакта для захвата, например `PRD-057`. На диске приводится к верхнему регистру. |
| `note` | `string \| null` | нет | Необязательная заметка, отображаемая при вызове `forgeplan_claims --active`. |
| `ttl_minutes` | `integer \| null` | нет | Срок захвата в минутах. По умолчанию 30, минимум 1, максимум 1440 (24 часа). `format`: `uint32`. `minimum`: `0`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Ответ содержит `id` (в верхнем регистре), `agent_id`, `claimed_at`, `expires_at`, необязательный `note` и `_next_action`. Если заметки нет, `note` не сериализуется. Этот обработчик не добавляет трассировку рабочего пространства.

Коллизия даёт ошибку MCP с текстом о текущем держателе и сроке захвата, а также рекомендательную подсказку выбрать другую работу. Это не объект `ok: false`; подсказка не разрешает принудительно снимать чужой захват.

## Проверки и побочные эффекты

- По схеме обязателен только `id`. Обработчик сначала берёт явно переданный непустой `agent`, затем идентификацию MCP `clientInfo`. Если нет обоих, возвращает отказ; не превращайте необязательное поле JSON в обязательное для всех клиентов.
- TTL по умолчанию — **30 минут**. Значения меньше 1 и больше 1440 отклоняются. Минимум 0 в схеме беззнакового числа не равен нижней границе обработчика.
- ID должен быть непустым ASCII-токеном и начинаться с буквы; имя файла захвата и сохранённый ID приводятся к верхнему регистру. Идентификация агента обрезается trim, ограничена 64 байтами и не допускает управляющих и маскирующих символов. Держатель сравнивается точным совпадением строки.
- Истёкший захват можно перезаписать. Продление тем же держателем заменяет и заметку: отсутствие `note` не сохраняет предыдущую.
- Хранилище захватов не проверяет существование артефакта в LanceDB. Успех подтверждает только запись координационного файла, а не существование артефакта, право доступа или выполнение работы.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "id": "RFC-001",
  "agent": "worker-1",
  "ttl_minutes": 30
}
```

## Типичная последовательность

1. [`forgeplan_dispatch`](/ru/docs/mcp/forgeplan_dispatch/) - оркестратор строит бакеты.
2. Работник вызывает `forgeplan_claim` на назначенном артефакте.
3. Работник делает реальные правки кода / артефакта.
4. [`forgeplan_release`](/ru/docs/mcp/forgeplan_release/) - снимает клейм по завершении.

## CLI эквивалент

[`forgeplan claim`](/ru/docs/cli/) - те же семантики, используется оркестраторами,
которые управляют суб-агентами через shell, а не через MCP.
