Помечает сессию исследования как `completed` и возвращает количества наблюдений, записанных через `forgeplan_discover_finding`. Обработчик 0.38.0 **не** запускает health и не генерирует предложения: `_next_action` просит отдельно вызвать `forgeplan_health`. Артефакты наблюдений уже созданы и остаются черновиками до ревью и явной активации.

**Категория**: Исследование существующей системы

## Когда агент вызывает эту функцию

- После прохождения семи фаз и записи всех наблюдений.
- По просьбе завершить исследование.
- Перед началом Shape → Validate → Code для принятого наблюдения.

## Что она делает

1. Загружает сессию по `session_id`.
2. Ставит статус сессии `completed`, записывает время завершения и сохраняет её.
3. Считает наблюдения по фазам и уровням и возвращает ID созданных артефактов.
4. Предлагает отдельный health и ревью черновиков.

## Ревью остаётся за вызывающим

Завершение не является валидацией или активацией. Прочитайте наблюдения, выберите нужные артефакты, заполните обязательные разделы и пройдите обычные проверки качества и жизненного цикла. `session_status: "completed"` не является статусом артефакта и не подтверждает истинность утверждений.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `session_id` | `string` | да | ID завершаемой сессии. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Поля `session_id`, `project_name`, `session_status`, `total_findings`, `phase_counts`, `tier_counts`, `artifacts_created`, `completed_at`, `_next_action`. `status` остаётся устаревшим псевдонимом статуса сессии; `_field_warnings` поясняет различие.

`artifacts_created` — ID артефактов, уже созданных при записи наблюдений. В обработчике 0.38.0 нет результатов `health`, `proposed` и `next_steps`.

`phase_counts` сопоставляет имена фаз с количеством; `tier_counts` — JSON-объект
с номерами уровней в строковых ключах. Появляются только фазы и уровни с наблюдениями.
`completed_at` — время в RFC 3339. Это JSON-сводка в текстовом содержимом MCP,
не созданный артефакт отчёта; полей трассировки пространства нет.

Обработчик не требует прохождения семи фаз, наличия наблюдений или активной сессии.
Можно завершить пустую сессию; повторный вызов заменяет `completed_at`. Статусы
артефактов наблюдений не меняются. Черновик уже мог быть активирован отдельно,
поэтому читайте текущие артефакты, не считайте подсказку новой проверкой их статусов.
Отсутствующая сессия и ошибки сохранения — текстовые ошибки инструмента;
выбор пространства для записи может завершиться ошибкой JSON-RPC.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "session_id": "disc-20261023-120000"
}
```

## Типичная последовательность

`forgeplan_discover_start` → повторные `forgeplan_discover_finding` → `forgeplan_discover_complete` → `forgeplan_health` → ревью черновиков → валидация и активация тех, которые нужно сохранить.
