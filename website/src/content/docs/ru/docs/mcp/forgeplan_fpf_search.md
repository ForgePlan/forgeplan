Ищет по **базе знаний FPF, загруженной в рабочем пространстве**. По умолчанию используется поиск по ключевым словам. `semantic: true` запрашивает BGE-M3, если сборка его поддерживает. Для этого пути нужны модель, её кеш и загруженный корпус. Ошибки возможностей сборки, модели или векторного поиска могут привести к поиску по ключевым словам с полем `warning`.

**Категория**: База знаний FPF

## Когда агент вызывает эту функцию

- Найти принцип FPF по понятию.
- Прочитать первоисточник перед рассуждением.
- Найти правила выбора между исследованием, проверкой и применением.
- При знакомстве с терминологией FPF.

Если база не загружена, выполните CLI `forgeplan fpf ingest`. Не считайте число разделов фиксированным и не предполагайте идентичное поиску по артефактам ранжирование.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `limit` | `integer \| null` | нет | Максимум результатов: по умолчанию 5, не более 50. По умолчанию в схеме: `null`. `format`: `uint`. `minimum`: `0`. |
| `query` | `string` | да | Search query - keyword or semantic depending on `semantic` flag |
| `semantic` | `boolean \| null` | нет | Запросить семантический (векторный) поиск вместо поиска по ключевым словам. Требует сборки с `semantic-search`. Иначе выполняется поиск по ключевым словам, а поле `warning` объясняет причину. По умолчанию в схеме: `null`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в текстовом содержимом MCP с полями `query`, `semantic`, `count`, `results`, `warning` (строка или `null`) и `_next_action`. Каждый результат содержит `id`, `section_id`, `title`, `snippet`, `line_count`; числовой оценки `score` и `path` нет.

Для следующего `forgeplan_fpf_section` используйте **`section_id`** как входное `id`, не внутренний ID результата. `semantic` отражает запрошенный режим: читайте `warning`, а не считайте `semantic: true` доказательством векторного поиска. Полей `mode` и `total` нет.

Пустые запросы и запросы длиннее 8192 байт отклоняются с `isError` и обычным текстом. Лимит по умолчанию — 5, максимум — 50. Сниппет объединяет первые три строки тела и обрезается до 200 символов; он не обязательно содержит место совпадения. Ключевые слова сопоставляются с заголовком/телом по OR с повышенным весом заголовка, а не BM25 по артефактам. Сбой хранилища при поиске по словам журналируется и может дать успешный пустой результат, поэтому ноль совпадений сам по себе не доказывает отсутствие текста.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "query": "trust calculus",
  "limit": 5
}
```

## Типичная последовательность

1. Вызвать `forgeplan_fpf_search` с нужным понятием.
2. Передать лучший `section_id` во входной `id` инструмента `forgeplan_fpf_section`.
3. Изучить текст в контексте агента либо использовать CLI `forgeplan reason --fpf`, если нужно такое дополнительное обоснование.

## Эквивалент CLI

```bash
forgeplan fpf search "trust calculus"
forgeplan fpf search "uncertainty" --semantic
```
