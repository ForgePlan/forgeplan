---

Запускает цикл FPF ADI (абдукция → дедукция → индукция) для артефакта через настроенного LLM-провайдера. Запрашивает конкурирующие гипотезы, проверяемые предсказания и итоговый вывод. Обработчик MCP передаёт контекст артефакта, но не дополнительный материал базы знаний FPF; входного флага `fpf` нет. Параметр CLI `--fpf` относится к другой поверхности.

**Категория**: Рассуждения и ИИ

## Когда агент вызывает эту функцию

- После валидации и до реализации, если процесс команды требует ADI. Требование ADI для Deep/Critical — политика процесса, а не обязательный гейт этого обработчика.
- Когда пользователь колеблется между двумя подходами - ADI формирует сопоставимые предсказания.
- Во время состязательной ревью: переосмыслить с другими ограничениями для стресс-тестирования текущего решения.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `id` | `string` | да | ID артефакта для анализа по циклу ADI. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Поля `artifact_id`, `artifact_title`, `analysis`, `provider`, `model`, сведения о рабочем пространстве и `_next_action`. Прочитайте текст `analysis`: отдельных JSON-массивов `hypotheses`, `deduction`, `induction` здесь нет.

Ответ LLM — предложение, не измеренное доказательство. Проверьте рассуждения и валидируйте артефакт, прежде чем на него опираться.

Обработчик загружает конфигурацию LLM с переопределениями из окружения и вызывает провайдера. Он не сохраняет анализ в артефакт и не создаёт доказательства. Отсутствующий ID возвращает ошибку MCP; сбой провайдера — `isError` с текстом и подсказкой по настройке/входу, а не подменный анализ.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "id": "PRD-001"
}
```

## Типичная последовательность

Рекомендуемый процесс: `forgeplan_validate` → `forgeplan_reason` → обсудить гипотезы и неопределённость с пользователем → уточнить решение или собрать доказательства → реализация. Инструмент не обеспечивает выбор пользователем, порог уверенности или автоматический переход к кодированию.
