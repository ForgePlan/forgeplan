title: forgeplan_list
description: "Перечислить артефакты с необязательными фильтрами kind и status. Возвращает ID, тип, статус и заголовок."
---

Возвращает отфильтрованный перечень артефактов в рабочем пространстве. Это самый экономичный вызов для обнаружения - агенты используют его для ответов на вопросы, такие как "какие PRD активны?" или "сколько у нас просроченных ADR?" без получения полного содержимого. Для полнотекстового обнаружения агенту следует использовать `forgeplan_search`.

**Категория**: Чтение артефактов

## Когда агент вызывает эту функцию

- Запуск сессии: агенту нужен быстрый обзор существующих элементов, прежде чем принимать решение о следующем действии.
- Фильтрация по состоянию: "покажи мне все черновики PRD" перед выполнением пакетной валидации.
- Ответ на вопрос пользователя, например "сколько RFC мы выпустили?" - полное содержимое не требуется.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `kind` | `string \| null` | нет | Необязательный фильтр по типу артефакта. По умолчанию в схеме: `null`. |
| `status` | `string \| null` | нет | Необязательный фильтр по статусу. По умолчанию в схеме: `null`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — объект JSON в MCP `content[0].text`: `artifacts`, `total` и `_next_action`. Каждая краткая запись содержит `id`, `kind`, `status`, `title`, `id_canonical` и `id_display`; `slug`, `predicted_number` и `assigned_number` появляются только при наличии. Краткая запись не содержит `depth`, `tags`, дат или тела. Подробности записи читайте через `forgeplan_get`. `total` считает отфильтрованный результат, а не всё рабочее пространство. Вызов не меняет статус артефактов.

Условный пример ответа (старые артефакты без необязательных полей идентификации):

```json
{
  "total": 2,
  "artifacts": [
    { "id": "PRD-042", "kind": "prd", "status": "active", "title": "Auth system", "id_canonical": "prd-042", "id_display": "PRD-042" },
    { "id": "PRD-041", "kind": "prd", "status": "active", "title": "FPF rules", "id_canonical": "prd-041", "id_display": "PRD-041" }
  ],
  "_next_action": "2 active artifact(s). Check trust: `forgeplan_health`."
}
```

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "kind": "prd",
  "status": "active"
}
```

## Типичная последовательность

Обычно это второй или третий вызов сессии - после `forgeplan_init`/`forgeplan_health` и перед `forgeplan_get` для конкретного ID. Агенты часто передают результат в сводку для пользователя без каких-либо дальнейших вызовов MCP.
