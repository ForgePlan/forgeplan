Полнотекстовый поиск по всем артефактам в рабочем пространстве. v0.18.0 использует производственный BM25 (`bm25` crate) с русской морфологией (Snowball stemmer), удалением шума из шаблонов и пакетным поиском O(N). Это основной инструмент агента для вопросов типа «найти что-либо о X» - он гораздо функциональнее, чем `forgeplan_list` (который работает только с метаданными), и значительно дешевле, чем цикл `forgeplan_get`.

**Категория**: Чтение артефактов

## Когда агент вызывает эту функцию

- Пользователь спрашивает: «У нас уже есть решение о повторных попытках?» - агент выполняет поиск, прежде чем создать новый ADR.
- Проверка на дубликаты перед `forgeplan_new`: убедиться, что ни один существующий PRD уже не охватывает эту тему.
- Сбор контекста для `forgeplan_reason`: извлечь 3-5 связанных артефактов для инициализации запроса ADI.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `depth` | `string \| null` | нет | Фильтр по глубине: `tactical`, `standard`, `deep`, `critical`. По умолчанию в схеме: `null`. |
| `kind` | `string \| null` | нет | Фильтр по типу артефакта, например `"prd"`, `"rfc"`. По умолчанию в схеме: `null`. |
| `limit` | `integer` | нет | Максимальное число результатов. По умолчанию 20. По умолчанию в схеме: `20`. `format`: `uint`. `minimum`: `0`. |
| `mode` | `string \| null` | нет | Режим поиска: `"keyword"`, `"semantic"` или `"smart"` (по умолчанию). По умолчанию в схеме: `null`. |
| `no_evidence` | `boolean` | нет | Только артефакты без доказательств, R_eff == 0. По умолчанию в схеме: `false`. |
| `no_expand` | `boolean` | нет | Отключить расширение графа на один переход для лучших результатов. По умолчанию в схеме: `false`. |
| `query` | `string` | да | Поисковый запрос: BM25 и необязательный семантический поиск, без учёта регистра. |
| `since` | `string \| null` | нет | Фильтр по дате `created_at` в формате YYYY-MM-DD. По умолчанию в схеме: `null`. |
| `status` | `string \| null` | нет | Фильтр по статусу, например `"active"` или `"draft"`. По умолчанию в схеме: `null`. |
| `with_evidence` | `boolean` | нет | Только артефакты со связанными доказательствами, R_eff > 0. По умолчанию в схеме: `false`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — объект JSON в MCP `content[0].text` с полями `results`, `total` и `_next_action` (не `hits` и не `query`). Каждый результат содержит `id`, `kind`, `title`, `status`, `matched_lines`, `score`, `bm25_score`, `semantic_score`, `r_eff`, `id_canonical` и `id_display`. Необязательные `slug`, `predicted_number` и `assigned_number` отсутствуют, если не заданы. Результат расширения графа может содержать `expanded_from` — ID исходного артефакта, а не тип связи.

В 0.38.0 режимы `smart` (по умолчанию) и `semantic` вызывают один путь BM25 smart-поиска **без семантических векторов** (#546). На этом пути `matched_lines` пуст. Расширение графа включено по умолчанию, если граф удалось загрузить; `no_expand: true` его отключает. `keyword` использует поиск подстроки, возвращает до пяти строк с номерами и нули во всех трёх поисковых оценках. Он применяет `kind` и `limit`, но игнорирует составные фильтры `status`, `depth`, доказательств и `since` (#544); дата `since` всё равно разбирается до выбора ветки. `limit: 0` превращается в 20. Пустой запрос возвращает текстовую ошибку инструмента; неверная дата `since` — ошибку JSON-RPC invalid params.

В smart/semantic фильтры применяются **только к прямым совпадениям**. Расширение графа по умолчанию добавляет соседей из полного набора записей без повторной проверки `kind`, `status`, `depth`, доказательств или даты. Итог поэтому может содержать соседа вне фильтров. Задайте `no_expand: true`, если весь результат smart/semantic должен соответствовать фильтрам; это не исправляет игнорирование составных фильтров в keyword.

Условный ответ keyword (не результат реального вызова):

```json
{
  "results": [
    { "id": "PRD-042", "kind": "prd", "title": "Auth system", "status": "active", "matched_lines": ["L12: OAuth2 authentication flow with refresh tokens"], "score": 0.0, "bm25_score": 0.0, "semantic_score": 0.0, "r_eff": 0.0, "id_canonical": "prd-042", "id_display": "PRD-042" }
  ],
  "total": 1,
  "_next_action": "1 hit(s). Read top result: `forgeplan_get PRD-042`."
}
```

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "query": "authentication flow",
  "limit": 5
}
```

## Типичная последовательность

`forgeplan_search` → агент выбирает кандидата → `forgeplan_get` читает тело → агент решает, изменить, заместить или создать артефакт. Поиск перед созданием — рекомендуемый порядок работы агента, а не встроенная в обработчик защита от дубликатов.
