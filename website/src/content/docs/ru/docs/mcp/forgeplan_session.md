Показать текущее состояние сессии методологии - в какой фазе вы находитесь (`idle` / `routing` / `shaping` / `coding` / `evidence` / `pr`), активный артефакт, управляющий сессией, маршрутизированную глубину и включено ли принудительное применение методологии. Сессия - это конечный автомат Forgeplan, который связывает Route → Shape → Code → Evidence → Activate воедино (PRD-019).

**Категория**: Качество

## Когда агент вызывает его

-   **Возобновить работу** - "что я делал раньше?" - сессия запоминает активный артефакт и фазу.
-   **Перед переходом** - прочитать состояние, затем вызвать `forgeplan_guard`, чтобы проверить, разрешен ли следующий переход.
-   **Проверки согласованности** - если вы думаете, что вы "coding", но сессия говорит `shaping`, что-то не так.
-   **Онбординг новых агентов** - они могут найти точку входа в рабочий процесс с помощью этого инструмента.

## Входные параметры

_Объявленных входных полей нет. Вызывайте инструмент с пустым объектом `{}`._

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

| Поле | Значение |
|---|---|
| `phase` | Сохранённая фаза сессии: `idle`, `routing`, `shaping`, `coding`, `evidence`, `pr`. |
| `active_artifact` | Артефакт, с которым связана сессия, если задан. |
| `route_depth` | Сохранённая строка глубины или `null`; обработчик MCP route её не сохраняет. |
| `enforced` | Вычисляется из глубины: false для `null` или точного `"tactical"`, иначе true. Не доказывает выполнение хуков или валидационных гейтов. |
| `phase_started_at` | Время начала текущей фазы. |
| `history_count` | Число записей истории, не сама история. |
| `next_action`, `_next_action` | Рекомендации следующего шага. |

Сессия отличается от фаз отдельных артефактов в [`forgeplan_phase`](/ru/docs/mcp/forgeplan_phase/). В ответе нет `depth`, `enforcement`, `started_at` или массива `history`.

Успешный ответ — JSON в текстовом содержимом MCP. Инструмент читает `.forgeplan/session.yaml`, не изменяя его; отсутствующий, нечитаемый или неверный файл даёт состояние idle по умолчанию с null в необязательных полях и пустой историей. Сохраняется до 20 переходов истории. Аргумента рабочего пространства для отдельного вызова нет. Состояние сессии отдельно от фактической работы над кодом; устаревшая сессия не доказывает, что работа не сделана.

## Типичная последовательность

1. `forgeplan_session` — прочитать состояние.
2. `forgeplan_guard` с целевой фазой сессии — проверить переход.
3. При разрешённом переходе выполнить соответствующую работу.
4. Прочитать сессию после операции, не выводя её состояние из отдельного маркера фазы артефакта.

## Эквивалент CLI

```bash
forgeplan session
```
