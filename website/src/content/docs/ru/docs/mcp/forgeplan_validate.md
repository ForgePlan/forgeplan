Запускает валидатор на основе правил для артефакта. Каждый тип (PRD, RFC, ADR, Epic, Spec) имеет набор правил, учитывающих глубину (более 30 правил), который проверяет обязательные разделы, поля frontmatter, плотность и перекрёстные ссылки. Сбои типа MUST блокируют `forgeplan_activate`. Это основной гейт качества агента перед объявлением артефакта «готовым».

**Категория**: Качество и валидация

## Когда агент вызывает эту функцию

- Сразу после заполнения заглушки - «покрыл ли я всё, что требуется шаблоном?»
- В цикле с `forgeplan_update`: валидировать → исправить результат → валидировать → повторять до статуса PASS.
- Проверка перед активацией: если остаются какие-либо MUST-сбои, `forgeplan_activate` всё равно завершится неудачей, поэтому сначала выполните валидацию.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `id` | `string \| null` | нет | ID артефакта для валидации. Если опущен, проверяются все артефакты. По умолчанию в схеме: `null`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в MCP `content[0].text` с `total_artifacts`, `total_passed`, `total_errors`, `total_warnings`, `results` и необязательным `_next_action`. Каждый результат содержит `artifact_id`, `kind`, `depth`, `passed`, `error_count`, `warning_count`, `findings`; каждое замечание — `rule_id`, `severity` (`MUST`, `SHOULD`, `COULD`), `message` и допускающее null поле `section`. Поля `status: PASS` нет.

Без `id` проверяются все записи хранилища. Заданный отображаемый ID сравнивается без учёта регистра; отсутствующий ID возвращает текстовую ошибку инструмента MCP (`isError: true`). Замечания валидации — успешный отчёт, даже если `passed` равен false. Успешная проверка может продвинуть рекомендательную фазу до `validate`, если отслеживание включено, но не активирует артефакт. Одного прохождения MUST недостаточно для всех гейтов активации; используйте `review`.

Условный ответ для пустого рабочего пространства:

```json
{
  "total_artifacts": 0,
  "total_passed": 0,
  "total_errors": 0,
  "total_warnings": 0,
  "results": [],
  "_next_action": "All passed! Implement → create EvidencePack with structured fields (verdict/congruence_level/evidence_type) → `forgeplan_link EVID-XXX <id>` → `forgeplan_activate <id>`."
}
```

```json

```

## Типичная последовательность

`forgeplan_update` → `forgeplan_validate` → (если есть MUST-сбои) `forgeplan_update` исправление → `forgeplan_validate` снова → PASS → `forgeplan_activate`. Этот же инструмент также полезен в цикле устранения проблем `forgeplan_health` при очистке слепых пятен.
