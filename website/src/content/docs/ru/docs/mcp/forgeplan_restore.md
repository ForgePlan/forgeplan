Применяет восстановление конкретного артефакта из его последней неиспользованной записи в `.forgeplan/trash/`. После delete пересоздаёт запись хранилища и пытается вернуть проекцию; после supersede/deprecate сбрасывает сохранённые статус и заголовок, а после supersede также пытается удалить связь с заменой. Сохранённые связи добавляются заново, если другой конец существует. Нужна доступная запись восстановления; restore запускает ленивое удаление записей старше 30 дней, поэтому не рассчитывайте на их сохранность после этого срока.

**Категория**: Жизненный цикл и восстановление

## Когда агент вызывает

- «Восстанови PRD-042» — пользователь выбрал ошибочно удалённый артефакт.
- Отменить конкретный ошибочный supersede/deprecate после изучения записи восстановления.
- Восстановить известный ID, когда [`forgeplan_undo_last`](/ru/docs/mcp/forgeplan_undo_last/) выбрал бы другую операцию.

Это изменение состояния, **не аудит записи, не предварительный просмотр и не dry-run**. До вызова изучите запись на диске и журнал активности. Параметра предварительного просмотра и интерактивного подтверждения нет.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `id` | `string` | да | ID артефакта для восстановления из последней неиспользованной записи в корзине. |
| `target_status` | `string \| null` | нет | Issue #291: optional explicit override of the restored status. Default behaviour reads `prior_status` from the receipt snapshot (which captures the artifact's status at the moment of `_delete` / `_deprecate` / `_supersede`). Pass `target_status: "active"` to force a specific status - useful when the operator wants to restore to a different state than was captured.  Valid values: `"draft"`, `"active"`, `"deprecated"`. Unknown values are rejected with a structured error. По умолчанию в схеме: `null`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Ответ содержит `restored`, `op_reversed` (`delete`, `supersede` или `deprecate`), `relations_restored`, `relations_skipped`, `projection_restored`, `restored_status`, `restored_status_source`, `warnings` и `_next_action`. Этот обработчик не добавляет сведения трассировки рабочего пространства.

`relations_skipped` перечисляет отсутствующие противоположные концы связей; другие проблемы записи связей попадают в `warnings`. Возможен успех с предупреждениями или `projection_restored: false`. Недоступные записи восстановления, коллизии и недопустимые переопределения дают текст ошибки MCP, а не JSON-объект `ok: false`.

## Проверки и побочные эффекты

- `id` выбирает последнюю неиспользованную запись по отображаемому ID или сохранённому slug. Это не ID самой записи восстановления и не доказательство того, что деструктивная операция завершилась успешно.
- Без `target_status` восстанавливается статус снимка. Переопределение нормализуется trim/lowercase и допускает только `draft`, `active`, `deprecated`. Если запись артефакта ещё существует, переход проверяется от её текущего статуса. Даже явная передача статуса снимка может вызвать отказ там, где отсутствие переопределения сработало бы.
- Для восстановления после delete запрещена любая уже существующая запись с тем же ID. После supersede/deprecate отклоняется существующая запись другого типа; заголовок снимка может перезаписать более позднее переименование.
- Запись восстановления помечается использованной. Проблемы связей и проекции могут стать предупреждениями, а не откатом. Если пометка использованной записи не удалась, ошибка возвращается **после восстановления хранилища**; изучите состояние, не повторяйте вызов и не удаляйте конфликтующий артефакт автоматически.

## Ограничения 0.38.0

- `restored_status_source` должен различать снимок и переопределение, но обработчик сравнивает запрос с уже применённым результатом. Поле может сообщить `receipt_snapshot`, даже если переопределение изменило сохранённый статус. Проверяйте `restored_status` и исходную запись, а не считайте поле источника доказательством.
- После supersede/deprecate оставшаяся Markdown-проекция не перерисовывается, а раздел тела о выводе из использования не удаляется. `projection_restored: true` здесь означает, что файл не перемещался, а не актуальность его статуса, связей или тела.
- Восстановление не повторяет проверки активации, не пересчитывает зависимые оценки и не сбрасывает историю рекомендательных фаз. Перед продолжением работы изучите запись хранилища и проекцию на диске.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "id": "PRD-001"
}
```

## Типичная последовательность

1. [`forgeplan_activity`](/ru/docs/mcp/forgeplan_activity/) - найти, когда произошла деструктивная операция.
2. `forgeplan_restore` - восстановить конкретный артефакт.
3. [`forgeplan_get`](/ru/docs/mcp/forgeplan_get/) - проверить тело, статус, связи.
4. При необходимости - вручную перевосстановить пропущенные связи.

## CLI эквивалент
