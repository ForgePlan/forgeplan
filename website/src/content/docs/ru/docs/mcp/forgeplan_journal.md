Показывает журнал решений: без `kind` временная шкала включает ADR, Note, PRD, RFC, Epic, Spec, Problem и Solution с плоским `R_eff` и числом доказательств. Явный фильтр `kind` принимает только `adr`, `note`, `problem` или `solution`; его четыре значения enum не ограничивают выборку без фильтра. Обоснование записи и поддерживающие связи читайте через `forgeplan_get`.

**Категория**: Панели мониторинга и графики

## Когда агент вызывает его

- **Начало сессии после долгого отсутствия** - просмотр последних N решений для восстановления контекста.
- **Перед принятием связанного решения** - проверка, охватывает ли предыдущий Note / ADR / Problem уже эту тему.
- **Аудит рисков** - вызов с `risk: true` для отображения только решений со слабыми или просроченными доказательствами.
- **Онбординг** - создание повествования об истории решений проекта.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `kind` | `string \| null` | нет | Фильтр по типу артефакта, только типы журнала решений. string: Значения enum: `"adr"`, `"note"`, `"problem"`, `"solution"`. |
| `risk` | `boolean \| null` | нет | Показывать только решения с риском. По умолчанию в схеме: `null`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в MCP `content[0].text`: `entries`, `total`, `_next_action`. Запись содержит ровно `id`, `title`, `kind`, `created_at`, `r_eff`, `evidence_count`, `has_stale_evidence`. Во внутренней записи есть статус, но MCP-сериализатор его не выдаёт. Массивов ID доказательств и поля `at_risk` у записи нет.

Записи отсортированы по строке `created_at` по убыванию, включены все статусы жизненного цикла. `risk` по умолчанию false; true оставляет записи без доказательств, с плоским `r_eff < 0.3` или просроченным допустимым доказательством. Подсказка отдельно считает риск по `< 0.5`, поэтому её число может отличаться от определения фильтра. `evidence_count` включает терминальные связанные пакеты, хотя их оценки/просрочка исключены из плоского расчёта. Это свежий плоский расчёт доказательств, а не кешированная рекурсивная оценка; он не сохраняет оценки и не меняет артефакты.

Условный ответ для одного ADR без доказательств:

```json
{
  "entries": [
    {"id": "ADR-005", "kind": "adr", "title": "Storage design", "created_at": "2026-04-03T00:00:00Z", "r_eff": 0.0, "evidence_count": 0, "has_stale_evidence": false}
  ],
  "total": 1,
  "_next_action": "1 at-risk of 1 entries. Score the worst: `forgeplan_score ADR-005`."
}
```

Ошибки пространства возвращаются текстом, сбои журнала/хранилища могут быть JSON-RPC ошибками, а не успешной пустой временной шкалой.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "kind": "adr",
  "risk": true
}
```

## Типичная последовательность

1. `forgeplan_journal` с `risk: true` - список рискованных решений.
2. `forgeplan_get` для каждой записи - чтение полного содержимого.
3. `forgeplan_new` доказательство → `forgeplan_link` → `forgeplan_score` - обновление R_eff.

## Эквивалент CLI

```bash
forgeplan journal --type adr --risk
```
