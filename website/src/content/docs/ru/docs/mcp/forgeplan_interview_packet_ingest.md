**В Forgeplan 0.38.0 инструмент возвращает `not_implemented` после проверки рабочего пространства и пути.** Установка [`forgeplan-brownfield-pack`](/ru/docs/marketplace/forgeplan-brownfield-pack/) не включает обработчик: плагин не загружается, расшифровка не читается. Подсказка установки описывает предполагаемый рабочий процесс, не реализованную передачу вызова.

Это объявленная сторона обработки ответов API интервью. Парный [`forgeplan_interview_packet_draft`](/ru/docs/mcp/forgeplan_interview_packet_draft/) тоже является заглушкой и вопросов не создаёт.

**Категория**: Прочее

## Что он делает сейчас

1. Разрешает рабочее пространство через путь записи, что также валидирует существование рабочего пространства.
2. Захватывает блокировку рабочего пространства.
3. Если передан `transcript_path`, проверяет относительность пути, отсутствие сегментов `..`, нулевых байтов и префиксов дисков Windows. Нарушение возвращает текстовую ошибку инструмента (`isError: true`) со строкой `_next_action:` после выбора пространства и получения блокировки.
4. Возвращает этот фиксированный JSON в текстовом содержимом MCP как успешный результат, не ошибку инструмента:

```json
{
  "_next_action": "Fix: install plugin — see marketplace issue #79 (`forgeplan-brownfield-pack`).",
  "marketplace_issue": 79,
  "message": "Install forgeplan-brownfield-pack plugin to enable; or invoke via shell pipeline temporarily.",
  "status": "not_implemented"
}
```

Файл не открывается, и артефакт не предлагается.

Файл по пути не обязан существовать: проверка только лексическая. Выбор
пространства может завершиться ошибкой JSON-RPC; получение блокировки — ошибкой
инструмента. Поля `resolved_via` и `resolved_workspace` в результат не добавляются.

## Отдельный рабочий процесс marketplace

Опубликованный навык `interview-packager` описывает обработку заполненных пакетов и обновление гипотез агентом. Запускайте его отдельно. Обработчик MCP core не вызывает навык, не предлагает артефакты и не записывает результаты интервью в граф.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `transcript_path` | `string \| null` | нет | Путь к заполненной расшифровке относительно корня рабочего пространства. Заглушка проверяет относительность пути и отсутствие `..`, но core 0.38.0 не передаёт файл плагину и не читает его. По умолчанию в схеме: `null`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Валидация пути

Путь с `..`, абсолютный POSIX-путь, нулевой байт или Windows-префикс диска отклоняется с подсказкой исправления.

На POSIX путь `C:\interviews\a.md` не является абсолютным, поэтому префикс диска проверяется отдельно. Эти проверки проверяют аргумент; в 0.38.0 за ними не следует чтение файла или передача его плагину.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "transcript_path": "interviews/billing.md"
}
```

## Примечания

- **Эхо пути санитизировано.** Текст ошибки пропускает нарушающий путь через тот же санитайзер, который используют подсказки продвижения, поэтому управляющие символы и escape-последовательности удаляются из того, что вы видите.
- **Повторный вызов ничего не импортирует.** Аннотация идемпотентности не гарантирует отсутствие ошибок выбора пространства и получения блокировки.
- **В отличие от заглушки draft, эта не возвращает разрешённое рабочее пространство.** Трассировка вычисляется и отбрасывается, поэтому если вам нужно доказательство роутинга, явно укажите `workspace` и прочитайте его обратно из другого инструмента.
- **Содержимое никогда не принимается встроенным.** Нет поля для тел расшифровок - только путь. Не проектируйте интеграцию, которая вставляет расшифровку в вызов.
- **Что использовать вместо этого сегодня:** протокол обнаружения ([`forgeplan_discover_start`](/ru/docs/mcp/forgeplan_discover_start/) плюс [`forgeplan_discover_finding`](/ru/docs/mcp/forgeplan_discover_finding/)) записывает находки в сессию, а [`forgeplan_hypothesis_promote`](/ru/docs/mcp/forgeplan_hypothesis_promote/) - это способ действовать на основе выводов интервью.
