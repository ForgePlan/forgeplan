Проверяет один сохранённый артефакт валидатором и общими методологическими гейтами активации. Для типов с жизненным циклом это минимальная длина тела, поиск заглушек и связи с доказательствами; связи с черновиками также дают предупреждения. Ревью не пересчитывает R_eff, не меняет статус и не запускает синхронизацию проекции или гейт происхождения изменений из обработчика активации. Поэтому `can_activate` — отчёт о готовности, а не гарантия успешной последующей активации.

**Категория**: Качество

## Когда агент вызывает его

- **Перед активацией** - убедитесь, что все гейты пройдены, чтобы избежать ошибок активации.
- **Ревью PR** - запускается для каждого затронутого артефакта, чтобы выявить отсутствующие разделы или сбои MUST.
- **Самопроверка автора** - быстрее, чем запуск `validate` + `score` + ручная проверка жизненного цикла.
- **Автоматизированные хуки качества** - pre-commit / CI может вызвать это и прервать сборку, если какой-либо артефакт регрессирует.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `id` | `string` | да | ID артефакта для ревью. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в MCP `content[0].text`: `artifact_id`, `can_activate`, `must_findings`, `should_findings`, `warnings` и `_next_action`. Замечания и предупреждения — массивы строк, а не вложенные объекты `validation`/`lifecycle`. `verdict`, `status`, `kind`, `depth` и значение R_eff не возвращаются.

Для `can_activate: true` нужны отсутствие MUST-замечаний и прохождение общих методологических гейтов. Сбои гейтов попадают в `warnings`, поэтому false возможен при пустом `must_findings`. Подсказка обработчика считает только MUST; читайте и `warnings`. Отсутствующий артефакт или ошибка жизненного цикла возвращает текстовую ошибку инструмента MCP (`isError: true`); отчёт о неготовности сам по себе не ошибка инструмента.

Условный ответ о готовности:

```json
{
  "artifact_id": "PRD-042",
  "can_activate": true,
  "must_findings": [],
  "should_findings": [],
  "warnings": [],
  "_next_action": "Ready. Activate: `forgeplan_activate prd-042`."
}
```

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "id": "PRD-001"
}
```

## Типичная последовательность

1. `forgeplan_review` → если `can_activate` равен false, прочитайте замечания и предупреждения.
2.  `forgeplan_update` для исправления тела.
3. `forgeplan_review` снова → проверьте `can_activate`.
4.  `forgeplan_activate` - перевести черновик → активный.

## Эквивалент CLI

```bash
forgeplan review PRD-042
```
