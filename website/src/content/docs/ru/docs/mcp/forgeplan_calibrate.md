---

Рекомендует глубину артефакта по детерминированным эвристикам, не меняя артефакт. Реализация этого релиза предлагает `Tactical`, `Standard` или `Deep`; отдельного уровня `Critical` не выдаёт. Валидация с учётом глубины и политика команды по ADI/ревью — отдельные от рекомендации механизмы.

**Категория**: Качество

## Когда агент вызывает его

- **После создания заглушки** - позвольте калибровке предложить правильный уровень глубины перед заполнением разделов.
- **Во время ревью** - проверьте, что автор выбрал разумный уровень глубины.
- **Аудиторская проверка** - найдите артефакты, помеченные как `Tactical`, которые на самом деле требуют `Deep` на основе содержимого.
- **При обучении агентов** - научите их, какие факторы повышают уровень глубины (безопасность, критические изменения, межкомандный охват).

Сигналы включают число чекбоксов, английские маркеры безопасности/несовместимых изменений, число исходящих связей, родительский Epic, число H2-разделов и строк тела. Пороги чекбоксов — >3 для Standard и >10 для Deep; связей >2/>5, H2-разделов >4/>8, строк >50/>200. Маркеры безопасности или несовместимых изменений дают Deep; родительский Epic — Standard. Выбирается наивысший сигнал, без сигналов — Tactical. Это эвристический поиск текста, а не семантический или независимый от языка анализ.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `id` | `string \| null` | нет | ID артефакта. Если опущен, проверяются все артефакты. По умолчанию в схеме: `null`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Условный JSON в текстовом содержимом MCP:

```json
{
  "results": [
    {
      "artifact_id": "PRD-042",
      "artifact_title": "Login flow",
      "current_depth": "tactical",
      "suggested_depth": "Deep",
      "escalation_needed": true,
      "signals": [
        {"name": "security_section", "value": "present", "minimum_depth": "Deep"}
      ]
    }
  ],
  "total_escalations": 1,
  "_next_action": "Illustrative guidance to review an under-depth artifact."
}
```

`results` включает каждую проверенную запись, а не только несоответствия. `total_escalations` считает только рекомендации выше текущей глубины. Рекомендуемая глубина и глубина сигналов — с заглавной буквы; `current_depth` сохраняет значение из записи. С `id` сравнение не учитывает регистр, неизвестный ID возвращает ошибку MCP. Ошибки чтения связей журналируются и считаются нулём связей. LLM и автоматической записи глубины нет.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.


## Типичная последовательность

1. `forgeplan_calibrate` - сканирует рабочее пространство.
2. Проверьте каждую рекомендацию повышения и явно измените глубину во frontmatter, если это обоснованно; повторный роутинг сам её не меняет.
3. Валидируйте с новой глубиной.
4. Выполните ADI/ревью по политике команды; калибровка эти шаги не обеспечивает.

## Эквивалент CLI
