Единственный поддерживаемый писатель для жизненного цикла `kind: hypothesis`. Гипотеза несёт
поле `hypothesis_state:` во frontmatter, и этот инструмент - единственное, что его перемещает.
[`forgeplan_activate`](/ru/docs/mcp/forgeplan_activate/) намеренно отклоняет этот kind и перенаправляет
сюда, потому что обычная активация переключила бы `status`, не затрагивая `hypothesis_state`, и оставила бы
два поля в противоречии.

Каждый вызов переписывает артефакт в трёх связанных местах:

1. `hypothesis_state:` во frontmatter перезаписывается целевым состоянием.
2. `status` выводится из этого целевого состояния в той же записи, поэтому пара никогда не может разойтись:
   `verified` становится `active`, `refuted` становится `deprecated`, а `parked` / `inferred` /
   `strong-inferred` все остаются `draft`.
3. Одна строка аудита добавляется в секцию тела `## Lifecycle State` - создаётся на месте, если
   устаревший артефакт предшествует ей.

Мутация проходит через вспомогательный механизм проекции file-first (сначала markdown, затем строка хранилища),
и весь обработчик выполняется под блокировкой записи рабочего пространства, поэтому два агента, продвигающие одну и ту же
гипотезу, не могут потерять строку аудита.

**Категория**: Прочее

## Когда агент вызывает это

- **Прибыло доказательство.** Проход извлечения brownfield припарковал утверждение, затем появилось подтверждающее доказательство:
  шаг вперёд, `parked` → `inferred` → `strong-inferred` → `verified`.
- **Появилось контр-доказательство.** `any` → `refuted` в любой момент; это также переключает `status` на
  `deprecated`, и список каскада в ответе называет нижестоящие артефакты для пересмотра.
- **Сигнал был недостаточным.** `any` → `parked` - это обратимая приостановка, а `parked` → `inferred`
  позже возобновляет работу.
- **Активация.** Продвижение в `verified` - единственный путь, который делает гипотезу `active`.
  Вызов [`forgeplan_activate`](/ru/docs/mcp/forgeplan_activate/) вместо этого возвращает ошибку, говорящую
  использовать этот инструмент с `new_state=verified` (активировать) или `new_state=refuted` (отменить).
- **После вызова.** Следуйте возвращённому `_next_action` и пересчитайте то, что питает гипотеза, через
  [`forgeplan_score`](/ru/docs/mcp/forgeplan_score/).

## Конечный автомат верификации

Прямая цепочка строго пошаговая. `parked`, `inferred` и `strong-inferred` - это рабочие состояния; `verified` и `refuted` - терминальные состояния, которые поглощают прямые переходы.

| Состояние | Значение | Допустимые следующие состояния |
|---|---|---|
| `parked` | На паузе - ничего ещё не собрано или работа намеренно приостановлена. Обратимо. | `inferred`, `parked`, `refuted` |
| `inferred` | Утверждение сформулировано с некоторым сигналом, подтверждающих доказательств пока нет. Значение по умолчанию в шаблоне. | `parked`, `inferred`, `strong-inferred`, `refuted` |
| `strong-inferred` | Одно или несколько независимых доказательств согласуются, но планка для `verified` не достигнута. | `parked`, `strong-inferred`, `verified`, `refuted` |
| `verified` | Терминальное. Нижестоящие артефакты могут считать утверждение несущим. | `parked`, `verified`, `refuted` |
| `refuted` | Терминальное. Контр-доказательство опровергло утверждение. | `parked`, `refuted` |

Правила, стоящие за этой таблицей:

- **Вперёд, на один шаг.** `parked` → `inferred`, `inferred` → `strong-inferred`, `strong-inferred` → `verified`. Пропуск шага (`parked` → `verified`) отклоняется.
- **Без понижения.** `verified` → `inferred` и `verified` → `strong-inferred` отклоняются - верифицированное утверждение не откатывается, вместо этого создаётся новая гипотеза.
- **Два универсальных стока.** `any` → `refuted` (контр-доказательство может появиться в любой момент) и `any` → `parked` (приостановить работу) всегда разрешены.
- **Из того же в то же** допустимо в конечном автомате, но короткозамкнуто этим инструментом - см. [Идемпотентное повторное применение](#idempotent-re-application).

## Входные параметры

| Имя | Тип | Обязательный | Описание |
|---|---|---|---|
| `hypothesis_id` | `string` | да | ID или slug артефакта гипотезы (`HYP-001`, `hyp-some-claim`). Должен разрешаться в артефакт, у которого `kind` равен `hypothesis`. |
| `new_state` | `string` | да | Целевое состояние в kebab-case: `parked`, `inferred`, `strong-inferred`, `verified` или `refuted`. Парсится без учёта регистра после обрезки пробелов, и `strong_inferred` / `stronginferred` принимаются как синонимы. |
| `evidence_refs` | `string[]` | нет | ID артефактов доказательств, обосновывающих переход, обычно `EVID-NNN`. По умолчанию пустой список, что допустимо для паузы, но не для `verified`. Каждая запись должна соответствовать формату ID: одна ведущая ASCII-буква, затем буквы, цифры, `-` или `_`. |
| `rationale` | `string` | да | Однострочная причина для аудиторского следа, сохраняется дословно в теле. Встроенные переносы строк и управляющие символы отклоняются. |
| `workspace` | `string` | нет | Явная директория рабочего пространства для этого вызова, чтобы агент в git worktree мог обратиться к своему собственному `.forgeplan/` вместо директории запуска сервера. Абсолютный путь или путь с тильдой. |

_Источник схемы: `crates/forgeplan-mcp/src/server.rs::HypothesisPromoteParams`_

## Что делает

1. Захватывает блокировку записи рабочего пространства, чтобы конкурентные промоушены выполнялись последовательно, а не состязались за добавление строки аудита. Удерживаемая блокировка возвращает ошибку с просьбой повторить попытку.
2. Парсит `new_state` до обращения к хранилищу. Неизвестное состояние быстро завершается с ошибкой и выводит допустимый набор.
3. Разрешает `hypothesis_id` (id или slug) в канонический id и загружает запись.
4. Применяет гейт по типу: всё, что не является `kind: hypothesis`, отклоняется с подсказкой проверить артефакт через [`forgeplan_get`](/ru/docs/mcp/forgeplan_get/) или найти валидную цель через [`forgeplan_list`](/ru/docs/mcp/forgeplan_list/).
5. Читает текущее состояние из поля `hypothesis_state:` во frontmatter. Отсутствующее, null, не-строковое или непарсимое значение по умолчанию становится `parked` - безопасный выбор, поскольку из него разрешены все переходы вперёд.
6. Проверяет переход по матрице выше. Недопустимый переход возвращает ошибку со списком разрешённых следующих состояний для текущего.
7. Короткое замыкание для no-op (`old == new`) в конверт `unchanged: true` без записи строки аудита - конечный автомат разрешает переход из состояния в себя для идемпотентного повторного применения, но дублирующая запись аудита была бы вводящей в заблуждение.
8. Валидирует `rationale` (без управляющих символов, без Unicode-разделителей строк или параграфов) и каждую запись `evidence_refs` (только форма id).
9. Только для `verified`: требует как минимум одну ссылку на доказательство и разрешает каждую из них в хранилище. Это гейт, который не даёт заглушке гипотезы достичь `status: active` с выдуманными доказательствами.
10. Переписывает frontmatter и добавляет строку аудита, затем сохраняет через хелпер проекции.
11. Перечисляет каскад: артефакты, указывающие на эту гипотезу через отношение `informs` или `based_on`. Только информационно - ничто ниже по течению не пересчитывается и не активируется автоматически.

## Возвращает

Успешный промоушен вперёд возвращает старое и новое состояние, переданные вами refs и rationale, а также каскад:

```json
{
  "_next_action": "Next: re-score downstream artifacts — `forgeplan_score HYP-001`.",
  "cascade": [
    "EVID-001",
    "PRD-001"
  ],
  "evidence_refs": [],
  "id": "HYP-001",
  "new_state": "inferred",
  "old_state": "parked",
  "rationale": "initial signal from the refund policy grep"
}

Строка аудита, записанная в `## Lifecycle State` для этого вызова, выглядит так:

```text
- 2026-09-16: parked → inferred (refs: none; rationale: initial signal from the refund policy grep)
```

Пустой `evidence_refs` отображается как `none`; пустой `rationale` отображается как `(no rationale provided)`.

## Идемпотентное повторное применение

Продвижение в состояние, в котором гипотеза уже находится, ничего не записывает и сообщает об этом:

```json
{
  "_next_action": "Done. - `HYP-001` already in `inferred`.",
  "cascade": [],
  "id": "HYP-001",
  "new_state": "inferred",
  "old_state": "inferred",
  "unchanged": true
}
```

Обратите внимание на пустой каскад в этом конверте: путь без операций возвращается до запуска перечисления каскада,
поэтому пустой список здесь означает «ничего не произошло», а не «от этого ничего не зависит».

## Отклонённые вызовы

Каждое отклонение — это корректная ошибка MCP, текст которой заканчивается строкой исправления `_next_action`.

| Отклонение | Текст ошибки |
|---|---|
| Неизвестное состояние | `unknown hypothesis state:` за которым следует переданное вами значение |
| Неизвестный артефакт | `Artifact 'HYP-999' not found.` |
| Неверный тип | `` artifact `PRD-001` is kind=`prd`, expected `hypothesis` `` |
| Недопустимый переход | `` illegal hypothesis transition for `HYP-001`: `inferred` → `verified` `` |
| Многострочный rationale | `rationale contains control characters or Unicode line separators` |
| Некорректный идентификатор доказательства | `` evidence_ref `not an id` is not a valid artifact id `` |
| Нет доказательств для `verified` | `Cannot promote to verified with no evidence_refs` |
| Отсутствующее доказательство для `verified` | `` evidence_ref `EVID-999` does not exist in workspace `` |

Ошибка недопустимого перехода содержит в подсказке разрешённый набор, например из `inferred`:

```text
Allowed next states from `inferred`: parked, inferred, strong-inferred, refuted.
```

## Замечания по безопасности

- **Это мутация тела.** Операция не является read-only и не помечена как идемпотентная в MCP-аннотациях — успешное продвижение изменяет артефакт на диске.
- **`status` следует за `hypothesis_state`.** Не боритесь с этим через [`forgeplan_update`](/ru/docs/mcp/forgeplan_update/); правило валидации `hypothesis-state-status-consistent` (серьёзность `should`) отмечает гипотезу, у которой эти два поля расходятся.
- **`refuted` отменяет.** Продвижение в `refuted` выводит `status: deprecated`, что сообщает остальной части рабочего пространства о том, что утверждение мертво.
- **Каскад — это совет.** Инструмент никогда не повышает автоматически нижестоящие артефакты по дизайну — агент сам решает, что пересчитывать.

## Пример вызова

```json
{
  "hypothesis_id": "HYP-001",
  "new_state": "strong-inferred",
  "evidence_refs": ["EVID-001"],
  "rationale": "grep evidence corroborates the gate"
}
```

Опровержение утверждения, которое не требует продвижения вперёд:

```json
{
  "hypothesis_id": "HYP-001",
  "new_state": "refuted",
  "evidence_refs": ["EVID-007"],
  "rationale": "integration test shows the gate is bypassed for refunds under 100"
}

Удержание утверждения, которому не хватает сигнала, без доказательств и с обязательным обоснованием:

```json
{
  "hypothesis_id": "HYP-004",
  "new_state": "parked",
  "rationale": "no second source found; revisit after the billing interview"
}
```

## Типичная последовательность

```text
forgeplan_hypothesis_status                    ← где сейчас всё находится
forgeplan_hypothesis_promote (parked → inferred)
forgeplan_hypothesis_promote (inferred → strong-inferred)
forgeplan_hypothesis_promote (strong-inferred → verified)
forgeplan_score HYP-001                        ← возвращённое `_next_action`
```

## Связанные команды

- [`forgeplan graph --brownfield-only`](/ru/docs/cli/graph/) - отображает узлы гипотез, окрашенные в соответствии с их текущим состоянием.
- [`forgeplan anomalies`](/ru/docs/cli/anomalies/) - помечает `untriangulated_hypothesis`, когда у утверждения меньше двух различных ссылок на доказательства.
