Создаёт новый артефакт-заглушку из встроенного шаблона для его типа. Агент вызывает это, когда он решил (обычно через `forgeplan_route`), какой тип артефакта нужен следующим - как правило, сразу после того, как запрос пользователя классифицирован как Standard или более глубокий. Возвращённый ID агент использует для каждой последующей операции.

**Категория**: Создание артефактов

## Когда агент вызывает это

- После того как `forgeplan_route` возвращает `Depth: Standard, Pipeline: PRD → RFC` и агенту нужна заглушка PRD.
- Когда агенту говорят «создать ADR для решения X, которое мы только что приняли», и он хочет получить скелет для заполнения.
- При декомпозиции работы - после того как `forgeplan_decompose` предлагает RFC, агент может вызвать `new` один раз для каждого предложенного RFC.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `kind` | `string` | да | Тип создаваемого артефакта. Значения enum: `"prd"`, `"epic"`, `"spec"`, `"rfc"`, `"adr"`, `"problem"`, `"solution"`, `"evidence"`, `"note"`, `"refresh"`. |
| `parent_id` | `string \| null` | нет | Issue #295: optional parent artifact ID for auto-link. When supplied AND kind=evidence, an `informs` link is created from the new EVID to the named parent in the same call. Reduces the 3-step EVID flow (new → update → link) to 2 steps (new+autolink → update). Accepts display id (`PRD-074`) or slug (`prd-auth-system`). For kinds other than `evidence` the parameter is rejected with a structured error (other auto-link patterns are intentionally out of scope for v1 - see issue #295). По умолчанию в схеме: `null`. |
| `title` | `string` | да | Заголовок артефакта. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Создание возвращает `id`, `kind`, `title`, `filepath`, предупреждения о похожих артефактах `warnings`, `_next_action`, `slug`, `predicted_number`, `assigned_number` при наличии, `id_canonical`, `id_display`, `hint`, `resolved_workspace` и `resolved_via`. Используйте возвращённые поля идентификации, не угадывайте следующий номер.

Для Evidence с `parent_id` поле `auto_linked` включается только при созданной связи с родителем; непустой `auto_link_warnings` описывает сбои. Это отдельное поле, не предупреждения о дубликатах `warnings`. Полного тела и ключа `path` в ответе нет. Прочитайте черновик через `forgeplan_get`, заполните обязательные разделы через `forgeplan_update` и валидируйте его.

## Проверки и побочные эффекты

- Обработчик проверяет заголовок и настроенный предел его размера в байтах, выбирает встроенный тип и шаблон, выделяет ID под координационными блокировками. Новый артефакт получает `draft` и глубину `standard`; аргументов начального статуса, тела или глубины здесь нет.
- Поиск дубликатов рекомендательный: похожие заголовки могут дать предупреждения **и всё равно создать ещё один артефакт**. Это не идемпотентный create-or-get; изучайте предупреждения до повтора после неопределённого результата.
- `parent_id` — необязательное сокращение только для `kind: "evidence"`. Для других типов наличие этого аргумента вызывает отказ до создания.
- Отсутствующий родитель или сбой автоматического связывания не откатывают создание Evidence. При успехе связь идёт от доказательства к родителю с `informs`; `parent_id` не активирует ни один артефакт.
- Создаются запись хранилища и Markdown-проекция. Запись идентификации и начальной рекомендательной фазы `shape` выполняется best-effort. В пути MCP нет интерактивного подтверждения дубликата или согласия.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "kind": "prd",
  "title": "Authentication system"
}
```

## Типичная последовательность

`forgeplan_route` → `forgeplan_new` → `forgeplan_update` (заполнить разделы MUST) → `forgeplan_validate` (PASS) → `forgeplan_reason` (ADI для Standard+) → код → доказательство → `forgeplan_activate`.
