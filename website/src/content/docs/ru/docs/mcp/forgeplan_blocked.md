description: "Показать невыполненные структурные зависимости. Active, deprecated и superseded разрешены; draft, stale и отсутствующие цели могут блокировать."
---

Показывает невыполненные структурные зависимости (`based_on`, `refines`, `supersedes`, `contradicts`): `from` зависит от `to`. Цели со статусом `active`, `deprecated` или `superseded` считаются разрешёнными. Другие цели, включая `stale` и отсутствующие записи, остаются неразрешёнными; проверка не ограничивается черновиками. Информационные связи не блокируют.

**Категория**: Дашборды и Графы

## Когда агент вызывает это

-   **Спринт-планирование** - определение, какие артефакты готовы к работе, а какие ожидают вышестоящих решений.
-   **Перед активацией** - подтверждение отсутствия невыполненных предварительных условий у артефакта перед вызовом `forgeplan_activate`.
-   **Диагностика узких мест** - выявление вышестоящего черновика, который блокирует множество нижестоящих артефактов.
-   **Начало сессии** - быстрый просмотр "что готово к работе" после восстановления контекста.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `id` | `string \| null` | нет | Необязательный ID артефакта. Если опущен, показываются все заблокированные артефакты. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Условный JSON в текстовом содержимом MCP:

```json
{
  "blocked": [{"id": "RFC-006", "blocked_by": ["PRD-039"]}],
  "ready_count": 1,
  "blocked_count": 1,
  "cycles": [],
  "_next_action": "Illustrative guidance to inspect dependencies."
}
```

`blocked_by` содержит строки ID, а не объекты со статусами/связями. В режиме всего пространства рассматриваются только узлы структурных связей; изолированных артефактов нет. Циклические узлы возвращаются в `cycles` и могут отсутствовать в счётчиках ready/blocked. С `id` обработчик переводит его в верхний регистр, проверяет прямые исходящие зависимости и возвращает ту же форму со счётчиками 0/1 и `cycles: []`. Он не проверяет существование запрошенного артефакта, поэтому неизвестный ID может выглядеть незаблокированным. Проверяйте наличие через `forgeplan_get`; это операция чтения графа, а не разрешение на активацию.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{}
```

## Типичная последовательность

1.  `forgeplan_blocked` - список заблокированных артефактов.
2.  `forgeplan_get` для вышестоящего `blocked_by` - проверка его потребностей.
3.  `forgeplan_activate` вышестоящего артефакта после прохождения валидации.
4.  `forgeplan_blocked` снова - подтверждение, что нижестоящий артефакт теперь разблокирован.

## Эквивалент CLI

```bash
forgeplan blocked
forgeplan blocked RFC-006
```
