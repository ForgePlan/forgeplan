Генерирует Mermaid `graph LR` для связанных артефактов рабочего пространства. Включает явные связи (`based_on`, `refines`, `supersedes`, `contradicts`, `informs`) и неявные рёбра `belongs_to` от дочернего артефакта к родителю из `parent_epic`. Разделы Composition моделей предметной области добавляют кластеры и их участников; это не перечень всех изолированных артефактов.

**Категория**: Панели мониторинга и графы

## Когда агент вызывает его

- **Визуализация архитектуры** - показать, как связаны цепочки PRD → RFC → ADR → Evidence.
- **Анализ влияния** - отслеживать, какие нижестоящие артефакты зависят от узла, прежде чем заместить его.
- **Генерация документации** - встроить диаграмму в README или на страницу веб-сайта.
- **Подготовка к ревью** - визуально проверять циклы или отсутствующие рёбра перед релизом.

Ответ — JSON в MCP `content[0].text`; извлеките строку `mermaid` и отобразите её в средстве с поддержкой Mermaid.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `brownfield_only` | `boolean \| null` | нет | Оставить только рёбра между brownfield-типами UC / GLOS / INV / SCEN / HYP / DM. По умолчанию false: показываются все рёбра, включая конвейер артефактов. По умолчанию в схеме: `null`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Объект содержит `mermaid` и `_next_action`, а не массивы узлов/рёбер или `node_count`/`edge_count`. Инструмент строит отчёт, но не добавляет связи и не изменяет артефакты. Число рёбер в подсказке считается до необязательного brownfield-фильтра.

Условный ответ для пустого графа:

```json
{
  "mermaid": "graph LR\n    %% No links found between artifacts\n",
  "_next_action": "No links yet — isolated artifacts. Inspect orphans: `forgeplan_blindspots`."
}
```

Обычно рёбра — сплошные стрелки с подписью, включая `informs` и `contradicts`. `belongs_to` — сплошная стрелка без подписи, `references` — пунктирная. Brownfield-рёбра могут иметь дополнительные настройки `linkStyle`, а узлы гипотез окрашиваются по состоянию. Не всякое отображённое ребро блокирует работу: `order` и `blocked` учитывают только структурные связи.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{}
```

## Типичная последовательность

1. `forgeplan_graph` - получить mermaid.
2. Отобразить его или сохранить в `docs/graph.md`.
3. `forgeplan_order` - получить топологическую сортировку для того же графа.
4. `forgeplan_blocked` - найти узлы, заблокированные невыполненными предварительными условиями.

## Эквивалент CLI

```bash
forgeplan graph
```
