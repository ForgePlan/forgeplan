Запускает **сессию исследования существующей системы**. Forgeplan возвращает семь фаз (`detect`, `structure`, `code`, `git`, `tests`, `docs`, `synthesize`); агент проводит исследование и сообщает наблюдения. `forgeplan_discover_complete` завершает сессию и возвращает количества. В 0.38.0 он не синтезирует предложения и не запускает health за агента.

**Категория**: Обнаружение Brownfield

## Когда агент вызывает это

- Первая сессия в незнакомом репозитории - «что это за проект и в каком он состоянии?»
- Внедрение устаревшей кодовой базы в методологию Forgeplan без создания артефактов из ничего.
- После крупного слияния или поглощения, когда агенту необходимо перестроить карту кодовой базы, прежде чем предлагать новые решения.
- Перед PRD миграции - обнаружение делает состояние «как есть» явным, чтобы цели миграции были обоснованными.

Протокол обнаружения намеренно **управляется агентом**: ForgePlan никогда не читает исходные файлы самостоятельно. Он указывает агенту, *что* искать и в *каком порядке уровней*, а затем принимает результаты.

## Приоритет уровней источников

В поставляемом протоколе **три**, а не четыре уровня:

| Уровень | Источники |
|---|---|
| 1 | Исходный код, git-история, манифесты пакетов. |
| 2 | Тесты, JSDoc-комментарии, конфигурация CI. |
| 3 | `docs/`, README, wiki. |

Протокол предписывает начинать с более надёжных источников, но сам противоречия не разрешает. `forgeplan_discover_finding` отклоняет tier вне 1–3; наблюдения tier 3 получают тег `source=legacy-doc`.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `project_name` | `string` | да | Имя проекта для сессии исследования. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Поля `session_id` (например `disc-20261023-120000`), `project_name`, `session_status`, `current_phase`, `protocol`, `_next_action`. В `protocol` находятся `version`, упорядоченный массив `phases` (поля `phase`, `order`, `name`, `instructions`) и `source_tier_rules` (`t1`, `t2`, `t3`).

`status` остаётся устаревшим псевдонимом статуса сессии с пояснением в `_field_warnings`. Это не статус артефакта. Сохраняйте полученный ID сессии, не составляйте его из имени проекта.

Начальный `session_status` — `started`, `current_phase` — `detect`.
Сессия сохраняется в `.forgeplan/discovery/<session_id>.json`; артефакты наблюдений
этот вызов не создаёт. Протокол — инструкции вызывающему, не сканер кода и не
автоматическая проверка порядка фаз. Успех — JSON в текстовом содержимом MCP;
обработчик не добавляет поля трассировки пространства. Ошибка выбора пространства
для записи возможна на уровне JSON-RPC; ошибка сохранения сессии — текстовая
ошибка инструмента, не успешный результат с протоколом.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "project_name": "billing-service"
}
```

## Типичная последовательность

`forgeplan_discover_start` → наблюдения tier 1 для кода, git и манифестов → tier 2 для тестов → tier 3 для документации → `forgeplan_discover_complete` → отдельный `forgeplan_health` и ревью созданных черновиков.

Для каждой фазы можно сообщать несколько конкретных наблюдений.
