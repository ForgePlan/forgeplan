Классифицирует описание задачи и рекомендует глубину и конвейер артефактов. Вызывайте перед созданием артефактов, если подходящий процесс неясен. Это совет: обработчик не создаёт артефакты, не меняет фазу сессии и не применяет предложенную глубину к последующим вызовам.

**Категория**: Рассуждения и ИИ

## Когда агент вызывает это

- Пользователь говорит «пожалуйста, добавьте X в проект» - агент выполняет роутинг, прежде чем решить, создавать ли артефакты.
- Перед `forgeplan_new`: глубина из роутинга определяет, какие разделы шаблона становятся обязательными.
- Когда агент не уверен, отнести ли рефакторинг к тактической или стандартной задаче - роутинг решает это.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `description` | `string` | да | Описание задачи на естественном языке. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Оба уровня классификации используют одну форму JSON в текстовом содержимом MCP: `depth`, `pipeline`, `triggers` (ID триггеров), `confidence`, `level`, `explanation`, `display`, `_alternatives` и `_next_action`. У каждой альтернативы есть `depth`, `pipeline` и `reasoning`; полей `rationale`, `alternatives` и `when` нет.

Обработчик пробует Level 1, если в разрешённом рабочем пространстве есть конфигурация LLM (с переопределениями из окружения), и при возможности добавляет контекст FPF. Отсутствие рабочего пространства/конфигурации, недоступный LLM или неразбираемый ответ приводят к Level 0 по ключевым словам. Явно выбранным локальным CLI-провайдерам не нужен HTTP API-ключ. Очень короткий ввод также использует Level 0. Поле `level` показывает выбранный путь; полный ADI-анализ автоматически не запускается.

Выпущенное ядро сопоставляет `Tactical` с отсутствием артефактов, `Standard` с PRD → RFC, `Deep` с PRD → Spec → RFC → ADR. Отдельного конвейера Critical нет, несмотря на описание инструмента с четырьмя уровнями.

Условный фрагмент ответа для разобранной классификации Standard уровня Level 1 (альтернативы, display и подсказка опущены):

```json
{
  "depth": "Standard",
  "pipeline": ["prd", "rfc"],
  "triggers": [],
  "confidence": 0.9,
  "level": 1,
  "explanation": "A feature with several implementation choices."
}
```

Уверенность Level 1 фиксируется реализацией на `0.9`, а не измеряет вероятность правильности рекомендации LLM.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "description": "Add rate limiting to the API"
}
```

## Типичная последовательность

Рекомендуемый процесс: роутинг → проверка рекомендации → поиск дубликатов → создание нужных артефактов → заполнение и валидация → ADI, если требует политика команды. Проверяйте фактический `pipeline`; роутинг его не выполняет. Level 1 может обращаться к внешнему провайдеру и не обязательно дёшев.
