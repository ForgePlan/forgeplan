Получает полный Markdown-текст загруженного раздела FPF по ID, например `B.3`, `C.2.2`, `A.1`. Доступные в пространстве ID ищите через `forgeplan_fpf_list` или `forgeplan_fpf_search`.

**Категория**: База знаний FPF

## Когда агент вызывает это

- **После `forgeplan_fpf_search`** - прочитать полный текст лучшего совпадения.
- **Прямой поиск** - когда вы уже знаете ID раздела из предыдущего контекста или ссылки.
- **Навигация** — ищите связанные ID через поиск или каталог; этот инструмент не возвращает дерево родителей и потомков.
- **Обоснование контекста** - включить конкретный принцип в запрос на рассуждение ADI.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `id` | `string` | да | ID раздела FPF, например `"B.3"` или `"C.2.2"`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в текстовом содержимом MCP с полями `section_id`, `title`, `body`, `line_count` и `_next_action`. Полей `parent`, `children`, `siblings`, `path`, `word_count` нет. ID точно сопоставляется с загруженным разделом; рекурсивного объединения дочерних разделов нет.

Неизвестный раздел возвращает `isError` с обычным текстом и подсказкой перечислить разделы; подсказка — текст, а не JSON-поле `_next_action`. Сбои хранилища тоже возвращают ошибки. При пустой базе сначала загрузите её через CLI. Чтение не меняет артефакты и не добавляет материал в ADI автоматически.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "id": "B.3"
}
```

## Типичная последовательность

1. `forgeplan_fpf_search` — найти релевантные загруженные разделы.
2. `forgeplan_fpf_section` с полученным ID раздела во входном `id` — прочитать тело.
3. Следовать ссылкам в тексте или искать связанные понятия.
4. Использовать текст в рассуждении агента. MCP `forgeplan_reason` не принимает аргумент для добавления FPF-контекста.

## Эквивалент CLI

```bash
forgeplan fpf section B.3
```
