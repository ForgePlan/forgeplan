Issue #289 - обнаружение аномалий конвейера (зависшие черновики, сиротские ссылки, опечатки в based_on, отсутствующие обязательные секции, просроченные доказательства, циклы, дубликаты и т.д.). Возвращает структурированный список с severity + tier + suggested_resolution, чтобы оркестраторы (`/forge-cycle`, `/forge-cleanup`) могли распределять задачи по уровням auto/adi/user без повторной классификации.

Каждая запись - это самоописывающий рабочий заказ: детерминированный `id`, затронутые артефакты `affected`, уровень серьёзности `severity`, уровень разрешения `tier` (`auto` / `adi` / `user`) и, когда существует каноническое исправление, `suggested_resolution`, указывающий точный инструмент для вызова. Вызывающая сторона сортирует и распределяет задачи; она не переклассифицирует их.

**Категория**: Other

## Когда агент вызывает это

- **Начало прохода самовосстановления** - `/forge-cycle` опрашивает это перед тем, как решить, пригодно ли дерево для работы.
- **Проходы очистки** - `/forge-cleanup` читает `tier`, чтобы решить, что можно исправить без запроса оператору.
- **После массового импорта или `scan-import`** - `orphan_link` ловит отношения, целевой id которых не существует в рабочем пространстве.
- **После активации** - `missing_must_section` ловит артефакты со статусом `active`, тела которых всё ещё содержат маркеры-заглушки (`TODO`, `TBD`, `placeholder`, `XXX`).
- **Длинные сессии и CI, режим diff** - передайте `since`, чтобы получить только аномалии, впервые обнаруженные после предыдущего сканирования, вместо повторного чтения всего списка.

## Что обнаруживается

Всего обнаруживается пятнадцать видов: десять детекторов на стороне конвейера выполняются внутри `detect_anomalies`, и пять детекторов brownfield подключаются из `crates/forgeplan-core/src/brownfield.rs`. Каталог v1 из issue #289 называет первые девять видов конвейера; `unbacked_displacement` присоединился позже как защита ADR-020. Severity и tier фиксированы для каждого вида:

| Kind | Severity | Tier | Suggested resolution |
|---|---|---|---|
| `stuck_draft` | medium | `auto` | `forgeplan_activate` на затронутом EVID- |
| `orphan_link` | high | `user` | нет - требуется решение оператора |
| `mistyped_based_on` | medium | `adi` | `forgeplan_link` с `replace=true` и отношением `informs` |
| `missing_must_section` | high | `user` | нет |
| `expired_evidence` | medium | `user` | нет |
| `weakest_link_unresolvable` | low | `adi` | `forgeplan_score` на слабом звене |
| `phase_mismatch` | low | `auto` | `forgeplan_phase_advance` |
| `circular_dependency` | high | `user` | нет |
| `duplicate_artifact` | medium | `adi` | `forgeplan_supersede` избыточный артефакт |
| `unbacked_displacement` | medium | `adi` | `forgeplan_score` на первой живой цели |
| `hypothesis_duplicate` | high, medium | `adi` | нет - `target` указывает на левую гипотезу |
| `uncovered_use_case` | medium | `adi` | `forgeplan_link` демонстрирующий SCEN- |
| `unverified_invariant` | medium | `adi` | `forgeplan_link` |
| `orphan_glossary_term` | low | `adi` | нет - сошлитесь на термин или отмените GLOS- |
| `untriangulated_hypothesis` | medium | `adi` | `forgeplan_link` второй EvidencePack |

Несколько правил обнаружения, которые стоит знать перед тем, как действовать на основе вывода:

- `unbacked_displacement` срабатывает, когда EvidencePack с вердиктом `refutes` / `weakens` был завершён (замещён или отменён) без рёбра-преемника `supersedes`, в то время как цель, которую он информировал, всё ещё живая.
- `duplicate_artifact` сравнивает заголовки плюс пересечение тел; `hypothesis_duplicate` - это только Jaccard токенов заголовков, и это та же находка, которую [`forgeplan_contradictions`](/ru/docs/mcp/forgeplan_contradictions/) сообщает самостоятельно.
- `uncovered_use_case`, `unverified_invariant`, `orphan_glossary_term` и `untriangulated_hypothesis` - это четыре корзины [`forgeplan_orphans`](/ru/docs/mcp/forgeplan_orphans/), преобразованные в каноническую оболочку аномалии.

## Входные параметры

| Name | Type | Required | Description |
|---|---|---|---|
| `kind` | `string` | нет | Оставить только один вид аномалии по его имени в snake_case (например, `orphan_link`). Неизвестное значение возвращает ошибку со списком допустимых видов вместо молчаливого расширения результата. |
| `severity` | `string` | нет | Фильтр точного совпадения по серьёзности: `low`, `medium` или `high`. Любое другое значение возвращает ошибку с указанием трёх допустимых значений. |
| `since` | `string` | нет | Временная метка RFC 3339. Возвращаются только аномалии, чей `observed_at` находится на этой отметке или после неё - см. примечания к журналу в разделе Returns. Значение не в формате RFC 3339 возвращает ошибку с примером. |
| `workspace` | `string` | нет | Разрешить рабочее пространство из этой директории вместо стартового CWD MCP-сервера. Абсолютный путь или с тильдой. Полезно, когда агент работает в git worktree отдельно от сервера. |

_Источник схемы: `crates/forgeplan-mcp/src/server.rs::AnomaliesParams` (общие DTO находятся в `crates/forgeplan-mcp/src/types.rs`)_

## Возвращает

```json
{
  "_next_action": "1 anomaly(ies) detected — 1 require user input. Run `forgeplan_get <id>` on affected artifacts to review.",
  "anomalies": [
    {
      "id": "anom-orphan-link-EVID-001-informs-PRD-999",
      "kind": "orphan_link",
      "severity": "high",
      "tier": "user",
      "affected": ["EVID-001", "PRD-999"],
      "observed_at": "2026-09-16T13:50:38.262275+00:00",
      "description": "EVID-001 --informs--> PRD-999 (target does not exist)",
      "evidence": { "source": "EVID-001", "target": "PRD-999", "relation": "informs" },
      "suggested_resolution": null
    }
  ],
  "total": 1,
  "by_severity": { "low": 0, "medium": 0, "high": 1 },
  "by_tier": { "auto": 0, "adi": 0, "user": 1 }
}
```

Этот payload был захвачен из `forgeplan anomalies --json` во временном рабочем пространстве, содержащем единственную ссылку на несуществующую цель; MCP-инструмент возвращает тот же объект отчёта, и обе поверхности вставляют одну и ту же строку `_next_action` (паритет PRD-071). Примечания к полям:

- `id` выводится из вида плюс затронутые id, поэтому повторный запуск сканирования даёт тот же id - это ваш ключ дедупликации и отслеживания.
- `affected[0]` - это основной артефакт (сам черновик для `stuck_draft`, источник для `mistyped_based_on`).
- `description` - человекочитаемое описание, ограниченное 200 символами.
- `evidence` - произвольная форма для каждого вида; форма документирована для каждого варианта в `crates/forgeplan-core/src/anomalies.rs`.
- `suggested_resolution` - `null` для видов, требующих суждения оператора, и в противном случае содержит `tier`, `action`, `target` и однострочное `rationale`.
- Записи отсортированы по серьёзности (сначала high), затем по `id`, поэтому вывод стабилен между запусками.
- `_next_action` - одна из четырёх строк: `No anomalies. Done.`, сводка с автоисправлением, сводка с требованием ввода пользователя (как выше) или сводка с требованием ADI-расследования.

## Пример вызова

Все аномалии в рабочем пространстве по умолчанию:

```json
{}
```

Только сиротские ссылки:

```json
{ "kind": "orphan_link" }
```

Только находки высокой серьёзности:

```json
{ "severity": "high" }
```

Режим diff - всё, что впервые обнаружено после известной временной метки:

```json
{ "since": "2026-09-16T00:00:00Z" }
```

Отчёт по worktree вместо CWD сервера:

```json
{ "workspace": "~/work/forgeplan-feature-branch" }
```

## Типичная последовательность

1. `forgeplan_anomalies` - читайте `by_tier`, а не только `total`.
2. `by_tier.auto > 0` - оркестратор разрешает их без запроса (полный черновик безопасно активировать).
3. `by_tier.adi > 0` - запустите цикл FPF ADI: существует несколько правдоподобных исправлений, выберите одно и запишите, почему.
4. `by_tier.user > 0` - эскалируйте с `NEED_USER_INPUT`; сначала выполните `forgeplan_get` на затронутых id, чтобы вопрос содержал контекст.
5. Повторно запустите с `since`, установленным на начало цикла, чтобы подтвердить, что ничего нового не появилось, пока вы работали.

## Примечания по безопасности

- Только для чтения хранилища артефактов: ничего не активируется, не замещается и не редактируется этим вызовом.
- Он читает и записывает `.forgeplan/anomalies-journal.jsonl` и берёт блокировку рабочего пространства для этого, поэтому конкурентные вызовы сериализуются, а не теряют записи журнала.
- Журнал - это то, что даёт `since` его семантику diff: аномалия, впервые обнаруженная в более раннем сканировании, сохраняет свой исходный `observed_at`. Записи для аномалий, которые больше не появляются, собираются сборщиком мусора.
- Отсутствующий или повреждённый журнал деградирует корректно - каждая аномалия рассматривается как только что обнаруженная в этом сканировании (поведение до 0.33), а сбои записи в журнал предупреждаются, но никогда не фатальны.
- Журнал - это эвристическое хранилище, а не источник истины. Детерминированный `id` - это идентичность аномалии.
- Нет вызова LLM и нет сетевого доступа. Это чистое сканирование локального рабочего пространства.
