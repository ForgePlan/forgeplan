Находит артефакты с истёкшей датой `valid_until`. Решение или доказательство может больше не отражать действительность, поэтому стоит изучить его перед продлением, переоткрытием или отменой. Сам вызов статус не меняет.

**Категория**: Качество

## Когда агент вызывает этот инструмент

-   **Периодические проверки** - запускается еженедельно для выявления просроченных решений до того, как они незаметно снизят R_eff.
-   **Перед релизом** - подтверждение того, что ни один активный артефакт не выпускается с просроченными доказательствами.
-   **Начало сессии** - дополняет `forgeplan_health`, показывая срок действия для каждого элемента.
-   **После длительного отсутствия** - многие артефакты могли стать просроченными (`valid_until`) за время вашего отсутствия.

Просрочка — производная актуальность, а не переход сохранённого статуса. Отчёт ничего не продлевает и не пересчитывает кеш оценки. Просроченное доказательство получает 0.1 в оценщике доказательств; это специальное правило срока действия, а не назначение CL0 или умножение на вес.

## Входные параметры

_Объявленных входных полей нет. Вызывайте инструмент с пустым объектом `{}`._

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в MCP `content[0].text`: `stale`, `total` и `_next_action`. Элемент содержит только `id`, `title`, `valid_until`, `days_expired`; нет `kind` и `linked_to`.

Хранилище выбирает даты строго раньше сегодняшней даты UTC для всех типов/статусов. Отсутствующие и неразбираемые даты пропускаются. Хранилище принимает дату и RFC 3339, но обработчик считает `days_expired` только из даты; включённый срок RFC 3339 поэтому может показать ноль дней. Записи сортируются по строке `valid_until`. Отсутствующее пространство возвращает текстовую ошибку инструмента; сбой хранилища может вернуть JSON-RPC ошибку.

Условный ответ при дате UTC 2026-04-11:

```json
{
  "stale": [
    {"id": "EVID-047", "title": "Auth tests", "valid_until": "2026-03-30", "days_expired": 12}
  ],
  "total": 1,
  "_next_action": "1 stale artifact(s). Inspect first: `forgeplan_get EVID-047`."
}
```

## Типичная последовательность

1.  `forgeplan_stale` - список просроченных артефактов.
2.  Для каждого: принять решение о продлении, переоткрытии или отмене.
3.  `forgeplan_renew` для продления `valid_until` (если решение всё ещё актуально).
4. Либо `forgeplan_reopen` для нового связанного по происхождению черновика из подходящего просроченного активного артефакта с жизненным циклом.
5.  `forgeplan_decay` - просмотр влияния на R_eff от оставшихся просроченных доказательств.

## Эквивалент в CLI

```bash
forgeplan stale
```
