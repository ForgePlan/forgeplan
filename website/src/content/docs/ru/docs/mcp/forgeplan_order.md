Возвращает топологический обход структурных связей (`based_on`, `refines`, `supersedes`, `contradicts`), отдельные списки ready/blocked и пути циклов. **Ограничение релиза:** хотя `from` означает «зависит от `to`», обход выдаёт `from` перед `to`; не используйте `order` как порядок выполнения предварительных условий. Опирайтесь на отдельный список `ready` и проверяйте зависимости.

**Категория**: Панели мониторинга и Графы

## Когда агент вызывает его

- **Планирование спринта** - сначала работайте со списком `ready`, чтобы избежать блокировки.
- **Планирование релиза** - определение порядка активации для пакета артефактов-черновиков.
- **Обнаружение циклов** - поиск циклических ссылок (например, два PRD взаимно `based_on` друг друга).
- **Проверка импорта** - после `forgeplan_import` убедитесь, что граф остаётся DAG.

## Входные параметры

_Объявленных входных полей нет. Вызывайте инструмент с пустым объектом `{}`._

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Условный ответ для одной связи `RFC-006 based_on PRD-039`, когда PRD — черновик:

```json
{
  "order": ["RFC-006", "PRD-039"],
  "ready": ["PRD-039"],
  "blocked": [{"id": "RFC-006", "blocked_by": ["PRD-039"]}],
  "cycles": [],
  "_next_action": "Illustrative guidance to work a ready artifact."
}
```

Успешный ответ — JSON в текстовом содержимом MCP. `order` и `ready` содержат строки ID, а не объекты артефактов; счётчиков нет. `cycles` содержит массивы путей ID, например `["PRD-042","PRD-043","PRD-042"]`. Циклические узлы могут отсутствовать в `order`, `ready` и `blocked`.

В граф попадают только концы структурных связей; изолированные артефакты и только информационные связи исключены. Зависимость разрешена лишь тогда, когда запись цели имеет статус `active`, `deprecated` или `superseded`; `stale` и отсутствующие цели не разрешены. Инструмент читает рабочее пространство сервера по умолчанию и не принимает `workspace` для отдельного вызова. Сбой рабочего пространства/хранилища возвращает ошибку, а не успешный пустой граф.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

## Типичная последовательность

1. `forgeplan_order` - получить полную последовательность.
2. Выбрать ID из отдельного массива `ready`, а не первый элемент `order`.
3. `forgeplan_get` → `forgeplan_validate` → `forgeplan_activate`.
4. Повторно запустить `forgeplan_order` - нижестоящие узлы теперь должны стать готовыми.

## Эквивалент CLI

```bash
forgeplan order
```
