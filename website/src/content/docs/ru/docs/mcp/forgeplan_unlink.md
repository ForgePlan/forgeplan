Удалить типизированную связь между двумя артефактами. Зеркальная операция к `forgeplan_link` для отмены или исправления неправильно типизированных рёбер. Issue #286.

**Категория**: Редактирование артефактов

`forgeplan_unlink` удаляет выбранное типизированное ребро, не заменяя его на месте. Для смены `based_on` на `refines` используйте `forgeplan_link` с согласованным `replace: true` либо последовательно unlink и link. Удаление меняет граф для R_eff, `forgeplan_order`, `forgeplan_health`; пересчёт оценки источника запускается, но не гарантирован.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "source": "EVID-001",
  "target": "PRD-001",
  "relation": "informs"
}
```

## Что делает

1. Захватывает блокировку пространства и разбирает `relation`, по умолчанию `informs`. Значения вне пяти вариантов MCP enum вызывают отказ на границе протокола.
2. Загружает исходящие связи источника и требует совпадения цели и отношения. Отсутствующее ребро — ошибка, в том числе при повторном unlink; отдельной проверки существования артефакта нет.
3. Синхронизирует проекцию источника и удаляет сохранённое ребро. Синхронизация цели и перерисовка обоих концов выполняются best-effort, а не как атомарная гарантия немедленного совпадения Markdown и хранилища.
4. Пытается пересчитать оценку источника. Сбой логируется, но не отменяет успешный unlink; подсказка об успехе не удостоверяет оценки предков.

## Когда агент вызывает это

- **Исправление неправильно типизированного ребра** - `contradicts`, которое должно было быть `refines`.
- **Отмена плохой связи**, созданной ранее в той же сессии, без ручного редактирования проекции.
- **Замена relation**, когда `forgeplan_link` с `replace: true` не подходит (например, когда агент хочет наблюдать удаление перед добавлением замены).
- **Исправление расхождения** между хранилищем и markdown-файлами после ручного редактирования.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `relation` | `string` | нет | Удаляемый тип связи. По умолчанию `informs`. Значения enum: `"informs"`, `"based_on"`, `"supersedes"`, `"contradicts"`, `"refines"`. |
| `source` | `string` | да | ID исходного артефакта. |
| `target` | `string` | да | ID целевого артефакта. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

```json
{
  "_next_action": "Unlinked. R_eff recomputed on source. Reconcile parents: `forgeplan_score_all`.",
  "message": "Unlinked: NOTE-001 --informs--> NOTE-002",
  "resolved_via": "cwd",
  "resolved_workspace": "/home/me/project/.forgeplan"
}
```

`resolved_via` и `resolved_workspace` обозначают пространство этого обработчика; не каждый изменяющий MCP-инструмент возвращает эти поля. `message` называет выбранное ребро, `_next_action` — рекомендательный текст. В частности, имя `forgeplan_score_all` из релизной подсказки не зарегистрировано как MCP-инструмент.

## Отказы

Удаление несуществующего ребра - это ошибка, а не молчаливый успех:

```text
Relation 'based_on' from NOTE-001 to NOTE-002 not found

_next_action: List existing edges from source: `forgeplan_get NOTE-001` (check the `## Related`
section). If the typo is on `target`, retry with the actual target id `NOTE-002`.
```

То же сообщение возвращается, когда `source` называет артефакт, которого вообще не существует - отдельной ветки "артефакт не найден" нет, потому что артефакт без исходящих рёбер и несуществующий артефакт неразличимы на этом этапе в графе.

## Примеры

Удалить ребро `refines`:

```json
{ "source": "RFC-012", "target": "RFC-003", "relation": "refines" }
```

Удалить relation по умолчанию (`informs`) без явного указания:

```json
{ "source": "EVID-057", "target": "PRD-042" }
```

Исправить неправильно типизированное ребро через unlink и re-link:

```text
forgeplan_unlink (EVID-057, PRD-042, contradicts)   ← неправильное ребро удалено
forgeplan_link   (EVID-057, PRD-042, informs)       ← правильное ребро добавлено
```

## Примечания

- Инструмент объявляет `idempotent_hint = true` и `destructive_hint = true`, но повтор удаления того же ребра даёт not-found. Такая ошибка сама не доказывает, что предыдущий вызов удалил нужную связь: проверьте ID и граф до вывода об успехе.
- CLI принимает более широкий набор, включая `supports`, `demonstrates`, `covers`, `triangulates`, `references`, `belongs_to`. MCP enum не позволяет удалить эти связи; используйте соответствующий CLI.
- **Ограничение регистра в 0.38.0:** предварительное сравнение цели не учитывает регистр, а предикат удаления сравнивает сохранённые строки точно. Используйте канонические ID источника и цели; сообщение об успехе с иным регистром цели не доказывает исчезновение ребра.
- Статусы не меняются: unlink не активирует, не отменяет и не замещает артефакты. Отдельного флага подтверждения нет; до вызова согласуйте удаление выбранной связи.
