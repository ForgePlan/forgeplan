Удалить типизированную связь между двумя артефактами. Зеркальная операция к `forgeplan_link` для отмены или исправления неправильно типизированных рёбер. Issue #286.

**Категория**: Editing Artifacts

`forgeplan_link` добавляет, а `forgeplan_unlink` удаляет: ничего не заменяется на месте. Чтобы изменить ребро с `based_on` на `refines`, либо используйте link с `replace: true`, либо сначала unlink, а затем link снова. Каждое ребро, которое удаляет этот инструмент, изменяет граф зависимостей, который читают R_eff, `forgeplan_order` и `forgeplan_health`, поэтому оценка исходного артефакта пересчитывается до возврата из вызова.

## Что делает

1. **Захватывает эксклюзивную блокировку рабочего пространства.** Та же дисциплина блокировок, что и у `forgeplan_link`, поэтому конкурентный писатель не может вклиниться в перезапись графа.
2. **Валидирует значение relation.** `relation` - это типизированный enum, поэтому значение вне набора из пяти вариантов отклоняется на уровне протокола до запуска обработчика.
3. **Загружает исходящие рёбра исходного артефакта** из хранилища.
4. **Проверяет существование ребра.** Пара должна совпадать и по target, и по relation. Эта проверка существует именно потому, что delete в LanceDB идемпотентен - без неё опечатка в relation выглядела бы как успешное удаление.
5. **Удаляет ребро и перезаписывает markdown-проекцию** в одной операции, чтобы блок `## Related` в файле исходного артефакта сразу соответствовал хранилищу.
6. **Пересчитывает R_eff для источника.** Удаление ребра может удалить родителя-слабого звена артефакта, поэтому оценка обновляется. Сбой здесь не приводит к сбою вызова: он логируется, и ответ всё равно сообщает, что unlink выполнен.

## Когда агент вызывает это

- **Исправление неправильно типизированного ребра** - `contradicts`, которое должно было быть `refines`.
- **Отмена плохой связи**, созданной ранее в той же сессии, без ручного редактирования проекции.
- **Замена relation**, когда `forgeplan_link` с `replace: true` не подходит (например, когда агент хочет наблюдать удаление перед добавлением замены).
- **Исправление расхождения** между хранилищем и markdown-файлами после ручного редактирования.

## Входные параметры

| Имя | Тип | Обязательный | Описание |
|---|---|---|---|
| `source` | `string` | да | ID исходного артефакта (артефакт, из которого выходит ребро). |
| `target` | `string` | да | ID целевого артефакта (артефакт, на который указывает ребро). |
| `relation` | `string` | нет (по умолчанию: `"informs"`) | Relation для удаления. Только точные значения в snake_case: `informs`, `based_on`, `supersedes`, `contradicts`, `refines`. |
| `workspace` | `string` | нет | Явный каталог рабочего пространства. Если задан, сервер разрешает `.forgeplan/` из этого пути вместо своего стартового CWD. PRD-078 / ADR-015. |

_Источник схемы: `crates/forgeplan-mcp/src/server.rs::UnlinkParams`_

Поле `relation` - это типизированный enum, поэтому допустимые значения обеспечиваются JSON Schema, которую видит клиент - агент, сэмплирующий по схеме, не может придумать relation. Всё остальное возвращается как ошибка протокола, а не результат инструмента:

```text
failed to deserialize parameters: unknown variant `based-on`,
expected one of `informs`, `based_on`, `supersedes`, `contradicts`, `refines`
```

Kebab-case и написание с заглавной буквы отклоняются здесь, хотя базовый парсер relation принимает kebab-case от других вызывающих. Используйте точные строки выше.

## Возвращает

```json
{
  "_next_action": "Unlinked. R_eff recomputed on source. Reconcile parents: `forgeplan_score_all`.",
  "message": "Unlinked: NOTE-001 --informs--> NOTE-002",
  "resolved_via": "cwd",
  "resolved_workspace": "/home/me/project/.forgeplan"
}
```

`resolved_via` и `resolved_workspace` - это трассировка рабочего пространства, которую возвращает каждый мутирующий инструмент, чтобы вызывающий мог подтвердить, какой каталог `.forgeplan/` был отредактирован. Человекочитаемое `message` называет точное ребро, которое было удалено.

## Отказы

Удаление несуществующего ребра - это ошибка, а не молчаливый успех:

```text
Relation 'based_on' from NOTE-001 to NOTE-002 not found

_next_action: List existing edges from source: `forgeplan_get NOTE-001` (check the `## Related`
section). If the typo is on `target`, retry with the actual target id `NOTE-002`.
```

То же сообщение возвращается, когда `source` называет артефакт, которого вообще не существует - отдельной ветки "артефакт не найден" нет, потому что артефакт без исходящих рёбер и несуществующий артефакт неразличимы на этом этапе в графе.

## Примеры

Удалить ребро `refines`:

```json
{ "source": "RFC-012", "target": "RFC-003", "relation": "refines" }
```

Удалить relation по умолчанию (`informs`) без явного указания:

```json
{ "source": "EVID-057", "target": "PRD-042" }
```

Исправить неправильно типизированное ребро через unlink и re-link:

```text
forgeplan_unlink (EVID-057, PRD-042, contradicts)   ← неправильное ребро удалено
forgeplan_link   (EVID-057, PRD-042, informs)       ← правильное ребро добавлено
```

## Примечания

- Инструмент объявляет `idempotent_hint = true` и `destructive_hint = true`. Повторные вызовы безопасны в том смысле, что они никогда не повреждают граф, но второй идентичный вызов на том же ребре **завершается с ошибкой** not-found выше, а не сообщает об успехе снова. Трактуйте ошибку как "уже выполнено".
- CLI принимает более широкий набор relation, включающий brownfield-relations (`supports`, `demonstrates`, `covers`, `triangulates`, `references`, `belongs_to`). Этот инструмент - нет: через MCP-поверхность эти рёбра нельзя удалить. Используйте CLI для них.
- Оба артефакта сохраняют свой статус. Unlinking никогда не активирует, не отменяет и не замещает ничего.

## Эквивалент в CLI

- [`forgeplan unlink`](/ru/docs/cli/unlink/) - `forgeplan unlink <SOURCE> <TARGET> --relation <RELATION>`, с более широким набором relation и той же ошибкой not-found.
