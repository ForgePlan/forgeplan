---

Возвращает каждый не истёкший клейм в `.forgeplan/claims/`, отсортированный по
возрастанию времени истечения (самые срочные - первыми). Пропускает клеймы за
пределами TTL - они считаются практически освобождёнными. По дизайну read-only и
без блокировок (audit-driven): оркестратор, опрашивающий с частотой 1 Гц, не должен
сериализовать запись суб-агентов. Битые файлы клеймов пропускаются со счётчиком,
чтобы health-проверки могли их подсветить.

**Категория**: Совместная работа агентов

## Когда агент вызывает

- Оркестратор на каждом тике диспатча: «какая работа уже в полёте?».
- Суб-агент перед клеймом: «другой работник опередил меня по этому артефакту?».
- Health-проверки: ненулевой `skipped` указывает на файлы для изучения — возможны ошибки разбора, размера или одновременного чтения с записью.
- После сбоя: изучите оставшиеся действующие захваты и убедитесь, что владелец больше не работает, прежде чем намеренно освобождать захват принудительно.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `active` | `boolean` | нет | Зарезервировано для будущих фильтров. Сейчас возвращаются только действующие захваты. По умолчанию в схеме: `false`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успех — JSON в текстовом содержимом MCP. Значения ниже условные.

```json
{
  "count": 2,
  "skipped": 0,
  "claims": [
    {
      "id": "PRD-057",
      "agent_id": "worker-1",
      "claimed_at": "2026-04-26T10:00:00Z",
      "expires_at": "2026-04-26T10:30:00Z",
      "note": "implementing FR-003"
    },
    {
      "id": "RFC-012",
      "agent_id": "worker-2",
      "claimed_at": "2026-04-26T10:05:00Z",
      "expires_at": "2026-04-26T11:05:00Z"
    }
  ],
  "_next_action": "2 active claim(s). Plan around them: `forgeplan_dispatch agents=3`."
}
```

`skipped > 0` означает ошибку разбора или превышение лимита размера файла;
пропуск также возможен при чтении одновременно с записью. Изучите
`.forgeplan/claims/` и health-отчёт, не считая каждый пропуск повреждением.
Отсутствующий `note` опускается, а не передаётся как `null`. Поле `active`
зарезервировано и не меняет фильтр действующих захватов. Захваты — рекомендательные
записи координации, не блокировки записи и не доказательство, что агент сейчас работает.
Ошибки выбора пространства и чтения захватов возвращаются как ошибки инструмента,
не как успешный ответ с нулевым количеством.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{}
```

## Типичная последовательность

1. `forgeplan_claims` - посмотреть, кто занят.
2. [`forgeplan_dispatch`](/ru/docs/mcp/forgeplan_dispatch/) - спланировать с учётом живых клеймов.
3. Передать каждый бакет суб-агенту, который вызывает [`forgeplan_claim`](/ru/docs/mcp/forgeplan_claim/).

## CLI эквивалент

[`forgeplan claims`](/ru/docs/cli/) - те же данные; оркестраторы, гоняющие
работников через shell, опрашивают эту команду.
