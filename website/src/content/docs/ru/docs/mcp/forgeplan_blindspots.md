Показывает решения без связанных доказательств и артефакты без входящих/исходящих связей. Доказательства требуются для PRD, RFC, ADR, Epic, Spec, Problem и Solution; draft, deprecated и superseded исключены из проверки слепых пятен. Это эвристический список для разбора, а не оценка истинности решения.

**Категория**: Панели мониторинга и Граф

## Когда агент вызывает это

- В начале сессии: если health сообщает о пробелах в доказательствах или изолированных артефактах при `needs_attention` / `unhealthy`, изучите подробности.
- **Перед слиянием PR** - убедитесь, что новая работа не оставляет новых слепых пятен.
- **Во время рефакторинга** - найдите сироты (артефакты без связей) Note / Problem, которые следует отменить или перепривязать.
- **Проверки качества** — получите ID для списка исправлений; владельца и тип, которых нет в отчёте, читайте через `forgeplan_get`.

## Входные параметры

_Объявленных входных полей нет. Вызывайте инструмент с пустым объектом `{}`._

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в MCP `content[0].text` с `blind_spots`, `orphans`, `total_blind_spots`, `total_orphans`, `_next_action`. Слепое пятно содержит `id`, `title`, `issue`; сироты — строки ID, не объекты. Нет вложенного `summary`, полей `kind`, `status`, `reason` или оценки элемента.

Условный ответ:

```json
{
  "blind_spots": [
    {"id": "PRD-042", "title": "Auth system", "issue": "No linked evidence — decision without proof"}
  ],
  "orphans": ["PRD-042"],
  "total_blind_spots": 1,
  "total_orphans": 1,
  "_next_action": "1 blind spot(s). Score `PRD-042` first: `forgeplan_score PRD-042`."
}
```

Вызов не создаёт доказательства, не добавляет связи, не отменяет артефакты и не исправляет пространство. Он читает пространство сервера по умолчанию (входного `workspace` нет). Ошибки пространства возвращаются текстом, сбои отчёта могут быть JSON-RPC ошибками. Чистый отчёт слепых пятен не означает отсутствия других замечаний health.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

## Типичная последовательность

1. `forgeplan_blindspots` - перечисляет нарушителей.
2. Собрать реальные доказательства → `forgeplan_new` evidence → `forgeplan_update` со структурированными `verdict`, `congruence_level`, `evidence_type` → `forgeplan_link` → `forgeplan_score`.
3. Для каждой сироты (артефакта без связей): либо `forgeplan_link` к родителю, либо `forgeplan_deprecate`.
4. Повторите `forgeplan_health` и прочитайте все оставшиеся замечания: исправление двух этих категорий само по себе не гарантирует `healthy`.

## Эквивалент CLI

```bash
forgeplan blindspots
```
