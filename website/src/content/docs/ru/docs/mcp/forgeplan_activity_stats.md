Читает тот же журнал активности, что и [`forgeplan_activity`](/ru/docs/mcp/forgeplan_activity/),
но возвращает по одной строке на каждое уникальное имя инструмента с роллапами:
число вызовов, число ошибок, p50 / p95 длительность, суммарное wall time.
Используйте как отправную точку при расследовании того, куда сессия потратила время,
вместо постраничного просмотра отдельных записей.

**Категория**: Наблюдаемость и аудит

## Когда агент вызывает

- Старт debug-сессии: «какой инструмент горячий за последние 24 часа?».
- Триаж стоимости / латентности, когда пользователь сообщает о медленном workflow.
- Pre-release sanity check: какие-то инструменты показывают повышенный `err_count`
  с прошлого билда?
- После марафонской сессии - убедиться, что число деструктивных вызовов совпадает
  с ментальной моделью агента (никаких сюрпризов в виде `forgeplan_delete`).

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `since_hours` | `integer \| null` | нет | Временное окно в часах. По умолчанию 24. По умолчанию в схеме: `null`. `format`: `uint32`. `minimum`: `0`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успех — JSON в текстовом содержимом MCP. Значения ниже условные, не результаты измерений.

```json
{
  "stats": [
    {
      "tool": "forgeplan_score",
      "count": 42,
      "err_count": 0,
      "p50_ms": 110,
      "p95_ms": 240,
      "total_ms": 5180
    },
    {
      "tool": "forgeplan_search",
      "count": 18,
      "err_count": 1,
      "p50_ms": 95,
      "p95_ms": 410,
      "total_ms": 2200
    }
  ],
  "total_calls": 60,
  "total_errors": 1,
  "total_ms": 7380,
  "since_hours": 24,
  "_next_action": "60 call(s), 1 error(s), 7380 ms total. Drill into busiest: `forgeplan_activity tool=\"forgeplan_score\"`."
}
```

Строки отсортированы по `total_ms` по убыванию (сначала самые дорогие), что совпадает
с тем, как подсказка `_next_action` выводит топовый инструмент.

По умолчанию окно 24 часа; `since_hours` ограничивается диапазоном 1–720.
В отличие от `forgeplan_activity`, лимита числа записей нет. `err_count` считает
статусы, отличные от `ok`; p50/p95 вычисляются методом ближайшего ранга по длительностям.
Суммарное время — сумма длительностей инструментов, не время сессии и не расход токенов
или денег. Повреждённые строки JSONL пропускаются, но предупреждения слоя запросов
в этот ответ не входят; для них вызовите `forgeplan_activity`. При отсутствии файлов
возвращаются пустой `stats` и нулевые суммы. Ошибки выбора пространства — ошибки
инструмента; ошибки чтения журнала — ошибки JSON-RPC.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{}
```

## Типичная последовательность

1. `forgeplan_activity_stats` - найти горячий или сбоящий инструмент.
2. `forgeplan_activity tool=<hot>` - углубиться в отдельные вызовы.
3. Если выделяются ошибки - `forgeplan_activity tool=<hot> status=tool_err`.

## CLI эквивалент

```bash
forgeplan activity-stats --since-hours 24 --json
```

[`forgeplan activity-stats`](/ru/docs/cli/activity-stats/) агрегирует те же журналы.
