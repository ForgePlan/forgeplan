Ищет дубли заголовков гипотез по сходству Жаккара >= 0.6. Остальные три класса требуют оценки LLM и не реализованы в этом обработчике ядра. Они перечислены в `limitations`; отдельных пустых массивов для них нет.

Прочтите описание буквально, прежде чем доверять ответу: **v1 обнаруживает ровно один класс**. Ответ честно сообщает о трёх остальных, но честность здесь означает массив `limitations`, а не обнаружение. Считать этот инструмент «детектором противоречий» и предполагать, что три других имени покрыты, - единственная ошибка, которую эта страница призвана предотвратить.

**Категория**: Прочее

## Что обнаруживается

### Покрыто в v1: `hypothesis_duplicate`

Два артефакта `HYP-`, чьи **заголовки** лексически почти идентичны.

- Токенизация оставляет только ASCII-буквы/цифры, приводит ASCII к нижнему регистру и разделяет по остальным символам. Не-ASCII буквы (включая кириллицу) отбрасываются, а не нормализуются морфологически.
- Оценка: сходство Жаккара `|A ∩ B| / |A ∪ B|` по двум множествам токенов.
- Порог: `>= 0.6` (`HYPOTHESIS_DUPLICATE_JACCARD_THRESHOLD` в `crates/forgeplan-core/src/brownfield.rs`). Два пустых или полностью непересекающихся заголовка дают `0.0` и никогда не помечаются.
- Серьёзность: `high` при `>= 0.85`, иначе `medium`.
- Область: только заголовки. Тела, секции и артефакты других типов не читаются.

### Не покрыто - отложено, требует LLM

Эти три имени существуют в отчёте как константы и перечислены в `limitations` при каждом вызове. Сегодня они ничего не возвращают:

| Класс | Статус | Что потребуется |
|---|---|---|
| `invariant_conflict` | отложено | LLM-оценка тел INV- |
| `glossary_divergence` | отложено | LLM-оценка определений GLOS- |
| `scenario_vs_invariant` | отложено | LLM-оценка текстов SCEN- и INV- |

Установка пакета маркетплейса не меняет область работы этого Rust-обработчика. Пустой `contradictions` означает, что эвристика не выдала дублей заголовков (либо проход пропущен из-за лимита), а не внутреннюю согласованность рабочего пространства.

### Ещё одно ограничение: DoS-лимит

Детектор имеет сложность O(N²) по гипотезам, поэтому он прерывается при превышении `CONTRADICTIONS_MAX_HYPOTHESES = 1000` гипотез: проход полностью пропускается, `contradictions` возвращается пустым, а `limitations` указывает на лимит. В унифицированном представлении аномалий этот лимит является действенным - см. ниже.

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в MCP `content[0].text` с двумя полями отчёта и `_next_action`. Значения условные:

```json
{
  "contradictions": [
    {
      "left_artifact": "HYP-003",
      "right_artifact": "HYP-011",
      "kind_of_contradiction": "hypothesis_duplicate",
      "severity": "medium",
      "suggested_resolution": "Review titles — Jaccard similarity 0.67. Either merge into one hypothesis or sharpen distinguishing wording."
    }
  ],
  "limitations": [
    "invariant_conflict requires LLM judgement (v1 deferred)",
    "glossary_divergence requires LLM judgement (v1 deferred)",
    "scenario_vs_invariant requires LLM judgement (v1 deferred)"
  ],
  "_next_action": "Next: review 1 contradiction(s) — `forgeplan_get <left>` then `forgeplan_get <right>`."
}
```

Примечания к полям (формы взяты из `Contradiction` и `ContradictionsReport`):

- `kind_of_contradiction` - строка, а не enum, чтобы будущие классы могли появиться без изменения формата. В v1 всегда `hypothesis_duplicate`.
- `severity` - `high` или `medium`; скрывает оценку, а не раскрывает её. Когда та же находка приходит через [`forgeplan_anomalies`](/ru/docs/mcp/forgeplan_anomalies/), она выражается как `jaccard_score` и уровень разрешения.
- Пары выдаются в порядке сканирования, каждая пара один раз и с меньшим индексом первым, поэтому отчёт детерминирован для фиксированного рабочего пространства.
- `limitations` всегда содержит три отложенных класса. Запись о лимите появляется только при его срабатывании.
- `_next_action` - либо `Done. - no contradictions detected.`, либо счётчик плюс инструкция по ревью.

## Типичная последовательность

1. `forgeplan_contradictions` - собрать пары дублирующихся заголовков после discovery-инжеста.
2. `forgeplan_get` обе стороны каждой пары и решить: одно и то же утверждение (слить) или действительно разные (уточнить формулировку).
3. Запишите решение и уточните заголовки действительно разных гипотез. Замещение не убирает гипотезу из детектора: сравниваются все записи гипотез независимо от статуса, поэтому повторный вызов может снова показать пару.
4. Только после этого продвигать выжившие гипотезы через [`forgeplan_hypothesis_promote`](/ru/docs/mcp/forgeplan_hypothesis_promote/) - продвижение дубликатов сначала означает, что одно и то же утверждение триангулируется дважды.

## Примечания по безопасности

- Только чтение: инструмент делает снимок записей и никогда не пишет артефакт.
- Чтение снимка происходит под блокировкой рабочего пространства; проход сравнения O(N²) выполняется без блокировки после этого.
- Ограниченная работа: в проход попадает не более 1000 гипотез, поэтому рабочее пространство, забитое заглушками гипотез, не может заблокировать сервер.
- Лексический, не семантический: два по-разному сформулированных заголовка с одним и тем же утверждением не будут помечены, а два похожих заголовка с разными утверждениями будут. Сигнал - это подсказка посмотреть, а не вердикт.
- Нет LLM-вызова и нет сетевого доступа.
- Ошибки рабочего пространства, блокировки и чтения снимка возвращаются как текстовые ошибки инструмента MCP (`isError: true`), а не успешный пустой отчёт.
- Нет CLI-эквивалента - это поверхность только для MCP. Те же находки попадают в терминал через [`forgeplan anomalies`](/ru/docs/cli/anomalies/) как тип `hypothesis_duplicate`.
