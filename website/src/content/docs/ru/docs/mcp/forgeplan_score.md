---

Вычисляет рекурсивный R_eff по собственным доказательствам артефакта и его зависимостям, никогда не среднее. Доказательства в superseded/deprecated остаются в детализации с `excluded: true`, но исключаются из минимума. Черновики доказательств учитываются. Непросроченное опровергающее доказательство даёт ноль; просроченное — 0.1. Листовой EvidencePack оценивается по собственным структурированным полям, без искусственных дочерних доказательств.

**Категория**: Качество и валидация

## Когда агент вызывает это

- После создания и связывания EvidencePack - "действительно ли R_eff поднялся выше нуля?"
- В рамках глубокого анализа `forgeplan_health`: какие активные артефакты всё ещё имеют R_eff = 0?
- Перед предложением `forgeplan_activate` для глубокого/критического артефакта, где доказательства обязательны.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `id` | `string` | да | ID артефакта для вычисления R_eff. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в MCP `content[0].text`. Поля: `id`, `title`, `r_eff`, `evidence`, `self_score`, `formality`, `granularity`, `reliability`, `overall_grade`, допускающее null `weakest_link`, `factors`, `decay_penalty` и `_next_action`. Элемент `evidence` содержит `id`, `verdict` (отладочное написание, например `Supports`), `congruence_level`, `score`, `expired`, `status`, `excluded`. Нет `breakdown`, `limiting_evidence`, `cl`, типа доказательства или коэффициента распада для отдельного элемента.

`score` в детализации использует плоский расчёт (вердикт минус штраф CL, либо 0.1 при просрочке). Рекурсивная оценка дополнительно вычитает штраф типа доказательства (test/measurement 0, benchmark 0.1, audit 0.2) и обходит исходящие зависимости `informs`, `based_on`, `refines`, `depends_on`. Штраф связи — 0.1 для `informs`/`based_on`, ноль для `refines`/`depends_on`. Черновые/терминальные зависимости и зависимости note/memory пропускаются; исходящие из доказательства `informs`/`based_on` к поддерживаемому артефакту не обходятся в обратном направлении доверия. Поэтому минимум показанных оценок доказательств может отличаться от `r_eff`; `weakest_link` указывает ограничивающую зависимость, не обязательно EvidencePack.

Несмотря на аннотацию read-only, обработчик берёт блокировку записи рабочего пространства и сохраняет пересчитанный кеш оценки. Если сохранение не удалось, он пытается пересчитать только для показа. Разрешение рабочего пространства может вернуть JSON-RPC invalid params; отсутствующий ID и сбой блокировки — текстовую ошибку инструмента. Вызов не активирует и не продлевает артефакты.

Условный фрагмент ответа (остальные поля перечислены выше):

```json
{
  "id": "PRD-042",
  "title": "Auth system",
  "r_eff": 0.8,
  "self_score": 0.8,
  "evidence": [
    {"id": "EVID-056", "verdict": "Supports", "congruence_level": 3, "score": 1.0, "expired": false, "status": "active", "excluded": false}
  ],
  "weakest_link": null,
  "factors": [],
  "decay_penalty": 0.0
}
```

Пример соответствует доказательству типа audit: плоская оценка 1.0, рекурсивная собственная оценка 0.8.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "id": "PRD-001"
}
```

## Типичная последовательность

Создайте доказательство через `forgeplan_new` (`kind: "evidence"`), заполните структурированные поля через `forgeplan_update`, добавьте связь и вычислите оценку решения. Перед активацией прочитайте `forgeplan_review`: одного `r_eff > 0` недостаточно для всех гейтов. `forgeplan_decay` — отдельное сравнение просрочки без записи, а не обновление кеша рекурсивной оценки.
