Рассчитывает предложенный план с отдельной группой (`bucket`) для каждого агента и последовательной очередью; не запускает агентов, не создаёт claims и не меняет артефакты. ID с действующими claims исключаются независимо от владельца. Без `affected_files` артефакт идёт в последовательную очередь; домен сопоставляется с навыками без учёта регистра.

**Ограничение безопасности релиза:** пересечение Жаккара проверяется как `>=` порога (по умолчанию 0.3), но кандидат сравнивается лишь с элементами той же группы. Конфликты между группами разных агентов не проверяются. Перед параллельным запуском самостоятельно проверьте межгрупповое пересечение файлов; план не гарантирует отсутствие конфликтов. Проверка зависимостей также опирается на выпущенный структурный граф; циклы проверяйте отдельно.

**Категория**: Совместная работа агентов

## Когда агент вызывает

- Старт multi-agent спринта: оркестратор хочет посадить 2–5 суб-агентов на
  непересекающуюся работу.
- После [`forgeplan_release`](/ru/docs/mcp/forgeplan_release/) - пересчитать план,
  потому что набор кандидатов изменился.
- После того как [`forgeplan_new`](/ru/docs/mcp/forgeplan_new/) создал свежие
  черновики - учесть их.
- Истечение TTL на застрявшем клейме - перепланировать, чтобы заполнить
  освободившийся слот.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `agent_skills` | `array<array<string>>` | нет | Списки навыков агентов в порядке индексов. Пустой список означает любые навыки; пропуск поля полностью отключает сопоставление навыков. По умолчанию в схеме: `[]`. |
| `agents` | `integer` | да | Число агентов, которым оркестратор может передать работу. Обязательное поле; обработчик приводит значение как минимум к 1. `format`: `uint`. `minimum`: `0`. |
| `epic` | `string \| null` | нет | Необязательный фильтр по ID родительского Epic. Сопоставляется с полем frontmatter `parent_epic`. |
| `kind` | `string \| null` | нет | Необязательный фильтр по типу артефакта (`prd`, `rfc`, `spec` и др.). Без фильтра рассматриваются все типы. |
| `overlap_threshold` | `number \| null` | нет | Порог Жаккара, выше которого артефакты считаются конфликтующими по файлам. По умолчанию 0.3; значение ограничивается диапазоном 0.0–1.0. `format`: `double`. |
| `status` | `string \| null` | нет | Необязательный фильтр по статусу, по умолчанию `draft`. Значение `"any"` включает все состояния жизненного цикла. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Обработчик принимает 1–64 агента, не более одного списка навыков на агента и 32 навыков в списке. Ноль/слишком большое число агентов и пороги вне `[0,1]` отклоняются с `isError` и текстом, а не молча ограничиваются. Статус по умолчанию — `draft`; точное `"any"` отключает фильтр статуса. Эти проверки обработчика строже некоторых описаний схемы выше. Обработчик использует путь разрешения пространства с возможностью записи, хотя только рассчитывает план.

Условный JSON в текстовом содержимом MCP:

```json
{
  "buckets": [
    ["PRD-057"],
    ["RFC-012"]
  ],
  "serial_queue": [{"id": "SPEC-018", "reason": "missing affected_files frontmatter"}],
  "reasoning": [
    "PRD-057: assigned to agent 0 (no file conflict)",
    "RFC-012: assigned to agent 1 (no file conflict, skill match)",
    "SPEC-018: serialized (no affected_files declared — treated as shared-ground, deferred for safety)"
  ],
  "generated_at": "2026-04-26T10:00:00Z",
  "agent_count": 2,
  "overlap_threshold": 0.3,
  "candidate_count": 3,
  "claimed_count": 0,
  "skipped_parse_errors": 0,
  "blocked_count": 0,
  "_next_action": "Plan ready: 3 candidate(s), 2 parallel bucket(s), 1 serial ..."
}
```

Передайте `buckets[i]` суб-агенту `i`. Перепланируйте, когда меняется набор клеймов
или кандидатов. `skipped_parse_errors > 0` означает, что у хотя бы одного кандидата
не удалось прочитать frontmatter - проверьте логи сервера.

`candidate_count` считается после фильтров frontmatter/epic/зависимостей, но до исключения claims. `claimed_count` — число действующих claims во всём пространстве, а не число исключённых выбранных кандидатов. `blocked_count` считает исключённых заблокированных кандидатов; они также добавляются в очередь объектами `{id, reason}`. Читайте причину каждого элемента: зависимость не разрешается от самого попадания в последовательную очередь. Claims — рекомендательная координация, а не блокировки записи. В этом релизе обработчик не добавляет трассировку рабочего пространства.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "agents": 2,
  "kind": "rfc",
  "agent_skills": [
    [
      "rust"
    ],
    [
      "docs"
    ]
  ]
}
```

## Типичная последовательность

1. `forgeplan_dispatch agents=N` - оркестратор получает план.
2. Каждый суб-агент `i` вызывает [`forgeplan_claim`](/ru/docs/mcp/forgeplan_claim/) на `buckets[i][0]`.
3. Суб-агенты работают; оркестратор опрашивает [`forgeplan_claims`](/ru/docs/mcp/forgeplan_claims/).
4. [`forgeplan_release`](/ru/docs/mcp/forgeplan_release/) по завершении → пере-диспатч.

## CLI эквивалент

[`forgeplan dispatch`](/ru/docs/cli/) - тот же движок. Оркестраторы на shell используют
