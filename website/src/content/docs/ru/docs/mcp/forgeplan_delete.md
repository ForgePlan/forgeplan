description: "Мягко удалить артефакт, сохранив запись восстановления в корзине."
---

Выполняет мягкое удаление: сохраняет запись восстановления в `.forgeplan/trash/`, пытается переместить туда Markdown-проекцию, затем удаляет запись хранилища. Восстановление через [`forgeplan_restore`](/ru/docs/mcp/forgeplan_restore/) или [`forgeplan_undo_last`](/ru/docs/mcp/forgeplan_undo_last/) возможно, пока доступна запись (обычно в пределах 30 дней) и пройдены проверки конфликтов. Операция остаётся деструктивной. Для вывода решения из использования предпочитайте переходы жизненного цикла; удаляйте только явно выбранный ненужный артефакт.

**Категория**: Редактирование артефактов

## Когда агент вызывает это

- Пользователь явно говорит: «удалить NOTE-099, я создал его по ошибке».
- Очистка тестового артефакта из запусков `forge-smoke`.
- Удаление сироты (артефакт без связей), созданного во время прерванного процесса декомпозиции.

Агентам НИКОГДА не следует вызывать это для «вывода из эксплуатации» активного решения - используйте `forgeplan_supersede` или `forgeplan_deprecate`, чтобы сохранить историю.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `id` | `string` | да | ID удаляемого артефакта. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Подтверждение содержит `id`, `title`, `message`, `receipt_id`, сведения о рабочем пространстве (`resolved_workspace`, `resolved_via`) и `_next_action`. Полей `deleted` и `removed_path` нет.

## Проверки и побочные эффекты

- Цель должна существовать, но гейт статуса не запрещает удалить активное решение. У вызова MCP нет флага `yes` или интерактивного подтверждения: до вызова получите явное согласие на удаление выбранного ID.
- Обработчик удерживает блокировку записи пространства. Запись восстановления создаётся до изменения хранилища; если её нельзя записать, удаление отменяется.
- **Ограничение 0.38.0:** перенос отсутствующей или недоступной для перемещения проекции выполняется best-effort. Запись хранилища может быть удалена, даже если исходный Markdown-файл остался. Успех не доказывает исчезновение проекции.
- Хелпер после создания записи удаляет сам артефакт, а не все связи графа и проекции зависимых артефактов. Не считайте входящие ссылки и зависимые оценки автоматически очищенными. Изучите граф и сохраните экспорт для долгосрочной копии.
- Ошибка после создания записи восстановления возможна уже после частичных изменений. Перед повтором или восстановлением изучите текущую запись хранилища, проекцию и корзину.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "id": "NOTE-001"
}
```

## Типичная последовательность

`forgeplan_list` или `forgeplan_get` для подтверждения цели → явное подтверждение пользователя → `forgeplan_delete` → `forgeplan_health` для проверки отсутствия сбоев. Для обратимого вывода из эксплуатации вместо этого используется `forgeplan_deprecate` (active → deprecated).
