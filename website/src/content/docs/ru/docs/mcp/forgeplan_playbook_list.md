Перечисляет все обнаруживаемые плейбуки (рабочее пространство + пакеты плагинов Claude). Возвращает имя, заголовок, количество шагов и путь к источнику для каждого. PRD-065 AC-1. Сканирование файловой системы только для чтения.

**Категория**: Прочее

## Что делает

1. Определяет рабочее пространство из текущего рабочего каталога сервера.
2. Обходит корневые каталоги поиска плейбуков (см. [Корневые каталоги обнаружения](#корневые-каталоги-обнаружения)), читая файлы `.yaml` и `.yml`.
3. Пропускает любой файл размером более 1 МиБ, любой файл, YAML которого содержит более 256 символов скобок, и любой файл, который не удаётся распарсить.
4. Парсит каждый оставшийся файл с помощью загрузчика SPEC-003 и сохраняет первое вхождение каждого `name` плейбука.
5. Сортирует оставшиеся по `name` и возвращает массив плюс общее количество `total`.

Сканирование никогда не выдаёт ошибок: несуществующий каталог, нечитаемый файл или некорректный плейбук приводят к пропуску, а не к сбою.

## Когда агент вызывает это

- Перед [`forgeplan_playbook_run`](/ru/docs/mcp/forgeplan_playbook_run/) - разрешить голое имя плейбука в реальное вместо угадывания.
- Когда `forgeplan_playbook_show` ответил `playbook target ... not resolvable` - это вызов для восстановления.
- Чтобы определить, поставляется ли рабочее пространство со своими собственными плейбуками в `.forgeplan/playbooks/` или полагается на установленный пакет.
- Дешёвая проверка возможностей во время роутинга: пустой список означает, что в этом рабочем пространстве оркестрация недоступна.

## Входные параметры

| Имя | Тип | Обязательный | Описание |
|---|---|---|---|
| (нет) | - | - | Инструмент не принимает параметров. Он только для чтения, идемпотентен, неразрушающий и работает в закрытом мире. |

_Источник схемы: `crates/forgeplan-mcp/src/server.rs::forgeplan_playbook_list` (сигнатура `Parameters(_p): Parameters<EmptyParams>`)_

## Возвращает

| Поле | Тип | Описание |
|---|---|---|
| `playbooks` | `array` | Один объект на каждый обнаруженный плейбук, отсортированный по `name`. |
| `playbooks[].name` | `string` | Идентификатор плейбука из поля YAML `name:`. |
| `playbooks[].title` | `string` | Человекочитаемый заголовок. |
| `playbooks[].steps_count` | `number` | Количество записей в `steps:`. |
| `playbooks[].source_path` | `string` | Абсолютный путь к файлу, из которого был загружен плейбук. |
| `total` | `number` | Длина массива `playbooks`. |
| `_next_action` | `string` | `forgeplan_playbook_show target="<first-name>"`, или `Done.`, когда список пуст. |

## Примеры

Пустое рабочее пространство. Инструмент терминальный, поэтому подсказка - `Done.` (этот ответ был захвачен вживую в репозитории без `.forgeplan/playbooks/`):

```json
{
  "_next_action": "Done.",
  "playbooks": [],
  "total": 0
}
```

Рабочее пространство с одним плейбуком в `.forgeplan/playbooks/brownfield-code.yaml`:

```json
{
  "_next_action": "forgeplan_playbook_show target=\"brownfield-code\"",
  "playbooks": [
    {
      "name": "brownfield-code",
      "source_path": "/Users/me/project/.forgeplan/playbooks/brownfield-code.yaml",
      "steps_count": 4,
      "title": "Brownfield code-first onboarding"
    }
  ],
  "total": 1
}
```

Пять возвращаемых полей - это точный набор ключей, выдаваемый `forgeplan playbook list --json`, CLI-близнецом этого инструмента.

## Корневые каталоги обнаружения

| Корень | Примечания |
|---|---|
| `.forgeplan/playbooks/` | Нерекурсивно: файлы `.yaml` и `.yml` непосредственно в этом каталоге. |
| `~/.claude/plugins/*/playbooks/` | Один уровень каталогов плагинов, каждый со своей папкой `playbooks/`. |

Оба корня нерекурсивны. Вложенный `playbooks/subdir/` не сканируется.

## Примечания

- **Сканирование MCP уже, чем сканирование CLI.** [`forgeplan playbook list`](/ru/docs/cli/playbook-list/) также ищет в `marketplace/playbooks/`; этот инструмент - нет. В самом репозитории ForgePlan CLI сообщает о 5 плейбуках (все из `marketplace/playbooks/`), в то время как этот инструмент сообщает `total: 0`. Если имя отсутствует здесь, но действительно в CLI, передайте **путь** в `forgeplan_playbook_show` и [`forgeplan_playbook_run`](/ru/docs/mcp/forgeplan_playbook_run/) вместо голого имени.
- **Молчаливые пропуски - это по дизайну.** Слишком большие, слишком глубоко вложенные и непарсируемые файлы отбрасываются без поля предупреждения. Используйте [`forgeplan_playbook_validate`](/ru/docs/mcp/forgeplan_playbook_validate/) для конкретного файла, чтобы узнать, почему он отсутствует.
- **Первый путь побеждает при дублирующихся именах.** Корни посещаются в порядке, указанном выше, поэтому плейбук рабочего пространства затеняет плейбук пакета плагинов с тем же `name`.
- **Рекомендации отсутствуют в этом ответе.** Рекомендация плейбука на основе сигналов проекта (`triggered_by`: `empty_repo`, `has_git`, `commit_count_min`, `has_docs`, `has_obsidian`, `has_cargo_toml`) вычисляется движком рекомендаций и выдаётся [`forgeplan init`](/ru/docs/cli/init/) в stderr. Установите `FORGEPLAN_HINTS=1`, чтобы принудительно включить эти подсказки в конвейере без TTY. Этот инструмент возвращает только перечисление.
- LLM-провайдер не требуется. Артефакты рабочего пространства не читаются и не записываются.

## Связанные команды

- [`forgeplan playbook list`](/ru/docs/cli/playbook-list/) - CLI-эквивалент с более широким путём поиска.
- [`forgeplan_playbook_show`](/ru/docs/mcp/forgeplan_playbook_show/) - следующий вызов для любого имени, возвращаемого этим инструментом.
- [`forgeplan_plugins_list`](/ru/docs/mcp/forgeplan_plugins_list/) - инвентаризация плагинов, которая определяет, какие плейбуки пакетов существуют на диске.
