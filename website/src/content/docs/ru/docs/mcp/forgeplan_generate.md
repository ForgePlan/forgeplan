Создает новый артефакт **с полностью сгенерированным текстом** из описания на естественном языке. В отличие от `forgeplan_new` (который создает пустой шаблон-заглушку), `generate` использует настроенный LLM (OpenAI / Claude / Gemini / Ollama / любую совместимую с OpenAI конечную точку) для создания всех необходимых разделов за один вызов. Агент все равно должен запустить `forgeplan_validate` после этого, поскольку LLM может пропустить обязательные правила (MUST rules).

**Категория**: Создание артефактов

## Когда агент вызывает это

- Пользователь предоставляет подробное описание и хочет получить готовый к ревью первый черновик, а не пустую заглушку.
- Миграция решения из истории чата в формальный ADR - используйте сводку чата в качестве описания.
- Массовая инициализация: превращение неформальной дорожной карты в 5 черновиков PRD за одну сессию.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `description` | `string` | да | Описание на естественном языке того, что нужно сгенерировать. |
| `kind` | `string` | да | Тип артефакта для генерации через LLM. Значения enum: `"prd"`, `"epic"`, `"spec"`, `"rfc"`, `"adr"`, `"problem"`, `"solution"`, `"evidence"`, `"note"`, `"refresh"`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в текстовом содержимом MCP с полями `id`, `kind`, `title`, `filepath`, `provider`, `model`, `resolved_workspace`, `resolved_via` и `_next_action`. В нём **нет** сгенерированного `body`, `status`, `path`, числа токенов или вложенного объекта `llm`. Прочитайте сохранённое тело через `forgeplan_get` до валидации.

Условный фрагмент ответа (трассировка и подсказка опущены):

```json
{
  "id": "PRD-043",
  "kind": "prd",
  "title": "OAuth2 login flow",
  "filepath": "/workspace/.forgeplan/prds/prd-043-oauth2-login-flow.md",
  "provider": "ollama",
  "model": "configured-model"
}
```

Артефакт сохраняется как `draft` с глубиной `standard`. Заголовок — первая строка описания, обрезанная до 80 символов; обработчик пишет Markdown-проекцию до синхронизации хранилища. Конфигурация LLM учитывает окружение и может явно выбирать локального CLI-провайдера. Сбой провайдера возвращает MCP `isError` с текстом и подсказкой по настройке/входу; подмены успехом с пустым шаблоном нет.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "kind": "prd",
  "description": "OAuth2 login flow"
}
```

## Типичная последовательность

Рекомендуемый процесс: роутинг → поиск дубликатов → генерация → чтение через `forgeplan_get` → валидация → исправления → ADI, если требует процесс команды → ревью и активация. Генерация не выполняет последующие шаги автоматически.
