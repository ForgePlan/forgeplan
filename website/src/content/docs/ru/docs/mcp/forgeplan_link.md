---

Создаёт типизированное отношение между двумя артефактами. Связи - это то, как Forgeplan строит свой граф зависимостей; они используются для отчётов о состоянии, расчёта R_eff, топологической сортировки и визуальных графов. Агент вызывает эту функцию каждый раз, когда он создаёт подтверждающее доказательство, замещающий RFC или дочерний PRD, который наследует от Epic.

**Категория**: Редактирование артефактов

## Когда агент вызывает эту функцию

- После создания EvidencePack: связывает `EVID-XXX` → `PRD-YYY` отношением `informs`, чтобы можно было рассчитать R_eff.
- При декомпозиции Epic: связывает каждый новый PRD обратно с Epic отношением `based_on`.
- При замене дизайна используйте [`forgeplan_supersede`](/ru/docs/mcp/forgeplan_supersede/) для перехода жизненного цикла. В 0.38.0 этот инструмент создаёт связь **от старого к замене**; не создавайте заранее обратное ребро `supersedes` по подсказке.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `auto_activate_source_if_complete` | `boolean` | нет | Issue #288: необязательная автоактивация источника. При true, если источник — evidence в draft, его тело содержит `verdict` и `congruence_level`, а R_eff после создания связи больше 0, источник активируется в том же вызове. Ответ содержит `auto_activated`. По умолчанию false. По умолчанию в схеме: `false`. |
| `relation` | `string` | нет | Тип связи. По умолчанию `informs`. Значения enum: `"informs"`, `"based_on"`, `"supersedes"`, `"contradicts"`, `"refines"`. |
| `replace` | `boolean` | нет | Issue #286: при true существующая связь между `(source, target)` с ДРУГИМ типом заменяется на `relation` в одном вызове. Без этого добавление может вернуть `relation already exists` или параллельные рёбра, исправляемые через `forgeplan_unlink`. По умолчанию false. По умолчанию в схеме: `false`. |
| `source` | `string` | да | ID исходного артефакта. |
| `target` | `string` | да | ID целевого артефакта. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ содержит `message`, `resolved_workspace`, `resolved_via` и `_next_action`. ID источника `auto_activated` включается только при состоявшейся автоактивации; иначе ключ отсутствует. Полей `ok`, `source`, `target`, `relation` в ответе нет. Текст `message` называет ребро и результат: добавлено, заменено или уже существует.

## Проверки и побочные эффекты

- `relation` по умолчанию равен `informs`; MCP принимает только пять значений enum из таблицы. Исходный артефакт должен существовать. Ссылка на себя, недопустимый ID и точный дубликат ребра на обычном добавляющем пути вызывают отказ.
- **Ограничение 0.38.0:** вопреки некоторым текстовым подсказкам обычный хелпер не требует существования цели локально и допускает другую связь для той же пары источник/цель. До записи изучайте концы и существующие рёбра; успех не доказывает существование цели.
- `replace: true` явно включает upsert. Если нужное отношение уже есть, оно не меняется; иначе заменяется первое существующее отношение к этой цели или создаётся новое. Все рёбра ранее возникшей многосвязной пары не схлопываются. Сначала добавляется новое ребро, затем удаляется старое; при ошибке могут остаться оба.
- Пространство блокируется. Синхронизация источника до изменения и запись связи обязательны; синхронизация цели, перерисовка обеих проекций и пересчёт оценки источника выполняются best-effort. Успех не удостоверяет актуальность всех проекций и оценок предков.
- `auto_activate_source_if_complete` по умолчанию равен `false`. При true подходит только источник типа Evidence в draft с явными `verdict` (`supports`, `weakens`, `refutes`) и `congruence_level` 0–3. Положительный кешированный R_eff **не требуется** реализацией, несмотря на устаревший текст описания схемы. Ошибка активации не откатывает связь.
- Одна связь `supersedes` не меняет статус жизненного цикла. Подсказки рекомендательные и могут показывать обратное направление замещения или незарегистрированное имя MCP `forgeplan_score_all`; не выполняйте их дословно.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "source": "EVID-001",
  "target": "PRD-001",
  "relation": "informs"
}
```

## Типичная последовательность

`forgeplan_new` (доказательство) → `forgeplan_update` (структурированные поля доказательства) → `forgeplan_link` → изучить ребро и `auto_activated` → пересчитать или проверить затронутые артефакты. Если автоактивация не запрошена, активируйте заполненное доказательство отдельным согласованным вызовом. Связь сама не гарантирует положительную оценку родителя.

Для декомпозиции Epic: `forgeplan_new` (epic) → `forgeplan_new` (prd) → `forgeplan_link` с дочерним артефактом как `source`, Epic как `target` и `relation: "based_on"` → повторить.
