---

Записывает рекомендательную фазу артефакта в `.forgeplan/state/<id>.yaml` и добавляет переход с временем и необязательной причиной. Ручное изменение допускает переходы вне порядка, в том числе сразу к `done`, а также **назад**. Это путь намеренного исправления состояния (PRD-086); автоматическое продвижение другими инструментами назад не идёт. Маркер не заменяет выполнение работы и не является полным контролем порядка фаз.

**Категория**: Жизненный цикл (рекомендательно)

## Когда агент вызывает

- Авто-продвижение пропустило: инструмент отработал, но трекинг фаз был выключен,
  теперь его включают.
- Переклассификация: артефакт повышен из `code` в `audit` после волны PR-ревью.
- Бэкфилл: legacy-артефакт старше PRD-056, агент проводит его до `done`.
- Запись осознанного пропуска: прыжок сразу в `done` для тривиальной правки с `reason`.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `id` | `string` | да | ID артефакта для изменения маркера фазы. |
| `reason` | `string \| null` | нет | Необязательное обоснование, сохраняемое в истории. По умолчанию в схеме: `null`. |
| `to` | `string` | да | Целевая фаза артефакта. Значения enum: `"shape"`, `"validate"`, `"adi"`, `"code"`, `"test"`, `"audit"`, `"evidence"`, `"done"`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Ответ содержит `artifact_id`, `current_phase`, `workflow_type`, `advanced_at`, `history_entries`, `reason` (очищенное значение запроса или null) и `_next_action`. Трассировка рабочего пространства не включается. При неизменной фазе `advanced_at` и история остаются прежними, хотя `reason` может повторять новое значение запроса.

Сбои дают текст ошибки MCP с началом `Failed to advance phase: ...`, а не JSON-объект `ok: false`. Слишком длинная причина вызывает ошибку неверных параметров JSON-RPC.

## Проверки и побочные эффекты

- Нужны безопасный для файлового пути ID артефакта и значение enum `to`. Необязательный `reason` ограничен 4096 байтами на границе MCP.
- Обработчик не загружает артефакт и не проверяет его существование. Отсутствующее состояние фазы инициализируется в `shape` с типом процесса `greenfield`, затем переводится в запрошенную фазу.
- Повтор той же фазы не создаёт дублирующего перехода; отсутствующий файл состояния всё равно создаётся. История ограничена 1024 записями с сохранением начальной и свежих, поэтому это не неограниченный неизменяемый журнал аудита.
- **Особенность 0.38.0:** ручное изменение не проверяет `phase.enabled`; эта настройка управляет автоматическими хуками. Общая подсказка об ошибке с упоминанием настройки не доказывает, что выключенный трекинг запретил ручной вызов.
- Инструмент меняет только состояние фазы. Он не активирует артефакт, не запускает тесты, не создаёт доказательство и не переводит сессию методологии. Перед намеренным переходом назад прочитайте текущий маркер; отдельного флага подтверждения нет.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{
  "id": "RFC-001",
  "to": "test",
  "reason": "Implementation ready for testing."
}
```

## Типичная последовательность

1. [`forgeplan_phase`](/ru/docs/mcp/forgeplan_phase/) - прочитать текущее состояние.
2. Сделать работу для рекомендуемой следующей фазы.
3. `forgeplan_phase_advance` - записать переход.
4. Повторять, пока `current_phase: "done"`.
