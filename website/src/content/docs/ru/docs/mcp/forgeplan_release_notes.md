Автоматически генерирует заметки о релизе в формате Keep-a-Changelog из артефактов, изменившихся между двумя git-ссылками. Проходит по `git log` в `.forgeplan/{prds, problems, evidence, rfcs, adrs, specs, epics, solutions}/`, классифицирует каждый затронутый артефакт (PRD→Added, PROB→Fixed, EVID-on-security→Security, RFC/ADR→Changed) и возвращает структурированный результат. Гейт качества (по умолчанию): включаются только артефакты со status==active или r_eff_score > 0. Передайте `draft: true`, чтобы отключить гейт. `since` по умолчанию - последний git-тег, `until` по умолчанию - HEAD. Пример: `{since: "v0.30.0", draft: false}`.

**Категория**: Прочее

Changelog пишется сам из графа артефактов: инструмент сравнивает две git-ссылки, чтобы найти затронутые артефакты, загружает каждый из хранилища, отбрасывает те, что не несут сигнала, и возвращает выжившие, распределённые по разделам Keep-a-Changelog. Задача агента - только вставить записи под `[Unreleased]` в `CHANGELOG.md`.

## Что делает

1. **Разрешает диапазон.** `since` валидируется и используется как есть; без него инструмент берёт ближайший достижимый тег (`git describe --tags --abbrev=0`) и откатывается к `HEAD~50`, если в репозитории нет тегов вообще. `until` по умолчанию - `HEAD`.
2. **Проходит по истории.** `git log --name-only` выполняется только по разрешённым директориям типов: `prds`, `problems`, `evidence`, `rfcs`, `adrs`, `specs`, `epics`, `solutions`. Note, Memory и Refresh находятся в директориях, которые changelog намеренно игнорирует.
3. **Загружает каждый затронутый артефакт** из хранилища по каноническому id. Артефакт, переименованный или удалённый после коммита, молча отбрасывается, а не сообщается как ошибка.
4. **Применяет гейт качества** (см. ниже) и классифицирует то, что выжило.
5. **Форматирует результат** как структурированный объект с одним ключом на раздел, плюс `since`, `until`, `draft` и `total`.

Обнаружение git работает с worktree: если `.git/` не рядом с `.forgeplan/`, инструмент поднимается вверх (ограничено ближайшим предком `.forgeplan/` или восемью шагами) и на один уровень вниз, чтобы найти его, отклоняя кандидатов-симлинков.

## Категории

| Артефакт | Раздел | Примечания |
|---|---|---|
| `prd` | `added` | выпущенная функция |
| `problem` | `fixed` | закрытый баг |
| `evidence`, связанный с тегом `security` | `security` | само доказательство или любой сосед с тегом `security` |
| `evidence` без связи с security | `internal` | исключён из пользовательских разделов, но виден в режиме черновика |
| `rfc`, `adr`, `spec`, `epic`, `solution` | `changed` | архитектурные и зонтичные изменения |
| `note`, `memory`, `refresh` | отброшены | никогда не выводятся, независимо от диапазона ссылок |

"Связан с security" - это проверка тега, а не типа: артефакт несёт тег `security`, или любой артефакт, на который он ссылается или который ссылается на него, несёт его.

## Гейт качества

Артефакт имеет **сигнал**, когда его статус `active` или его R_eff-оценка выше нуля. Без `draft: true` всё без сигнала отбрасывается, что не даёт полуготовым черновикам попасть в changelog. Передача `draft: true` полностью отключает гейт и позволяет увидеть недоказанную работу в процессе.

## Входные параметры

| Имя | Тип | Обязательный | Описание |
|---|---|---|---|
| `since` | `string` | нет (по умолчанию: ближайший достижимый git-тег, иначе `HEAD~50`) | Git-ссылка для начала, например `v0.30.0`. Валидируется перед передачей в git. |
| `until` | `string` | нет (по умолчанию: `HEAD`) | Git-ссылка для конца. Валидируется так же. |
| `draft` | `boolean` | нет (по умолчанию: `false`) | Отключить гейт качества: включить артефакты без доказательств и черновики с R_eff равным нулю. |
| `workspace` | `string` | нет | Явная директория рабочего пространства. Когда установлена, сервер разрешает `.forgeplan/` из этого пути вместо своего стартового CWD. PRD-078 / ADR-015. |

_Источник схемы: `crates/forgeplan-mcp/src/types.rs::ReleaseNotesParams`_

Обе ссылки проверяются перед передачей в `git`: пустая строка, начальный `-`, диапазон `..`, начальный не-буквенно-цифровой символ или любой символ вне `A-Za-z0-9 _ / . -` отклоняется. Это намеренно строже собственных правил git для ссылок, потому что ссылка, начинающаяся с тире, иначе была бы распознана как опция CLI git.

## Возвращает

```json
{
  "_next_action": "1 entries. Paste under [Unreleased] in CHANGELOG.md.",
  "added": [
    {
      "commit": "2d7a6ee",
      "id": "PRD-001",
      "kind": "prd",
      "title": "Ship the payment gateway"
    }
  ],
  "changed": [],
  "draft": true,
  "fixed": [],
  "internal": [],
  "security": [],
  "since": "v0.1.0",
  "total": 1,
  "until": "HEAD"
}
```

Каждый ключ раздела всегда присутствует, пустой или нет, так что потребителю никогда не нужно гадать, отсутствует раздел или пуст. Внутри записи:

- `id`, `title`, `kind` берутся прямо из записи артефакта.
- `commit` - короткий (7-символьный) SHA первого коммита в диапазоне, затронувшего файл. Опускается, когда коммит не удалось разрешить.
- `evid` - id связанного EvidencePack, и прикрепляется только к не-evidence артефактам. Записи Evidence никогда его не несут.

Когда гейт отфильтровывает всё, результат всё равно валиден, и подсказка сообщает об этом:

```json
{
  "_next_action": "No artifacts changed between v0.1.0 and HEAD. Widen range or pass draft=true.",
  "total": 0,
  "since": "v0.1.0",
  "until": "HEAD",
  "draft": false
}
```

## Примеры

Заметки с последнего релиза, с гейтом:

```json
{ "since": "v0.30.0" }
```

Тот же диапазон, включая недоказанную работу:

```json
{ "since": "v0.30.0", "draft": true }
```

Всё, что слито с последнего тега, позволяя инструменту выбрать тег:

```json
{}
```

## Примечания

- Инструмент только для чтения: он запускает `git log`, читает хранилище артефактов и ничего не пишет. Он не обновляет `CHANGELOG.md` за вас.
- Плохая ссылка всплывает как ошибка инструмента, а не пустой результат. Ссылка с начальным тире отклоняется валидатором, а ссылка, не существующая в репозитории, возвращается от самого git:

```text
release-notes failed: git log failed: fatal: bad revision 'v9.9.9..HEAD'
```

- В ответе нет трассировки рабочего пространства: это путь чтения, поэтому в отличие от мутирующих инструментов он не сообщает `resolved_via` / `resolved_workspace`.
