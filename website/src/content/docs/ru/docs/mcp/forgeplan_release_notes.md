Автоматически генерирует заметки о релизе в формате Keep-a-Changelog из артефактов, изменившихся между двумя git-ссылками. Проходит по `git log` в `.forgeplan/{prds, problems, evidence, rfcs, adrs, specs, epics, solutions}/`, классифицирует каждый затронутый артефакт (PRD→Added, PROB→Fixed, EVID-on-security→Security, RFC/ADR→Changed) и возвращает структурированный результат. Гейт качества (по умолчанию): включаются только артефакты со status==active или r_eff_score > 0. Передайте `draft: true`, чтобы отключить гейт. `since` по умолчанию - последний git-тег, `until` по умолчанию - HEAD. Пример: `{since: "v0.30.0", draft: false}`.

**Категория**: Прочее

Инструмент выбирает затронутые файлы артефактов из git-истории, затем читает их **текущие записи хранилища** и группирует по разделам Keep-a-Changelog. Он не восстанавливает содержимое на момент `until`, не проверяет выпуск работы и не записывает `CHANGELOG.md`. Проверьте заголовки и доказательства перед использованием записей в релизе.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{}
```

## Что делает

1. **Разрешает диапазон.** `since` валидируется и используется как есть; без него инструмент берёт ближайший достижимый тег (`git describe --tags --abbrev=0`) и откатывается к `HEAD~50`, если в репозитории нет тегов вообще. `until` по умолчанию - `HEAD`.
2. **Обходит добавленные/изменённые файлы.** `git log --name-only --diff-filter=AM` охватывает только `prds`, `problems`, `evidence`, `rfcs`, `adrs`, `specs`, `epics`, `solutions`. Другие каталоги типов не сканируются; удалённые файлы и чистые переименования не выбираются этим фильтром.
3. **Разрешает имена файлов** как канонические ID либо pre-merge slug и читает текущую запись. Неразрешимые или отсутствующие записи пропускаются. Переименованная текущая запись включается, если старый кандидат ещё разрешается.
4. **Применяет гейт качества** (см. ниже) и классифицирует то, что выжило.
5. **Форматирует результат** как структурированный объект с одним ключом на раздел, плюс `since`, `until`, `draft` и `total`.

Обнаружение git работает с worktree: если `.git/` не рядом с `.forgeplan/`, инструмент поднимается вверх (ограничено ближайшим предком `.forgeplan/` или восемью шагами) и на один уровень вниз, чтобы найти его, отклоняя кандидатов-симлинков.

## Категории

| Артефакт | Раздел | Примечания |
|---|---|---|
| `prd` | `added` | классификация по типу, не доказательство выпуска |
| `problem` | `fixed` | классификация по типу, не проверка закрытия бага |
| `evidence`, связанный с тегом `security` | `security` | тег у самого evidence или соседа на расстоянии одной связи, без учёта регистра |
| `evidence` без security-тега/связи | `internal` | включается в обоих режимах, если проходит применимый гейт качества |
| `rfc`, `adr`, `spec`, `epic`, `solution` | `changed` | архитектурные и зонтичные изменения |
| `note`, `memory`, `refresh` | отброшены | никогда не выводятся, независимо от диапазона ссылок |

"Связан с security" - это проверка тега, а не типа: артефакт несёт тег `security`, или любой артефакт, на который он ссылается или который ссылается на него, несёт его.

## Гейт качества

**Сигнал** — сохранённый статус `active` **или** сохранённый `r_eff_score` выше нуля. Это не новый рекурсивный расчёт и не валидация. Черновик с положительной оценкой может попасть в результат; `active` тоже достаточно сам по себе. `draft: true` снимает этот гейт, но не включает исключённые типы, неотслеживаемые/незакоммиченные изменения или файлы вне диапазона git.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `draft` | `boolean` | нет | Отключить гейт качества и включить артефакты без доказательств. По умолчанию false. По умолчанию в схеме: `false`. |
| `since` | `string \| null` | нет | Начальная git-ссылка, например `v0.30.0`. По умолчанию последний тег. |
| `until` | `string \| null` | нет | Конечная git-ссылка. По умолчанию HEAD. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успех — JSON в текстовом содержимом MCP. Значения ниже условные.

```json
{
  "_next_action": "1 entries. Paste under [Unreleased] in CHANGELOG.md.",
  "added": [
    {
      "commit": "2d7a6ee",
      "id": "PRD-001",
      "kind": "prd",
      "title": "Ship the payment gateway"
    }
  ],
  "changed": [],
  "draft": true,
  "fixed": [],
  "internal": [],
  "security": [],
  "since": "v0.1.0",
  "total": 1,
  "until": "HEAD"
}
```

Каждый ключ раздела всегда присутствует, пустой или нет, так что потребителю никогда не нужно гадать, отсутствует раздел или пуст. Внутри записи:

- `id`, `title`, `kind` берутся прямо из записи артефакта.
- `commit` — первые 7 символов лексикографически минимального SHA, собранного для имени файла. Обработчик **не** выбирает хронологически первый или последний коммит. Поле опускается, если SHA не найден.
- `evid` — первый источник входящей связи с префиксом ID `EVID-`, независимо от типа связи. Поле опускается для evidence и при отсутствии такого источника; оно не доказывает валидность или свежесть пакета.

Когда гейт отфильтровывает всё, результат всё равно валиден, и подсказка сообщает об этом:

```json
{
  "_next_action": "No artifacts changed between v0.1.0 and HEAD. Widen range or pass draft=true.",
  "added": [],
  "fixed": [],
  "security": [],
  "changed": [],
  "internal": [],
  "total": 0,
  "since": "v0.1.0",
  "until": "HEAD",
  "draft": false
}
```

## Примеры

Заметки с последнего релиза, с гейтом:

```json
{ "since": "v0.30.0" }
```

Тот же диапазон, включая недоказанную работу:

```json
{ "since": "v0.30.0", "draft": true }
```

Всё, что слито с последнего тега, позволяя инструменту выбрать тег:

```json
{}
```

## Примечания

- Инструмент только для чтения: он запускает `git log`, читает хранилище артефактов и ничего не пишет. Он не обновляет `CHANGELOG.md` за вас.
- Неверные git-ссылки дают текстовую ошибку инструмента (`isError: true`), не пустой результат. Начальное тире отклоняет валидатор; несуществующая ссылка вызывает ошибку git. Условный пример:

```text
release-notes failed: git log failed: fatal: bad revision 'v9.9.9..HEAD'
```

- Этот обработчик не возвращает `resolved_via` / `resolved_workspace`. Ошибки выбора пространства — ошибки инструмента. Это контракт данного обработчика, не общее правило отсутствия трассировки у всех инструментов чтения.
