Показать дашборд состояния проекта - пробелы, риски, слепые пятна, сироты (артефакты без связей), просроченные доказательства и рекомендуемые дальнейшие действия. Это самый важный инструмент MCP для ИИ-агента: вызывайте его в начале сессии, чтобы понять состояние проекта перед началом любой работы.

**Категория**: Дашборды и Графы

## Когда агент вызывает инструмент

- В начале сессии — узнать текущее состояние рабочего пространства. Внешняя память, если подключена, является отдельной системой.
- Перед новой задачей — проверить пробелы в доказательствах, изолированные и просроченные артефакты.
- После изменений или перед релизом — изучить новые замечания.

LLM не требуется. Отчёт помогает выбрать, что изучить, но не заменяет чтение затронутых артефактов.

## Входные параметры

_Объявленных входных полей нет. Вызывайте инструмент с пустым объектом `{}`._

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

| Поле | Значение |
|---|---|
| `total`, `by_kind`, `by_status` | Общее количество и массивы количеств по типам и сохранённым статусам. |
| `by_derived_status`, `stale_count` | Производное состояние актуальности и число просроченных артефактов. `stale` не является сохранённым статусом жизненного цикла. |
| `blind_spots` | Объекты с `id`, `title`, `issue` для решений без доказательств. |
| `orphans` | Строки с ID артефактов, не объекты. |
| `at_risk` | Объекты с `id`, `title`, `reason`. |
| `possible_duplicates`, `active_stubs`, `stale_drafts` | Дополнительные замечания по качеству. |
| `advisory_phase_mismatches`, `phase_read_errors` | Рекомендательные замечания о фазах и число ошибок чтения. `phase_mismatches` также возвращается как совместимый псевдоним. |
| `gitignore_drift` | Пути и причины расхождений правил исключения из git. |
| `next_actions` | Рекомендуемые действия. |
| `verdict`, `verdict_summary` | Машинный вердикт (`empty`, `healthy`, `needs_attention`, `unhealthy`) и пояснение. Не используйте старое значение `debt`. |
| `active_claims`, `active_claim_count`, `skipped_claim_files` | Данные журнала захватов MCP. Захваты рекомендательные и не блокируют запись другими инструментами. |
| `_next_action` | Конкретный рекомендуемый следующий вызов. |

Полей `total_artifacts`, `risks` и массива `stale` нет. Для подробностей об истечении срока используйте [`forgeplan_stale`](/ru/docs/mcp/forgeplan_stale/).

Успешный ответ — JSON в MCP `content[0].text`. Элементы `by_kind` имеют вид `{kind, count}`, оба массива статусов — `{status, count}`. Элемент `possible_duplicates` содержит `id_a`, `id_b`, `similarity`, `title_a`, `title_b`, `kind`; `active_stubs` — `id`, `kind`, `title`, `markers_found`, `message`; `stale_drafts` — `id`, `kind`, `age_hours`, `verdict_set`, `has_links`, `recommendation` (`ready_to_activate` или `incomplete_or_orphan`). Элемент фазы содержит `id`, `title`, `status`, `current_phase`, `advisory`; gitignore — `path`, `reason`; действующая заявка — `id`, `agent_id`, `expires_at`.

`at_risk` и оценки доказательств для `by_derived_status` вычисляются заново как **плоский минимум доказательств**, а не рекурсивная оценка из кеша `forgeplan_score`. Health не переносит оценки по цепочке зависимостей и не применяет штрафы типа доказательства рекурсивного движка. Для `at_risk` нужны связанные доказательства и плоская оценка строго ниже `0.3`; целевые артефакты deprecated/superseded исключаются. Цель без связанных доказательств не попадает в эту проверку риска (но может быть слепым пятном). Поэтому сбой рекурсивной зависимости не обязательно отражается как соответствующий риск health.

Отчёт не исправляет замечания, не активирует черновики, не продлевает доказательства и не задаёт код завершения CI. Внешний вызывающий код должен разобрать `verdict` и применить свой гейт. Рекомендательные расхождения фаз показываются, но не повышают строгость вердикта. Пустое инициализированное пространство возвращает `verdict: "empty"`, а не `healthy`. Сбой рабочего пространства может вернуть текстовую ошибку инструмента, сбой хранилища/отчёта — JSON-RPC ошибку. Ошибки нельзя разбирать как JSON отчёта.

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

{}

## Типичная последовательность

1. Вызвать `forgeplan_health` и прочитать вердикт и замечания.
2. При `needs_attention` или `unhealthy` изучить перечисленные артефакты и выбрать исправление.
3. Повторить после изменений, затем вызвать `forgeplan_route` для следующей задачи.

## Эквивалент CLI

```bash
forgeplan health
```
