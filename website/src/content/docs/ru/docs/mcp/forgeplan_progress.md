Показывает выполнение чекбоксов одного или всех артефактов по строкам списков задач в собственном сохранённом теле каждого артефакта. Группировки по разделам и свёртки дочерних артефактов нет. Парсер распознаёт маркеры `-`/`*` с отступом, затем `[ ]`, `[x]` или `[X]` и пробел; примеры внутри блоков кода не исключаются.

**Категория**: Качество

## Когда агент вызывает её

- **Возобновление сессии** - посмотрите, сколько из PRD / RFC вы фактически реализовали.
- **Проверка спринта** — сравните числа чекбоксов по артефактам, а не по разделам или фазам реализации.
- **Генерация описания PR** - укажите текущий процент завершения, чтобы сообщить о статусе.
- **После отметки чекбоксов** - убедитесь, что парсер увидел ваши обновления `- [x]`.

## Входные параметры

| Имя | Тип JSON | Обязательно | Описание и ограничения |
|---|---|---|---|
| `id` | `string \| null` | нет | ID артефакта. Если опущен, показываются все артефакты со списками задач. По умолчанию в схеме: `null`. |
| `workspace` | `string \| null` | нет | Необязательный явный каталог рабочего пространства для этого вызова. Сервер ищет `.forgeplan/` по этому пути, а не в каталоге запуска. Используйте для агента в отдельном git worktree. PRD-078 / ADR-015. Принимает абсолютный путь или путь с `~`. По умолчанию в схеме: `null`. |

Обязательное поле означает, что ключ должен присутствовать. Значение `null` допустимо только тогда, когда оно перечислено в типе JSON. Значения по умолчанию в схеме не обязательно совпадают с теми, которые использует обработчик и описывает текст.

_Источник схемы: MCP `tools/list`, Forgeplan 0.38.0, `inputSchema`._

## Возвращает

Успешный ответ — JSON в MCP `content[0].text` с `artifacts`, `total_checkboxes`, `total_completed` и `_next_action`. Элемент содержит `id`, `title`, `kind`, `total`, `completed`, `percent`, округлённый до целого процента. Нет `done`, `groups` и верхнеуровневого процента.

Без `id` записи без чекбоксов исключаются. Явный отображаемый ID сравнивается без учёта регистра и включает запись без чекбоксов с `percent: 0.0`; отсутствующий ID возвращает текстовую ошибку инструмента (`isError: true`). Инструмент не отмечает чекбоксы, не активирует артефакты и не проверяет реализацию. Его подсказка об активации не отменяет гейты жизненного цикла.

Условный фрагмент ответа (динамический `_next_action` опущен):

```json
{
  "artifacts": [
    {"id": "RFC-006", "title": "Auth implementation", "kind": "rfc", "total": 18, "completed": 12, "percent": 67.0}
  ],
  "total_checkboxes": 18,
  "total_completed": 12
}
```

## Пример вызова

Аргументы этого инструмента, а не оболочка JSON-RPC. Замените условные ID, идентификаторы сессий и пути значениями из своего рабочего пространства. Соответствие схеме не отменяет проверки рабочего пространства, жизненного цикла и согласия на выполнение.

```json
{}
```

## Типичная последовательность

1. `forgeplan_progress` для конкретного RFC - посмотрите, на чём вы остановились.
2. Реализуйте следующий неотмеченный пункт.
3. `forgeplan_update`, чтобы изменить `- [ ]` на `- [x]`.
4. Снова `forgeplan_progress` - убедитесь, что процент изменился.

## Эквивалент CLI

```bash
forgeplan progress
forgeplan progress RFC-006
```
