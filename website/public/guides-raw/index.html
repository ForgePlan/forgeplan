Интерактивные разборы методологии

Восемь самодостаточных страниц, которые объясняют ForgePlan-методологию через аналогии, визуализации и worked examples. Каждая открывается двойным кликом, читается одним человеком, идёт по сценарию от концепции до cli-команды. Ниже — три способа найти нужный разбор: через вопрос, через рекомендуемый порядок, или через тему.

Откуда начать · по вопросу

три типичных входа

Выберите вопрос, который ближе всего к вашей ситуации. Каждая карточка ведёт в разбор, который отвечает именно на этот вопрос — не на всю методологию сразу.

если вы хотите понять «Как принимать архитектурные решения, чтобы через год команда понимала, почему именно так?» → decision-cycle если вы хотите понять «Как одна строка из Slack превращается в production-ready фичу без скоупа-монстра?» → bmad-cycle если вы хотите понять «Что вообще такое ForgePlan и почему это не очередной ADR-шаблон в Notion?» → forgeplan-cycle

Рекомендуемый порядок чтения

Каждый последующий разбор опирается на предыдущие. Можно скакать, но если читаете впервые — сверху вниз даёт наименьшие пробелы.

01
фундамент · одно решение теория
ADI · DDR · Trust Calculus
Как работает следователь: три гипотезы, проверяемые следствия, evidence. DDR — мотивировочная часть с условиями пересмотра. Trust Calculus — F/G/R-оценка силы доказательств с правилом WLNK.
→
02
приложение к 01 · интерактив 3D-чарт
Trust Calculus в 3D F/G/R
3D-сцена с семью evidence на сценарии /search latency. Плоскость порога F+G+R=12, hover-карточки, выбор гипотезы по WLNK. Сцену можно крутить мышью — учебный артефакт для проектора.
→
03
одна фича теория
BMAD · 13-step PRD · Adversarial Review
Четыре фазы воронки (Brainstorming → Modeling → Architecting → Delivery), 13 секций PRD из которых 3 критичные (Non-Goals, Risks, Open Questions), и adversarial review чужими глазами как third quality gate.
→
04
одна спецификация теория
Spec · Delta · R_eff
Spec против PRD: проверяемое поведение, а не намерение. Delta-формат ADDED/MODIFIED/REMOVED как git diff для требований. R_eff = min(scores) с Evidence Decay — почему среднее обманывает, а минимум — нет.
→
05
сам инструмент meta
Forgeplan как operational layer
POS для методологий: CLI + MCP + .forgeplan/ забирают на себя FPF, BMAD, OpenSpec, QuintCode. 10 типов артефактов (6 в активном ходу) с DAG зависимостей. Четыре depth-уровня и три quality gates в одном validate.
→
06
приложение к 05 · интерактив 3D-граф
DAG Explorer · артефакты в 3D
Plotly 3D scatter с узлами-артефактами и линиями-рёбрами. Knowledge Vault MVP как реальный пример: 22 артефакта, 30 связей, фильтры по типам. Покажет паттерны (здоровая цепочка / blindspot / orphan / разветвление) и трейсируемость одной картинкой.
→
07
приложение к 05 · интерактив калькулятор
Depth Calibrator · routing в реальном времени
Три слайдера (complexity / blast radius / reversibility) + три хард-гейта (public API / security / cross-team) → реал-тайм depth tier + pipeline. Пресеты для типовых сценариев (cosmetic / team feature / public API / auth rewrite). Покрутите слайдеры — увидите, как двигается маркер и меняется список артефактов.
→
08
что после activate теория
Lifecycle · от draft до terminal
State machine с 5 состояниями и 6 переходами: draft → active → {superseded | deprecated | stale} → renew/reopen. Аналогия паспорта с визой. Stale как «забытое состояние», требующее явного решения.
→
09
язык агента ↔ инструмента теория
Hint Contract · 5 маркеров
Как агент перестал галлюцинировать next steps. Пять маркеров (Next: / Or: / Wait: / Done. / Fix:) + пять правил контракта (Presence / Actionability / Determinism / Conditionality / Consistency). Reference card.
→
10
параллельная работа теория
Multi-agent · dispatch · claim · release
Координация 2–5 agent'ов в одном репо без конфликтов. Planner режет работу на конфликт-free buckets, worker берёт под себя с TTL, release возвращает в pool. WIP=1 hard limit. Adversarial review всегда в отдельном agent'е.
→
