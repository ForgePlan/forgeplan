Зачем калибровать

аналогия досмотра в аэропорту

«Полный pipeline ко всему» остановит работу. «Никакого pipeline» обрушит качество

В аэропорту три процедуры: внутренний рейс — быстрая проверка, международный — полный, transit — отдельная. Применить «полный» ко всем — аэропорт остановится. Применить «быстрый» — безопасность рухнет. Нужна калибровка под ситуацию.

Forgeplan делает то же самое для разработки: депт-уровень определяется по характеристикам задачи, а pipeline (какие артефакты создавать) выводится из уровня. Спорить можно — но с CLI, не друг с другом. Калькулятор ниже — это та же формула, только наглядно.

Четыре tier'а · что значит каждый

Шпаргалка по типам артефактов и quality gates на каждом уровне.

● tactical
pipeline: пусто
Косметика, переименования, тривиальный bug-fix. Достаточно commit message. Quality gates не запускаются.
● standard
PRD → RFC → Evidence
Новая фича внутри одной команды без breaking changes. ADI рекомендован, validation gate — да.
● deep
PRD → Spec → RFC → ADR → Evidence → Review
Архитектурный выбор, новая внешняя зависимость, breaking change публичного API. ADI обязателен.
● critical
Epic → PRD[] → Spec[] → RFC[] → ADR[] → Adversarial Review
Security, cross-team, регуляторика. Полный evidence-граф + adversarial review в чистой сессии.
Калькулятор — это не приговор

Хард-гейты (security / cross-team / public API) форсят минимум, потому что цена ошибки высока даже при низкой сложности. Слайдеры — это эвристика, а не закон. Если вы видите «standard», но интуиция кричит «нужен ADR» — создайте ADR. Если калькулятор говорит «deep», а задача обратима за один git revert — упростите. CLI знает правила, но решение принимаете вы.

Как читать этот калькулятор

  1. Начните с пресета «cosmetic». Маркер уйдёт в левый край, pipeline станет пустым, verdict — TACTICAL. Это шкала «нижней границы»: переименование переменной, цвет кнопки, опечатка в README.
  2. Переключитесь на «team feature». Маркер пойдёт в зону standard, pipeline покажет PRD → RFC → Evidence. Это «новая фича внутри команды без breaking changes» — типичная работа sprint.
  3. Затем «public API». Чекбокс Public API API загорится, маркер уедет в зону deep с пометкой «public API forces ≥ deep». Pipeline добавит Spec и ADR. Это контракт, который видят external consumers — стоит ADR.
  4. Финал — «auth rewrite». Security-гейт включит критический режим. Pipeline добавит Epic и Adversarial Review. Это правило «if security → critical» — даже если сложность невысокая, цена ошибки в auth слишком велика.
  5. Покрутите слайдеры вручную. Обратите внимание: при низкой reversibility (легко откатить) tier может опуститься на ступеньку. Обратимость — это страховка от плохого решения. Если можно вернуть всё одним git revert, риск меньше.
  6. В блоке «why» читайте, какие правила сработали. ⚡ перед строкой — это хард-гейт (forces tier), → — score-based. Если видите ⚡, ваш слайдер-скор не главный — гейт перекрыл.
