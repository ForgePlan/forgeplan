Trust Calculus в 3D

Каждое доказательство, на котором держится решение, — это вектор в трёх независимых осях: F (Formality), G (Granularity), R (Reliability). Чтобы выбрать гипотезу после ADI-разбора, мы не считаем среднее по этим осям. Доверие ограничено самым слабым звеном — trust = min(F, G, R). Это правило WLNK.

Три оси, по которым оценивается каждое утверждение

Шкала 0–9 для каждой оси, оси независимы. Одно доказательство может быть строгим, но из ненадёжного источника — слабое звено решит за всё.

Как читать этот разбор

  1. Сначала проекция на одну ось. Посмотрите на E5 (whitepaper, F=7) и E4 (Slack-реплика, F=2). По F кажется, что E5 явно сильнее. Это правда — но только по одной оси. Теперь поверните сцену.
  2. Поверните сцену так, чтобы видна R-ось. E5 опускается к R=3. Тот самый whitepaper, который выглядел твёрдо по формальности, на оси «источник» оказывается внизу. Это и есть момент, когда видно, как среднее обманывает.
  3. Обратите внимание на плоскость F+G+R=12. Всё, что под ней, — слабое evidence. Это не запрет принимать решение. Это требование честно отметить в DDR: «принято при слабом evidence, пересмотреть через 30 дней или после конкретной метрики».
  4. Почему min, а не average. Каждая ось отвечает за свой риск: F — за проверяемость, G — за детализацию, R — за источник. Если хоть один риск провален, решение шатается. Слабое звено = реальное доверие.
  5. Связь с ADI. Trust Calculus без ADI бесполезен. Одна гипотеза — evidence собирается только под неё (confirmation bias). Три гипотезы — три независимых набора evidence — три независимых WLNK. Только тогда выбор честный.
  6. Что можно отдать AI-агенту. Сбор источников, предзаполнение F/G/R-таблицы, поиск противоречий. Финальную R-оценку оставляйте за собой: агент переоценит популярный источник, не увидит коммерческий интерес или потеряет контекст вашей компании.
